## Validated DID_l recipe (binary, non-absorbing, same_switchers=TRUE)

Notation: `F` = a unit's first up-switch period (`_dcdh_first_switch`);
reference period = `F-1`.

* **Effect horizon mapping.** Effect_l (1-based, l = 1..L) ↔ event_time `l-1`.
  The long difference compares `ref = F-1` to `tgt = F + (l-1)`. So Effect_1 is
  exactly the `F-1 → F` long difference (event_time 0). This differs from a naive
  reading of "tgt = F-1+l" only in the off-by-one of the 1-based ℓ; the validated
  form is **tgt = F + event_time** with event_time = l-1.

* **Control set per (F, target).** baseline=0 units with `D = 0` for *every*
  period `s ≤ filter_period`, observed at both `ref` and `tgt`. For effects,
  `filter_period = tgt`. Switch-back units (the `id % 6 == 0` cohort) remain valid
  *switchers* but are excluded from *controls* once ever treated — handled
  automatically by the cumulative-D filter.

* **same_switchers = TRUE.** The switcher set per cohort is the units observed at
  `F-1` AND at all effect horizons `F .. F+L-1`. This makes the switcher count
  constant (72) across the three effects, matching the oracle.

* **Cohort aggregation.** Across cohorts F, weight each cell by its switcher count
  `w_F = n_sw_F / Σ_F n_sw_F`.

* **Placebos.** Placebo_l (1-based, l = 1..P) is the symmetric PRE long difference
  `Y[F-1-l] - Y[F-1]`. The **命门 of the placebo口径**: its control set is the
  SAME never-treated-through-`(F-1+l)` set used by **Effect_l** — i.e. the control
  filter uses the *effect* horizon `F-1+l`, NOT the placebo period `F-1-l`. Using
  the placebo period as the filter gives the wrong numbers (≈0.045 vs oracle
  0.0615). With the effect-horizon filter the placebos match to 1e-16.

### Placebo event_time mapping (chosen)

Placebo_l is reported at **event_time = -(l+1)**: Placebo_1 → -2, Placebo_2 → -3.
This keeps the reported axis strictly monotone (`[-3, -2, 0, 1, 2]`) and leaves
event_time -1 unused (it is the reference period F-1, which is identically 0 by
construction). Oracle Placebo_l / Effect_l are joined to columns **by index**
(Placebo_1 = the least-negative placebo column; Effect_1 = the event_time-0
column), NOT by raw event_time value.

## SE 命门 — analytic influence function

Per (F, target) cell the estimator is a difference of two subgroup means of the
long difference `Δy = y_tgt - y_ref`. The entity influence function is the usual
difference-in-means IF summed across cells per unit, **with one critical DYN
finite-sample detail**:

> Each subgroup's demeaned long difference carries a within-cell **Bessel factor
> `sqrt(n / (n-1))`** (n = that subgroup's size in the cell).

For a switcher i in cohort cell with switcher count `ns`, control count `nc`,
weight `w`:

```
ψ_i += w * (Δy_i - mean_sw) / ns * sqrt(ns/(ns-1))      # switchers
ψ_i += -w * (Δy_i - mean_ctrl) / nc * sqrt(nc/(nc-1))   # controls
```

summed over all cells the unit appears in. The reported IF column is `ψ * N`
(N-scaled to the project convention) so that
`cs_aggregate._se(IF[:,k], arange(N), N)` — which computes `sqrt(Σ ψ²)/N` for the
identity (per-entity) cluster — reproduces the oracle per-ℓ SE.

### Achieved tolerance

| quantity            | spec target | spec fallback | **achieved**        |
|---------------------|-------------|---------------|---------------------|
| point estimates     | 1e-6        | —             | **~1e-16**          |
| per-ℓ SE (from IF)   | 1e-6        | 1e-4 + doc    | **~1e-16** (no gap) |
| IF column mean-zero  | 1e-6        | —             | **~1e-15**          |

The Bessel-within-subgroup correction closed the口径 gap *exactly* (the
uncorrected IF was a uniform ~1.8% low across all five columns; the per-cell
Bessel factor matches DYN element-wise). No residual difference remains, so the
test threshold is set to `1e-9` (well inside machine precision) rather than the
loose `1e-4` fallback.

> Honesty note: this reconstructs the DYN *reported SE* to machine precision via
> a difference-in-means IF + within-cell Bessel correction. It is NOT a claim that
> the array equals DYN's internal influence-function object byte-for-byte — only
> that the clustered (by id) sum of squares of this IF equals the DYN variance.

## Post-core additions (T6–T12, controller)

- **`estimate_dcdh` (bundle assembly).** Wraps the dynamic result into the shared
  `EventStudyBundle` (engine/event_study.py). Added an axis-aligned `estimate`
  list to `estimate_dcdh_dynamic`'s return because `effect_estimate`/
  `placebo_estimate` are in their own (Effect_l/Placebo_l) order, NOT the
  event_time/if_columns axis order — the bundle needs axis-aligned estimates.
  Cluster guards mirror SA (`DCDH_CLUSTER_COL_MISSING/NAN/SINGLE/BAD`, `.astype(str)`).
- **`run_dcdh`.** Reuses `multiplier_bootstrap` (raw arrays, not the bundle type) for
  sup-t bands; emits the result dict; does NOT call `_finalize_did_bundle` (guarded
  by `test_dcdh_no_finalize_touch`). overall ATT = switcher-weighted mean of effect
  columns, flagged `experimental: true`.
- **BUGFIX (T12, caught by the golden's string entity ids `"u00"`).**
  `estimate_dcdh_dynamic` built `unit_ids` via `float(i)` which raised
  `could not convert string to float: 'u00'`. The sa/cs fixtures all use integer
  ids so it never surfaced. Fixed to store `list(ids)` as-is; added a string-id
  regression test. **Lesson (again): fixtures with only integer ids hide string-id
  bugs — the golden's string ids are what caught it.**

## Environment / oracle gotchas

- **R `polars` is a hard dependency of `DIDmultiplegtDYN` 2.3.4** (not on CRAN;
  install from `rpolars.r-universe.dev`). It MUST be `library(polars)`-loaded before
  `did_multiplegt_dyn()` or it errors `object 'pl' not found`. Oracle-generation only;
  the Python suite never calls R.
- **`did_multiplegt_dyn` deparses the `effects`/`placebo` LITERAL expression**, so
  passing a variable (`effects = L`) errors "Positive integer required". Pass literals
  (`effects = 3`). See `generate_oracle.R`.

## Deviation from spec (flagged)

- Capabilities **group = "DID"** (not the spec's tentative "dCDH"), consistent with
  cs_did/sa_did and the contract's allowed-groups vocabulary — keeps the DID family
  in one UI bucket. `requires = ["entity","time","treatment_path"]`.
