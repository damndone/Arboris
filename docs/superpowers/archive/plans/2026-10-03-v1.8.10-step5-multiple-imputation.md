依据：objective 第 5 步、设计文档 §3.5；Codex 2026-09-28 核查（`docs/superpowers/archive/handoff/2026-09-28-codex-verification-request.md` 第 2 条）。参考：P7 分支 `0ef1110c` 的插补实现。按 Codex 建议作为独立功能评审，不混进第 4 步。

## 与 P7 实现的取舍

| 部分 | P7 分支 | 本步 |
|---|---|---|
| 生成 m 份数据 + manifest、派生种子、任何一份不完整就一份都不写 | 有 | **移植**（`imputation.py`），m 上限从 1000 降到 100（与合并上限一致） |
| 合并公式 | 旧 Rubin 自由度 (m−1)(1+1/r)²；“缺失信息比例”实为 λ | **重写**：Barnard–Rubin (1999) 自由度，按 mice 3.19 的写法（λ = 0 无需特判）；分别报告 riv、λ、fmi，定义与 mice 一致 |
| 合并对象 | 每个系数的估计与标准误 | 推断核心：参数向量与完整协方差，同时保存 ū、B、T 矩阵（以后 D1 联合检验要用） |
| 参与的模型族 | 只写死 OLS | 按推断核心判断，并且只开放经 R 对照验证过的（族, 协方差）组合；其余拒绝并列出已开放的组合 |
| 完整数据自由度 | 无 | 取单次拟合的参考分布：t 用 N−K 或 G−1，z 用无穷（Stata 惯例） |
| 合并结果上的推断说明 | 删除 `covariance_evidence` | 保留协方差声明，改写为“t，每个系数各自的 Barnard–Rubin 自由度”，不再显示第一份数据的 t(N−K) |
| 后估计 | 未处理 | 合并结果的推断核心标为不可用并写明原因（需要 D1），所有后估计（含联合检验）读到同一原因 |
| 复杂抽样 | 未处理 | m > 1 且声明了抽样设计时，插补前就拒绝 |
| 插补不完整 | 有缺失值的列被跳过时仍继续 | m > 1 时，模型列有缺失却无法插补（非数值、缺失率超阈值）就拒绝：否则合并结果会悄悄丢掉这些行 |
| 增量缓存 | 未处理 | 只有 m = 1 走缓存命中；多重插补每次重算（缓存只保存一份数据） |

保留了 main 后续的改进：survey 样本一致性修复、标签展示（P7 分支的 diff 会把它们回退，没有搬）。

## 结果

- 合并核心 `backend/workbench/combinators/multiple_imputation.py`；估计阶段分支 `engine/stages/mi_pooling.py`：先拟合第一份数据并检查能否合并，再拟合其余 m − 1 份。
- 已开放：OLS（默认、HC1、聚类）、logit（默认）。对照：R 的 5 份插补数据各自拟合后 `mice::pool`，估计、ū、B、T、标准误、自由度、riv、λ、fmi、t 值、p 值、置信区间全部一致（相对 1e-7；区间端点按标准误尺度）。
- 端到端：运行结果 = 对它自己保存的 m 份数据逐份普通拟合再合并（1e-10），因此运行链路与 R 对照接上。
- 不显示单份数据的数字：规则与族无关——m 次拟合之间取值不同的字段（R²、残差、logit 的 odds ratio 与边际效应等）一律不放进合并结果，并在 `omitted_single_dataset_fields` 里列出名字；残差诊断不做，报告和诊断都写明原因。初版只按清单删字段，自查时发现 logit 的 odds ratio 和边际效应仍是第一份数据的，因此改成这条规则。报告的回归表每个系数显示 df 和 FMI，表下写明 m、Rubin 规则与 Barnard–Rubin 自由度。
- Agent：`model.genesis` 新字段 `multiple_imputations`（2–100），说明文字从已验证清单生成；未开放的族、带抽样设计的请求在计划阶段就拒绝。数据准备步骤 `imputation.mice` 只产出一份数据，传 m 时提示改用建模步骤的字段。Agent 读到的系数行带 df 与 FMI，另有 `multiple_imputation` 段写明 m、合并方法、哪些不报告、联合检验暂不可用。
- 前端：表格视图在合并结果上多出 df、FMI 两列；推断说明一行显示“t，Barnard–Rubin df per coefficient · Pooled from m = 5 imputations”；插补摘要说明是否合并。
- 性能：1 万行、m = 20、OLS，整条运行 6.3 秒（预算 30 秒）。

## 浏览器验收（2026-10-03，本机 country dataset，531 行，只在本地使用）

- 场景 ①：在 Notebook 的 Action 里用中文请求“用多重插补（m = 5）估计 lifeexp 对 imprv_h2o、imprv_san、urban、ind_va 的 OLS（普通标准误）”。Agent 给出 `model.genesis` + `multiple_imputations: 5` 的方案，确认、校验、执行后运行完成。表格视图显示 “Inference: t, Barnard–Rubin df per coefficient · Pooled from m = 5 imputations (Rubin's rules)”，每个系数有 df 和 FMI 两列，没有 R²。把这次运行自己保存的 5 份插补数据交给 R `mice::pool`：系数、标准误、自由度、FMI 全部一致到小数点后 10 位。
- 场景 ②：在合并结果上请 Agent 做 imprv_h2o 与 imprv_san 的联合检验。Agent 明确说合并结果上的联合检验暂不可用（需要 D1），确认 m = 5，并列出各系数的 df 与 FMI。
- 验收中发现并已修复的问题：
  1. 开放清单写成 “ols with the default covariance”，而 Agent 看到的协方差取值是 unadjusted / robust / clustered，本产品 OLS 的默认协方差又恰好是 robust。Agent 因此判断“普通标准误不在开放范围内”，拒绝规划。现在开放清单用请求里的取值来写。
  2. Notebook 单模型路径：方案校验没有把 `multiple_imputations` 交给建模合同去校验，物化时却按白名单把它当成未知参数拒绝。现在两边共用 `GENESIS_RUN_LEVEL_FIELDS`，物化时把它转成运行的插补请求。
  3. 全局 Agent 读的是 `inspect_project_model_coefficients` 和项目总览，不是我先改的 `inspect_result_summary`。它因此无法确认这是合并结果，也说不出联合检验为什么不可用（又一次“验证的不是消费者读的那份”）。现在三处投影都带 `multiple_imputation` 段和每个系数的 df/FMI，总览标签后面加上 “pooled from m = 5 imputations”。
- 自审补充：请求里的 m 不是整数时交给插补模块给出清楚的报错；带权重的拟合在补上 R 对照之前不参与合并。
- 记下未修的模型措辞问题：方案的一条假设把“不报告 R²”的原因说成“协方差是 unadjusted”，实际原因是合并。

## 行为变化

- 建模向导里选择 MICE、没有给 m 时，沿用配置默认 m = 5，现在会真正做多重插补并合并；以前名为多重插补，实际只用一份数据拟合并附一条提示。未开放合并的模型族现在会明确失败并说明原因，不再静默用一份数据。
- m = 1 时仍是单份插补，摘要和报告写明“标准误不反映插补的不确定性”。
