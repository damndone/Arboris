# v1.8 ARMA–GARCH Volatility Workbench Implementation Plan

> Execution checklist for the approved v1.8 specification. This is not a second design document.

**Goal:** Ship one public `time_series.arma_garch` Model Pack for any confirmed time column and numeric value column, with bounded automatic selection, manual orders, sequential ARMA–GARCH, joint AR–GARCH, one-step rolling validation, traceable artifacts, UI, Agent proposals, Compare, and known-truth acceptance.

**Non-goals:** No custom likelihood/optimizer, joint MA–GARCH, multivariate/exogenous/seasonal models, automatic interpolation/filling/aggregation, multi-step forecasting, or automatic VaR claims.

**Reuse:** Existing Pack loader and capability registry, `ModelOptionsContract`, immutable dataset/run model, PipelineDraft/Graph/child-run lifecycle, Artifact index, NodeOperationContext, `model.rerun`, `graph.fork`, Compare, shared task cancellation, FMS, and Development Efficiency Control.

**Libraries:** `statsmodels.tsa.arima.model.ARIMA` for ARMA; public `arch` APIs for ConstantVariance/ARCH/GARCH and joint AR–GARCH. Sequential results keep mean-stage and variance-stage IC separate.

## Delivery controls

- Work only in `.worktrees/workbench-v1.8`; do not pull, rebase, reset, stash, clean, or create another v1.8 worktree.
- Use TDD for each slice: focused failing test, minimal implementation, focused green test.
- Freeze train/validation before selection and persist its hash. Selection code receives training data only.
- Use one implementation owner at a time in the shared worktree; parallel agents perform read-only spec/quality/statistical reviews at checkpoints.
- Record only material failures, decisions, and gates in FMS/DECS. Stop a slice if it exceeds its declared boundary.
- Do not push, open PRs, merge, or tag without separate approval.
