# v1.8.1 Gate 3 — Core Agent Trace v1 · 实施计划

> Spec：`specs/2026-07-22-v1.8.1-agent-notebook-analysis-option.md` §13、DEC-TRACE-001。
> 前置：Gate 2（Context Compiler）已完成 —— `context.compiled` 事件要引用
> `context_id` / `generation_context_hash` / `compiled_context_blob_ref`，
> 没有编译器这条事件是空的。
> 范围：**只做 Core Trace**。评测 episode 切分、成功标签、reward、评分指标、
> 专家标注 UI、训练数据导出，全部 v1.8.2（spec §13.1 的分界线逐条有效）。

## 为什么现在采，而不是 v1.8.2 一起做

以下信息**当时不存，事后无法恢复**：Agent 看到哪一版上下文、哪些内容因预算被截断、
当时的 prompt/模型/vocabulary 版本、原始生成了哪几条 Option、哪条被 validator 拒绝、
用户看见的是 revision 2 还是 3、用户选/改/延后/拒了什么、执行后 required Artifact
是否满足、active head 为何推进或未推进。

但**现在不设计完整评测 Schema**——因为 episode 怎么切、"用户选择"算不算正反馈、
排序准确率怎么算，这些都还没拍板。

```
Trace              = 当时真实发生了什么          ← 本 Gate
Evaluation Episode = 哪些事件组成一个样本，如何评价 ← v1.8.2 从 Trace 构建
```

## 不是"随便多写一点 JSONL"

存储复用 `agent/events.py: AgentEventStream`（已是 per-session durable + replayable
JSONL，幂等 `event_id` + 原子追加）。但**写入内容必须先过版本化 schema**——
否则它只是 debug log，不是以后能稳定消费的证据。现有低层 debug 日志继续保留，
**不整体升级成长期公共 schema**。

## 验收步骤的写法约定（同 Gate 1/2，强制）

- ❌ "事件已写入" → ✅ "第 3 条事件 `event_type == "option.revision.created/v1"`，
  且 `refs.option_revision == 2`、`versions.context_profile == "notebook-plan/v1"`"

## 风险

| 风险 | 缓解 |
|---|---|
| Trace 沦为 debug log | Task 1 的 typed payload 注册表 + 未知类型拒写 |
| 用户选择被当成正确答案 | Task 3 的命门测试（schema 拒绝 reward/label 字段） |
| 原始数据被复制进 JSONL | Task 4 Step 2 的单事件长度上限 |
| 项目数据经遥测外泄 | Task 5 的白名单投影 + 路径断言 |
| 事件写入拖慢 Agent 回合 | 复用既有原子追加；Task 6 Step 1 量实际开销 |
