# v1.8.12 第 8 步计划：公式项名的引号转义（V1811-PUBLIC-TERM-QUOTE）

用户 2026-10-08 裁定：第 8 步本版只做本项；LMM 可读项名与 `context_tools.py` 拆分转 v1.8.13。

## 现状（2026-10-08 核实）

模型公式用 `Q(<Python 字面量>)` 引用列名，大多数地方用 `repr(column)` 生成：

- 普通列名生成 `Q('x')`。
- 列名含单引号时生成 `Q("o'brien")`。
- 同时含两种引号或含反斜杠时，生成带转义的字面量，如 `Q('a"b\'c')`。

反向解析却散落在至少 7 处，各自用 `startswith` / 正则手写：

| 位置 | 问题 |
|---|---|
| `econometrics/normalize._public_term` | 只剥外壳，不还原转义：`a"b\'c`、反斜杠被加倍 |
| `egress._TERM_RE`（外发脱敏） | 只认 `C(Q('…'))`，且引号内不允许 `'`。**列名含单引号时，受保护列的分类取值不被隐去，会外发** |
| `term_parser._C_QUOTED_INNER` | 非贪婪匹配，引号不配对，不还原转义 |
| `checks/context._QUOTED` | 同上 |
| `term_labels._QUOTED` / `_CATEGORICAL` | 不还原转义 |
| `diagnostic_summary._term_base_name` | 只剥外壳 |
| 导出的 Python 脚本 `wb_public` | 只认单引号形式 |

另有两处生成端不一致：

- ANOVA 包用 `f"Q('{column}')"` 生成，列名含单引号时公式直接语法错误。
- MANOVA 用 `json.dumps`。

## 设计

1. 新增 `workbench/formula_terms.py`（只依赖标准库），作为唯一实现：
   - `quote_column(column)` 生成 `Q(<repr>)`。
   - `unquote_column(text)`：`Q(...)` 内若是一个字符串字面量，用 `ast.literal_eval` 还原原列名，否则返回 `None`。
   - `QUOTED_COLUMN_PATTERN`：一段正则，能匹配任一种引号与转义的 Python 字符串字面量，供需要在长文本中查找的地方（外发脱敏、分类项解析）组合使用；匹配到的字面量一律交给 `unquote_column` 还原。
2. 各解析处改为调用它；ANOVA 与 MANOVA 生成端改为 `quote_column`。
   - 实施结果：MANOVA 保留 `json.dumps` 引号，因为它的公式文本是结果信封里的合同；统一读取函数照样能读回。见评估文档。
3. 导出的 Python 脚本助手 `wb_public` 改为同样用 `ast.literal_eval` 还原（脚本自带，不依赖 Workbench）。

## 测试（先写失败）

- 对一组列名做往返测试：
  - 普通列名、`o'brien`、`say "hi"`、同时含两种引号、反斜杠、中文、空格、制表符。
  - 往返路径：`quote_column` → 各解析函数，应还原原列名。
- 外发脱敏：受保护列 `o'brien` 的分类项 `C(Q("o'brien"))[T.Alice]` 必须被隐去为 `[withheld]`。
- 端到端：
  - OLS 用含单引号的列名拟合，结果中的项名等于原列名。
  - ANOVA 用含单引号的因子名拟合成功。
- 原有项名相关测试全部通过。
