## 1. How to read this plan

### 1.1 Task ID convention

`T<track>.<n>` where `<track>` ∈ {1, 2, 3, 4, 5}. T0 is pre-flight.

- T1.x → SSE + Progress
- T2.x → Auto-select first review
- T3.x → LeftRail
- T4.x → Topbar
- T5.x → Polish bundle

### 1.2 Effort sizing

| Size | Wall-clock budget |
|---|---|
| **S** | < 30 min |
| **M** | 30–90 min |
| **L** | 90–180 min |
| **XL** | half a day (use sparingly) |

If a task overruns 2× its budget, **stop** and escalate. Don't push through with thrashing.

### 1.3 Per-task fields

- **Owner**: FE-A / FE-B / BE / shared
- **Effort**: S / M / L / XL
- **Touched files**: exact paths
- **Steps**: sequential, no decision points (those are in the spec)
- **DoD**: observable test or behaviour; no "looks good"
- **Depends on**: upstream task IDs that must be green first

### 1.4 Per-track gate (three-level review)

Per memory `feedback_review_workflow.md`:

1. **Implementer** completes all tasks in track; full FE + BE suites green locally
2. **Test & QA** independently runs full suites + browser smoke for visual tracks
3. **Reviewer** reads full diff, runs smoke independently, signs off
4. **Push** branch only after reviewer signs off

Each track ships one push. T<n+1> starts only after T<n> push.

### 1.5 Execution order

```
T0 pre-flight  →  T5 polish  →  T1 SSE  →  T2 auto-select  →  T3 LeftRail  →  T4 Topbar
   (0.5d)        (2d)          (3d)        (0.5d)            (5-7d)          (3-4d)
```

T5 first because: smallest blast radius, lowest risk, builds team rhythm for the sprint. T1 second because: closes the highest-priority vulnerability and unblocks confidence in the polling code path before we add UI on top. T3 and T4 are the visual heavy lifts; running them last means they benefit from any infrastructure stabilisation T1/T5 produced.

- **Owner**: FE-B
- **Effort**: L
- **Touched files**:

- **Steps**:
  1. Extract polling loop into private `_pollUntilTerminal(...)`.
  2. Add private `_subscribeUntilTerminal(...)`:
     - Open `connectRunEvents(projectRoot, runId, callbacks)`.
     - On every event, build `lastEvent: RunProgressEvent` and call `opts.onTick?.(detail, lastEvent)`. (Need to fetch `detail` lazily — only on terminal — to avoid extra HTTP.)
     - On terminal event, `await fetchRunDetail(...)` once and resolve.
     - On EventSource error, close handle and reject with a marker error.
  3. New `waitForRunTerminal(...)` body:
     - If `typeof EventSource === "undefined"`, return `_pollUntilTerminal(...)`.

  4. Update `onTick` JSDoc to mention optional `lastEvent` second arg. **Signature stays callable with single arg** (TS optional param) — no breaking change for callers that don't care about events.
  5. Bump default `maxMs` from 5 min → 30 min (rationale: SSE is cheap, polling fallback keeps 5 min).
