# v1.8.12 第 4 步计划：全部 133 个接口的生成类型（V1812-OPENAPI-TYPES）

用户决定（2026-10-07）：全部 133 个接口声明响应结构，前端改用生成类型；做成模块化，不逐个穷举手写。

## 现状

133 个操作，仅 1 个声明响应；75 个有请求体；前端手写 `api.ts` 60 个、`notebook/contracts.ts` 50 个类型。

## 设计

1. **声明方式**：处理函数只写返回注解 `-> RunDetail`（TypedDict）。路由类 `TypedAPIRoute` 把注解登记进 OpenAPI，并关闭 FastAPI 的运行时响应校验——线上返回逐字节不变，类型写错不会 500、不会丢字段。
2. **类型模块**：`backend/workbench/http/responses/`，按领域分文件；跨接口复用的结构只定义一次（`common.py`）。内嵌 JSON Schema 记作 `JsonSchema`；由自身合同管理的版本化数据包在信封以下保持 `dict[str, Any]`，除非前端手写类型描述了更深层。
3. **初稿来自真实响应**：`tests/response_recorder.py`（`WORKBENCH_RECORD_RESPONSES`）+ `scripts/infer_response_types.py`（按字段集去重、可选性、映射识别、深度上限）。初稿再对照处理函数代码核对必填性与样本缺失的字段。
4. **统一校验（测试期）**：conftest 中间件对每个 2xx JSON 响应按其声明严格校验（缺字段、类型不符、未声明字段都失败），现有 TestClient 测试即合同测试。
5. **生成与漂移**：`scripts/generate_api_types.py` → `frontend/src/generated/api-schema.ts`；`tests/test_api_types_drift.py` 检查已提交文件与后端一致，并以棘轮把未声明响应数从 132 降到 0。
6. **前端切换**：`api.ts` / `notebook/contracts.ts` 的 HTTP 类型改为生成类型的别名；带版本的运行时解析器保留。

## 执行结果（2026-10-08）

全部批次完成，验收见 `evaluations/2026-10-08-v1.8.12-openapi-types.md`。执行中在设计上补了四件，使“模块化”贯彻到前端：

- `view_of` 也能从 pydantic 模型派生（`stored=True` 表示旧记录可能缺带默认值的字段）；嵌套 dataclass 自动转视图，序列化与字段不一致处用 `define_view` 声明一次。
- 生成器关闭 `defaultNonNullable`：TypeScript 与测试期合同一致，带默认值的请求字段保持可选。
- 前端 `ResponseOf<路径, 方法>` / `RequestOf<路径, 方法>`：API 函数写路径即得类型。
- `apiTypeProvenance.test.ts`：编译器逐字段判断 API 函数返回值是否来自生成文件，手写结构 66 → 0 后作为不变量。
