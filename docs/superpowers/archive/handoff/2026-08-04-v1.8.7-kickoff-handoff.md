## 4. 执行方式

### 4.1 TDD 是硬要求

先写失败测试，**贴出修复前的失败输出**，再实现。不接受「测试通过」但没有修复前失败证据。

自查命令（用来识破「拿 baseline 既有测试当修复证据」）：

```bash
git log -S "def <test_name>" --oneline
```
```bash
git show --stat <commit>
```

### 4.2 验收一律以「用户可达」为准

**这是 v1.8.6 最贵的一条教训，必须继承。**

那一版有四处「内核写好、单测通过、用户完全碰不到」：

| 能力 | 症状 |
|---|---|
| FeatureRecipe 5 个算子 | `http/` `services/` `frontend/` 零引用 |
| 8 个统计函数 | 后端非自身引用数全部为 0 |
| `frequency_weight` | API 传不进来 |
| `SampleSpec.content_hash()` | 全仓从未被调用 |
| 单样本/配对/Wilcoxon | 唯一调用点不传参数，API 无字段 |

全部测试通过，全部等于不存在。

所以每条验收都要写成「**跑一次真实 run / 点一次真实 UI，能看到什么**」的形式。
反例：「函数已实现且有单测」。正例：「一次普通 run 产出的 `statistical_tests`
artifact 中必须出现 `anova_posthoc` 条目」。

### 4.3 数值正确性要有外部 oracle

v1.8.6 发现的最严重缺陷（`frequency_weight` 执行成了分析权重语义，SE 全错）
**不是靠测试发现的**，是靠对照独立实现发现的。

- 有第三方实现的（Stata / R）→ 逐位对照，标注容差
- 没有的 → 用**定义**构造 oracle（如频数权重＝按权重展开行后跑普通 OLS）
- 用同一个执行引擎（如 statsmodels）复核**不算**外部 oracle，必须如实标注为内部一致性

release notes 里必须按能力**分别标注验证等级**，三选一：
「对 X 逐位验证」/「仅内部一致性测试」/「未对外部实现验证」。

### 4.4 其他硬规则

- 不做枚举式修复，优先修共享契约与通用入口
- 不写死作业名、固定年份、特定数据集列名
- regex 用仓库现行的非 `\b` 边界规则
- `# legacy-compat` 只能读已有旧键，不能写新后门
- FMS 的 FAILURE / ERROR / GAP / WASTE / REVIEW / GATE / STATE_CHANGE 一律走正式 CLI
- 未经明确授权，不 push / 不建 PR / 不 merge / 不 tag

## 5. 验收标准

### 5.1 门槛（v1.8.6 实测基线，只许涨不许跌）

```
bash scripts/gate.sh --full        → GATE PASSED
后端全量                            → 4631 passed, 2 skipped, 1 xfailed
golden / invariants / snapshot      → 23 passed，0-drift
前端                                → 188 files / 1634 tests passed
TypeScript                          → tsc --noEmit 通过
devline_control.py verify --all     → 通过
```

**golden 0-drift 是硬约束。** 若某项行为变更确实需要改 goldens：

1. 先确认这是**有意的产品决定**，由人拍板，不是让测试变绿
2. 重新生成后必须做**结构化比对**，逐文件确认差异范围（不能只看行 diff）
3. 用户可感知的变更必须写进 release notes

v1.8.6 有过实例：PDF/XLSX 改按需导出 → 15/16 golden 漂移 → 确认是有意决定 →
重生 + 结构化审计确认「差异仅限 `report_pdf` / `tables_xlsx` 移除」→ 写进行为变更章节。

### 5.2 真机验收

确定性测试盖不住的必须真机走：UI 交互、Agent 端到端、跨页面状态。
v1.8.6 靠真机 + 真 DeepSeek 抓到了「Agent 读不到统计证据」这个纯可达性缺陷。

服务启动一律走 `.claude/launch.json` + preview 工具，**不要用 Bash 起 dev server**。
已有可用条目：`backend-v186`(8026) / `frontend-v186`(5186)。
v1.8.7 新增条目时换新端口，避免多会话冲突。

### 5.3 收尾

- release notes 逐项标注验证等级，已知限制写清楚**用户自己发现不了的那些**
- 每个数字写进文档前对着日志核一遍
- 未完成项如实列出，不要用「已完成」概括

## 6. 范围候选与推荐

### 方向 A · 统计工具箱（对标 SPSS/Stata）

当前覆盖约六成。剩余缺口按要紧程度：

1. **svy 分层 + PSU**（`strata` / `PSU` 目前只存在于错误信息里）
   —— 不做，调查数据（CGSS/CFPS/CHARLS/NHANES）的方差估计就是错的
2. **有序 logit 的自动路由或提示** —— 整数量表现在静默跑 Poisson，用户看不出来
3. 双因素 ANOVA / ANCOVA / 重复测量、Tobit / 截断 / Heckman / 条件 logit
4. PCA / EFA / Cronbach's α / 聚类（**这批不是加模型，是加新节点类型，成本高一档**）

### 方向 B · ML 正确性（关闭下一类不可见失败）

1. **列级可得性（availability provenance）** —— v1.8.6 只关闭了「行的泄漏」。
   实测：把时间序列标成 IID，一个显式未来位移的特征能跑出 r² > 0.9 而不被拦截。
   `AvailabilitySpec` 字段已留好，这一版是填空不是重建。
2. **正对照** —— 现在只有负对照。一个永远返回「无发现」的假实现能通过全部现有对照。

### 推荐

**A1 + A2 + B1，其余不做。**

理由：这三条的共同点是「不做就会静默出错，而用户没有能力发现」。其余缺口的性质是
「暂时没有」，用户至少知道自己没有。

另外强烈建议加一条不新增任何功能的工作：**给 v1.8.6 的四个新模型族补外部 oracle**
（ordinal / multinomial / quantile 目前只有内部一致性，复核用的还是执行引擎自己）。
它把「六成能力」变成「六成**可信**能力」，比变成「九成存疑能力」值钱。

## 7. 常见坑（本轮真踩过）

| 坑 | 表现 | 规避 |
|---|---|---|
| shell cwd 重置 | heredoc 后 cwd 回到主 checkout，命令静默跑错仓库 | **每条命令显式 `cd`**；用日志里的路径反查跑在哪 |
| Vite 占用端口 | `test_gate_script.py` 11 个失败，报 `REFUSING: a vite dev server is running` | 跑 gate 前先停 Vite |
| 中文路径 locale | 假失败 | `LANG/LC_ALL=en_US.UTF-8` |
| worktree 缺依赖 | import 失败 | `link-shared-deps.sh <绝对路径>` |
| 测试 glob 写错 | **测试通过是假象** | 断言用到路径时，先打印实际产物路径核对 |
| 阈值设太松 | 泄漏 run r²=0.988 低于 0.99 阈值而假通过 | fixture 要让「信号」与「泄漏」可区分 |
| 嵌套 Seatbelt | 约 20 个 containment 假失败 | gate 在宿主终端跑；先跑一次 containment 测试探路 |
| 多 agent 同 worktree | 整文件提交会卷入他人在制品 | 提交前 `git diff -U0` 数 hunk，确认哪些是自己的 |
