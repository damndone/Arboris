### Critical:legacy-run 处理在生产上死掉
根因:`GET /graph`(`build_project_forest`)硬编码 `legacy: False`,且 `build_headset` 会**跳过** legacy 成员(无 node_index 的老 run)。所以 `WorkbenchHome` 里 `forest.legacy && focusRunId` 这个分支永远进不去,`LegacyGraphWorkbench` 变成死代码。后果:
- **(a)** `/runs/{legacyRun}` 深链(重定向成 `?run=`)现在静默渲染**最新 head 的森林**,而不是那个 legacy run 的图。
- **(b)** 一个**所有 run 都早于血缘索引**的项目,会渲染 `EmptyProjectCanvas` 显示「这个项目还没有数据」——**事实错误**,项目明明有 run。

**修法(在 `frontend/src/workbench/WorkbenchRouteContainer.tsx`):**
1. **深链恢复**:`WorkbenchHome` 里当 `focusRunId` 存在但**不在** `forest.heads` 的 run_id 集合中时,单次 fetch `getRunGraphHeadSet(focusRunId)`(旧的 run-keyed 端点仍提供 R5 legacy 降级,`api.py:1020`);若返回体 `legacy:true` → 渲染 `LegacyGraphWorkbench`(恢复旧行为)。非 legacy 的 miss → 维持现状(落最新 head)。
2. **全 legacy 项目的诚实空态**:项目返回体的 `families` 即便 heads 为空也非空(`project_forest.py:96-98`)。把 `families` 透传出来(扩展 `adaptHeadSet` 输出一个 families count,或在 `useForestData` 里从原始响应读出 `familyCount`)。`WorkbenchHome`:heads 空 **且** familyCount>0 → **不要**说「这个项目还没有数据」,改诚实文案:「该项目的 N 个 run 早于血缘索引(legacy),不能在图中显示——可通过 run 详情页(`?tab=overview`)查看」,**并保留**「＋ 新链路」创世 CTA(legacy 项目照样能起创世链)。
3. 修 `WorkbenchRouteContainer.tsx:92-95` 那条现在已失真的注释。
- 两条都加测试(legacy 深链恢复渲染 `LegacyGraphWorkbench`;全 legacy 项目显示诚实文案+CTA,不是假空态)。

## 5. 方案核心(冷启动需要的 mental model)

**三层分离,赌契约不赌 UI**:
1. **数据模型层**(倒转发生地):节点先于 run 存在。创世 = 无父 draft 链,泛化 v1.6.7 的 `draft→validated→executed` 生命周期。execute 收敛进 `_submit_run`,回填后与 rerun 产的节点在森林里**无差别**——不存在两种图。
2. **操作契约层**:`NodeOperationContext`(v1.6.2)为唯一语义入口。未来 v1.6.9 的 compare/askAI/report 都是往这层「加操作」。
3. **宿主层**(可换):抽屉/底部面板/画布右键只负责渲染,不承载语义。

**路由倒转**:`/`=Launcher,`/p/:slug/graph`=项目的家(slug=base64url(project_root),避开路径段 `%2F` 的雷),`/runs/*` 重定向,`/submit` 隐藏兜底。**`?run=` 是 run 深链参,`?focus=` 归 workbench URL schema(节点聚焦键)——两者绝不混用**(这是 T9 评审抓到的 C1 真雷)。

- spec:`docs/superpowers/specs/2026-07-03-v168-graph-native-genesis-design.md`(含 §10 自审 F1–F10)
