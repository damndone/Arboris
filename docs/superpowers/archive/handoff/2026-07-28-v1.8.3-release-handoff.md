# Workbench v1.8.3 release handoff

## 当前状态

`v1.8.3` 是 Capability Factory、受控 `model.custom` 和双层领域记忆的
发布版本。发布后的准确版本身份应以 Git tag `v1.8.3` 为准，不要以某个开发
worktree 或本地 `main` 的历史 SHA 推断。

代码范围已完成并有完整 host gate 证据；生产 authority/key provider 以及
跨宿主部署验收仍是刻意保留在部署环境的后续工作，不是产品内置 fallback。

## 已实现

- CF1–CF4：能力需求解析、候选比较、bundle validity、scoped admission、
  Adapter、独立证据/晋级、Notebook option、确认、唯一 dispatch、Run/Graph/
  Artifact/Report 投影。
- B0/CORE/B1：通用 authority verifier、local identity、Darwin experimental
  containment adapter、broker/supervisor 与 terminal attestation join。
- CF2 本机 scanner worker：密封依赖树 metadata、许可证 allowlist、OSV、
  SBOM/build/policy binding、worker digest pin 与 freshness expiry。
- MEM1–MEM3：项目索引、双开关的领域记忆、候选/批准/来源访问/冲突/审阅和
  Notebook projection。
- `WORKFLOW_STEP_SPEC_CONTRACTS` 驱动可组合 workflow 的协议投影。

## 已验证

- `bash scripts/gate.sh --full`：backend 4141 passed、8 skipped、1 xfailed；
  golden 23 passed；frontend 169 files/1430 tests；TypeScript 通过。
- 当前 macOS 真机：real generated-adapter Darwin E2E 与 Notebook
  `model.custom` HTTP E2E 均通过。
- Browser：普通 Notebook/OLS 用户流程 smoke 已完成；`model.custom` 的
  browser-click acceptance 未单独执行，不能补写为已验收。

## 未完成及原因

1. **生产 authority/key provider。** 产品只提供 verifier 和 deployment port，
   不应把测试或本机私钥写入仓库。需要未来受信部署提供 key custody、trust
   snapshot、nonce/revocation state 和 execution-result attestation source。
2. **部署级 scanner/attestation 服务。** 本机 worker 是安全的 experimental
   基线；集中式许可证裁定、CVE snapshot 保留/撤销和企业 SBOM attestation
   需要部署方选择并接入，不能由 Agent 自行配置。
3. **跨宿主 acceptance。** 当前证据只覆盖本机 macOS experimental profile。
   Linux、Docker/VM、其他 Darwin 版本/硬件或多用户场景需各自独立 canary 与
   E2E；不要由本机通过推导。

## 不可破坏的边界

- 不在 Workbench 主环境动态安装依赖；网络 fetch、quarantine、验证和分析
  必须保持分离。
- 不为可用性加入弱 containment fallback；canary 失败或过期时拒绝执行。
- Agent 不能提供 scanner command、签名材料、admission/evidence tier，或绕过
  Proposal/Risk/用户确认。
- `model.custom` 不得复用内置模型的 diagnostics、figure、compare 或 rerun
  解释；每个 consumer slot 必须显式声明。
