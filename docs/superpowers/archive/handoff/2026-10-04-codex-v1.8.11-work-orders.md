## 0. 所有 Lane 都必须遵守的规则

违反规则时怎么处理：
- **误写了 owned files 以外的已有文件**：先运行 `git diff --stat` 和 `git status --short`。没有变化（内容与基线一致）→ 在报告“事故”一节记一行，**继续工作**，不要停。
  有变化 → `git checkout -- <路径>` 恢复，记一行，继续。
- **只有这几种情况需要停下来报告**：无法恢复的改动；任何 push、merge、rebase、tag 或删除；需要改合同或中心文件才能继续（写进“合同变更请求”，然后做能做的其余部分）。

命令的写法：
- 一次工具调用只做一件事；必须连写时用 `set -euo pipefail` 或 `&&`。
- 不用 perl 或 sed 改复制来的脚本。R / Stata 脚本的输出目录与参数从命令行读；运行生成脚本前先打印将写入的目录，确认在你的 owned 目录下。

规则：

1. **不 push、不 merge、不 rebase、不 tag、不删除任何分支、worktree、tag 或 stash。** 不在 `main` 或 `workbench-v1.8.11` 上提交。

## 1. 工作方式

- **限时**：每条 Lane 的每个子项都有限时（见各节）。到时没有结论，把证据写进报告、标为“未决”，转到下一项。
