## C1 联合 ARMA(p,q)–GARCH（Lane M1）

### 函数

`backend/workbench/engine/packs/arma_garch/joint_mle.py`（新文件）：

```python
def fit_joint_arma_garch(
    values: np.ndarray,
    *,
    mean_p: int,
    mean_q: int,                 # >= 1；q == 0 仍走现有 fit_joint_ar_garch（arch 后端，不改）
    include_constant: bool,
    variance_spec: VarianceCandidateSpec,
    time_index_semantics: str,
    presample: Literal["stata"] = "stata",
    vce: Literal["opg", "oim", "robust"] = "opg",
    start: Mapping[str, float] | None = None,
    max_iterations: int = 500,
) -> JointArmaGarchResult
```

`estimation.py`：

- `ResolvedStrategy` 增加 `"joint_arma_garch"`；`resolve_estimation_strategy("joint", mean_q>0)` 返回它，不再抛 `UNSUPPORTED_JOINT_ARMA_GARCH`。
  `"auto"` 的映射**不改**（q > 0 仍是 sequential）；是否改由 Lane A 决定。
- `estimate_arma_garch` 对 `joint_arma_garch` 调 `fit_joint_arma_garch`，返回 `JointArmaGarchResult`。

`volatility.py`：

- `fit_joint_variance_candidate` 与 `search_joint_variance_candidates` 接受 `mean_order[1] > 0`，内部调用 `fit_joint_arma_garch`；
  返回的 `VarianceCandidateResult` 字段不变（`estimation_strategy="joint"`、`joint_likelihood=True`）。

### 统计语义（必须与 Stata 18 `arch` 默认一致）

- 模型：`y_t = μ + u_t`，`u_t = Σφ_i u_{t−i} + Σθ_j ε_{t−j} + ε_t`，`ε_t | F_{t−1} ~ N(0, σ²_t)`，σ²_t 为 `variance_spec` 指定的 GARCH(r,s)/ARCH(r)。
  ARMA 作用在扰动项上，`μ` 是均值而不是截距（与 Stata `arch y, ar() ma()` 的参数化相同）；`include_constant=False` 对应 `noconstant`。
- 预样本：`presample="stata"` 复现 Stata 的 `arch0(xb)` 与 `arma0(zero)` 默认（含 Stata 对预样本方差的具体定义），全样本参与似然，不丢弃观测（`hold_back = 0`）。
  实现前先用 Stata 文档与实跑确认定义，写进模块 docstring。
- 方差：`vce="opg"` 为 Stata `arch` 默认；`oim`、`robust`（准 ML 夹心）对应 `vce(oim)`、`vce(robust)`。参考分布为正态。
- 失败要明确：不收敛、参数越界（ω ≤ 0、α/β < 0、平稳性）、非有限似然都抛带代码的错误（沿用 `errors.py` 的 `diagnostic` 形式），不返回部分结果，也不静默改用 sequential。

### `JointArmaGarchResult`

frozen dataclass，`to_dict()` 输出以下键（与 `JointArGarchResult.to_dict()` 同名的键语义相同）：

| 键 | 说明 |
|---|---|
| `display_name` | `"Joint ARMA(p,q)-variance(r,s)"` |
| `model_family` | `"arma_garch"` |
| `mean_order`、`variance_order` | `[p, q]`、`[r, s]` |
| `estimation_strategy`、`resolved_strategy` | `"joint"`、`"joint_arma_garch"` |
| `backend` | `"workbench_joint_mle"` |
| `innovation_distribution` | 本版只支持 `"normal"`；其他分布抛 `UNSUPPORTED_JOINT_DISTRIBUTION` |
| `joint_likelihood` | `true` |
| `hold_back` | `0` |
| `presample` | `{"method": "stata", "arch0": "xb", "arma0": "zero", ...实际使用的预样本值}` |
| `nobs` | 进入似然的观测数 |
| `converged`、`convergence_details` | 优化器、迭代次数、梯度范数 |
| `parameter_names` | Stata 顺序：`mu`（若有）、`ar1..arp`、`ma1..maq`、`omega`、`arch1..`、`garch1..` |
| `parameters` | `{name: value}` |
| `standard_errors` | `{name: value}`，按 `vce` |
| `covariance` | `{"names": [...], "matrix": [[...]]}` |
| `vce` | `"opg"` / `"oim"` / `"robust"` |
| `parameter_constraints` | 同 `validate_variance_parameters` |
| `log_likelihood`、`aic`、`bic` | AIC = −2LL + 2k，BIC = −2LL + k·ln(nobs)，k 含全部估计参数（同 Stata `estat ic`） |
| `conditional_series` | 键同现有：`alignment`、`mean`、`residual`（ε_t）、`variance`、`volatility`、`standardized_residual`、`squared_standardized_residual` |
| `persistence` | `persistence_payload(...)` |
| `warnings` | 列表 |

### 对照与验收

- Stata `arch`（本机 StataMP，用 `tests/stata_oracle.py`）：至少 ARMA(1,1)–GARCH(1,1) 有常数 / 无常数、ARMA(2,1)–GARCH(1,1)、ARMA(1,1)–ARCH(2) 四组合成数据（`set seed`，N 在 1500–3000）。
  对数似然相对差 ≤ 1e-6；参数绝对差 ≤ 1e-4；标准误相对差 ≤ 1e-3（三种 vce 各测一组）。数据与 Stata 结果存 `tests/fixtures/arma_garch_joint/`。
- 性能：N = 2540 的 ARMA(1,1)–GARCH(1,1) 单次拟合 < 10 s（目标 < 2 s，便于 509 次滚动重估 < 3 min）。
- VIX 真实数据只由 Claude 在本地验收，Lane M1 不读 `~/Downloads`。

## C2 负二项（Lane M2）

### 函数

新模块 `backend/workbench/econometrics/count_models.py`（拟合与检验的实现都放这里）；`runner.py` 里只改 `run_negative_binomial` 与 `run_glm` 两个函数体，改为委托新模块，签名只增加关键字参数：

```python
def run_negative_binomial(frame, y, x, model_id, categorical_x=None, *,
                          dispersion: Literal["mean", "constant"] = "mean",
                          alpha: float | None = None) -> tuple[dict, Any]

def run_glm(frame, y, x, model_id, family_name, categorical_x=None, *,
            alpha: float | None = None) -> tuple[dict, Any]
```

### 统计语义

- `negative_binomial`，`alpha=None`：ML 联合估计 β 与 α。`dispersion="mean"` 为 NB2（Var = μ + αμ²，Stata `nbreg` 默认），
  `"constant"` 为 NB1（Var = (1+δ)μ，Stata `nbreg, dispersion(constant)`）。标准误为 OIM（同 Stata 默认）。
- `negative_binomial`，`alpha=a`（a > 0）：α 固定、只估计 β，对照 Stata `glm y x, family(nbinomial a) link(log)`（默认 OIM）。不报告 α 的区间与 LR 检验，结果写明固定值。
- `glm` 且 `family_name="negative_binomial"`：`alpha` 必须给出，否则抛 `ValueError("GLM_NB_ALPHA_REQUIRED: ...")`；不再默认 1。
  标准误沿用 IRLS 的期望信息（与 R `glm(family = MASS::negative.binomial(theta = 1/alpha))` 一致，已有工单 B 对照）。
- GLM 收敛：所有 GLM 族统一收紧，使系数对 R `glm.control(epsilon = 1e-14)` 一致到 1e-8；binomial、poisson 已有对照必须继续通过。
- 过度离散检验（仅 α 被估计时）：H0: α = 0（NB1 为 δ = 0），LR = 2(LL_NB − LL_Poisson)，在边界上用 χ̄²(01)：p = ½·P(χ²₁ ≥ LR)，LR ≤ 0 时 p = 1（同 Stata 输出 `LR test of alpha=0`）。
  Poisson 的 LL 在同一估计样本上拟合得到。
- α 的区间：在 ln α 上用 Wald 区间再取指数（同 Stata 的 `/lnalpha` 与 `alpha` 两行）；NB1 同理用 ln δ。

### 结果字典（在现有 `normalize_statsmodels_result` 输出上增加 / 调整）

| 键 | 说明 |
|---|---|
| `model_type` | `"negative_binomial"` 或 `"glm"`（不变） |
| `coefficients`（及现有系数表结构） | **只含回归系数**，不再有 `alpha` 行 |
| `ancillary_parameters` | 列表，每项 `{name, estimate, std_error, conf_low, conf_high, scale}`：估计 α 时为 `lnalpha`（scale `"log"`）与 `alpha`（scale `"natural"`，标准误用 delta 法）；NB1 为 `lndelta` 与 `delta` |
| `dispersion` | `"mean"`（NB2）/ `"constant"`（NB1） |
| `alpha_estimated` | `true` / `false` |
| `alpha_fixed_value` | 固定时的 α，否则 `null` |
| `overdispersion_test` | 仅 α 被估计时：`{statistic, df: 1, p_value, distribution: "chibar2(01)", restricted_model: "poisson", log_likelihood_restricted}`；否则 `null` |
| `information_matrix` | `"observed"` / `"expected"` |
| `convergence` | `{converged, iterations, tolerance, criterion}` |

返回的第二个值（fitted 对象）仍是 statsmodels 结果，推断核心的提取由 Lane A 调整（α 作为辅助参数标注，后估计只接受回归系数的假设）。
M2 在报告里写明 fitted 对象里 α 的位置与名字。

### 对照与验收

- Stata：`nbreg`、`nbreg, dispersion(constant)`、`glm, family(nbinomial 0.5) link(log)`；R：`MASS::glm.nb`（θ = 1/α）。
  系数 ≤ 1e-6 绝对差（ML 优化器差异，写明），标准误相对差 ≤ 1e-4，LR 统计量相对差 ≤ 1e-5，α 相对差 ≤ 1e-4。数据与结果存 `tests/fixtures/count_models/`。
- 工单 B 的 `tests/test_admission_oracle_glm_negative_binomial.py` 在显式 `alpha=1.0` 下通过（测试调用需要加 alpha 时，在报告里写明，由 Lane A 改调用方）。
- 性能：NB2，10 万行、10 个自变量 < 5 s。

## C3 脚本导出（Lane S）

### 输入与输出

- 输入：`ScriptPlan`（`backend/workbench/script_export/plan.py`，已冻结）。由 Lane A 从血缘构建；Lane S 只消费，不读图、不读 `run_inputs.json`。
- 入口（新文件 `backend/workbench/script_export/render.py`）：

```python
def export_script(plan: ScriptPlan, language: Language, *, require_native: bool = False) -> ScriptExport
```

  `require_native=True` 且有步骤不能原生导出时，抛 `ScriptExportRefusal("NOT_FULLY_NATIVE", ..., steps=(...))`，列出这些步骤，不生成脚本。

### 导出声明（不在生成器里按名字写死）

- 新包 `backend/workbench/script_export/exporters/`：每个操作一条 `ExporterSpec(operation, per_language)`，
  每种语言给出 渲染函数 + 覆盖状态（`native` / `native_with_equivalence_note` + 说明），或 `snapshot` + 原因。
- 漂移测试：`data_operation_declarations()` 里每个数据操作、`MODEL_FAMILY_CONTRACTS` 里每个模型族、`postestimation.registry.OPERATIONS` 里每个后估计操作，
  三种语言都必须有一条声明（原生或带原因的快照）；新增能力缺声明时测试失败。只读这些注册表，不改它们。

### 脚本结构（三种语言相同）

1. 头部：Workbench 版本、project/run id、`lineage_hash`、生成时间不写（脚本内容须可复现，同一 plan 生成同一文本）。
2. **覆盖表**（注释）：每一步一行：step_id、操作、状态、说明。
3. 读入源文件：按文件名读脚本同目录的文件，先校验 SHA-256，不一致即报错停止。读法须与 Workbench 一致（CSV 全部按双精度读，Stata 用 `import delimited ..., asdouble`）。
4. 逐步执行：原生步骤写原生命令；快照步骤读 `snapshot.filename`、校验 SHA-256 与行列数，写明“此步在 Workbench 中完成：<label>”。
5. **末尾自检**：对每个步骤 `expected` 里的数字写断言，容差取 `step.tolerances`，否则 `DEFAULT_TOLERANCES`；任一不符即报错退出（Stata `assert`/`exit 9`、R `stop()`、Python `raise AssertionError`）。
6. 随机步骤设置 `seed`。

Python 优先直接调用与 Workbench 相同的引擎库（statsmodels、linearmodels、arch、pandas），只有 Workbench 自实现的估计量才 `import workbench`，并在覆盖表里注明需要安装 Workbench。

### 本版须原生覆盖的组合（每个都要实跑对照测试）

- 数据：`data.subset`、`data.recode`、`data.rename`、`data.fill_missing`、`data.dedupe`、`data.merge`、`data.append`、`data.aggregate`、`data.reshape`、`data.lag`、`data.tsset`。
- 模型：`ols`（unadjusted / robust HC1 / clustered CR1 t(G−1) / hac Newey–West）、`logit`、`probit`、`poisson`、`negative_binomial`（NB2）、`glm`（binomial、poisson）、`iv_2sls`、`panel_ols`、`did`；分类自变量的基准水平与 Workbench 一致；带权重的 OLS（频数、分析、抽样权重中 Workbench 支持的那些）。
- 后估计：`wald`、`lincom`、`nlcom`、`lr`、`margins`（在上述族已开放的范围内）。
- 其余（ARMA–GARCH、LMM、DID 系列估计量、Cox 等）本版可以是快照或 `native_with_equivalence_note`，但必须有声明与理由。
- 对照方法：用 `tests/fixtures/script_export/` 下的数据与 plan，在测试里先用 Workbench 的数据操作注册表与 runner 函数执行 plan、填入 `expected`，再生成三种脚本，
  分别用本机 Stata（`tests/stata_oracle.py` 的二进制）、`Rscript`、`.venv/bin/python` 实跑，断言脚本退出码为 0（即自检全部通过）。缺软件或缺 R 包时测试明确失败并说明，不静默 skip。

### 已知坑（照 Stata / R 的行为对齐 Workbench，而不是反过来）

- 缺失值：Workbench 列表删除；Stata 的缺失值大于任何数（`if x > 5` 会包含缺失），筛选条件要加 `!missing()`。
- 字符串分类变量：基准水平取 Workbench 实际使用的水平（看结果里的项名），Stata 用 `ib#.` 或先 `encode` 再指定基准，R 用 `relevel`。
- 聚类：Stata `vce(cluster)` = CR1 + t(G−1)；R 用 `sandwich::vcovCL(type = "HC1")` + `lmtest::coeftest(df = G − 1)`；fixest 的 `ssc` 要对齐。
- 去重 `keep first/last` 依赖行序：先按 Workbench 的行序（源文件行号）稳定排序。
- 数字格式：断言用完整精度，不用格式化后的显示值。

### 安全

- 导出文本与快照只写本地；生成函数不做任何网络或外发调用。外发管控（把脚本交给大模型或发出）由 Lane A 接入。
- 文件名只用 plan 里的裸文件名，拒绝路径分隔符（合同已检查）；脚本里不写绝对路径。
