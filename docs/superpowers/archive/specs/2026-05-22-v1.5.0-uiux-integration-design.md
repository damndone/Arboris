## 1. Goals and non-goals

### 1.1 Goals

Deliver a forward-compatible foundation for the UIUX redesign by:

1. Establishing the **GraphViewModel boundary** (adapter layer) so UI never consumes backend schema directly
2. Adding **`stage`** to the backend graph (only backward-compatible schema change)
3. Reorganising the lineage frontend into stable layers: `api/`, `graph/`, `detail/`, `decisions/`, `hooks/`, `tokens/`
4. Replacing the V1.4.1 Inspector with a **section-based DetailDrawer** (read-only)
5. Migrating Decision / folding / pathBuilder / dpRegistry assets without behavioural change
6. Adopting the design-system tokens via a **root-level CSS variable swap**
7. Refreshing React Flow node / tooltip / canvas chrome to match the design language

### 1.2 Explicit non-goals (deferred — see §18)

AI integration · editable controls · code editing · report composer · multi-tab drawer · compare mode · Zustand store · Postgres migration · Pipeline-as-entity · `RunResultView` internal split · Python sandbox · BottomTerminal shell · node shape/density toggles · workspace/permission model.

### 1.3 Success criteria

- All V1.4.1 frontend test scenarios covered (count may shift due to rename, but coverage is equivalent or stricter)
- V1.4.1 backend tests pass; new tests cover schema v3 round-trip + per-factory stage tagging
- Browser smoke **L1–L20** all pass
- All six extension self-check questions (§17) answer "only the listed files" without exception

## 4. GraphViewModel contract

### 4.1 Design principles

- **Forward-compat shape**: every field a future version will populate is declared with `?` in V1.5.0. The shape does not break when V1.5.x fills it.
- **Don't fabricate**: adapter never invents data. If backend lacks a field, the corresponding ViewModel property is `undefined` / `[]`. Sections gate on presence.
- **Stable identity**: `id` and `nodeKey` are aliases of the backend's logical id in V1.5.0. V2.0 may split them; consumers must use `nodeRef` helper (§11.3) rather than treating `id` as a business key.

### 4.2 Types

```ts
// frontend/src/lineage/api/graphViewTypes.ts

export type Stage =
  | "source" | "eda" | "clean" | "transform"
  | "model" | "diag" | "viz" | "report"

export type Trust = "ok" | "review" | "caution";

// Full V1.4.1 backend enum preserved — no information loss

  | "needed"
  | "passed"
  | "failed"
  | "waived"
  | "unknown";

  id: string;                         // ← decision_id
  question: string;                   // decisionRegistry humanised title
  picked: string;                     // ← selected (safe-formatted; non-string → fallback)
  alternatives: string[];             // ← candidates (safe-formatted; non-string[] → [])
  why: string;                        // ← reason.explanation || decisionRegistry fallback || ""
  evidence: string[];                 // backend/registry-derived when available; [] if absent
  reviewStatus: DecisionReviewStatus;
  // Forward-compat slots — V1.5.0 always undefined
  requiresConfirmation?: boolean;
  confirmedBy?: string;
  confirmedAt?: string;
}

export interface ArtifactRef {
  name: string;
  mime: string;
  sizeBytes?: number;
  sha256?: string;
  url?: string;                       // signed download URL (V2.0)
}

/** Editable form control descriptor. V1.5.0 declares the shape but does
 *  not consume it; V1.5.2+ adapter and OperationSection will populate &
 *  render. Mirrors `EditableControl` in handoff/api.openapi.yaml. */
export interface EditableControl {
  kind: "radio" | "select" | "multiselect" | "slider" | "text" | "textarea" | "toggle";
  key: string;
  label: string;
  value?: unknown;
  options?: Array<string | { value: unknown; label: string }>;
  min?: number;
  max?: number;
  step?: number;
  unit?: string;
}

export interface GraphViewNode {
  // ── identity (V1.5.0 populated) ──
  id: string;                         // backend stable id; serves React Flow node.id
  nodeKey: string;                    // logical key (alias of id today; UUID-split in V2.0)
  raw: unknown;                       // original backend node payload, for Raw JSON / debugging

  // ── core display (V1.5.0 populated) ──
  stage: Stage;                       // ← backend v3 stage or "unknown"
  kind: string;                       // ← backend kind verbatim (e.g. "model", "dataset_stage")
  title: string;                      // ← display_label
  subtitle?: string;                  // adapter-derived only from existing fields (e.g. `${stage} · ${kind}`)
  summary?: string;                   // ← summary

  // ── trust (V1.5.0 populated; adapter normalised — see §4.4) ──
  trust: Trust;
  trustReason?: string;               // ← trust_reason

  // ── decisions (V1.5.0 populated) ──
  decisions: DecisionViewModel[];

  // ── timing (V1.5.0 populated where backend provides) ──
  createdAt?: string;                 // ← created_at (already present in V1.4.x backend)

  // ── forward-compat slots — V1.5.0 undefined ──
  runtimeMs?: number;                 // populate when backend exposes NodeExecution stats
  status?: "queued" | "running" | "waiting_review" | "done" | "failed" | "cancelled";

  // ── extension slots — V1.5.0 always undefined ──
  artifacts?: ArtifactRef[];
  stats?: Record<string, unknown>;
  coefficients?: Array<{ name: string; est: number; ci: [number, number]; p: number }>;
  preview?: Array<Record<string, unknown>>;
  schemaFields?: Array<{ name: string; type: string; missing: number; hist?: number[] }>;
  code?: { lang: string; body: string };          // V1.5.1+ read-only
  editableSchema?: EditableControl[];             // V1.5.2+
}

export interface GraphViewEdge {
  id: string;
  source: string;
  target: string;
  op?: string;
  reversible?: boolean;
  inverseOp?: string | null;
}

export interface GraphViewModel {
  schemaVersion: number;
  runId: string;
  legacy: boolean;
  nodes: GraphViewNode[];
  edges: GraphViewEdge[];
  stats: { nodeCount: number; edgeCount: number; leafCount: number; hasDpCount: number };
}
```

### 4.3 Safe formatters (no fabrication)

The adapter MUST use these helpers when transforming optional or polymorphic fields:

```ts
function safeString(v: unknown, fallback = ""): string {
  return typeof v === "string" ? v : fallback;
}

function safeStringArray(v: unknown): string[] {
  return Array.isArray(v) ? v.filter((x): x is string => typeof x === "string") : [];
}
```

Adapter MUST NOT inspect `chosen_params` or other free-form JSON to **invent** evidence strings. Evidence comes only from:
1. backend-provided `evidence` list (when added in future)
2. `decisionRegistry` if and only if the registry has a documented evidence template for that `decision_id` and the required source fields are present

Otherwise → `evidence: []`.

### 4.4 Trust normalisation table

V1.4.x backend emits a four-value trust enum. The adapter collapses it to the three UI values:

| Backend `trust` | ViewModel `trust` | Notes |
|---|---|---|
| `"ok"` | `"ok"` | passthrough |
| `"warning"` | `"review"` | V1.4 backend uses this for "human review suggested" |
| `"caution"` | `"caution"` | V1.4 backend uses this for "explicit hazard noted" |
| `"blocker"` | `"caution"` | hard-fail collapses to caution in UI |
| anything else / missing | `"review"` | conservative default; logs `console.warn` once per session |

The adapter helper:

```ts
function normalizeTrust(t: unknown): Trust {
  if (t === "ok") return "ok";
  if (t === "warning") return "review";
  if (t === "caution" || t === "blocker") return "caution";
  return "review"; // unknown / missing → conservative
}
```

Unit test must cover all five rows + the "unknown" fallback.

## 5. Adapter contract

### 5.1 Public surface

```ts
// frontend/src/lineage/api/graphAdapter.ts

import type { GraphResponse } from "../types";
import type { GraphViewModel } from "./graphViewTypes";

/** Thrown when the adapter receives a graph whose `schema_version`
 *  is not explicitly supported. UI surfaces this as a `corrupt graph`
 *  error state (the same path V1.4.1 uses for 422 responses). */
export class UnsupportedGraphSchemaError extends Error {
  constructor(readonly schemaVersion: number) {
    super(`Unsupported graph schema_version: ${schemaVersion}`);
  }
}

/** Top-level adapter for Run-scoped graphs.
 *  V2.0 will introduce a sibling `adaptPipelineGraph` (Pipeline-as-entity). */
export function adaptRunGraph(backend: GraphResponse): GraphViewModel {
  if (backend.schema_version === 2) return adaptGraphSchemaV2(backend);
  if (backend.schema_version === 3) return adaptGraphSchemaV3(backend);
  throw new UnsupportedGraphSchemaError(backend.schema_version);
}

function adaptGraphSchemaV2(backend: GraphResponse): GraphViewModel { /* … */ }
function adaptGraphSchemaV3(backend: GraphResponse): GraphViewModel { /* … */ }
```

Naming rule: `adaptGraphV2`/`adaptGraphV3` are **internal** dispatchers. The exported entry is `adaptRunGraph`. V2.0 may add `adaptPipelineGraph` without retconning these names.

### 5.2 Mandatory unit tests

`api/graphAdapter.test.ts` covers (minimum 11 cases):

1. **v2 input** → every node has `stage === "unknown"`
2. **v3 input with stage** → stage passes through unchanged
3. **trust normalisation** — all five mappings from §4.4: `ok→ok`, `warning→review`, `caution→caution`, `blocker→caution`, unknown/missing→`review`
4. **empty `decision_points`** → `decisions: []`
5. **multi-DP node** → `decisions.length === decision_points.length` and order preserved
6. **legacy graph** (`legacy: true`) → `legacy: true` and `nodes/edges` empty without throwing
7. **safe formatter behaviour** — non-string `selected` falls back to `""`, non-array `candidates` falls back to `[]`, no exception
8. **no-fabrication rule** — input with empty `chosen_params` → output `evidence: []` (regression of V1.4.1 P1.1)
9. **schemaVersion preserved** — `model.schemaVersion === backend.schema_version`
10. **createdAt mapped** — backend `created_at` populates `node.createdAt`
11. **unsupported schema throws** — `schema_version: 99` raises `UnsupportedGraphSchemaError`; the worktree's error boundary will surface this as the "corrupt graph" state (same path as V1.4.1 422)

## 6. Backend schema v3 — minimal change

### 6.1 The only field added

```python
# backend/workbench/graph_model.py
class Stage(StrEnum):
    SOURCE = "source"
    EDA = "eda"
    CLEAN = "clean"
    TRANSFORM = "transform"
    MODEL = "model"
    DIAG = "diag"
    VIZ = "viz"
    REPORT = "report"

@dataclass(frozen=True)
class Node:
    ...
    stage: Stage | None = None   # new in schema v3; nullable for back-compat with v2 files
```

`schema_version` bumps 2 → 3. Writer always emits v3.

### 6.2 Two rules, both tested

**Rule A — backward compatibility on read.**
- A v2 file on disk parses cleanly. Resulting nodes have `stage = None`.
- Test: `tests/test_graph_store.py::test_v2_file_loads_with_stage_none`.

**Rule B — newly produced v3 graphs must always tag stage.**
- Every factory in `graph_decision_factory.py` and every orchestrator-emitted node MUST set a non-`None` stage. The only legitimate `None` is when re-reading legacy v2 data from disk.
- Test: `tests/test_graph_orchestrator_integration.py::test_freshly_generated_v3_graph_has_no_unstaged_nodes`. Runs a representative pipeline, asserts `all(n.stage is not None for n in graph.nodes.values())`.

### 6.3 Stage assignments by trigger site

| Orchestrator trigger | Resulting node `kind` | `stage` |
|---|---|---|
| Raw data load | `dataset_stage` | `source` |
| Missing-value handling | `dataset_stage` | `clean` |
| Winsorize / clip outliers | `dataset_stage` | `clean` |
| Log / Box-Cox / scale / dummy / interaction | `variable` | `transform` |
| Model fit (any) | `model` | `model` |
| Diagnostic checks (V1.5+ when emitted) | `dataset_stage` | `diag` |
| Plot / chart artifacts (future) | reserved | `viz` |
| Report HTML | `report` | `report` |
| EDA schema-inference output (future) | `dataset_stage` | `eda` |

The mapping table is defined as a constant in `graph_decision_factory.py`; future kinds extend the constant rather than duplicate logic.

### 6.4 No other backend changes

V1.5.0 backend **does not** add: artifacts, stats, coefficients, preview, hist, code, editable_schema, runtime, status. Each would imply a feature commitment we are explicitly deferring.

## 8. Section registry

### 8.1 Mechanism

```ts
// frontend/src/lineage/detail/sections/sectionRegistry.ts

import type { GraphViewNode } from "../../api/graphViewTypes";

export interface SectionSpec {
  id: string;
  order: number;
  shouldRender: (node: GraphViewNode) => boolean;
  Component: React.FC<{ node: GraphViewNode }>;
}

export const sectionRegistry: SectionSpec[] = [
  { id: "trust",     order: 10, shouldRender: needsTrust,                 Component: TrustBanner },
  // 20  AskAISection           — V1.5.2
  // 30  OperationSection       — V1.5.2
  // 40  CodeSection            — V1.5.1 read-only
  { id: "lineage",   order: 50, shouldRender: () => true,                 Component: LineageChainSection },
  { id: "basic",     order: 60, shouldRender: () => true,                 Component: BasicInfoSection },
  { id: "decision",  order: 70, shouldRender: (n) => n.decisions.length > 0, Component: DecisionSection },
  // 80  CoefficientSection     — V1.5.x
  // 90  ArtifactSection        — V1.5.x
  // 100 PreviewSection         — V1.5.x
  // 110 HistogramSection       — V1.5.x
];

function needsTrust(n: GraphViewNode): boolean {
  if (n.trust !== "ok") return true;
  return n.decisions.some(d => d.reviewStatus === "needed" || d.reviewStatus === "failed");
}
```

### 8.2 Critical rule — header is NOT in the registry

```tsx
function DetailDrawer({ node }: { node: GraphViewNode }) {
  return (
    <aside role="dialog" aria-labelledby="detail-drawer-title">
      <DetailHeader node={node} />              {/* Stable layout anchor + aria-labelledby */}
      {sectionRegistry
        .filter(s => s.shouldRender(node))
        .sort((a, b) => a.order - b.order)
        .map(s => <s.Component key={s.id} node={node} />)
      }
    </aside>
  );
}
```

Header lives in `header/DetailHeader.tsx`, outside the section registry, because:
- It hosts the dialog's `aria-labelledby` target — accessibility skeleton must not be coupled to section logic
- Layout (close button, title, breadcrumb) is invariant across all node kinds
- Future "Section system" evolution (V1.5.x adds sections) must not be free to remove the header by mistake

### 8.3 Adding a section in later versions

V1.5.x adds a section in **two changes**:
1. Create `sections/NewSection.tsx`
2. Register an entry in `sectionRegistry.ts`

`DetailDrawer.tsx` is not touched. This is the test of whether the extension boundary holds.

## 9. Raw JSON handling

### 9.1 Decision: modal, not constant section

The V1.4.1 Inspector embedded Raw JSON as a permanent footer. V1.5.0 promotes it to a modal:

- `frontend/src/lineage/modals/RawJsonModal.tsx`
- Opened by:
  - `⌘J` keyboard shortcut when inspector dialog is open
  - "View Raw JSON" item in `NodeActionMenu`
  - **No** permanent section in DetailDrawer

Rationale: power-user tool; cluttering every node's pane with raw payload conflicts with the editorial aesthetic of the new design language.

### 9.2 Modal contract

- `role="dialog"` `aria-labelledby` "Raw JSON"
- `Escape` closes (consistent with `MoreMenu` pattern from V1.4.1)
- Pretty-printed JSON; **no `dangerouslySetInnerHTML`** (drop the prototype's hand-rolled highlighter; use a small typed component that walks the value)
- Copy-to-clipboard button (existing implementation re-used)

### 9.3 Test coverage

`RawJsonModal.test.tsx`:
1. Opens via `⌘J` when a node is selected
2. Closes via `⌘J` again (toggle)
3. Closes via `Escape`
4. Closes via close button
5. Copy button writes to clipboard
6. Does not render dangerouslySetInnerHTML (sanity assertion against `outerHTML`)

This subsumes V1.4.1's `LineageTab.test.tsx::test_cmd_j_shortcut`.

## 10. NodeActionMenu

### 10.1 What it is

Renamed/refined `MoreMenu`. Right-click on a node (or click on the node's `⋯` affordance) opens it.

### 10.2 V1.5.0 menu items

| Item | Action | Notes |
|---|---|---|
| Copy node ID | `navigator.clipboard.writeText(node.nodeKey)` | from V1.4.1; copies the **logical** key, not the future UUID. In V1.5.0 `nodeKey === id`; in V2.0 they diverge and users still get the readable key. |
| Copy as JSON | clipboard write of `JSON.stringify(node.raw, null, 2)` | from V1.4.1 |
| View Raw JSON | opens `RawJsonModal` for this node | new path; same modal as `⌘J` |
| Copy lineage path | clipboard write of `buildBranchPath(...)` | new in V1.5.0; uses existing `pathBuilder` |

### 10.3 Items intentionally absent from V1.5.0 (documented, not rendered)

These appear in the design prototype but are **not** in the V1.5.0 menu. No placeholders, no disabled rows, no "Coming soon" tooltips — the menu shows only items that work today.

- Ask AI about this node (lands V1.5.2)
- Rerun from this node (lands V1.5.2+)
- Mark as bad decision (lands V1.5.x)
- Pin to compare (lands V1.5.1)

Test: `NodeActionMenu.test.tsx` must assert that none of the reserved labels appear in the rendered DOM (regression guard against accidental UI promises).

### 10.4 Accessibility

- Outside-click and `Escape` close
- Focus management: focus returns to invoking element on close
- `role="menu"` and `role="menuitem"` per WAI-ARIA
- Permission states wired but always-on in V1.5.0 (no role system yet)

## 11. Selection, URL state, and the `nodeRef` helper

### 11.1 URL state (single tab)

```
/runs/:runId?tab=lineage&node=<nodeKey>
```

Identical to V1.4.1. Encapsulated in `useSelectedNode()`.

### 11.2 Multi-tab future-proofing

`useSelectedNode` is the *only* place that parses or writes `?node=`. V1.5.1 replaces this hook with `useTabs()` that produces `?nodes=a,b,c&active=b&compare=1`. **No other file is allowed to read or write the `node` query param directly**.

### 11.3 `nodeRef` helper — no scattered `id` semantics

V1.5.0 introduces a tiny helper to centralise "how to identify a node":

```ts
// frontend/src/lineage/api/nodeRef.ts

export interface NodeRef {
  id: string;       // currently equal to nodeKey
  nodeKey: string;
}

export function refOf(node: GraphViewNode): NodeRef {
  return { id: node.id, nodeKey: node.nodeKey };
}

export function refEquals(a: NodeRef | null, b: NodeRef | null): boolean {
  return !!a && !!b && a.id === b.id;
}
```

**Engineering convention** (no automated enforcement in V1.5.0): outside of `nodeRef.ts`, `graphAdapter.ts`, and direct React Flow integration points (where `node.id` is a library contract), prefer `refOf()` / `refEquals()` for node identity comparisons. Three-level review catches drift; CI grep gates are deferred — they would generate false positives in React Flow's many legitimate `id` comparisons.
