# Workbench v1.8 Browser Debug Closure — Design Spec

Date: 2026-07-21
Worktree: `.worktrees/workbench-v1.8`
Status: approved by user after VIXCLS browser reproduction

## Goal

Close every product defect observed in the real VIXCLS browser workflow without replacing the
ARMA–GARCH estimation core or creating a new framework. The raw known-truth CSV must run inside
Workbench, the generated graph must remain truthful and operable after both success and failure,
and Report/Compare/chart surfaces must expose the evidence already produced by the pack.

## Fixed boundaries

- Keep `REFERENCE_SEMANTICS = "directional_or_workflow_regression"`.
- Joint ARMA(q>0)–GARCH estimation remains outside this bug-fix release.
- Reuse the existing v1.8 worktree, operation registry, graph/index bridge, report facts, and SVG
  chart renderer.
- Do not add a generic row-transformation platform. The existing auditable
  `missing_value_policy=drop_missing_confirmed` is the supported VIX recovery path.
- Do not mutate `graph.json` when creating Compare nodes.
- Intermediate generated stages may be inspected and queried, but only a canonical terminal model
  node may expose model rerun/compare/result actions.
- Do not push, open a PR, merge, or tag during this work.

## 1. Input, recommendation, and Genesis

`ArmaGarchControls` must expose both supported missing-value policies. Choosing
`drop_missing_confirmed` is an explicit confirmation, is serialized into `model_options`, and is
restored on edit/rerun. The raw VIXCLS upload must therefore complete without an out-of-product CSV
rewrite while preserving source row IDs and immutable source bytes.

Genesis must use the same ARMA–GARCH controls and contract builder as `/submit`. ARMA–GARCH is
univariate: its selected value column maps to `y`, and `x=[]` is valid. Both frontend save guards
and backend Genesis validation must enforce that model-specific shape.

Transform advice must come from the existing full-data transform-profile implementation, not the
first preview rows. A small read-only preflight request returns eligibility, evidence, and the
recommended transform for the selected time/value columns and missing policy. The form presents
that advice but never auto-confirms the transform. Rerun surfaces fall back to the persisted
transform profile when no preview is available.

## 2. Truthful failed-run recovery and efficient Agent behavior

When a structured ARMA–GARCH failure occurs after raw/config materialization, write a partial
`node_index.json` only for materialized nodes. Also persist one explicitly failed configured-model
entry (a tombstone) carrying its model type, model options, status, failure code, and immutable
hash. It must never carry fitted parameters, convergence, forecasts, or a completed result status.

That failed model identity enables the existing `model.rerun` operation. Agent capability context
must advertise the ARMA–GARCH vocabulary and the supported missing-value recovery immediately.
Known invalid node/context requests must become stable `ToolVisibleError` responses containing a
code, a short explanation, and valid node IDs; the Agent must not burn repeated calls probing an
OLS-only analysis loop or a nonexistent generic row filter.

Run-code actions stay disabled when no real payload can be resolved, but the UI must show the
specific reason instead of appearing inert. No identity may be fabricated for an unmaterialized
data artifact.

## 3. Stage identity, Compare, and Report

Each of the six generated `stage:ts-*` graph nodes must receive a stable node-index entry tied to
its actual stage-local artifact references. Drawer lineage falls back to graph edges when operation
context is unavailable. ARMA–GARCH result and operation sections match `kind==model`, not every
node whose broad stage field happens to equal `model`.

The runtime `split_hash` remains contract-bound for execution integrity. Compare derives a separate
sample-membership identity from analysis-view hash, train/validation row IDs, boundary, cadence,
and split method. The Compare builder receives the actual forest relation. Ancestor/descendant
comparisons enforce source-child lineage; unrelated project-forest peers are allowed when sample,
forecast origins, and required evidence match.

Report facts add a bounded whitelist of atomic time-series evidence: selected mean/variance
specifications and parameters, separate mean/variance information criteria, diagnostics, rolling
metrics, persistence/half-life, and next forecast. Object/array values are rejected or skipped;
`[object Object]` is never rendered. No joint/composite likelihood criterion or VaR label is
invented.

## 4. Complete chart accounting and export

All 17 `ts.chart.*` artifacts must have a visible state. A valid zero-row
`quantile_exceptions` payload renders an explicit zero-exception panel. The object-form
`model_comparison` payload renders a summary panel. Unavailable and malformed artifacts remain
visibly distinct from valid empty evidence.

The existing chart `Frame` adds native SVG download by serializing the displayed SVG. The control
must state that the SVG represents the displayed/decimated view; structured JSON remains the full
evidence. No new charting dependency is introduced.

## Acceptance

1. Focused backend and frontend regression tests demonstrate red/green for every requirement.
2. Existing ARMA–GARCH, Agent, Compare, Report, lineage, Genesis, and chart suites remain green.
3. `scripts/gate.sh --full` is green with golden 0-drift and without overlapping heavy processes.
4. A clean browser run starts from committed `examples/datasets/VIXCLS.csv`, explicitly confirms
   missing-row dropping and transform, completes manual and automatic models, shows operable stage
   nodes, creates a valid Compare node, generates truthful report facts, accounts for all 17 chart
   artifacts, and downloads at least one SVG.
5. A real DeepSeek V4 Pro Agent session identifies the failed configured-model node, proposes the
   typed missing-policy rerun, executes only after confirmation, and reaches a completed child run.
6. Screenshots, run IDs, Agent transcript, Compare JSON, report output, exported SVG, commands, and
   any residual limitation are recorded in a final browser-debug handoff and Failure Memory entry.
