# Workbench v1.8.6 Report review 工作区设计

状态：已确认方向，待实现前复核

日期：2026-08-04

## 1. 背景与问题

当前 Report 页把报告正文预览、Float/Pin/Collapse 和 revision 输入框挂在
`ReportView` 自己的页面内容中。右侧仍由节点 DetailDrawer 占用，因此会出现
以下问题：

- Report 页的右侧宽度和 Graph/Table 不一致，页面布局显得更窄；
- 报告预览不是 Workbench 的工作区级标签，切换 Notebook/Graph/Table 时不能可靠地保持；
- 节点标签和报告预览的层级关系不清楚；
- `Report evidence` 的完整 provenance 库和本次发送给 writer 的裁剪 packet 容易被
  “included” 文案混淆；
- 未来增加模型、报告类型和导出格式时，报告状态如果继续留在单一页面组件中，会形成
  难以扩展的特例。

## 2. 目标

1. 只保留一个 Report 页面；不增加专门的 Run export 页或 Data export 页。
2. 把 `Report review` 作为 Workbench 右侧的工作区级系统标签，与节点标签同级共存。
3. 进入 Report 页面时自动激活 `Report review`；没有报告显示明确空状态，有报告显示
   当前正文和审阅信息。
4. 右侧面板使用 Graph/Table 现有的宽度、分隔线和调整行为。
5. Float 模式把 review 面板提升到 Workbench 根级，跨 Notebook/Graph/Table 保持
   悬浮并处于最上层。
6. 保留 Float、Pin、Collapse、拖动和底部 revision 输入框；Collapse 必须释放右侧
   空间，但不能关闭或丢失 Report review 标签。
7. 用户可以修改报告文字并产生新的不可变 revision，但不能修改 run、事实表、模型结果、
   诊断 artifact 或 lineage。
8. 顶部操作精简为 `New`、`Edit`、`Export`、`More formats`，并明确区分报告导出、
   结果表导出和数据节点导出。
9. 为后续模型、报告标准和格式扩展提供稳定的工作区级状态边界。

## 3. 非目标

- 不在本项中增加新的统计检验、模型或数据变换能力。
- 不允许 LLM 通过报告编辑接口执行 run、改写 artifact 或修改事实来源。
- 不增加独立的“导出页面”。清洗/变换后数据仍由对应的数据节点负责导出。
- 不把 Report review 固定成永远占据右侧空间；用户必须能收起它。

## 4. 已确认的交互决策

### 4.1 A：平行工作区标签

`Report review` 是一个保留的系统 tab，和 `ols_robust` 等节点 tab 位于同一条右侧
tab strip 中。它不是某个节点的详情，也不继承节点的 `nodeKey`。

- 系统 tab 永久存在，不提供关闭按钮；
- 系统 tab 不计入现有节点 tab 的 8 个名额，打开或激活它不能挤掉节点 tab；
- 节点 tab 继续按现有规则打开、切换、LRU 关闭；
- 在 Graph/Table/Notebook 中点击 `Report review`，可以直接查看报告，不必先进入
  Report 主页面；
- 进入 Report 主页面时自动激活 `Report review`；节点 tab 列表和节点选择不被删除；
- 离开 Report 主页面时，若 review 为 docked，恢复进入 Report 前最后一个节点 tab；
  `Report review` 仍留在 tab strip 中；
- 若 review 已 Float，则它作为独立 overlay 继续显示，底下页面的节点 tab 正常工作。

### 4.2 Docked / Float / Pin / Collapse

右侧 review 面板和节点 DetailDrawer 共享同一个 panel host 与宽度模型。

- **Docked**：面板位于 Workbench 右侧，使用 Graph/Table 的默认宽度、拖拽分隔线和
  session 级宽度记忆。
- **Float**：面板通过 Workbench 根级 portal 渲染为 `position: fixed` overlay；其
  生命周期不依赖当前 `view`，因此切换 Notebook、Graph、Table 时不卸载。
- **Pin**：保留现有 Pin 控件和视觉语义，用于固定浮动面板的位置/状态；Pin 不会把
  数据复制成另一份，也不改变报告来源。
- **Collapse（docked）**：折叠整个右侧面板为窄的恢复把手，释放右侧列宽；不关闭
  system tab，不清除报告，不清除拖动位置。恢复把手固定在右侧边缘并保持可键盘聚焦，
  点击或按 Enter 恢复。
- **Collapse（floating）**：保留浮层标题栏和恢复入口，仅折叠正文；浮层仍可跨页面
  存在，底部 revision 输入框在展开后恢复。

面板状态应提升到 Workbench shell 的状态边界，并按 project/run 保存必要的 session
偏好（布局、折叠、位置、尺寸）。报告内容本身仍以 report record/revision 为准，
不放入布局状态。

### 4.3 Report 页面布局

Report 页面中间区域保留：

- 顶部通用写作指令输入框、模型选择和上下文入口；
- `Report evidence` 的选择/审阅区域；
- history 和生成失败的具体原因。

报告正文不再在中间区域另起一个窄的 preview panel；正文、引用 chip、真实 figure、
质量状态和 revision 输入框统一由右侧 `Report review` 面板呈现。这样不会出现同一份
报告两处滚动、两套 Float 控件或两套正文状态。

## 5. 状态与组件边界

### 5.1 工作区 tab 类型

将当前仅含节点的 tab 模型扩展为带判别字段的工作区 panel tab，概念上为：

```ts
type WorkbenchPanelTab =
  | { kind: "node"; id: string; nodeKey: string; openedAt: number }
  | { kind: "report-review"; id: "report:review"; openedAt: number };
```

序列化继续使用现有 `tabs` / `active` URL 参数；旧的节点 tab URL 必须保持可解析。
`report:review` 是保留 ID，不参与 `selectedKey` 的节点推导、Graph 高亮或节点
operation context。`Report review` 的活动不会覆盖当前节点选择。

工作区状态还需要保留 `lastNodeTabId`，以支持进入/离开 Report 时的恢复行为。它是
导航偏好，不是分析证据，也不能影响 run 结果。

### 5.2 Report workspace provider

新增一个工作区级的 Report workspace controller/provider，负责：

- 当前 run 的 report history、当前 revision 和 stale 状态；
- report evidence inventory、writer packet 选择和 figure 选择；
- 生成、revision、prose edit、保存和导出动作；
- report review 面板的 dock/float/pin/collapse 状态；
- 对 Report 主页面和右侧 review 面板提供同一份对象引用。

Provider 应按 project root + active run 惰性初始化：普通 Graph/Table 使用节点面板时，
不因为报告功能重复加载所有 report evidence；当用户进入 Report、打开 report tab 或
保持浮动 review 时才建立所需资源。

未来扩展应通过可判别的 report standard / writer packet / export format 类型接入，
而不是在 `ReportView` 中继续堆叠页面特例。

### 5.3 Panel host

Workbench shell 提供一个统一的右侧 `PanelHost`：

```text
WorkbenchShell
├── WorkbenchTopbar
├── main row
│   ├── RunHistoryRail
│   ├── center view (Notebook / Graph / Table / Report)
│   └── docked PanelHost (node tabs or Report review)
├── BottomPanel / Agent surface
└── global floating PanelHost (portal, when Float)
```

浮动 host 必须位于 view 内容和普通 drawer 之上，并使用明确的 stacking context；不能
把 overlay 继续挂在会随 `WorkbenchMain` 重挂载的 `ReportView` 子树中。

## 6. Report review 内容规范

### 6.1 无报告

显示：

- 标题：`Report review`；
- 状态：`暂时没有报告`；
- 说明：当前 run 尚未生成报告，生成入口在 Report 页的写作区域；
- 在非 Report 页面提供一个轻量 `Open Report` 入口，在 Report 页面不重复生成第二个
  输入框。

空状态不是伪造的 preview，不显示示例文字、不显示旧 run 的正文。

### 6.2 有报告

显示：

- 报告标题、当前 run、生成模型、生成时间；
- `exportable` / stale / quality issue 状态；
- 正文、事实引用 chip 和真实 figure artifact；
- provenance / writer packet 摘要；
- 底部 revision 输入框和只改 prose 的 revision 操作。

编辑模式只开放报告正文。保存会生成新的 report revision，保留原始生成文本、事实
快照、figure 快照、排除项、指纹和质量结果。若 evidence 已变化，当前 revision 标记
为 stale，并禁止把它误当作新 run 结果导出。

## 7. Evidence 文案和发送边界

当前两个数字的含义必须在界面上明确拆开：

- **Evidence inventory / provenance**：当前 run 可追溯的完整事实与 figure 清单。它
  可能显示 `Facts 133 available · Figures 10 in provenance`；它的作用是审计、跳转
  到来源节点和复核，不代表每项都发送给 LLM。
- **Writer packet**：本次 writer 请求实际发送的裁剪子集，例如 `Facts 13 sent ·
  Figures 1 of 10 sent`。只有这部分允许被模型引用或插入报告。

完整 inventory 仍保存在 report provenance；发送 packet 由用户选择和推荐策略决定。
排除项必须记录在 report record 中。建议使用 `available / in provenance / sent`，
不再把完整 inventory 和 writer packet 都写成 `included`。

图表选择区域应显示：

```text
Evidence inventory       10 figures in provenance
Writer packet              1 of 10 figures sent to the writer
```

并提供短说明：`完整 inventory 会保留在 report provenance；只有选中的 figures 会发送
给 writer。`

## 8. 顶部操作和导出边界

Report 写作输入框下方只放四个并列动作：

1. `New`：清空当前 review 草稿并开始新的报告请求；不删除 history，不修改 run。
2. `Edit`：进入 prose 编辑模式；事实、模型结果、诊断和 artifact 只读。
3. `Export`：对当前通过质量检查且未 stale 的报告执行默认 PDF 导出。
4. `More formats`：打开菜单，提供 HTML、Word、LaTeX 等报告格式，以及明确命名的
   `Result table (XLSX)`。

`Result table (XLSX)` 只有用户在菜单中明确选择时生成；不在 run 完成时默认生成，
也不与清洗/变换后数据混在报告导出中。清洗/变换数据的导出入口仍属于对应数据节点。

导出失败必须显示具体错误，不生成空文件或伪造成功 artifact。

## 9. 可扩展性约束

- `Report review` 只依赖 report workspace contract，不依赖某个具体模型名称。
- writer packet、report standard、质量状态和 export format 都使用显式枚举/判别对象；
  新增模型或报告标准不应改变 panel tab 协议。
- provenance inventory 与 writer packet 永远分层，未来增加表格、诊断或 figure 类型时，
  仍能做到“完整留档、选择发送”。
- report editor 只接受 prose revision；任何需要改变数据、模型或 lineage 的动作必须
  走独立的 Workbench operation/confirmation 流程。
- 右侧 panel host 作为通用能力，未来可承载其他工作区级 review surface，但本项只实现
  Report review。

## 10. 验收标准

### 状态和导航

- [ ] 进入 Report 页会激活 `Report review`，但不会清除任何节点 tab。
- [ ] `Report review` 与节点 tab 同级显示且没有关闭按钮。
- [ ] `Report review` 不计入节点 tab 上限，打开它不会触发节点 LRU eviction。
- [ ] 无报告时只显示诚实空状态；不会显示旧 run 或示例正文。
- [ ] 有报告时 review 内容、引用和 figure 与当前 report record 一致。
- [ ] 从 Report 离开后节点 tab 恢复；report tab 仍可手动重新激活。

### 面板和空间

- [ ] Report 页右侧宽度和 Graph/Table 共用同一默认宽度、拖拽分隔线和记忆。
- [ ] Docked Collapse 释放整列空间，并可以从窄把手恢复。
- [ ] Float 后切换 Notebook、Graph、Table，review 仍存在且在最上层。
- [ ] Float / Pin / Collapse / 拖动 / revision 输入框均可用；切换 view 不丢失输入。

### 证据、编辑和导出

- [ ] inventory 与 writer packet 的标签能让用户区分“可追溯全集”和“实际发送子集”。
- [ ] 只有 writer packet 进入模型请求；完整 inventory 仍写入 provenance。
- [ ] 编辑只能生成新的 prose revision；run、事实、模型结果、artifact 指纹不变。
- [ ] `Export` 默认 PDF；`More formats` 明确包含其他报告格式和用户主动选择的结果表
  XLSX；run 完成不自动生成 XLSX。
- [ ] 清洗/变换数据导出不出现在报告导出菜单中。

### 测试与浏览器验收

- [ ] tabs/url schema、Report workspace controller、collapse/float 生命周期有单测。
- [ ] ReportView、ReportReviewPanel、panel host 有组件测试。
- [ ] typecheck、前端全量测试和相关后端 gate 通过。
- [ ] 原生浏览器验收：无报告、有报告、编辑保存、More formats、Collapse、Float 后跨
  Notebook/Graph/Table 均实际操作验证；不能只以 DOM 渲染作为替代证据。

## 11. 实施顺序

1. 先建立 workspace tab / panel host 的类型和 reducer 测试，锁定旧 URL 兼容与系统 tab
   规则。
2. 提取 Report workspace provider/controller，使 ReportView 和 review panel 共用状态。
3. 接入 docked Report review 和统一宽度/Collapse。
4. 接入 root-level Float/Pin 生命周期和跨 view 验收。
5. 调整 evidence 文案、顶部四个动作和导出菜单。
6. 删除 ReportView 内重复的 preview mount，补单测、全量 gate 和浏览器验收。
