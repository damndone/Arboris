## 2. 动手前必须理解的两条硬约束

这两条是 plan 里最容易被"顺手绕过"的地方。

### 2.1 fallback 不得成为新写入路径

读取优先级：

```
persisted run_family_id 存在   → 用持久化值
persisted 缺失                 → legacy_family_anchor() 计算，记兼容性告警
新建 run 但无 persisted family → 拒绝（RUN_FAMILY_REQUIRED）
```

第三行是命门。写代码时最自然的做法是"没有就算一个"，那会让派生逻辑永久留在新路径上，
本次改造等于白做。plan Task 2 Step 5 专门为此写了一条测试。

### 2.2 验收步骤必须断言内容，不能只断言存在

plan 开头写了这条约定，理由是实测教训：上一份
`plans/2026-07-21-v1.8-deliverables-closeout-plan.md` 的 Task 1 Step 1 要求
"an XLSX workbook with the eight named non-empty sheets"——**这条通过了**，
而三张表仍不可用（`Rolling forecasts` 只有 18 列里的 2 列）。

所以：迁移测试用 `assert before == after` 逐字节比对（不是 `startswith`），
fixture 从**真实 run 目录**复制（不手写）。

## 4. 两处未认领缺口（需用户拍板，不要自行决定）

这两条是 2026-07-22 review 时发现的，**当前 spec 和 plan 都没有覆盖**。

### 4.1 Trace 采集无人认领

roadmap §3.1 写着"现在不训练 ≠ 现在不采集"，要求从 v1.8.1 起记录：
Agent 看到什么上下文、生成哪些候选、proposal 是否通过 schema validation、
用户选择/修改/拒绝了什么、执行是否成功、诊断是否通过、结果是否被 Compare 推翻、
结论是否忠于 Artifact。

**但 spec 和 plan 里都没有它。** 若 v1.8.1 就这样发版，v1.8.2 的评测工装开局
零历史。成本在 v1.8.1 很低（Agent 已在写 JSONL），拖到 v1.8.2 就变成
"我们没有过去的数据"。

### 4.2 Context Compiler 的排期自相矛盾

roadmap §5 判定"RAG 可以延期，**有界上下文编译不能延期**——Notebook Agent
本身就依赖它"。但 v1.8.1 spec 里没有它。

二选一，需拍板：
- 明确 Notebook 在没有它的情况下可工作 → 修改 roadmap 的"不能延期"表述；
- 或它是**隐藏的第二个前置项** → 排进 v1.8.1，plan 需相应扩展。

### 4.3 三条不变量没有执行点（提醒，非阻塞）

roadmap §1 的三条不变量目前只存在于文档。参照：共享依赖规矩在进 `gate.sh`
preflight 之前也只存在于文档，结果三个 worktree 各装一份、浪费 431 MB。
**没有可执行判据的不变量是愿望。** 值得在某个版本里为它们找强制点。

## 5. 实施顺序（plan 的 6 个 Task）

```
Task 1  RunFamily 持久化实体（id 不编码 run，run-family:<uuid>）
Task 2  run↔family 成员关系持久化 + 三级读取优先级  ← 含 §2.1 的命门测试
Task 3  既有数据迁移（legacy-family:<root_run_id> 字符串逐字节不变）+ 幂等
Task 4  冲突语义（persisted 优先且报错，不静默重写）+ RUN_FAMILY_MISMATCH
Task 5  rerun/fork 继承来源 run 的 family
Task 6  收口：跑 spec §9.1 六条验收、grep 残留调用点、full gate（golden 须 0-drift）
```

**Task 6 Step 1 的第 1 条验收（无 Run 的 Notebook）依赖本计划范围外的 Notebook
对象，标为 deferred——不得因"暂时无法验证"而声称通过。** 其余五条必须闭合。
