## 2. Two hard-won operational rules

**2.1 Never run a heavy suite while anything else heavy is running.**
A full gate run concurrently with a vite dev server, followed by a second gate
started before the first had exited, drove the machine to ~40 GB (it has 24 GB)
and the suite was OOM-killed mid-run — which surfaced as a truncated log and a
bare `exit 1`, i.e. it *looked* like a test failure.

Mitigations are now in the repo (`273f2a2`):
- `frontend/vite.config.ts` caps vitest at `maxWorkers: 4`. Measured peak for a
  whole gate is now **~1.1 GB**. Do not raise this.
- `scripts/gate.sh` takes a lock and **refuses** (exit 3) if another gate, a
  vitest, or a vite dev server is running, naming the pids to stop.

Before gating: `preview_stop` any dev server, then
`ps -eo pid,args | grep -E "node \(vitest|uvicorn|vite.*--port"`.

**2.2 The in-app browser cannot trigger React `onClick` with synthetic clicks.**
Coordinate/ref clicks reach the DOM but React's root listener does not treat
them as activation. **Only `element.click()` via `javascript_tool` works.** Form
inputs need `form_input` or a native setter + `input` event; `computer.type`
does not reach controlled React state. There is no file-upload tool, so dataset
upload cannot be automated at all.

This is an environment limitation, not an app bug — real mouse input works.
Every UI verification in this branch was done with `.click()`.

## 4. The one thing v1.8 deliberately does NOT do

**The reference Do-file estimates ARMA(1,1)+GARCH(1,1) by joint MLE:**

```stata
arch y if insample, ar(1) ma(1) noconstant arch(1) garch(1)
```

**This pack cannot.** When `arma.q > 0`, joint estimation is refused with
`UNSUPPORTED_JOINT_ARMA_GARCH`; the pack fits the mean first, then the variance
on its residuals. This was an explicit scope exclusion from the outset.

Consequences you must not paper over:
- Coefficients and standard errors will not match Stata.
- **The Do-file's variance-model IC table is not reproducible.** Its
  `scalar ll = e(ll)` is the *joint* log-likelihood; ARCH0 / ARCH1–10 /
  GARCH(1,1) are ranked by joint AICc. A sequential fit has no comparable
  composite likelihood, which is exactly why the pack refuses to report a
  composite information criterion.

The codebase already states this honestly:
`tests/fixtures/models/arma_garch/vix_profiles.py` →
`REFERENCE_SEMANTICS = "directional_or_workflow_regression"` — only directional
and workflow parity is ever asserted, never per-parameter equality. **Keep that
framing.** Changing the estimator is a separate versioned decision, not a bugfix.

### Remaining minor differences (documented, not defects)

- `summarize z, detail` percentiles — skew/kurtosis present, percentiles not.
- `corrgram` prints per-lag Q for lags 1–30; the pack reports Ljung-Box at lags
  5/10/20 only (the Do-file's `wntestq lags(20)` *is* covered).
- `graph combine` panels and `graph export` PNG — the pack emits inline SVG;
  there is no combined-panel export.
- The Do-file does both a single-point `n+1` holdout (Part 6) and a last-20%
  rolling window (Part 7). One run has one validation window, so reproducing
  both needs two runs (`validation_n: 1`, then `validation_n ≈ 0.2·N`).
- Its eval window is a *proportion*; `validation_n` is an absolute count.

## 5. Architecture you need to know before editing

### 5.1 Artifacts are the contract

The pack writes structured `ts.*` artifacts; everything downstream (dashboard,
agent, compare packets) reads them. `_REQUIRED_LOGICAL_ARTIFACTS` in
`backend/workbench/engine/packs/arma_garch/runner.py` is the inventory —
**if you add one, you must also add it to `_NODE_BY_ARTIFACT`** or it has no
owning graph node.

### 5.2 Golden 0-drift is the discipline

`scripts/gate.sh --full` runs a golden/invariant/snapshot suite that must stay
**0-drift**. Every change in this branch was additive: existing keys keep their
names and meanings. Adding artifacts is safe; renaming or repurposing a field is
not.

### 5.3 Compare nodes never touch `graph.json`

`backend/workbench/lineage/compare_nodes.py` + `services/compare_node_service.py`.
Records live at `<project>/workbench/compare-nodes/`, and
`build_project_forest` merges them in **at response time**. This is what keeps
per-run graphs byte-identical. Merging happens at the project-forest level, not
the head-set level, because a comparison can join two *different* families.

Identity is symmetric (`compare_id` = hash of the two sorted forest node keys),
so A-vs-B and B-vs-A are one node. `canonical_endpoint_order()` decides the
baseline for **both** the record and the packet built against it — if you ever
need that ordering elsewhere, call that function, do not re-derive it.

Records are write-once; the conflict check deliberately **excludes
`created_at`**, or asking the same question twice looks like a divergent
rewrite.

### 5.4 Agent tool budgets

`inspect_operation_contract` and `inspect_time_series_summary` carry
`max_output_budget=12288`; the other inspectors keep 8192. Both exceptions are
documented in place. They return *schema* and *bounded conclusions*, not row
dumps.

Two guard tests exist because both were breached in live turns — assert against
**the tool response**, not the view it wraps:
- `tests/test_agent_context_tools.py::test_the_arma_garch_contract_payload_fits_the_tool_output_budget`
- `tests/agent/test_arma_garch_agent_compare.py::test_the_inspect_tool_response_fits_its_budget_not_just_the_view`

### 5.5 Labelling invariants travel with the data

`LABELLING_INVARIANTS` in `agent/recipes/arma_garch_vocabulary.py` is the single
source for both the vocabulary's `prohibited_claims` and the result view's
`labelling_invariants`. They are attached to `inspect_time_series_summary`, not
only to the operation contract, because **a question-answering turn never
fetches an operation contract** — that was a live failure where the model
reported the 5% conditional quantile as 95% VaR.

`unsupported_requests` (what the pack cannot *do*) and `prohibited_claims` (what
must not be *said*) are separate lists on purpose. Do not merge them.

## 8. How to work on this

The user expects, and has repeatedly corrected for:

- **Evidence over assertion.** "Tests pass" is not "it works". Verify against
  real data and, for UI, a real browser (with `.click()`).
- **Fixtures copied from real responses, never invented.** A component and its
  test once agreed with each other and not with the backend, so a comparison the
  server had marked `blocked_by_integrity` rendered as clean. Copy the shape from
  a served payload.
- **Say what is not done.** Scope exclusions, unverified steps, and limitations
  belong in the report, not omitted because the rest went well.
- **Do not fabricate numbers.** A context-window value was left as "not declared
  by this provider" rather than invented, on purpose.
- Communicate in Chinese.
