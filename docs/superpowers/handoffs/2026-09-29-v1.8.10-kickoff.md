     --baseline-sha <main 的完整 SHA> --affected-path <...> --test <...> --known-gate "scripts/gate.sh --full"

## 四、做法与已知坑（v1.8.9 学到的）

- 每项先写复现问题的失败测试再修；提交前跑相关测试 + 前端 `tsc`。
- 任何 Python 命令都加 `PYTHONPATH=backend`（共享 `.venv` 会导入别的 worktree 的代码）。
- **发版 gate 必须在宿主终端跑**（`bash scripts/gate.sh --full`），先停 Vite，独占机器；日志存进
  `docs/superpowers/evaluations/gate/`。验收中改过代码就重跑 gate。
- 发版前的 Agent 真机评测：`scripts/agent_live_eval.py`（常规 32 例、`agent_adversarial_cases.json`
  对抗用户）和 `scripts/agent_chaos_eval.py`（注入服务商故障与并发）。故障后同一会话必须能继续答对。
- 浏览器验收用真实数据与真实界面状态（例如选中模型节点、长会话），不要只靠单元测试。
- DeepSeek：思考模式在同一轮用过工具后再次作答会 400（数字核对的改写用 user 角色的新一轮）；
  本机经代理访问，TLS 可达 10–24 s，不要把连接超时调短。
- 分析诚信规则是硬约束：为让结果显著而改数据或挑设定，对用户和 Agent 一律拒绝。
- merge / tag / push 需用户明确授权；worktree 与缓存绝不自动删；对话用中文，产品界面用英文。
- 用户 `~/Downloads` 里的真实 `.dta` / `.sav` 只在本地用于测试，不提交、不外发。
- Codex 可能在同一仓库工作：开工时明确 worktree 归属；它的产出需审计后再合入。
