## 2. 需要修复的问题

### [P2] 复数序列静默丢弃虚部并返回 accepted result

位置：`backend/workbench/engine/packs/arma_garch/joint_mle.py:207`。

`np.asarray(values, dtype=float)` 对 complex ndarray 仅产生 ComplexWarning，随后返回针对实部的联合估计结果。输入 `fixture_y.astype(complex) + 1j` 仍得到正常结果，没有 `ArmaGarchInputError`。因此调用者请求的数据与实际估计的数据不一致，违背非法输入明确拒绝及不静默换方法。

独立复现：`tests/eval_v1811/m1_review_contract.py::test_complex_input_is_rejected_without_discarding_imaginary_values`；本轮 fresh **Failed: DID NOT RAISE ArmaGarchInputError**，warning 精确定位207行。

建议：在浮点转换之前检查输入是否为复数，明确抛 `JOINT_ARMA_GARCH_INVALID_INPUT`。不要用丢弃虚部、仅转 real 或降低 warning 的办法修复。测试必须保持原始输入不变。

### [P2] 非法方差阶数绕过 structured diagnostic

位置：`backend/workbench/engine/packs/arma_garch/joint_mle.py:197–205`，下游比较在 `volatility.py:81`。

函数先调用 `VarianceCandidateSpec.create()`、后检查阶数类型，并只捕获 ValueError。直接构造的冻结 spec 若 p/q 为 `None` 或字符串，下游 `< 1` 抛裸 TypeError；没有 code、severity、diagnostic。作者已有恶意 spec 测试证明本函数的责任包含防御未经 create 的 spec，因此这不是要求重写公共合同。

独立复现：`m1_review_contract.py::test_malformed_variance_orders_raise_structured_errors` 四个参数组 `(None,1)`、`(1,None)`、`('bad',1)`、`(1,'bad')` 均为 TypeError。建议在 `.create()` 前完成 p/q 类型验证（同 mean_p/q 的严格 int 检查），再进行模型/阶数语义校验；统一抛 `JOINT_ARMA_GARCH_INVALID_PARAMETERS`，不改 volatility 的 owned 范围外内容。
