## 3. 当前已实现什么：只列已被代码、测试或浏览器证实的能力

### 3.1 Agent Harness 后端基础

`backend/workbench/agent/` 已经形成以下分层：

- `core.py`：provider-agnostic 的 AgentCore、prompt、continue、abort、steer、follow-up、
  busy guard、预算和超时边界；
- `model.py`：OpenAI-compatible `ModelAdapter`、归一化 stream event、tool-call wire format；
- `session.py` / `storage.py`：append-only JSONL session tree 和原子写入；
- `events.py`：项目级 AgentEventStream、sequence 和 replay；
- `context.py`：custom AgentMessage、context snapshot、branch/compaction 相关基础；
- `tools.py`：ToolDefinition、ToolRegistry、ToolRuntime、schema/allowlist 边界；
- `context_tools.py`：节点上下文、OperationContract、diagnostics、result summary、artifact
  preview 等 provider-owned read-only tools；
- `operations.py`：OperationDefinition、OperationRegistry、OperationRecord 和状态转换；
- `proposals.py`：proposal revision、fingerprint、confirmation、stale precondition；
- `chains.py`：project-local chain/fork record 和 request-independent rerun seam；
- `orchestrator.py`：Main/Chain 编排、命令 scope、proposal、confirmation、执行和恢复对账。

这不是一个可以任意执行 shell/Python 的 coding agent。现有设计明确禁止任意代码执行、
任意网络请求、运行时改写 Workbench schema 和自由 multi-agent swarm。

### 3.2 后端 HTTP Agent surface

`backend/workbench/http/agent_routes.py` 已接入 `backend/workbench/app.py`，当前路由为：

~~~text
POST /agent/sessions
GET  /agent/sessions/{session_id}
POST /agent/sessions/{session_id}/turns
GET  /agent/sessions/{session_id}/events?after_seq=N
~~~

当前已证实：

- project root 校验；
- bounded context：序列化 context 最大 24,000 chars；
- bounded question：prompt 最大 4,000 chars；
- session metadata 和 message 持久化；
- event replay；
- unknown project/session 的结构化错误；
- provider secret 不返回；
- 未配置 LLM 时 fail closed；
- Agent turn 使用 existing OpenAI-compatible provider adapter 和有限预算。

### 3.3 前端 Agent Workbench

已经实现并在浏览器 smoke 中看到：

- GraphCanvas 下方的 graph-width Agent composer；
- 半透明背景、四角圆角、轻阴影；
- `Ask Agent` 输入框，Enter 提交，Shift+Enter 保留多行；
- context-length ring，配置未知时显示 unknown capacity，不伪造容量；
- active provider 的 model list；模型更新复用现有 LLM Settings 的 `updateLlmProvider`；
- scope、Thinking/idle 等状态和可访问错误提示；
- bottom panel 中的 `Agent` tab，排在 `Logs` 前面；

- URL panel enum 支持 `panel=agent`，默认仍是 `logs`，不破坏旧 URL；
- browser reload 后通过 `GET /agent/sessions/{session_id}` 恢复 transcript。

## 5. 设计目标中尚未完成的部分

下面这些不是“猜测”，而是根据当前 HTTP route、前端 API 文件和 v1.7 完成定义核对出的
明确缺口。

### 5.1 HTTP Agent turn 尚未接入完整 WorkbenchOrchestrator

当前 `run_agent_turn()` 直接创建一个带 provider adapter 的 `AgentCore`。它已经能完成
bounded durable text turn，但当前 route 尚未在这个 HTTP seam 中注册
`WorkbenchContextProvider` 的 scoped read-only tools，也没有把 Agent turn 直接连接到
`WorkbenchOrchestrator` 的 proposal/confirmation executor。

因此：后端 Harness primitives 已存在且有测试；当前浏览器 HTTP surface 仍主要是 advisory
text conversation。不要把它描述成已经能从自然语言直接安全 rerun。

### 5.2 Proposal / Confirmation 尚未成为 Agent UI 的完整交互

v1.7 设计要求：

~~~text
read-only tools
→ structured Proposal
→ schema validation
→ user confirmation
→ context + active-head revalidation
→ existing request-independent rerun executor
→ child run / fork / verifier / diff / operation record
~~~

当前 Agent panel 已有 typed proposal card、confirmation HTTP seam、proposal
decline/revision 交互、stale/cross-scope fail-closed contract 和真实 DeepSeek
confirmation smoke。operation progress、child run/verifier 和 diff 链接投影仍需继续
加强；confirm→execute→reconcile 已完成并经过真实闭环验证。

### 5.3 Main Agent / Chain Agent 仍未完整呈现为用户可操作 UI

当前 composer 提交的是 `role=chain` 的 project/run-scoped session。设计中要求的：

- Global Main Agent；
- Main → Chain structured command；
- Chain Agent status tree；
- Main 汇总 child status；
- sibling chain scope；
- message branch 与 graph fork 双向投影；

还没有全部通过当前 Agent panel 暴露出来。已有 orchestrator 和 chain/fork primitives 不能
替代浏览器验收。

### 5.4 Event cursor 已接入前端，但完整事件投影仍未完成

前端 `agentApi.ts` 现在调用 `GET /agent/sessions/{session_id}/events?after_seq=N`，
`AgentSurfaceProvider` 在 session hydration 时从 0 replay，turn 运行中 polling，维护
单调递增 cursor，并在 Agent terminal 显示最后事件序号。真实 DeepSeek smoke 已验证
`events #0 → #17 → #22`，reload 后仍恢复 `#22` 和 transcript。当前仍未把每一种
`proposal_ready`、`needs_confirmation`、`verifying` payload 拆成独立 activity UI；
typed tool/proposal transcript 仍是主要可见投影。

### 5.5 Fork、Operation Record、Diff 的 UI projection 未闭环

设计中的 project-local `chains/`、`forks/`、session tree、operation records 和 backend
verifier 已有基础代码/测试，但仍需要真实 UI 路径证明：

- 从图节点 Fork 能打开对应 child Agent；
- 从 Agent message Fork 能创建对应 graph fork node；
- child run 完成后 active head、diff、operation record 和 AI Activity 对应；
- reload/recovery 后不靠 event stream 猜测成功状态。

### 5.6 V11 数据层图内化不是当前 Agent slice 的附带任务

cleaning、异常值规则、类型覆写等 data-layer operation 仍属于 V11 主线。Agent 不能绕过
typed operation registry 直接改原始数据，也不能把任意 Python、shell、网络请求作为“工具”
暴露给模型。

## 9. TDD、浏览器和反脆弱开发纪律

### 9.1 每个功能切片都先写失败测试

至少覆盖：

- happy path；
- malformed/incomplete payload；
- unknown project/session；
- context/prompt budget；
- duplicate command/confirmation；
- stale active head；
- provider timeout/error；
- reload/recovery；
- unhandled frontend error；
- visible error and status。

不要只断言“按钮存在”或“tests passed”。

### 9.2 Agent 安全边界

- 只允许 allowlisted typed tools；
- tool 必须声明 input/output schema、scope、budget 和 side effect；
- 前端传来的 node/run/context 只是引用，不是写操作事实来源；
- 后端重新读取 graph、manifest、OperationContract 并生成 fingerprint；
- confirmation 前不创建 child run、不改 graph、不改 active head、不改原始数据；
- stale 必须阻断，不自动替用户改 target 或重试 mutation；
- provider/API key/Authorization/raw provider error body 不进入日志或 session；
- 不把任意 shell、Python、文件写入、网络请求暴露给模型。

### 9.3 浏览器验收不是可选项

每次影响 Agent surface 的 slice 至少检查：

- Graph composer 是否真的在图下方，而不是只在 DOM 中存在；
- bottom Agent tab 是否可点击、URL 是否可恢复；
- model/context/status/error 是否可见且可操作；
- request 完成后 transcript 是否更新；
- reload 后是否恢复；
- 浏览器 console 是否出现 React/application unhandled error；
- graph/run/active head 是否发生预期之外的 mutation。
