## 2. 与 Do-file 的逐段对照

### 数据处理（Do-file §0–5）

| Do-file | Workbench | 结果 |
|---|---|---|
| `import delimited` 2610 行 | 上传后显示 `2610 rows · 2 columns` | 一致 |
| `drop if missing(vix)` | `drop_missing_confirmed` 显式确认 | 排除 **68** 行 |
| 剩余样本 | `analysis_row_count` | **2542** = 2610−68 |
| `gen t = _n` 交易日索引 | 时间语义 `business_or_trading_observations` | 一致 |
| `gen dlvix100 = 100*D.ln(vix)` | 系统建议并经确认 `log_return_pct` | 一致 |
| 日期跨度 | 2015-12-14 → 2025-12-12 | 与 Do-file holdout 日期一致 |

差异：Do-file 用 `drop` 直接改内存数据；Workbench 保持源文件不可变
（`source_unchanged: true`），仅在分析视图内排除。语义等价，审计性更强。

### ARMA 定阶（Do-file §"用 BIC 选 ARMA"）

Workbench 自动搜索评估了 26 个候选。取 Do-file 的 8 个（c/n × 00/10/01/11）按 BIC 排序：

| Stata | k | logL | AIC | AICc | BIC |
|---|---|---|---|---|---|
| **n11** | 3 | −8784.1137 | 17574.227 | 17574.237 | **17591.725** |
| c11 | 4 | −8784.1096 | 17576.219 | 17576.235 | 17599.549 |
| n01 | 2 | −8799.1930 | 17602.386 | 17602.391 | 17614.051 |
| n10 | 2 | −8799.6155 | 17603.231 | 17603.236 | 17614.896 |
| c01 | 3 | −8799.1924 | 17604.385 | 17604.394 | 17621.882 |
| c10 | 3 | −8799.6148 | 17605.230 | 17605.239 | 17622.727 |
| n00 | 1 | −8807.5190 | 17617.038 | 17617.040 | 17622.870 |
| c00 | 2 | −8807.5184 | 17619.037 | 17619.042 | 17630.702 |

**BIC 最优 = n11 = ARMA(1,1) 无常数项**，与 Do-file 的选择一致。
Do-file 另有一张"检验 AICc≈AIC"的表：此处 AICc−AIC 最大 0.010，印证该判断。

**但自动模式选的是 ARMA(2,1)-n**（AICc 17570.420 < n11 的 17574.237）。
原因是准则优先级不同：Do-file 注释写明"BIC优先"，Workbench 自动模式的
`final_selection_basis` 是 `frozen_training_gates_aicc_bic_parsimony`（AICc 主导）。
**这不是缺陷，是口径差异**，但用户若期望复现 Do-file 必须手动指定或用 Agent 改写。

### 方差模型（Do-file §Part 4 + Step C）

候选集完全对应：ARCH(0)=`variance-constant-normal` + ARCH(1..10) + GARCH(1,1)，共 12 个。

按 AICc：ARCH(4) 17152.949 最优。
按 BIC：**GARCH(1,1) 17176.339 最优**（ARCH(4) 为 17182.067）。
Do-file 最终采用 GARCH(1,1)，与 BIC 口径一致。

全部候选 `joint_likelihood: false`。

### 诊断（Do-file §Part 3 / 8 / 9）

| Do-file 命令 | Workbench | 值 |
|---|---|---|
| `dfuller y` | `adf` | −20.993056, p=0, lag 7, n 2513 |

## 5. 本次发现的问题

### 影响可用性

**P1 — 内联 Compare 仍是 raw JSON 对拍。**
点节点抽屉的「Compare with another node…」，结果显示为两段各约 900 字符的
`model_options` JSON 并排加 `→`，标注"2 differences"却不做字段级高亮。
用户须肉眼 diff 才能看出实际只变了
`constant_mode/p/q/estimation_strategy/selection_mode/garch_p/garch_q/model`。
`analysis_loop/time_series_compare.py` 的人类摘要修复覆盖的是**持久化时序 Compare 节点**，
**未覆盖用户实际点到的这个内联界面**。ledger 的
`human_readable_compare_and_agent_handoff` 仍只有 focused test 支撑，本次真机复现证实
该界面的可读性问题依旧存在。

**P2 — `form_input` 设值不触发 React onChange，Send 按钮保持 disabled。**
用 `form_input` 向 Agent 输入框写入 124 字符后，DOM value 已更新但
React 内部 state 为空，`Send` 始终 `disabled`，点击无任何网络请求。
改用真实键盘输入（click → type）后立即恢复正常。
这不是产品缺陷（真人用键盘不会遇到），但**任何浏览器自动化脚本都会踩**，
应写进自动化约定：**受控输入必须用真实键入，不能用 form_input**。

### 记录备查

**P3 — `inspect_time_series_summary` 返回 `tool_output_budget_exceeded`。**
Agent 的时序摘要工具输出超预算被截断。Agent 靠其余两个工具仍完成了任务，
但这条工具在 ARMA-GARCH 上实际不可用。

**P4 — `propose_operation` 首次 `ToolVisibleError`。**
嵌套 patch 合并语义仍会让模型第一次写错。Agent 能自行恢复，但每次都要多花一轮。
错误信息足够指导恢复，属可接受但可优化。

**P5 — 残差 PACF 无图表 artifact。** 见 §2 图表段。

**P6 — 滚动窗口口径与 Do-file Part 7 不同。** 20 vs 最后 20%。见 §2 滚动验证段。

### 非问题（排查后排除）

- `reports/report.pdf` 一度以为缺失 → 实为 `ls | head` 截断，文件在。
- 半衰期一度以为未报告 → 实为不在 `ts.final_model` 而在事实表
  `ts:volatility:half_life_observations`，值与手算一致。
- `residual_exceedance` 一度怀疑算在原始残差上 → 独立验算确认算在标准化残差上。
- 事实 `c6 = 2610` 一度以为误导 → AI 报告正确区分了原始 2610 与分析 2542。

## 5b. 修复（2026-07-22，本次复现后）

P1/P3/P4/P5 已修，P2 转为自动化约定，P6 判定为参数取舍不需改代码。

**P1 — 内联 Compare 字段级 diff。**
`nodeDiff.ts` 新增 `flattenRecord`，在 diff 前把嵌套对象展平成点号叶子路径。
真机复验：修前"2 differences" + 两坨 ~900 字符 JSON；修后"9 differences"，
逐行为 `model_options.arma.constant_mode  exclude → auto` 等 8 个真正变化的叶子。
数组与空对象保持整体不展开（阶数向量按索引 diff 比向量本身更吵）。

**P3 — 摘要预算，两个根因。**

其一，库警告泄漏进候选记录：statsmodels 每次 ARIMA 拟合都会触发 NumPy 的
shape 赋值 `DeprecationWarning`，被 `str(item.message)` 原样收进每个候选的 `warnings`，
8 行就占 1424 字节，还会让用户误读为模型问题。新增
`statistics.modelling_warnings()` 滤掉 Deprecation/Future/Import/Resource 类并去重，
在 `arma.py` / `volatility.py` / `estimation.py` 三处统一调用。
真实拟合复验：同一候选修前带该警告，修后 `warnings == ()`。

其二，固定行数无法约束可变行宽。`_bounded_rows` 改为**行数与字节双重约束**
（每表 2000 字节），并略过 `failure_code: null` / `warnings: []` 这类空字段。
自动 run 摘要 14388 → **11797**（含旧警告的原始记录也降到 11921），
三种情形全部落在 12288 预算内，被略过的行数如实记入 `candidate_rows_omitted`。
这是同一失败模式第三次出现（前两次是 comparison row ids），已补针对候选表宽度的测试。

**P4 — patch 形状范例。**
`fields[].path` 以 `arma.p` 点号形式广告，patch 却必须嵌套，模型自然照抄点号。
vocabulary 新增 `patch_shape_example`，并排给出 `wrong_flat_dotted_keys` 与
`correct_nested_objects`。测试**执行**这个范例：正确的一半必须通过真实校验器并产出
所声称的模型，错误的一半必须真的抛 `ArmaGarchContractError`，
`{"arma": {"q": 2}}` 必须保留 `arma.p`——否则范例会悄悄漂移成谎言。

**P5 — 残差 PACF 图表。**
后端 `ts.chart.residual_pacf`（三处登记 + payload），前端 chart 注册表与
gallery 面板同步。数据本来就在 `ts.final_diagnostics.residual_pacf`。

**P2 — 不改代码，转为约定。**
`form_input` 直写 DOM value 绕过 React onChange，组件 state 为空、提交按钮恒 disabled、
点击不发请求。受控输入必须 click 后真实键入。另：`computer` 的 `coordinate` 是
**截图像素空间**（800×474），不是 CSS 像素（1637×970），拿 `getBoundingClientRect()`
的值直接传会落空——优先用 `ref`。已写入长期记忆。

**P6 — 不改。** `validation_n` 本就是用户可设参数，20 vs 最后 20% 是性能取舍，
需要严格复现 Do-file Part 7 时把它调到 508 即可。
