## 一句话目标

把 Arboris 的 Agent 做成"研究版的 Claude Code"：
- 用户自己选择 **Ask every step（每步都问）** 或 **Auto within plan（计划内自主执行）**，两种模式都打磨到可以日常使用；
- 只给它原始数据和一个研究问题，它能自己组织并做完一项完整、经得起审稿的分析，包括数据理解、估计、诊断、多设定稳健性、表格和报告；
- 计划始终可见、可以编辑；随时插话纠正、中断、整段撤回；关掉窗口后照样在后台运行。

是否做到，由公开评测、已发表论文的复现和多分析师数据来证明，而不是自评。

## 设计原则

1. **两种模式同等重要**。"每步都问"不是降级版：确认之后 Agent 必须自动接着做，用户永远不需要说"请继续"。
2. **安全边界不随模式放松**。改原始数据、导出、外发、已登记的高风险操作，在两种模式下都逐次批准；中断永远可用。
3. **谱系分支即检查点**。每一步都落在谱系图上，对话和谱系一起回退；一次自主执行在一个分支上完成，可以整段撤回或分叉对比。
4. **计划即预先设定**。批准计划就写入台账 `criteria_fixed`：按计划执行的分析标为预先设定，看到结果后新增的步骤标为探索性（设计文档 §7）。
5. **做完要自证**。Agent 宣布完成之前，必须对照剧本的完成标准自检：诊断、稳健性、数字核对、结论边界。
6. **评测驱动**。先测 v1.9.0 基线、预注册阈值，再实现。只用 DeepSeek V4.1 Flash（`deepseek-flash`）。花费不设上限但不浪费：
   回归测试用录制回放；真实调用只用于基线、两轮中期、最终评测和浏览器验收。
7. **重构服务于能力**。只拆本版要动的大文件，行为保持；验收看"加一个新能力要改几处"和依赖关系，不设行数指标（Codex 核查结论）。

## 核心规格一：两种执行模式与权限

**共同规则**
- 输入框旁有模式开关，`⇧Tab` 切换（同 Claude Code），当前模式始终可见；按项目记住上次的选择。**新项目默认 Ask every step。**
- 只读检查（`inspect_*`、`calculate` 等）在两种模式下都不询问。
- 改原始数据、导出、外发、已登记的高风险操作，在两种模式下都逐次批准（保留现有 risk authorization）；改动类操作在批准前显示"会改变什么"的预览。
- **权限规则**（同 Claude Code 的 permissions）：
  - 卡片上可以选"本会话内同类操作不再询问"；
  - 项目可以写规则文件（allow / ask / deny × 操作类别 × 风险等级），也可以在设置里编辑；
  - 规则不得放宽上面的安全底线，有测试守住。
- 随时可以：
  - 插话：在下一个工具调用间隙生效，对话里显示"已采纳"；
  - 追加：当前任务完成后再执行；
  - 中断：≤ 1 s 停下，正在跑的长计算经运行级取消在 ≤ 2 s 内停止，已完成的步骤保留；
  - 整段撤回：对话和谱系一起回到分支起点。
- Agent 任何时候都知道当前模式、已批准了什么、刚执行了什么。

**Ask every step（每步都问）**
- Agent 可以先给出计划（显示在面板里，不需要批准），然后每个改变状态的操作都以"已填好的表单"提出：确认、编辑后确认、跳过、停止。
- **确认之后，执行结果在同一轮内交回 Agent，它接着推进下一步。**
- 键盘操作：`↵` 确认，`E` 编辑，`S` 跳过，`Esc` 停止。
- 连续的同类操作合成一张卡片（例如 6 个稳健性重跑），卡片内可以逐项勾选。

**Auto within plan（计划内自主执行）**
- Agent 先起草计划，内容包括：问题、步骤（操作类型、输入、预期产物、风险等级、依赖关系）、判断标准、资源预算、允许的操作类别。
- 批准之前做 L0/L1 预检（设计文档 §5.2）：数据是否支持、每一步的预计耗时。
- 用户可以直接编辑计划：增删步骤、调整顺序、改参数、收紧允许的操作类别。
- 批准一次，写入 `criteria_fixed`，并开出一个分支。
- 步骤是**有向无环图**：互相独立的步骤并行执行（受机器重负载锁约束）。
- 在已批准的类别和预算内，Agent 自主执行、读取结果、调整后续步骤；新增的步骤标为探索性，面板上显示"新增"。
- 遇到以下情况暂停并出卡片：越出允许的操作类别、超出预算、高风险操作、同一步连续失败 2 次、需要修改判断标准（修改后的分析一律标为探索性）。
- **后台运行**：关掉窗口或重启服务后继续，或从断点恢复（幂等，不重复执行）；需要批准或完成时发系统通知。
- 完成后给出总结：做了什么、哪些按计划、哪些是新增、自检结果、产物链接。

**两种模式之外**
- **斜杠命令**：`/plan`、`/auto`、`/ask`、`/stop`、`/undo`，以及每个技能自动生成的命令。
- **无界面运行**：`workbench agent run --project … --prompt … --mode auto --approve-plan`（参照 Codex `exec`），输出机器可读的事件流。
  评测、复现挑战和 CI 都走它；安全底线与界面模式完全相同。

## 核心规格二：会做完整分析

1. **完整分析剧本**（内置技能）：横截面因果、面板 / DID、IV、时间序列、描述性研究、预测。每个剧本声明：
   - 必做的诊断；
   - 必做的稳健性；
   - 报告必须包含的内容；
   - 完成标准（自检清单）。
2. **自检后才能宣布完成**：对照剧本逐项检查，并核对数字；缺了什么就说缺什么，不能用"已完成"掩盖。
3. **多设定稳健性**：Agent 列出可辩护的备选设定（样本、控制变量、函数形式、标准误口径），作为计划中的一组并行步骤执行，
   生成设定曲线（Simonsohn, Simmons & Nelson 2020）。设定集合在看到主结果之前写入计划，由 `criteria_fixed` 保证。
4. **开放问题的方案比较**（原 v1.9.1 研究规划范围，设计文档 §5）：
   - 2–3 个候选方案，**比较时看不到任何估计值和 p 值**，由上下文编译器剥离，有测试断言；
   - 比较维度固定：是否回答了所问的问题 → 数据是否支持 → 假设强弱 → 成本 → 领域惯例；
   - 结论是推荐 / 打平 / 证据不足，任何方案都可以 Run anyway 并记入台账；
   - 支持从结尾反推规划，记录 `question_change`。
5. **独立复核子 Agent**：用隔离上下文复核方法选择、稳健性和数字。Auto 模式完成时自动运行，Ask 模式按需运行；意见附在总结和报告里。
6. **失败恢复**：一步失败时，先读错误、修正后重试，最多 2 次；仍失败就暂停，并说明根因和可选方案，不静默跳过。

## 核心规格三：扩展插槽与内置技能

- **技能**：`SKILL.md` 格式（与 Claude Code、Codex 兼容）。
  - 分内置、个人（`~/.config/econometrics-workbench/skills`）、项目（`<project>/skills`）三级；
  - 平时只给名字和描述，按需加载全文；
  - 附带的脚本只能经能力工厂沙箱执行。
- **外部工具**（类似 MCP）：受外发管控和内容分类约束，输出一律当作数据。
- **钩子**：操作前、操作后、回合结束、计划批准时。
- **每个插槽**都有准入、来源、版本和禁用开关，登记 `egress.py` 并重生成手册。
- **内置技能**：
  - 第 2 条里的完整分析剧本；
  - 统计报告审查：吸收 `nature-statistics`，看独立单位与 n、结论到分析的映射，缺失信息标 `AUTHOR_INPUT_NEEDED`，并按台账和结果核对事实（设计文档 §13.4）；
  - 科研图的契约与质检：吸收 `nature-figure`，先写核心结论、证据链和图型再出图，做多面板对齐与碰撞检查，走 Arboris 自己的绘图管线；
  - 社科和经济学结果写作。
- **许可**：遵守 Apache-2.0，固定到具体提交，保留许可与署名，说明修改；不用 `figures4papers` 等第三方素材，不接它用到的外部服务。
