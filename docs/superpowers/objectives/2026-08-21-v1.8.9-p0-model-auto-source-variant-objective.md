# v1.8.9 P0 model.auto source variant

## Objective

Make the declaration-derived `model.auto` workflow contract accept its typed
generic capability request when the compiler has added the standard `source`
binding. The source binding is a cross-operation workflow field, not a second
model.auto variant. Selector and generic-capability variants must remain
exclusive, typed and fail closed for unknown fields.

## Scope

- Update the model.auto contract/variant admission in
  `backend/workbench/agent/workflow_contracts.py`.
- Add focused contract coverage for selector, generic capability, and source
  binding behavior in the new test file.
- Preserve declaration-derived dispatch and unknown-field rejection.

## Non-goals

- Do not change model estimation, family selection, or post-estimation logic.
- Do not remove source dependencies from compiled workflows.
- Do not add a second capability list or a model.auto-specific runtime bypass.
- Do not modify workflow seam migration tests, providers, browser or release
  gates.

## Acceptance

- Generic `model.auto` with compiler-added `source` resolves its trusted
  dispatcher.
- Selector and generic variants remain distinct.
- Unknown fields still fail closed.
- Focused contract tests and `git diff --check` pass.
