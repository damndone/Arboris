# Workbench v1.8.9 P0 Workflow Derived Node Identity

## Objective

Make workflow dataset-producing node identities deterministic and
input-bound. A step specification fingerprint alone is not sufficient when
the same transform is applied to different source bindings or when a chain
contains repeated derivations. The node id, artifact paths, graph child, and
`node_index.json` entry must agree on the producing step and the actual source
identity, remain stable on replay/resume, and never collide across inputs.

## Scope

- `backend/workbench/agent/workflow_runtime.py`
- `tests/test_v189_workflow_derived_node_identity.py`

## Acceptance

- Repeated identical execution against the same bound source is idempotent.
- Identical transform specs against different source bindings produce distinct
  deterministic node/artifact identities.
- Chained numeric derivation and prepared/capability dataset lineage can write
  and resume without `node identity is not deterministic` collisions.
- Existing artifact digest, server-owned evidence port, and fail-closed path
  protections remain unchanged.

## Boundary

- Affected paths: the two paths above
- Allowed paths: the two paths above
- Protected paths: Agent/Notebook routes, evidence authority, registry, release state
- Dependencies: current workflow produced-dataset and node_index contracts
- Tests: `PYTHONDONTWRITEBYTECODE=1 PYTHONPATH=backend:tests .venv/bin/pytest -q tests/test_v189_workflow_derived_node_identity.py`
- Known gates: full backend, browser, production host/provider, and release acceptance remain separate
