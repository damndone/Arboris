# Workbench v1.8.9 P0 workflow legacy-test contract migration

Migrate legacy Agent workflow/data-management tests to the current fail-closed
workflow scope and server-owned metadata contracts without weakening runtime
authority.

Required outcomes:

- generic and natural-language workflow fixtures include the active-head scope
  required by the compiler;
- missing-value filters use confirmed metadata registry input rather than
  bypassing the data-consumer trust boundary;
- multi-step workflow tests continue to prove composition, derived columns,
  survey design propagation, and execution behavior under the current typed
  admission contract;
- no production authority, metadata, or execution boundary is relaxed.

## Migration status

The owned fixtures now carry `active_head_run_id` in every compiled workflow
scope, and the missing-value filter path seeds a confirmed server-owned
metadata envelope with detached schema and source hashes. The survey execution
fixture exercises the currently supported weight/strata/PSU design and keeps
unsupported FPC fail-closed.

The focused suite is partially green: 61 tests pass. One preserved execution
assertion remains blocked by the current production adapter boundary:
`data.rename` writes its derived data and recipe to the public artifact index,
but does not register those outputs in the active workflow receipt's
server-owned artifact registry. The following `model.genesis` step therefore
fails closed with `WORKFLOW_ARTIFACT_REGISTRY_REQUIRED: result artifact was not
admitted by a server-owned producer`. This line records the issue without
weakening the assertion or changing production authority code.
