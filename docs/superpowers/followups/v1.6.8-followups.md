## 0. 一句话结论

v1.6.8 已把「Launcher → 项目图 → 创世 draft 链 → 第一个 run」搬进图工作台，旧 Submit 表单只作为隐藏兜底保留。剩余事项分两类：一类是本轮暴露的工程债，另一类是 spec 明确划出 v1.6.8 的产品范围。

## 1. 工程债

- [ ] **`POST /runs` project_root 校验不对称**：`/uploads`、`/graph` 已显式校验项目根；`POST /runs` 仍沿用旧路径语义。后续应统一成同一套 `PROJECT_NOT_FOUND`/权限边界。
- [ ] **pipeline draft execute dedupe 响应形状不对称**：deduped 响应的 `produced_lineage` 与 fresh execute 不完全同形。本轮忠实保留 from-node 既有行为，未顺手改协议。
- [ ] **`useCapabilities.test.tsx` 负载相关 flake**：全量 vitest 偶发只红 `fetches /capabilities`，单跑稳定。建议单独修测试隔离或网络 mock 生命周期。
- [ ] **后端 `-k "draft or upload or genesis"` 排序下的 429 flake**：组合选择器偶发 run-slot 泄漏；逐文件和全量 gate 路径稳定。建议单独追踪测试清理纪律。
- [ ] **`runHistory.tsx` / `RunHistoryPanel` 生产死代码**：App 路由倒转后已无生产调用方；`RunHistoryRail` 是另一套组件。后续删除或标注计划复用，避免误维护。
- [ ] **run-detail Lineage 行为变化需写进版本说明**：现代 run 的 `/runs/:id?project_root=...` 深链现在落到项目森林并 focus 目标 run，而非只显示该 run family headset。这是 v1.6.8 有意方向，不是回归。
- [ ] **全量孤儿 upload/draft GC**：本版只做 discard 创世链时回收无引用 upload；项目级后台 GC 仍需单独设计。

## 2. v1.6.8 明确范围外

- [ ] **画布拖放建链**：数据模型已支持无父创世链，但本版宿主是右侧向导，不做拖放 builder。
- [ ] **Submit 表单代码删除**：本版只摘除主导航和 Launcher 入口；`/submit` 保留给 Command Palette 的「快速 run（旧表单）」和 batch run 兜底。
- [ ] **batch run (`y_list`) 图内化**：创世向导 v1 只做单 run；batch 继续留在 `/submit`。
- [ ] **后端项目注册表 / 项目级设置页**：Launcher 最近项目仍走前端 localStorage；项目根仍是文件系统路径。
- [ ] **图内任选对比 / 节点 Ask AI / 引用报告**：原 roadmap v1.6.8 内容已改签到 v1.6.9。

## 3. 建议排序

1. **发版前说明**：把 run-detail Lineage 行为变化和 `/submit` 隐藏兜底写进 release notes。
2. **v1.6.9 前置清债**：先处理 `POST /runs` project_root 校验、dead RunHistory、测试 flakes，避免新图内操作继续叠在旧边界上。
3. **v1.6.9 主线**：在项目森林 + 创世链完成后，再做任选对比、节点 Ask AI、引用报告。
4. **v1.7+ 宿主升级**：画布拖放建链、全量 GC、项目注册表/设置页可以拆成独立版本，不与 v1.6.9 的图内操作混排。

## 4. 2026-07-08 Claude review 追加发现

> 来源：Claude 对 Codex 修复批次的 review + 真机 smoke。
> 本轮已顺手修掉的不在此列（见 commit：drawer 角色区 node-hash、genesis 轮询长 run 卡死、`?genesis=1` 粘滞、resume 参数丢失、`..` 项目名、聚合边染色）。

### 4.1 同族债（建议 v1.6.9 前置清）

- [ ] **rerun-child draft execute 与 genesis 同族的长 run 窗口期**：`handleExecuteDraft` 在 execute POST 返回后立即移除 draft 节点并 refetch，但 run 是后台异步的——长 run（honest-DID ~157s）期间新 head 未入 index，画布回到旧状态、`pendingFocusTarget` 4s（20×200ms）就放弃 focus，用户观感是"draft 消失了、什么都没发生"。genesis 路径本轮已修（running 不烧重试预算 + failed/blocked 标记 draft 失败）；rerun 路径应统一到同一个 run-pending 状态机，而不是两套轮询。
- [ ] **RUNS rail 30s 轮询延迟**：`useRunHistory` 固定 30s 轮询，genesis/rerun 完成后 rail 最长 30s 才显示新 run（本轮 smoke 恰好被 forest refetch 掩盖）。建议 forest index 命中时主动触发 rail refresh，或统一走 SSE 事件。
- [ ] **pending 轮询缺集成测试**：`pendingGenesisExecution` / `pendingFocusTarget` 的成功/失败/超时分支只有人工 smoke 覆盖；fake-timer 单测（wizard 全流程驱动 + 异步 timer）过脆，建议放 Playwright smoke 层（见 handoff §5.5）。

### 4.2 UX / 产品层（需要拍板，不是纯代码修）

- [ ] **drawer 元信息行裸机器串**：DetailHeader 渲染 `{runId} · {nodeKey}`（森林下 nodeKey 是 64-hex hash，截成 `·…`）和裸 `owner_resolution` 枚举（`active_head_contains_node`）。这是 v1.6.2 NodeOperationContext 有意的调试可见性，有测试钉住；改法应是人类可读文案 + tooltip/copy 保留机器串，需要连同 v1.6.2 验收意图一起改。
- [ ] **role 缩写 `X` 二义**：`focal` 和 `explanatory_unspecified` 现在都显示 `X`（v1.6.8 把 `X?` 改掉响应"看不出变量名"的抱怨），仅 tooltip 可区分。如果 unspecified 的视觉信号还重要，需要新的呈现方案（如淡色/斜体 X）。
- [ ] **covariance 默认值硬耦合**：GenesisWizard 对非 DID 家族总是显式发送 `covariance_options[0]`（今天恰好 = 后端默认 `robust`）。前端 options 顺序一变就静默改变所有默认 run 的标准误。要么后端 capabilities 明确标 `default` 字段，要么前端只发用户显式选择。

### 4.3 既有记录确认在案（不重复展开）

- Variables 面板规模化（搜索/虚拟列表/role tabs）→ handoff §5.3
- Browse 产品边界 / workspace root / 项目注册表 → handoff §5.1 + 本文件 §2

- `WorkbenchRouteContainer` 拆分 → handoff §5.4（本轮轮询修复又 +40 行，拆分优先级上调）

## 5. 从更早版本滚入、仍未解决的债

> 整理 followups 时（2026-07-08）逐份核销，只有下面这条经代码核实**仍未解决**，
> 滚入本 live backlog；其余更早版本的 followups 已冻结进 `archive/`。

- [ ] **REV-3（v1.5.0 提出）：`classifyError` 把 adapter 层 bug 误报成 "network"**。
  `frontend/src/lineage/hooks/useGraphData.ts` 的 `classifyError` 对任何非 `ApiError`、
  非 schema 异常一律 fall through 成 `{ kind: "network" }`（现仍如此，`GraphError`
  联合里没有 `adapter_error`）。后果：`adaptRunGraph` 里的真 bug（TypeError/RangeError）
  会以「Could not load lineage」+ JS 栈的形式呈现，既误导用户、也让我们收到假的
  "network error" 反馈。P2 诊断正确性，非功能回归。
  修法（原 v1.5.0-followups 记录）：给 `GraphError` 加 `adapter_error` 分类；
  `classifyError` 仅当 `TypeError` 且 message 含 `"fetch"` 才判 network，其余判
  `adapter_error`；`statusViews.tsx` 的 `ErrorBanner` 加对应文案（与 network 视觉区分）；
  补 `classifyError` 单测（`Failed to fetch`→network；`Cannot read property`→adapter_error；
  `RangeError`→adapter_error）。
