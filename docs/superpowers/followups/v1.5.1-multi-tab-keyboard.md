# V1.5.1 follow-up: window-scoped keyboard listener won't survive multi-tab

**Source**: V1.5.0 Step 5 REV-3 adversarial review #8
**Status**: deferred — not blocking V1.5.0 (single GraphWorkbench instance)
**Owner**: V1.5.1 multi-tab design

---

## Problem

[`useGraphKeyboard`](frontend/src/lineage/hooks/useGraphKeyboard.ts:64) attaches its
`keydown` handler to `window`:

```ts
window.addEventListener("keydown", onKey);
```

V1.5.0 mounts exactly one `GraphWorkbench`, so the single listener is fine.
V1.5.1 introduces multi-tab, which will mount two or more workbenches
simultaneously. Each hook instance registers its own window listener, so a
single ⌘J fires every handler — the Raw JSON modal toggles once per mounted
tab and lands back where it started (or worse, in an inconsistent state if
tabs disagree on `enabled`).

Same hazard applies to ⌘K (search palette opens N times) and Escape (every
tab's dismissal handler runs).

## Options (pick one as part of V1.5.1 design)

1. **Singleton guard.** Module-level ref-count; only the first mount attaches
   the window listener, last unmount removes it. Cheapest change, but the
   "active" tab still has to be resolved by the callbacks — every tab's
   `onToggleRawJson` would fire unless we also track focus.

2. **Scope to a DOM root** (react-aria style). Hook takes a `ref` to the
   workbench container and binds `keydown` there instead of `window`. The
   shortcut only fires when focus is inside that subtree, which naturally
   routes ⌘J to the focused tab. Requires the container to be focusable
   (`tabIndex={-1}`) and the spec §12 wording to change from "global" to
   "when the workbench has focus".

3. **Coordinate via context.** One listener at the top of the tree dispatches
   to whichever workbench is currently active via a context-provided
   subscription. Most flexible, most plumbing.

Recommendation to revisit at V1.5.1 kickoff: **option 2** matches how the rest
of React Flow / react-aria handle scoped shortcuts and keeps each tab
self-contained, but the spec change needs sign-off.

## Acceptance check for V1.5.1

With two workbench tabs open side-by-side:

- ⌘J toggles Raw JSON exactly once, in the focused tab only.
- ⌘K opens the search palette exactly once.
- Escape dismisses the focused tab's modal without affecting the other.
- Closing one tab does not leak a listener (verify with Chrome DevTools →
  Memory → Event listeners).
