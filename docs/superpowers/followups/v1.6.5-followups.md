## 2. 本次测试发现的问题清单（含根因 + 是否在 v1.6.5 范围）

### A 组 — 画布角色可视化（v1.6.5 角色层应落地、属本版本补完）

- **P1 双路径冗余**：model 同时有 `stage:cleaned --ols_robust.fit--> model`（原聚合边）和 4 条 `var:* --enters_as_*--> model`（角色边）。
  根因：角色层之前变量节点不连 model；我新增的角色边制造了第二条平行路径。
  方向：变量可见（展开/角色化）时，**隐藏聚合边 `cleaned→model`**，由角色边承担「变量进入模型」语义；折叠时反之。
- **P2 展开 marker 位置错乱**：`▼ Variables (expanded)` 只有 `cleaned→marker` 一条虚线边，dagre 把它排进 4 个变量中间（第 4 位）。
  方向：marker 不进 dagre 自由布局，固定到组容器标题位（或并入 P3 容器，取消独立 marker 节点）。
- **P3 变量无外框容器**：展开后是 4 个独立节点，看不出「同属一个变量集合」。
  方向：用 React Flow group/parent 节点把这组变量框进一个带标题的容器（用户选定）。
- **P4 x/y/z 角色没上画布（spec §8 核心缺口）**：画布变量节点是裸 `wage (cleaned)`，看不出 Outcome(Y)/Focal(X)/Covariate(Z)。
  方向：① 变量节点加角色徽章（Y/X/Z…）+ 按角色染色/排序；② 角色边按 spec §8 用 solid（实体/识别/exposure）vs dashed（unit/time/cluster）；③ model 节点 `roles: unspecified` tag 上画布。
  注：抽屉里的 RoleGroupsSection / ModelSpecBlocks 可保留为「读法」，但画布必须自身可读。

### B 组 — 独立老问题（**spec §2 明确不在 v1.6.5 范围**，是 v1.6.4 polish 欠项）

- **P5 Pipeline 标签页是空的**：`workbench/views/PipelineView.tsx` 自 V1.5.2 就是 placeholder，从未实现，未排进任何已发版本。
  说明：用户记忆的「这个版本做 pipeline MVP」实为 **v1.6.4 的 Pipeline *Draft* MVP**（从 model 节点 Open as Draft Graph 的草稿编辑链路），与「Pipeline 视图标签页」是两个不同东西。
- **P6 Draft Graph 无法返回上一级**：打开 Draft Graph 后回不到 History-Lineage-Graph。spec §2 列为 v1.6.4「Draft Graph return/layout」polish，未做。
- **P7 Draft Graph 布局丑、内容挤在一起**：同上，v1.6.4 layout polish 欠项。

- **后端 `pipeline_drafts.py`**：v1.6.5 仅追加 focal_x 相关逻辑，未改 v1.6.4 的草稿契约/校验/dedupe。
