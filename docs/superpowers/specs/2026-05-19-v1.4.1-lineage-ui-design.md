## Overview

V1.4.0 shipped the lineage graph **substrate** — data model, JSON store, orchestrator hooks, 6 decision-point trigger sites, and a `GET /runs/{run_id}/graph` endpoint. There is no UI yet; the substrate is invisible to users.

V1.4.1 makes lineage visible. Three coordinated workstreams:

| Stream | Owner | Independence |
|---|---|---|
| **A. Backend polish** (factory consolidation, multi-DP support, patsy unification, summary field) | Other engineer | Cross-cuts API contract |
| **B. Lineage UI** (graph view + Inspector + decision review UX) | Claude (frontend) | Depends on §1-§4 contract |
| **C. Frontend metadata layer** (`dpRegistry.ts`) | Claude (frontend) | Fully frontend-internal |

Parallel development is feasible because the cross-cutting contract (§1-§4 below) is locked up-front. Backend and frontend then build to the contract independently and meet at integration.

## Cross-boundary contract

These four sections are the handoff document for the parallel backend engineer.

### §1 — Multi-DP schema

**Goal:** A node may carry multiple DecisionPoints. V1.4.0 limited it to one and the orchestrator emitted a `UserWarning` when discarding a second. V1.4.1 lifts the limit.

**Data shape (in-memory + serialized):**

```python
@dataclass(frozen=True)
class Node:
    ...
    decision_points: tuple[DecisionPoint, ...] = ()
    # `decision_point` removed from the dataclass entirely
```

**`graph_from_json` parser behavior** (backward-compat with V1.4.0 files):

| Input shape in JSON | In-memory `decision_points` |
|---|---|
| `{"decision_point": {...}}` (legacy V1.4.0 single DP) | `(DP,)` |
| `{"decision_point": null}` (legacy V1.4.0 empty) | `()` |
| `{"decision_points": [...]}` (V1.4.1 format) | unchanged |
| Both `decision_point` and `decision_points` present | use `decision_points`, ignore `decision_point` |
| Both absent | `()` |

**`graph_to_json` writer behavior:** always writes `decision_points` (never `decision_point`); empty case writes `decision_points: []`.

**Orchestrator change:** `orchestrator.py:461` no longer needs the `or` precedence logic or the discard warning — both DPs now ride together in `decision_points`.

**`resolve_decision_id()` helper update:** `graph_model.py:217-230` currently iterates `node.decision_point`. Update to iterate `node.decision_points` (loop over the tuple, return first match). Without this fix, alias resolution silently breaks.

**Schema version bump 1 → 2.** The on-disk field name changes (`decision_point` → `decision_points`) and a new `summary` field is added on Node. This is exactly what `schema_version` is for:

- Writer always writes `schema_version: 2`.
- Reader accepts both `1` (V1.4.0 files) and `2` (V1.4.1+) and applies the parser truth table above.
- Files written under `1` are auto-migrated to in-memory V1.4.1 shape on read. Re-saving any V1.4.0 file produces a `2`-shaped file — this is expected, not a bug, but fixture comparisons in tests must use semantic equality (parsed Graph) rather than raw JSON byte comparison.

**Required migration tests** (`tests/test_graph_store.py`):
1. `test_legacy_v1_single_dp_promoted_to_list` — `schema_version=1` JSON with `decision_point` only → in-memory `(DP,)`
2. `test_v2_multi_dp_round_trips` — `schema_version=2` JSON with `decision_points: [DP, DP]` → unchanged
3. `test_dual_field_uses_decision_points` — JSON with both fields → `decision_points` wins
4. `test_missing_dp_field_yields_empty_tuple` — neither field → `()`
5. `test_writer_emits_schema_version_2` — round-trip of legacy v1 file produces v2 output

### §2 — API response shape

```jsonc
GET /runs/{run_id}/graph
{
  "schema_version": 2,                     // ← bumped from 1 in V1.4.1
  "run_id": "...",
  "legacy": false,
  "stats": {                             // ← new in V1.4.1
    "node_count": int,
    "edge_count": int,
    "leaf_count": int,                   // nodes with no outgoing edges
    "has_dp_count": int                  // nodes with len(decision_points) > 0
  },
  "nodes": {
    "<node_id>": {
      "id": str,
      "kind": "model" | "dataset_stage" | ...,
      "display_label": str,
      "summary": str | null,             // ← new in V1.4.1
      "created_at": "ISO8601",
      "parent_stage_id": str | null,
      "branch_id": str,
      "trust": "ok" | "caution" | "warning" | "blocker",
      "trust_reason": str | null,
      "archived": bool,
      "payload_ref": str | null,
      "decision_points": [DP, ...],      // ← changed (was decision_point)
      "annotations": []                  // reserved
    }
  },
  "edges": {...},                        // unchanged
  "branches": {...}                      // unchanged
}
```

Edge `summary` field and Node `trust_explanation` field NOT added — current `op` + `trust_reason` are sufficient.

### §3 — Copy as branch path

**Format:** plain text, root-to-current human-readable decision chain. Suitable for IM/Notion/PR paste.

**Per-node rendering priority:** `summary` → `display_label` → (on edges) `op` → `id`.

**Per-decision_point rendering at a node:** `[<friendly_title>: <selected_display> | <whyShort>]` where `friendly_title`, `selected_display`, and `whyShort` come from `dpRegistry.ts` (frontend metadata, see §6).

**Example output** for a typical run, copied from the `model:ols_1` node:

```
Cleaned data (32 rows × 3 cols, 3 dropped) → [Handle missing values: Drop rows | 3 rows removed] → Variables (5) → [Model type: OLS | y appears continuous] [Standard errors: HC1 | system default] → Primary OLS (OLS · HC1 · n=32)
```

JSON / deep-link variants live behind the **More** menu (§7 Frontend) and are V1.4.1-trivial extras (`Copy node ID`, `Copy as JSON`), not feature commitments.

### §4 — `summary` field generation rules (backend responsibility)

The backend fills `Node.summary` at node-creation time. Rules per NodeKind:

**Plumbing requirement:** `GraphRecorder.record_stage` / `record_variable` / `record_model` / `record_report` all gain a `summary: str | None = None` keyword argument. `_add_node` stores it on the constructed `Node`. The orchestrator computes the appropriate string per the table below at each of its 12+ `record_*` call sites and passes it in. Without this signature change, summary cannot reach the node.

| NodeKind | `summary` content |
|---|---|
| `DATASET_STAGE` (raw) | `"Raw: {N} rows × {M} cols"` |
| `DATASET_STAGE` (cleaned) | `"Cleaned: {N} rows ({K} dropped)"` if `K>0`, else `"Cleaned: {N} rows"` |
| `VARIABLE` (kept numeric) | `"Kept as numeric"` |
| `VARIABLE` (categorical dummy) | `"Dummy-encoded ({n_levels} levels, ref={ref_level!r})"` |
| `VARIABLE` (coerced) | `"Coerced to numeric ({conversion_rate:.0%} convertible)"` |
| `VARIABLE` (dropped) | `"Dropped: {reason_display}"` (uses `reason_display` from V1.4.0 P2-E refactor) |
| `MODEL` (OLS) | `"OLS ({se_type}, n={n})"` |
| `MODEL` (Logit) | `"Logit (n={n})"` |
| `MODEL` (Poisson) | `"Poisson rate (exposure={exp}, n={n})"` if exposure else `"Poisson (n={n})"` |
| `REPORT` (HTML) | `"HTML report"` |
| `OPERATION` / `TEST` / `PLOT` | `null` for V1.4.1 (no current emitters) |
| Unrecognized `DATASET_STAGE` subtype (future) | `null` |
| Any unhandled case | `null` (frontend MUST fall back to `display_label`) |

Tests: one test per row that constructs the node and asserts `summary == expected`. Suggested location: `tests/test_orchestrator_summary.py` (new file).

**Legacy V1.4.0 graph.json files:** when read, `summary` is always `null` (the field didn't exist). The frontend MUST treat `null` as "no summary, fall back" — see F2/F5 rendering rules.

### F1. Lineage tab in `runDetail`

- Tab strip: `Overview` (existing content) / `Lineage` (new).
- Tabs persist in URL query: `?tab=overview` / `?tab=lineage`. Default to `overview`.
- `LineageTab` fetches `GET /runs/:id/graph` on mount; spinner during load.
- `legacy: true` response → show empty state: "No lineage data for this run" + brief explanation that the run predates V1.4.
- HTTP 404 → "Run not found"; HTTP 422 (`GRAPH_CORRUPT`) → "Lineage data is corrupt" + `Try again` button + show error code; network error → "Could not load lineage" + retry button.

**State placement rules** (apply across F1-F9 — codify here to avoid ad-hoc patterns):

| State | Storage | Rationale |
|---|---|---|
| Active tab (`overview` / `lineage`) | URL query `?tab=` | Shareable deep-link, browser back/forward |
| Selected node ID | URL query `?node=` | Shareable deep-link to a specific node Inspector |
| Group folding state (which clusters expanded) | React local state in `LineageTab` | Ephemeral, no value in URL |
| DP card expanded/collapsed state | React local state in `Inspector` | Ephemeral, resets on node re-select |
| More menu open state | React local state in `MoreMenu` | Always ephemeral |
| Raw JSON modal (⌘J) open state | React local state in `Inspector` | Power-user transient |

No React Context, no Redux. Local state lifts to nearest common ancestor when shared between siblings.

### F2. Graph view (`GraphCanvas` + `NodeCard`)

React Flow with `nodesDraggable={false}` (lineage is read-only), `nodesConnectable={false}`, `panOnDrag={true}`, fit-view on mount.

Auto-layout: use `dagre` for vertical DAG layout (top-down, left-aligned). React Flow re-runs layout when group nodes toggle.

`NodeCard` (custom node type) — iOS compact card:

```
┌──────────────────────────────────┐
│ Primary OLS                      │  ← display_label (14px / semibold)
│ OLS · HC1 · n = 32               │  ← summary (12px / secondary color)
│                                  │
│ ⚠ Review · 2                     │  ← status pill (only if applicable)
└──────────────────────────────────┘
   240×~78px · border 1px / 10px radius / 12-14px padding
```

**Status pill rules:**
- Compute `review_count = sum(1 for dp in node.decision_points if dp.contestability.review_status in {'needed','failed'})`
- If `review_count > 0` → `⚠ Review · {N}` orange pill
- Else if `node.trust in {'warning','blocker'}` → small trust pill in the trust color
- Else nothing (clean node)

**Summary line rules:**
- If `node.summary` is a non-empty string → render as the second line
- If `node.summary` is `null` or empty (legacy V1.4.0 reads, or NodeKinds without summary rules) → **hide the second line entirely** (no placeholder, no fallback text — node card becomes 1-line)
- `display_label` is always shown as the first line regardless

Selected state: tint border + 4px tint shadow (no other change to layout).

### F3. Folding: variable/dropped clusters

When all of these hold:
- More than 3 variable nodes hanging off `stage:cleaned`
- They share the same `parent_stage_id`

…the frontend wraps them into a single virtual `node` of kind `group:variables` rendered as a NodeCard with title `Variables ({n})` and subtitle `Tap to expand`. Same applies to dropped-variable nodes → `Dropped variables ({n})`.

Group expansion is local-only frontend state (no API call); toggling re-runs dagre layout.

Group nodes never carry their own DecisionPoints; clicking the group expands the cluster, not the Inspector.

### F4. Hover tooltip (`NodeTooltip`)

**Trigger rule:** appears on hover **only when the node is not the currently selected node**. Selected node never gets a tooltip (Inspector is already open).

Content: title + summary + one status line ("N choices need review" if `review_count > 0`, else nothing) + "Tap to inspect" CTA. **Never** show warning text or DP details — those are Inspector-only.

Delay: 200ms hover-in, instant hover-out.

**Collapsed `DecisionCard`** — compact row:
- `⚠` icon if `review_status in {needed, failed}`

### F8. Copy as branch path (`pathBuilder.ts`)

Pure function: `(graph, targetNodeId) => string`. Walks the edges backward from target to root (only one parent per node in current V1.4.0 — DAG without merges), composes the prose per §3.

**Topology safety:**
- Maintain a `visited: Set<string>` of node ids; if walking a parent edge revisits a node, treat the chain as terminated (cycle or shared ancestor — return path so far with " [truncated: cycle]" suffix).
- Hard cap at 100 hops; exceeding renders " [truncated: too deep]" suffix.
- If a node has multiple incoming edges (multi-parent — not produced by V1.4.0 but possible in future merges), pick the edge with the lexicographically smallest `source_id` deterministically and continue.
- All three guards have unit tests in `pathBuilder.test.ts`.

Wired to the Inspector's `Copy path` button via `navigator.clipboard.writeText`. After successful copy, button text briefly changes to `✓ Copied` for 1.5s (iOS-style transient feedback).
