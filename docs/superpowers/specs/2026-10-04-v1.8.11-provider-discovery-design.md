# v1.8.11 Provider Model Discovery

用户已授权 objective 内自主设计；本设计落实第 9 步，不改变统计口径。

现有保存要求 model 非空，刷新要求 provider 已保存，造成首次添加时只能手填模型才能发现列表。选择保存前只读发现，而非猜测默认模型或先持久化不完整配置。

- POST /llm/providers/models/discover 只接收 base_url、api_key、timeout_s，沿用 URL/超时校验、上游错误清洗及 /models 解析。凭据仅用于该请求，不写配置、不回显。/models 不需要已有模型名；聊天的完整配置要求不变。
- 新增/复制服务商输入完整 URL 与 API key 后，在离开该输入时自动发现；也可点击 Refresh models。请求期间和失败/空列表都有明确状态；失败保留手填和旧列表。
- 表单模型来自服务商返回，默认模型保留空值或用户已填值，使用建议列表由用户选择，绝不猜第一个。保存仍由用户明确点击。
- 已有服务商刷新继续使用现有带 store 并发保护的 endpoint，保留其自定义显示名/上下文/模型默认。发现时配置变更使旧响应失效，防止填错服务商列表。
- 删除 UI 版本模型预设按钮和环境配置中版本显示名映射；环境只声明实际配置的模型。兼容已有持久化用户模型名，不改用户配置。

验证：真实 HTTP client MockTransport 测试任意/版本变化模型、无 model 的发现、无持久化、URL/超时/秘密清洗、失败与空列表。React 先失败覆盖创建自动发现、建议/手填、失败保留、异步旧响应；旧 refresh 测试继续。浏览器用可控本地模型服务验证新增/离线手填，真实 DeepSeek discovery 与余额/评测阶段另记。
