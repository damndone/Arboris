# v1.8.9 P1 Data Consumer Remediation Design

## Scope

This remediation is package-local to the Data Consumer interchange and
canonical data-operations UI seam. The implementation baseline is
`73a09151aa3ab4eb1cdb2e3c94fca2df93df92b3`; the remediation formal line starts
from the exact current closeout tip
`dff7c6d9f0dcdc8f243a83a6f0f048e90ba3c4bb`.

It does not change central Agent, Notebook, Report, provider, browser, host,
merge, or release behavior. Those boundaries remain explicitly unverified.

## Findings and decisions

### Interchange

The existing helper writes a temporary file only as an implementation detail
of `round_trip_frame`; there is no typed public writer/capability result. The
fix adds a public writer branch that checks the format capability before
creating a file. A missing optional dependency returns a stable typed
`unavailable` result with `reason_code=optional_dependency`; it never claims a
format is supported and never creates a partial artifact.

The round-trip path uses the same writer branch and then reads the produced
file back. The result reports frame equality, dtype/schema equality, and the
explicit metadata-loss boundary. Parquet uses an available pandas engine
(`pyarrow` first, then `fastparquet`) for both write and read-back. CSV, XLSX,
and Parquet are each tested as real file round-trips when their capabilities
are available, otherwise the test asserts the typed unavailable boundary.
`.sav`, `.zsav`, and `.dta` continue to be unavailable when `pyreadstat` is not
installed.

### Canonical data editor

`DataOperationsSection` remains the single user-facing operation editor. The
canonical workbench section registry receives a thin adapter that:

1. obtains the typed node-operation identity and project root;
2. obtains the server-resolved source artifact identity;
3. fetches the live server-owned operation manifest; and
4. passes raw preview/confirm transports to `DataOperationsSection`.

The adapter does not calculate operation results, synthesize descriptors, or
confirm locally. Preview and confirm continue to be server routes selected by
the server manifest, and the existing strict typed completion/effect/output
validation remains authoritative.

The old read-only evidence projection is not used as the canonical data
operation editor. It remains available only as a declaration/evidence helper
where existing callers require it.

## Rejected alternatives

- Keeping the private round-trip helper would leave real write capability
  undiscoverable and would not provide a typed missing-dependency boundary.
- Reimplementing operation forms in the registry would duplicate the existing
  server-confirmation and typed-completion checks.
- Inferring an artifact ID from display labels or raw graph payloads would
  weaken source identity. The adapter uses the existing typed context seam.

## Verification matrix

- Backend: focused interchange and ingestion metadata tests, including writer
  capability, real Parquet write/read-back, CSV/XLSX/Parquet availability or
  unavailable assertions, and native statistical-file unavailable assertions.
- Frontend: focused `DataOperationsSection` tests plus canonical registry
  registration/user-path coverage. Existing strict typed-completion tests stay
  in the focused run.
- Hygiene: `compileall` for changed Python modules, `git diff --check`, formal
  event-stream verification, and CLI retrospective regeneration.

Browser acceptance, external provider/full gate, host gate, central Agent /
Notebook / Report integration, merge, and release remain `NOT VERIFIED`.
