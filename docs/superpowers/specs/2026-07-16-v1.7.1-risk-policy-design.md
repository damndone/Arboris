# v1.7.1 P-RISK1：高风险操作策略、发布后 blocker 与测试卫生

状态：实现完成（P-RISK1、B1、B2、N-COV、P-SBX1）；P-SBX2 延期为独立设计债
基线：v1.7 / `1a46c0ae182cb0e2d43e2b0e96cf780463777a1b`

## 1. 目标

让 registry 中的 `risk_level=high` 参与后端执行策略，而不是只作为 capability/UI 元数据。
本版本只落地已有 typed `code.execute` 入口，并把规则接入通用 operation lifecycle，确保未来任何高风险 typed operation 都不能绕过同一条策略。
P-RISK1 完成后，追加两个已实证的发布后 blocker：code.execute 部分物化后的 replay 自愈，以及 explicit LLM pin 的 fail-closed 边界。

## 2. 明确不做

- 不开启 `code.execute` 的自然语言能力；`natural_language_enabled` 继续为 `false`。
- 不调用真实 DeepSeek、不读取真实 API key；测试使用本地 fake/local provider 或纯本地 operation handler。
- 不做 P-CE1 preview cache；preview 仍按既有 v1.7 语义运行，不能把 preview 当作执行缓存。
- 不做多步骤编排、多 worker、V11 扩展、时间序列集成或统计学研究 Agent。
- 不重做 v1.7 的 sandbox、active-head 校验、typed proposal lifecycle 或 lineage 逻辑。
- 不做 P-CE1 preview cache 或执行去重重写；B1 只删除危险早返回，允许确定性代码按既有幂等步骤 replay。
- 不处理 N3 的根目录 untracked 规划文件。
- 不修改两个 adversarial protected tests。

## 3. 风险策略状态机

```text
pending
  └─ ordinary confirmation ──> confirmed / operation record pending
                                  │
                                  ├─ non-high: existing lifecycle execution
                                  │
                                  └─ high: risk authorization required
                                             │ explicit user acknowledgement
                                             v
                                      risk_authorized / token issued
                                             │ one-time consume, before effect
                                             v
                                      submitted/running/executing
                                             │ crash or request loss
                                             v
                                      recovering ──> reconcile with same execution key
```

`confirmed` 不是高风险执行许可。高风险 operation 在产生任何 child effect、文件写入或 domain commit 前必须持有已消费且绑定正确的 risk authorization。

## 4. 授权凭证契约

风险授权记录采用 project-local append-only durable storage。持久化原始 token 的 SHA-256 digest，不持久化原始 token；原始 token 只在签发响应中返回。

授权必须绑定以下字段：

- `authorization_id`
- `operation_id`、`operation_version`
- `proposal_id`、`revision`、`fingerprint`
- `session_id`、`chain_id`
- `active_head_run_id`
- `execution_key`
- `issued_at`、`expires_at`、`actor_type`

规则：

1. TTL 为短时窗口（实现默认 5 分钟），过期授权拒绝执行。
2. token 只能消费一次；同一个 `authorization_id + execution_key` 的重试是幂等的，其他 execution key 的再次消费是 replay，必须拒绝。
3. proposal revision、fingerprint、active head、operation identity 任一变化都视为 stale/replay，不能借用旧授权。
4. 授权消费必须在 operation record 已经绑定 `authorization_id` 后发生；因此请求崩溃不会留下“已授权但无法恢复定位”的执行。
5. recovery 不签发新 token、不生成新 execution key；如果已有消费记录，必须用原绑定继续 reconcile；如果只有 issued 未消费，恢复路径 fail closed。

## 5. 后端职责边界

### HTTP typed confirm

- `POST /data-operations/code-execute/risk-authorize`：复核 preview、source、session/Chain scope 和 active head；完成 ordinary confirmation；在显式风险确认后签发一次性授权。
- `POST /data-operations/code-execute/confirm`：复核当前 preview/fingerprint/active head；要求 `authorization_id + risk_authorization_token`；绑定并消费授权后才可进入执行。
- 缺少授权、过期、replay、stale 都是明确的 409 类错误，不返回“已应用”或伪造 operation success。

### Orchestrator

- 读取 registry 的 `risk_level`，将高风险 operation 的授权上下文写入 durable operation record。
- 负责把 token 消费和稳定的 `execution_key` 关联起来。
- 不把前端按钮、自然语言文本或 `sandboxed` 文案当作安全边界。

### Generic lifecycle

- 在 claim 后、调用 handler `prepare/execute` 之前，对 `risk_level=high` 强制检查授权已消费且所有绑定字段相等。
- 普通 operation 保持 v1.7 行为。
- 授权检查失败不得产生 domain lease、child effect、effect binding 或 domain commit。

## 6. UI 流程和文案

typed `CodeExecuteSection` 的流程为：

1. 运行现有 sandbox preview。
2. 展示 schema/row diff 和风险提示：sandboxed 只表示隔离执行环境，不表示这个操作低风险；它仍会创建新的 child data node、使下游模型需要 rerun。
3. 用户明确勾选/确认风险后请求 risk authorization。
4. 只有拿到授权后，`Apply as new node` 才能提交执行；授权错误继续显示为错误，不显示完成。

Agent panel 的普通 proposal 文案继续区分 proposal confirmation 与 execution。当前 `code.execute` 不进入自然语言 proposal surface，因此不为它增加 NL 入口。

## 7. 测试矩阵

- Registry/API：`code.execute` 仍为 high、required、NL disabled；授权接口签发并返回绑定元数据。
- Stale/replay：错误 fingerprint、revision、active head、operation/proposal、过期 token、重复 token 都拒绝。
- Lifecycle：缺少授权在 effect 前拒绝；正确授权只消费一次；同 execution key 重试幂等。
- Failpoint/reconcile：`after_claim`、`before_child_effect`、`after_child_effect`、`after_effect_binding`、`before_domain_commit`、`after_domain_commit`、`before_terminal_reconcile` 崩溃后沿原 execution key 恢复，不重复 child effect。
- Frontend contract：风险文案可见，必须先授权再 Apply；代码/格式/source 变化会清除旧授权。
- Browser smoke：仅验证现有 typed code operation 的可见两步流程，不使用真实 provider/API key。
- Existing non-high regression：`model.rerun`、`graph.fork`、typed casts 的 v1.7 confirmation semantics 不变。

## 8. 验收标准

1. 对 `code.execute`，没有有效一次性 risk authorization 时，后端永远不进入 effect handler。
2. 风险授权不能跨 proposal revision、preview fingerprint 或 active head 使用。
3. 同 execution key 的崩溃恢复最多产生一个 child effect；重复 confirm 不重复执行。
4. `code.execute` 的 NL surface 仍关闭，真实 DeepSeek/API key 未被测试读取。
5. 两个 protected adversarial tests 和 v1.7 worktree 保持不变。

## 9. P-RISK1 之后的独立 review blockers

### B1：code.execute 部分物化后的 replay 必须自愈

`apply_code_execute` 不得因为 recipe 和 artifact 已存在而提前返回。崩溃可能发生在 artifact/recipe 落盘之后、artifact registry、graph store 或 node index 更新之前；replay 必须重新运行确定性代码，并依次执行既有的 `_write_frame_artifact`、`_ensure_registered_artifact`、graph mutate 和 `_ensure_node_index_entry` 幂等步骤。不得借此引入 P-CE1 的 preview 缓存或重复执行重写。

验收：用户提供的 orphan replay 脚本在允许本地 sandbox 的环境中输出 `✅ replay 自愈`；常驻测试覆盖 registration 前 failpoint 后的 replay，并确认 artifact registry、graph child、node index 都恢复。

### B2：explicit LLM pin 的不完整 active provider 必须 fail-closed

当 `WORKBENCH_LLM_CONFIG_PATH` 已设置时，store 缺失、无效、active provider 不存在或 provider 未配全都不得调用 `environment_provider_from_env()`。返回不可调用的 explicit-config source 和真实配置错误；只有 `explicit is None` 的默认路径允许环境 fallback。测试不得调用真实 provider 或读取真实 API key。

### N-COV：保留默认路径的环境 fallback 覆盖

默认路径（没有 `WORKBENCH_LLM_CONFIG_PATH`）即使存在一个 active provider 但其 key 已被 Settings UI 清空，仍必须回退到环境配置。显式 pin 路径继续 fail-closed；两条语义分别由测试固定。

### P-SBX1：B1 恢复测试的无后端守卫

`tests/test_code_execute_recovery.py` 使用与三个兄弟沙箱测试一致的模块级 `pytestmark`：没有 OS sandbox backend 时合法 skip，并保持 code.execute 生产路径的 fail-closed 行为不变。这个测试卫生债已在 v1.7.1 清掉。

### P-SBX2：沙箱后端“存在”与“可用”的能力探测（延期）

`isolation_backend()` 继续保持生产路径的轻量探测语义，不在本版引入执行开销。后续独立设计仅供测试使用的、模块级缓存的能力探针：无后端可以 skip；后端存在但执行被拒绝时必须以 gate 可见的失败或醒目 skip 原因暴露，不能静默吞掉安全测试。
