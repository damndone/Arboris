## 为什么先写这份

v1.8.4 的范围漂移不是执行问题：三条 devline 对着各自冻结的 objective 都交付了，
个别还超额。问题是**从来没有一份文档回答过「这个版本整体交付什么」**——
`specs/` 里 v1.8.1/8.2/8.3 都有设计文档，v1.8.4 一份没有，范围只活在逐线的
Context Pack 里。于是版本号被复用成了另一个主题，roadmap §5 至今没同步。

这份文档就是那个缺失的层。**范围以本文件为准，devline 的 objective 是它的切片。**

## 目标

本版由三段按依赖顺序组成，目的相同：让已建成的子系统以可见、可撤销、可验证的
方式真正作用到 Agent 行为上。

1. **A — Typed Memory 产品化**：v1.8.3 建了 `domain_memory` 子系统，v1.8.5
   先补齐作用强度与有效性，再提供本机持久化 bootstrap、项目/全局管理和二次确认。
2. **B — 受限默认值注册表**：把 OLS 专用的 `suggest_default` 扩展为受服务端控制的
   `DefaultTargetContract`，让 Panel 与已验证的时序 Recipe 能安全使用记忆建议。
3. **C — 可执行分析契约**：在 `ModelFamilyContract` 中纳入已有回归能力，并用独立的
   `RecipeContract` 纳入 ETS 与 ARMA/GARCH；两者共享授权、谱系和结果投影，但不共享
   错误的字段形状。

## 非目标（明确排除，防止再次漂移）

- **Context Compiler 六层检索链**（Graph 邻域 → 元数据过滤 → 有界投影 → 关键词 →
  语义 → rerank）。`domain_memory/retrieval.py` 现有的谓词匹配够本版用；六层检索
  是另一个量级，单列后续版本。**本版不宣称实现了项目历史检索。**
- 向量库、语义检索、rerank。
- `require_confirmation` 档（与既有 Proposal/Risk 生命周期职责重叠，见 §1.2）。
- 任意公式、代码执行、原始数据浏览、自动执行。
- 新估计器、自动调参、模型竞赛、机器学习或量化。v1.8.6 的预测 SplitPlan、样本外
  评估与 packet schema 版本闸门不得提前并入本版。
- 为了 Notebook 接入而新造一批无 schema 版本的 artifact。只能复用现有稳定产物；
  新 packet 留待 v1.8.6 的 artifact schema 工作完成后再引入。

## 1. Typed Memory 作用面

### 1.0 现状（v1.8.3 已有，不重建）

`DomainMemoryContentRevision` 已带 `memory_id` / `revision` / `scope` /
`memory_kind`(5 类) / `applicability_predicates` / `compact_lesson` /
`recommended_effect_kind` / `source_summary_refs` / `evidence_status`(3 档) /
`review_after` / `supersedes_revision` / `conflicts_with` / `content_hash`；
`MemoryCandidate` 带 `expires_at`；另有 candidate/approval/validity 记录、
scope、冲突、脱敏、curator、review scheduler。

### 1.1 补齐 Registry 字段

| 新增 | 语义 | 为什么需要 |
|---|---|---|
| `memory_kind` 增 `project_domain_fact` | 财年 4 月起、`customer_id` 是分析单位、某字段单位 mg/L | roadmap 四类分级里唯一没有对应 kind 的一类 |
| `apply_mode` | `inform_only` \| `suggest_default` | 见 §1.2 |
| `vocabulary_version` | 记忆断言所依赖的词汇表版本 | 词汇表变了，记忆的 `recommended_target_refs` 可能指向已不存在的字段 |
| `verifier` | 指向能重新判定该记忆是否仍然成立的具体检查 | 没有 verifier 的 `last_validated_at` 是无法维护的 |
| `last_validated_at` | 上次**验证**通过的时刻 | 与既有 `review_after`（计划性）区分：一个是「该复查了」，一个是「确实还成立」 |

`confidence` **不新增**：既有 `evidence_status` 三档已经承担这个角色，再加一个
连续型置信度会产生两个可互相矛盾的可信度来源。

### 1.2 apply_mode：记忆能改什么

```
apply_mode ∈ { inform_only, suggest_default }
```

- `inform_only`：只作为可见提示进入上下文。当前全部记忆的隐式语义。
- `suggest_default`：**可以改变 typed proposal 的默认值**，但
  - 用户仍必须确认（不绕过 Proposal/Risk 生命周期）；
  - 界面必须显示「这个默认值来自哪条记忆」，带 `memory_id` 与 `revision`；
  - 记忆**永远不能获得 `bypass_validation`**——改默认值不等于跳过当前数据检查。

不做 `require_confirmation`：Workbench 已有 Proposal/Risk 确认生命周期，再引入
一档「记忆要求确认」会产生两套确认语义，谁覆盖谁没有非任意的答案。

**不变量（必须有测试钉死）**
- 一条 `inform_only` 记忆在任何路径上都不改变 proposal 字段。
- 一条 `suggest_default` 记忆改了默认值时，proposal 必须携带其来源；
  来源缺失即 fail-closed，不允许出现「无主的默认值」。
- 记忆不改变 evidence、admission、推荐排序或执行授权（v1.8.3 已有的边界，
  本版扩大 apply_mode 后要重新钉一遍）。

### 1.3 有效性执行者（两层，都要）

**A. 运行时判定（兜底）**
`retrieve_domain_memory` 返回前判定 `expires_at` / `review_after` /
`vocabulary_version`：
- 已过期 → 不返回，记一条 `RetrievalOmission`（现有类型，复用）；
- `vocabulary_version` 与当前词汇表不符 → 不返回，omission 说明版本不符；
- `last_validated_at` 早于 verifier 要求的窗口 → 降级为 `inform_only` 返回，
  **不允许一条久未验证的记忆去改默认值**。

保证：**过期或失效的记忆永远影响不到 Agent**，无需外部调度。

**B. gate.sh preflight（可见性）**
在 gate 里判定仓库内所有已批准记忆的有效性，把「即将过期 / 已失效 /
verifier 缺失」列出来。CI 层可见，但**不阻塞**——阻塞会让一条记忆过期直接把
gate 弄红，与产品正确性无关。

两层职责不同：A 保证正确性，B 保证可见性。只做 B 的话，一条过期记忆在两次
gate 之间仍会影响 Agent；只做 A 的话，没有人会知道记忆正在批量失效。

### 1.4 A：本机持久化与用户管理

Workbench 首次启动时创建一个**空**的本机 `DomainMemoryStore`。创建空库不是启用
记忆：全局库、项目库和每个项目对全局库的继承都默认关闭。产品不扫描或长期学习全部
聊天历史；只有用户明确批准的记忆，或用户明确允许产生的有界 candidate，才会进入库。
Store 位于应用自有的本机数据目录、以不含原始项目路径的 scope identity 分隔，并由
既有安全目录/锁定语义保护。目录不可用、损坏或权限不安全时，启动不得崩溃：记忆功能
显示不可用且 fail-closed，不能退化为临时的未审计内存库。

bootstrap 必须同时安装服务端 `LocalMemoryScopeResolver` 与 `MemoryStoreSet`：前者从
本机安装身份和当前项目的规范化身份导出 global/project scope，后者只按这两个已解析的
scope 打开 store 并合并 retrieval。前端和 Agent 不得提交 `MemoryScope`、文件系统路径
或 owner identity；HTTP 路由只接收当前 project 的受限引用，由服务端解析。项目根移动或
identity 不可解析时，默认不继承旧记忆，显示恢复/迁移说明，而不是猜测它属于哪个项目。

```
本机 DomainMemoryStore（初始为空）
├── Global library：可复用的已批准记忆
└── Project library：仅当前项目的已批准记忆

项目使用 Global library
    = 全局库已启用 AND 当前项目明确授权继承
```

前端管理必须完整，不要求用户编辑文件或调用 API：

| 位置 | 能力 |
|---|---|
| Settings → Memory | 总开关、全局库列表、单条编辑/停用/删除、清空全局库 |
| Project → Memory | 项目库列表、继承全局库、允许候选生成、单条/批量管理 |
| Draft / Option | 每一项实际采用的记忆来源、revision、目标字段、风险与恢复原值操作 |

**确认与删除语义**

- 开启全局记忆、项目记忆、项目继承或 candidate 生成前，必须二次确认，明确可读取的范围、
  仅提示/建议默认值的作用强度，以及“不自动执行”的边界。
- 删除单条、批量删除和清空库前，必须二次确认，明确 scope、数量和未来影响。
- 二次确认不是纯前端效果：服务端只接受绑定 `action`、`scope`、目标 revision/数量和
  短时有效期的 `MemoryMutationConfirmation`。缺失、过期、scope/revision 不匹配的
  写入一律拒绝；支持的 Agent 工具没有签发该 receipt 的能力，不能绕过弹窗。
- 这是单用户本机产品中的**用户意图闸门**，不是对同一操作系统账户下任意进程的访问控制。
  将来多用户/远程部署必须另接认证身份与部署 authority，不能把本机 confirmation 误称为
  多租户安全边界。
- 删除使记忆立即不能影响未来计划、Draft 或默认值；已完成 Run 中已经持久化的
  `memory_id`/`revision` provenance 不回写、不抹除。这是可复现分析的历史证据，
  不是仍可被读取的活动记忆。
- 关闭读取只停止未来 retrieval，不删除记忆；关闭 candidate 生成只停止未来候选写入。

### 1.5 B：`DefaultTargetContract`

所有 `suggest_default` 必须通过单一服务端注册表。记忆只引用 `target_ref`，不得携带
任意字段路径或自由文本补丁：

```
DefaultTargetContract:
  target_ref:           稳定、发布的目标标识
  executable_kind:      model_family | recipe
  executable_id:        具体模型族或 Recipe
  field_path:           唯一允许修改的 Draft 字段
  value_validator:      枚举或受控解析器
  applicability:        当前数据必须满足的前置条件
  verifier_requirement: 默认值保持 suggest_default 所需的验证窗口
  conflict_policy:      显式值 / 项目记忆 / 全局记忆 / 无默认值
  presentation:         用户可见标签、方法风险和恢复原值说明
```

第一批只覆盖已能逐项验证的 OLS covariance 与 Panel OLS covariance。ETS/ARMA-GARCH
的目标必须等 `RecipeContract` 发布其字段、频率和序列长度 preflight 后，作为 B2 单独
准入；不能先凭手工表单字段向记忆开放。时序的频率、季节性或常数处理可能影响方法选择，
必须带较高方法风险标识；ARMA/GARCH 阶数、任意因变量、任意训练样本和未注册字段一律
不得由记忆注入。

**优先级和失效处理**

1. 当前请求中用户或 Agent 明确写出的值永远优先。
2. 满足当前数据校验的项目记忆优先于全局记忆。
3. 同层多个记忆冲突时，不猜测、不选一个：不注入默认值，并向 Draft 报告冲突。
4. vocabulary 不符、verifier 过期、字段失效或值验证失败时，降级为 `inform_only`
   或完全省略；不得静默继续修改 Draft。

每个被采用的默认值都必须携带 `memory_id`、`revision` 与 `target_ref`；用户必须能在
Draft 恢复为未采用记忆时的值。记忆不能改 evidence、admission、推荐排序、执行授权或
绕过任何当前数据验证。

## 2. 可执行分析契约

### 2.0 现状

`workflow_contracts.py:868` 白名单 `{"ols","panel_ols"}`；panel 必须有
entity/time、ols 必须没有；`workflow_runtime.py:814` 产物 id 由 `model_family`
推导。**但**产物准入与 `model_params` 构造是硬编码分支：

- `:917` `if model_family == "ols"` → 否则填 entity/time
- `:962` `if model_family == "ols" and "diagnostic_summary" not in ids`
- `:966` 无条件要求 `ci_lower`/`ci_upper`
- `:972` `if model_family == "ols" and missing_figures`

panel 没有自己声明的预期产物集，只是**跳过了 ols 的检查**。

### 2.1 `ModelFamilyContract`

把上述硬编码收敛成每族一份声明：

```
ModelFamilyContract:
  family:                  已注册的回归/面板/因果推断模型族
  required_spec_fields:    ("entity_col","time_col") / ("cohort_col",...) / ()
  forbidden_spec_fields:   ols 拒绝 entity_col/time_col
  build_model_params:      族专属的 model_params 构造
  expected_artifacts:      该族必须产出的 artifact id 集合
  result_shape:            coefficient_intervals | effect_estimate_bundle | event_study_bundle
```

`_run_model_branch` 变为族无关：查契约 → 校验 spec → 构造 params → 执行 →
按契约声明的产物集与结果形状准入。

**关键点**：DID 家族产出的是 `EffectEstimateBundle` / `EventStudyBundle`，
不是带 `ci_lower`/`ci_upper` 的系数表。现在那条无条件的 CI 检查对它们必然误报，
所以 `result_shape` 必须由契约声明，不能继续无条件断言。

### 2.2 原始范围：扩到 DID 家族

`cs_did` / `sa_did` / `dcdh` 已注册、手动 run form 可跑、各有 golden 护栏。
本版只做**工作流准入**，不碰估计器。

**验收（每族一条，不可省）**
- 该族能从 Notebook 一句话请求 → typed option → 确认 → 执行 → 结果在
  Table/Report 可见。
- 该族的产物**按自己的契约**准入；把 DID 产物误当 OLS 产物、或对
  `EventStudyBundle` 断言 `ci_lower` 的情况，各有一条专门的拒绝测试。
- 缺 `cohort_col` 之类必需字段时 **fail-closed 且给出可执行的下一步**，
  不静默退化为 OLS。
- **golden 23 保持 0-drift**：本版不改任何估计器，数值必须逐位不变。

### 2.3 与 panel 的关系

现有 panel FE 与 dummy FE 的 `1e-8` oracle 继续作为回归护栏。注意它绕过
materialization 直接调 `_compile`，所以它证明的是 **runtime 支持 panel**，
不是证明 materialization 的修复——不要把它当成后者的证据。

### 2.4 C1：既有回归模型族的工作流准入

不新增估计器，只准入已经具备 handler、能力声明和稳定 primary artifact 的能力。分批
接入，以便每族保留自己的结构/诊断边界：

1. **广义回归**：`logit`、`probit`、`poisson`、`negative_binomial`。每族声明
   因变量类型、允许的 covariance、结果形状、拟合/诊断产物与必要的拒绝路径；不得把
   非二元因变量静默送入 Logit/Probit，或把计数模型降级成 OLS。
2. **工具变量**：`iv_2sls`。强制 `endog` 与 `instruments`，并声明第一阶段与
   IV 专属诊断；缺字段或识别前提不成立时 fail-closed。
3. **既有 TWFE DID**：`did`。强制声明面板、实体、时间与处理定义；不得因字段缺失
   降级为普通回归。它与 `cs_did`/`sa_did`/`dcdh` 共享 DID 语义，但保留各自结果
   形状与诊断契约。

`glm:*` aliases 不在 C1 首批范围：它们不能仅因与前述模型共享 handler 就重复暴露为
独立 Notebook 能力。只有在 link/family、结果标签与诊断投影都具有独立契约时才可另行
准入。

每个族只有在所有条件满足后才出现在 Notebook 可选方案中：输入字段和当前数据结构通过
校验；Result/Table/Report 有明确、稳定的结果投影；Agent 能读取受限数值证据并引用
artifact，而非看不到结果时编造结论；Draft 可编辑且仍经 Proposal/Risk 确认；既有
known-truth/golden 不漂移并完成浏览器验收。

### 2.5 C2：时间序列 `RecipeContract`

ETS、ARMA/GARCH 是单变量序列配方，不应伪装成带 `x` 的回归 `ModelFamilyContract`。
新增同一运行时可消费、但语义独立的 `RecipeContract`：

```
RecipeContract:
  recipe_id:              time_series.ets | time_series.arma_garch
  required_inputs:        时间列、序列列及受控频率声明
  input_preflight:        单调性、缺口、频率、序列长度和转换前置条件
  parameter_vocabulary:   仅该 Recipe 发布的字段和值
  expected_artifacts:     manifest、预测、诊断、图表、比较结果
  result_projection:      Table / Report / Agent 可读取的有界数值投影
  memory_targets:         该 Recipe 可接受的 DefaultTargetContract 集合
```

两类契约共享 typed option、editable Draft、确认、授权、执行 receipt、Graph lineage 与
浏览器验收；但互不伪造字段、artifact 或统计解释。时间序列的图形结论只能在 Agent 有
受控图像或数值证据时作出；没有证据必须说明不能判定。

**本版执行边界**：`RecipeContract` 先编译为独立 dataset `model.genesis` Draft，并把
经 Recipe 词表验证的参数置入已有的 `model_options` binding。Recipe 的 `time_column` 与
`value_column` 在 binding 前对当前数据列校验；它们不是回归的 `y`/`x`，客户端也不能
额外提交任意 node 参数。通用 genesis 验证必须从 `RecipeContract` 读取“无 predictors”
及输入字段规则，替代对单个 ARMA/GARCH 模型名的特例，确保 ETS 不会被错误要求填写回归
自变量。不把 ETS/ARMA-GARCH 塞进 `operation.multi_step` 的回归 branch 结构。后续若要
支持时序多步骤工作流，必须另行设计其依赖、比较与结果形状，不能复用回归的
`outcome/predictors/branches` 语义。

## 3. 交付顺序与开发线

本扩展刻意拆成独立 development line，而不是在既有、allowlist 已冻结的初始
v1.8.5 FMS line 上继续堆叠：

1. **A1 bootstrap**：本机 store 的安全初始化、服务装配、默认关闭与故障 fail-closed。
2. **A2 管理体验**：Settings/Project 管理、二次确认、停用/删除与历史 provenance。
3. **B1 默认值注册表**：`DefaultTargetContract`、OLS/Panel 回归 targets、冲突与
   失效测试。
4. **C1 回归族**：广义回归 → IV/2SLS → TWFE DID；每族独立验收，不以“其他族已绿”
   推定可用。
5. **C2 时序 Recipe**：ETS → ARMA/GARCH；每个 Recipe 有 input preflight、artifact
   投影与无证据拒答验收。
6. **B2 时序默认值**：仅在 C2 发布 Recipe 字段与 preflight 后，准入 ETS/ARMA-GARCH
   的受控 targets。
7. **收口**：真实浏览器验收、release notes、handoff、FMS verification/index 与在
   可接受宿主环境中运行 full gate。

A1 是 A2/B1/C 的前置；A2 与 B1 可并行；C1 与 C2 只能在 B1 的 target registry 形状
稳定后开始；B2 依赖 C2。任何开发线都必须在 start 时一次列全 allowlist；`backend/workbench/*.py`
顶层文件需要在 start 时纳入，不能事后用 rescope 补入。

### 3.1 统一验收不变量

- **A**：首次启动只创建空库；默认不读取、不生成 candidate。没有服务端确认 receipt 的
  启用/删除请求必须被拒绝；伪造 body scope/owner 的请求也必须被拒绝；删除后新的
  retrieval 为空，而旧 Run 的 provenance 仍可读。
- **B**：未注册 target、无来源的默认值、过期/verifier 不符的默认值、同层冲突和显式值
  覆盖各有拒绝或回退测试。无一条记忆可修改注册字段之外的 Draft。
- **C**：每个族/Recipe 有有效路径、缺前置条件的拒绝路径、稳定 artifact 投影、Agent
  数值取证路径、既有 known-truth/golden 回归和真实浏览器验收。图形缺少证据时必须拒答。
- **Recipe 回归**：ETS 与 ARMA/GARCH 都必须通过同一份 `RecipeContract` 的无 predictors
  验证；“仅 ARMA/GARCH 特例可运行”不构成 ETS 准入证据。
- **兼容性**：既有手工 Run 表单和历史 Run 不被新契约重解释；新功能不产生无 schema
  版本的 artifact，不把回归结果当作时序结果，或反之。

## 4. 本版不宣称

- 不宣称实现了项目历史检索 / Context Compiler。
- 不宣称记忆经过独立事实核验——`evidence_status` 是来源分级，不是真值判定。
- 不宣称删除会抹除已完成 Run 的历史 provenance，或记忆关闭会删除用户库。
- 不宣称回归与时序共用相同统计解释或相同输入字段；它们只共享执行生命周期。
- 不重新宣称任何既有估计器的数值性质；本版对每个能力只宣称**工作流可达且其既有
  数值护栏未漂移**。

## 5. 统一实施计划

本节是本文件唯一的实施计划；不另建分散 plan 文档。每个编号是一条独立 FMS
development line，先写失败测试并保存失败输出，最小实现后跑同一测试，再提交。不得以
已有测试绿或另一模型成功替代本条的前后对照证据。

### A1：本机 bootstrap 与 scope 解析

**文件边界**

- 新建 `backend/workbench/domain_memory/local_runtime.py`：`LocalMemoryRuntime`、
  `LocalMemoryScopeResolver`、`MemoryStoreSet` 与本机根目录/权限验证；不含 HTTP 或 UI。
- 修改 `backend/workbench/app.py`：仅在 startup 装配 runtime，并以明确的 public status
  公开“可用/不可用”；不在路由中构造 scope。
- 修改 `backend/workbench/http/memory_routes.py`、`backend/workbench/http/notebook_routes.py`：
  只向 runtime 请求当前项目的 service/projection，删除客户端提交的 scope/owner 作为
  权威来源。
- 新建 `tests/test_domain_memory_local_runtime.py`；修改
  `tests/test_domain_memory_routes.py`、`tests/test_notebook_routes.py`。

**先失败后通过的验收**

1. 同一安全本机根目录下，两个项目解析到不同 project scope；同一项目重启后解析到同一
   scope；global scope 不含原始项目路径。
2. 缺失/不可安全打开的根目录返回 `DOMAIN_MEMORY_UNAVAILABLE`，应用仍能提供非记忆
   Notebook；不得临时改为内存 store。
3. `/domain-memory` 请求伪造另一 owner/scope 时被拒绝，且支持的请求只由
   `project_root` 解析 scope。
4. 初始状态没有 active memory、没有 retrieval、没有 candidate；显式启用前规划结果
   不含 memory projection。
