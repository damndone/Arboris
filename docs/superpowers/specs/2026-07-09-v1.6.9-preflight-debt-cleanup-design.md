## 4. B1 详细设计（中风险，本节即 B1 的 brainstorm 产物）

### 4.1 两层，不是一台机器（review 修正 A）
- **索引等待层**（`usePendingRun`）：run 提交后，等它到达 terminal 且进入 forest 索引；running 期间不烧预算；terminal-fail 标 draft failed。**genesis 已有此层；rerun 缺此层 = bug。**
- **聚焦层**（`pendingFocusTarget` + `WorkbenchShell` effect）：run 已在 model 里后，找到节点 key → `select()`。**保持不变。**
- 三条调用者归属：genesis-execute → 仅索引层；rerun/draft-execute → 索引层 **然后** 聚焦层；深链接（query param，run 已存在）→ **直接聚焦层**（不碰）。

### 4.2 `usePendingRun` 契约
```
usePendingRun({
  pending: { runId, draftId } | null,
  projectRoot,
  forest,                       // 用于判断 runId 是否已入索引
  refetch,
  onIndexed(runId),             // 入索引：genesis→activate；rerun→activate+setPendingFocus
  onFailed(draftId),            // terminal fail：dispatchDraft failed
})
```
- 轮询 `fetchRunDetail`；`status==="running"` → 不烧 attempts、继续；`failed|blocked` → onFailed、停；其它 → 烧 attempts。
- 每 tick `refetch()`；forest 出现 runId → onIndexed、停。
- attempts ≥ 预算 → warn + 停（预算只覆盖 terminal 后的索引追赶，沿用现 30×1s）。

### 4.3 rerun-execute 改动（`handleExecuteDraft`）
- 移除：`setActiveRunId` + `setPendingFocusTarget` + 立即 `dispatchDraft remove`。
- 改为：`dispatchDraft executing`（draft 节点显示执行中，**不消失**）+ `setPending({runId, draftId})`；draft 的删除移到 onIndexed 之后。
- onIndexed(runId)：`setActiveRunId(runId)` + `setPendingFocusTarget(...)`（原聚焦目标）+ `dispatchDraft remove` + best-effort `deletePipelineDraft`。
- onFailed(draftId)：`dispatchDraft failed`（与 genesis 一致）。

### 4.4 第 9 步决定（容器拆分）——cohesion 驱动，不为拆而拆
抽出功能改动真正需要的两个 hook（`usePendingRun` §4.2、`useDraftActions`），`ForestWorkbench` 成薄组合。**到此为止**：不把 JSX/providers 硬拆成多文件（无安全收益的 churn）。容器瘦身是副产品，顺带还台账 D1 前端对称债。判据 = 既有容器测试不回归 + 每个 hook 有独立单测契约。
