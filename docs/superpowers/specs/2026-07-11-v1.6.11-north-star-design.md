## 2. 切片 A 设计（本版先行，细化到实现级）

### 2.1 后端 `workbench/llm/`（新模块，单向依赖：http → llm）

- `llm/config.py` — `LLMConfig` 从环境读取，**运行时每请求解析**（不缓存进程级状态，测试可 monkeypatch）：
  - `WORKBENCH_LLM_BASE_URL`（如 `https://api.deepseek.com`）
  - `WORKBENCH_LLM_API_KEY`
  - `WORKBENCH_LLM_MODEL`（如 `deepseek-chat`）
  - `WORKBENCH_LLM_TIMEOUT_S`（默认 60）
  - 三必填项缺任一 → `is_configured() == False`。
- `llm/client.py` — 唯一线协议 = **OpenAI-compatible Chat Completions**
  （`POST {base_url}/chat/completions`，DeepSeek/GLM/Moonshot/Qwen/OpenAI 原生，Anthropic 有兼容端点）。
  零新依赖（httpx 已在）。错误taxonomy：
  - `LLMNotConfiguredError` → HTTP 503 `{detail: "LLM not configured"}`（诚实降级，FE 显示错误文本）
  - 上游非 2xx / 超时 / 响应缺 `choices[0].message.content` → `LLMUpstreamError` → HTTP 502，
    detail 只含 status 与截断的上游错误摘要，**绝不回显 API key**。
- `http/llm_routes.py` — `POST /llm/chat`：
  - 请求体 = FE 现有形状：`{mode: "workbench_node_context_v1", question, packet, response_guardrails}`；
    mode 不识别 → 422。
  - system prompt 服务端组装：角色（计量工作台节点助手）+ guardrails 逐条注入
    （advisory-only / 不得输出可执行动作 / 必须披露可见性边界）+ packet JSON 作为上下文。
  - 响应 = `{text, model, context_fingerprint}`（FE `AskAIResponse{text}` 向后兼容，多余字段容忍；
    `context_fingerprint` 回显 = 朝"可检查操作记录"迈的第一步，报告 C 的 cite 校验也用它）。
  - v1 非流式（FE client 现约定 JSON）；流式列为 A 后续增强，不阻塞。
- `app.py` `include_router(llm_router)`。

### 2.2 前端

  （全站约定 `/api` 前缀走 vite 代理，现状 dev 下必 404）。
- flag `VITE_WORKBENCH_ASK_AI` 保留但文档化为默认开启路径；错误态（503/502）以文本显示在 Section 内

  上游畸形 JSON→502；mode 错→422。

## 3. 切片 B 设计（对比，概要级，实现前细化）

- 交互：图上节点右键/工具栏「Compare with…」进入拾取态 → 点第二个节点 → 抽屉/面板出 diff。
- 数据：复用 `NodeOperationContextV1` 双份 + 前端纯函数 diff（params/decisions/metrics/
  估计系数表逐行对齐）；跨 run 节点靠 forest 已有 node_index/Merkle identity 对齐。
- **U3 顺路修**：capabilities 给 covariance 等 select 项加显式 `default` 字段，前端不再依赖 `options[0]`。
- 增强（可选，依赖 A）：「Explain this diff」按钮把双 packet + diff 摘要发 `/llm/chat`。

## 4. 切片 C 设计（引用报告，概要级）

- 勾选 N 个节点 → 确定性骨架（节点元数据、系数表、诊断）+ AI 散文段落；
  每个引用数字渲染为 cite-chip，携带 `{forest_node_key, context_fingerprint, 字段路径}`，点击跳图上节点。
- **反幻觉契约**：AI 只允许引用 packet 里实际存在的数字；渲染前对 chip 做存在性校验，校验失败的 chip
  标"未验证"。替换顶栏「Generate report」死按钮。
- 战略衔接（对抗审查 2026-07-10）：报告生成记录 = 第一份完整"带类型的可检查 AI 操作记录"
  （输入节点集、模型、输出、引用校验结果），为 v1.7 Agent 的 propose→execute→review 环打样。

## 5. 非目标（YAGNI）

- 不做多轮对话记忆/会话存储（单问单答，v1.7 再议）。
- 不做厂商 SDK 集成、不做模型列表 UI（env 配置即全部）。
- 不做 AI 触发的图操作（guardrails 明令禁止，v1.7 Agent 的事）。
- A 不做流式（列为增强）。

## 6. Gate 与交付判据

- 每切片：BE pytest 全绿 + golden 0-drift + FE vitest + tsc 0（worktree 内跑，LANG/LC_ALL=UTF-8）。
- A 判据：无 key 时 Section 显示诚实错误；配 DeepSeek key 后图上任一节点可问可答。
- B 判据：跨 run 任意两模型节点 diff 出参数与系数差异；covariance 默认不再依赖 options[0]。
- C 判据：勾选节点生成报告，每个 cite-chip 可点击回溯，未验证引用有标记。
