# v1.8.6 设计 — Predictive Research 正确性基础

> 状态：已冻结设计，尚未开正式开发线，尚未实现。
>
> 本文件是 v1.8.6 版本范围的唯一权威。正式开线时必须从已发布的 v1.8.5
> 精确 SHA 建立 worktree，并把本文件切成可独立验收的 objective；不得从本文件所在
> commit 反推未来 baseline，也不得把后续量化路线混进 v1.8.6。

## 0. 一句话结论

v1.8.6 不扩充大量机器学习模型，而是把现有轻量 prediction 路径改造成第一条可信的
样本外预测流程：数据结构和实际切分参数必须显式声明，SplitPlan 必须持久化，预处理必须
声明拟合语义，最终 holdout 不得进入交叉验证，运行时负对照必须随结果产生，协议级未来
泄漏诱饵必须进入发布验收，新 packet 必须带最小 payload schema 契约，历史随机切分结果
保持可读但不得与新协议静默比较。

```text
通用统计与机器学习研究底座
├── v1.8.6：Predictive Research 正确性基础（本版）
├── 后续：模型扩展、调参与 Notebook 规划
└── 后续 Quant Research Profile
    ├── point-in-time 与 available_at
    ├── 历史股票池、公司行动和标签可得性
    ├── 截面运算、FactorSpec / FactorSet
    ├── Trial Ledger / Sealed Holdout
    └── 成本、换手、容量与目标组合导出
```

量化不另起一套 Graph、Agent、Run、Artifact 或 Compare；它是同一预测研究底座上的
更严格 profile。Workbench 不建设实盘下单能力，只允许研究、模拟评估和目标组合导出。

## 1. 为什么是这个版本

### 1.1 现有 prediction 是起点，不是可信预测协议

仓库已有 Lasso、Ridge 和 Random Forest Regressor，并把 `StandardScaler` 放在
scikit-learn Pipeline 中。这保证 scaler 在每个训练折内拟合，是正确的基础。

但当前协议还有四个结构性问题：

1. `train_test_split` 无条件随机切分，系统不知道数据是 IID、隐藏分组、时间序列还是
   面板；
2. `cross_val_score` 使用完整数据，最终 test 行也进入 CV，导致 CV 与最终 test 指标
   不独立；
3. split 只由随机种子隐式决定，不是持久化、可检视、可复用的 lineage 对象；
4. `prediction_result` 只保存聚合指标，不保存样本外预测、fold 归属、基线比较或负对照。

随机切分对经确认的 IID 数据可以合理；问题是当前默认把未知结构当作 IID。v1.8.6
必须把默认改为 `unknown` 并 fail-closed，而不是通过提示词猜测数据结构。

### 1.2 Artifact schema 债已成为前置

当前 `register_artifact` 记录 `artifact_id`、`path`、`artifact_type`、`step`、hash、
inputs 与代码版本，但不声明 payload 符合哪个 schema。DEC-ART-001 因此明确规定：
旧 Notebook 只能校验 artifact identity/type/count/step，不得声称 payload 已验证。

这一限制已经阻塞外部 Capability 从 experimental 晋升 verified。若 v1.8.6 再新增
SplitPlan、PredictionPacket、EvaluationPacket 等无版本 payload，Table、Report、
Compare 和 Agent 只能继续靠 `artifact_type` 猜结构，历史 run 会在 packet 演化后静默
失去解释能力。

本版不完成全仓 Artifact Schema Registry，也不迁移所有历史 artifact；但所有 v1.8.6
新 packet 必须先通过一个最小版本闸门，避免继续扩大架构债。

### 1.3 为什么负对照与泄漏诱饵进入 M0

“测试通过”只能说明实现与测试一致，不能证明评估协议没有把未来信息、行身份或目标结构
错误地带进模型。M0 每次真实预测运行至少需要两种便宜且通用的统计负对照：

- 置换标签：模型表现应退化到与随机预测相符的范围；
- 噪声特征：合成噪声不应被稳定识别为主要预测来源。

这两项不是量化专属功能。它们是 Workbench 首次宣称“可信样本外预测流程”所需的运行证据。

除此之外，发布验收必须加入第三种**协议级泄漏诱饵**：带显式未来位移来源的合成特征。
由于 M0 不执行 temporal/panel prediction，这项诱饵不是每个用户 run 都重复运行的统计负对照，
而是 conformance/release fixture；它必须在拟合前被数据结构或 transform provenance 闸门
拒绝，并证明没有生成模型结果。这个测试只证明“已声明的未来依赖不会被静默执行”，不宣称
M0 能自动识别用户未声明的未来信息。通用 feature/label availability 检查仍属于后续时间安全
profile。

### 1.4 评估过的三种路线

| 路线 | 优点 | 主要风险 | 裁定 |
|---|---|---|---|
| 先设计完整 ML/Quant Q0 契约平台 | 表面完整 | 契约可能先于真实路径膨胀，重复 v1.8.4“合同存在但用户走不到”的失败 | 不采用 |
| 只修 `prediction.py` 的两处切分代码 | 改动小 | Split、schema、legacy 和消费者仍不可追溯，下一批 packet 继续扩大架构债 | 不采用 |
| 最窄 M0 垂直切片 + 最小 schema 闸门 | 能跑通真实用户路径，同时只抽取已经被使用的共享契约 | 需要明确拒绝 temporal/panel、调参和量化范围 | **采用** |

因此本版既不先造完整 ML/Quant 平台，也不把问题缩成局部函数补丁；它只冻结第一条真实
预测链路必需的契约。

## 2. 产品定位与边界

### 2.1 主线关系

Workbench 的主线仍是通用统计学工具：

```text
统计推断
+ 时间序列
+ 通用机器学习
+ 领域专用 Research Profile
```

量化被定义为：

> 通用统计与机器学习研究底座上的一个更严格 profile，额外增加时间可得性、股票池历史、
> 截面运算、因子批量研究和可交易性评估。

### 2.2 v1.8.6 交付

本版只交付 M0：

1. 可被 Run、Graph、Agent、Compare、Report 共同引用的 typed `SampleSpec` envelope；
2. 显式 `SamplingSpec`（sampling / analysis / frequency weight 三种语义分离）与
   不支持时的 fail-closed 执行；
3. 通用表格回归预测的显式 `PredictionTaskSpec`；
4. `StructureSpec` / `AvailabilitySpec` 声明、校验与阻塞边界，默认结构为 `unknown`；
5. 内容寻址、可复用、不可变的 `SplitPlan`，包含 random/grouped/temporal 策略及其全部参数；
6. `stateless` / `date_local` / `period_fitted` 预处理语义，且所有 fit-state 只来自当前训练 fold；
7. 受限、typed、可复现的 `FeatureRecipe`，不开放默认 `code.execute`；
8. development CV 与 final holdout 的隔离；
9. 简单基线与候选模型 Compare；
10. 样本外逐行预测和有界评估证据；
11. 每次运行的置换标签与噪声特征负对照，以及发布级 future-shift 泄漏诱饵；
12. 新 packet 的最小 payload schema 声明、验证和消费者版本协商；
13. 历史 `prediction_result` 的明确 legacy / incomparable 策略；
14. 独立的通用统计证据片（含效应量、事后检验、配对/单样本检验与方差/正态性检验）；
15. 最小用户可见投影：Run、Graph、Table、Report、Compare 与 Agent 只读证据。

### 2.3 明确不做

以下内容不属于 v1.8.6：

- 任何量化数据、FactorSpec、Factor DSL、FactorSet 或 Factor Passport；
- point-in-time 数据源、历史股票池、公司行动或回测；本版只保存并校验
  `AvailabilitySpec`，不实现完整 PIT 数据源或量化可得性引擎；
- 成本、换手、容量、风险暴露、组合优化或 Paper Trading；
- 实盘凭证、订单、成交、券商连接或自动下单；
- 超参数搜索、AutoML、自动 FeatureRecipe 搜索或无限分支搜索；
- 任意 Python/SQL 片段及默认 `code.execute`；
- 深度学习、新的第三方模型库或动态安装依赖；
- 分类、排序、异常检测、生存分析或新的预测模型族；
- 完整 Sealed Holdout 状态机、PBO 或 Deflated Sharpe Ratio；
- 全仓 Artifact Schema Registry、所有旧 artifact 的迁移；
- Agent 自主选择数据结构、绕过确认或自动执行；
- 重写时间序列、DID、Panel、OLS 或任何统计估计器。统计证据片只扩展
  `statistical_tests.py` 的独立检验函数与结果 schema，不自动接入预测模型选择。

现有 Lasso、Ridge、Random Forest Regressor 是本版候选模型全集；本版修协议，不以模型
数量作为交付。

## 3. 端到端用户路径

```text
用户选择目标列与特征列
        ↓
声明数据结构（默认 unknown，必须解决）
        ↓
生成 PredictionTaskSpec
        ↓
服务端校验并冻结 SplitPlan
        ↓
按 transform 语义构建 PreprocessingPlan
        ↓
只在 development partition 内做 CV
        ↓
拟合基线与候选模型
        ↓
对 final holdout 评估一次
        ↓
运行置换标签与噪声特征负对照
        ↓
持久化版本化 packet 与 lineage
        ↓
Graph / Table / Report / Compare / Agent 读取同一证据
```

如果数据结构、必需列、payload schema、SplitPlan binding 或预处理语义缺失，流程在模型
拟合前停止，不得回退到旧随机切分。执行确认界面必须在拟合前展示 Split profile、final
holdout 比例、CV fold 数、shuffle、seed 和 group binding 等实际生效参数；服务器默认值可以
提供起点，但不能在确认后才作为隐藏常量注入。

## 4. `PredictionTaskSpecV1`

### 4.0 共享 `SampleSpecV1` envelope

`SampleSpecV1` 是预测任务的样本与可得性真相源，也是 Run、Graph、Agent、Compare、Report
共同引用的 typed persisted envelope。`PredictionTaskSpecV1` 必须携带
`sample_spec_ref`；不能在各消费者中重新解释抽样、结构或切分。

```json
{
  "payload_schema": "workbench.prediction.sample-spec",
  "schema_version": 1,
  "sample_spec_id": "content-addressed-id",
  "dataset_ref": {"dataset_sha256": "64-lower-hex", "row_identity": "snapshot_ordinal_v1"},
  "sampling": {
    "sampling_weight": null,
    "analysis_weight": null,
    "frequency_weight": null,
    "semantics_version": 1
  },
  "split_plan_ref": "sha256:...",
  "structure": {
    "kind": "unknown",
    "group_column": null,
    "time_column": null,
    "entity_column": null,
    "provenance": "user_confirmed"
  },
  "availability": {
    "kind": "unspecified",
    "feature_available_at": null,
    "label_available_at": null,
    "reservation_policy": "fail_closed"
  },
  "feature_recipe_ref": null,
  "reproducibility": {"seed": 20260429, "code_version": "..."}
}
```

`SamplingSpec` 的三个字段不可互换：

- `sampling_weight` 表示抽样设计权重，不能被当作回归器的 `sample_weight`；
- `analysis_weight` 表示拟合或评估时的分析权重；
- `frequency_weight` 表示观测频数，指标和支持的估计器必须按频数语义处理。

M0 至少支持显式无权重的 spec，并仅在模型、指标和消费者 registry 明确声明语义支持时
执行对应权重。任一权重被声明但当前路径不支持、类型/范围不合法或三种语义被合并时，
在拟合前返回稳定错误；不得静默忽略、转换成另一种权重或回退到 legacy prediction。

`StructureSpec` 与 `AvailabilitySpec` 在本版是声明、校验和 fail-closed reservation：未知
结构不得自动当作 IID；缺失的未来可得性信息不得被推断为可用。完整 PIT source、时间/面板
切分执行和 quant validation 仍是后续 profile。

### 4.1 最小形状

```json
{
  "schema_version": 1,
  "task_id": "content-addressed-id",
  "task_kind": "tabular_regression",
  "dataset_ref": {
    "dataset_sha256": "64-lower-hex",
    "row_identity": "snapshot_ordinal_v1"
  },
  "target": "declared-column-ref",
  "features": ["declared-column-ref"],
  "sample_spec_ref": "sha256:...",
  "data_structure": {
    "kind": "iid",
    "group_column": null,
    "time_column": null,
    "entity_column": null,
    "provenance": "user_confirmed"
  },
  "split_plan_ref": "sha256:...",
  "preprocessing_plan_ref": "sha256:...",
  "model_specs": [
    {
      "model_id": "prediction_ridge",
      "model_contract_version": 1,
      "effective_parameters": {"alpha": 1.0},
      "parameter_source": "policy:prediction-ridge-v1"
    }
  ],
  "baseline": "mean_regressor",
  "negative_controls": ["permuted_target", "seeded_noise_features"],
  "random_seed": 20260429
}
```

### 4.2 数据结构声明

```text
data_structure.kind ∈ {unknown, iid, grouped, temporal, panel}
```

规则：

- 默认值必须是 `unknown`；
- `unknown` 必须以 `PREDICTION_DATA_STRUCTURE_UNKNOWN` 阻塞；
- Agent 可以提出候选结构和理由，但不能把推断结果标成用户确认；
- `iid` 必须由用户明确确认，不能由“没发现 group/time 列”反推；
- `grouped` 必须声明 `group_column`；同一 group 不得跨 development/final 或 CV fold；
- `temporal` 必须声明 `time_column`；
- `panel` 必须声明 `entity_column + time_column`；
- M0 执行支持 `iid` 与 `grouped`；
- `temporal` / `panel` 在通用 prediction 路径中被识别但 fail-closed，返回可执行下一步，
  不得随机切分。它们由后续注册的时间/面板 Split profile 承接。

识别但暂不执行 temporal/panel，是扩展边界，不是“系统支持时间/面板 ML”的交付声明。

`StructureSpecV1` 是独立 typed contract，至少保留 `kind`、`group_column`、`time_column`、
`entity_column`、确认主体/来源和验证状态。未知值、冲突列声明、重复实体时间键或无法验证
的结构必须阻塞；不得用“没有发现 group/time 列”代替 IID 确认。

`AvailabilitySpecV1` 至少保留 feature/label availability reference、reservation policy、
验证状态和阻塞原因。它可以拒绝显式的未来依赖或缺失 reservation，但不会凭列名推断
point-in-time 可得性，也不会声称完成历史源、股票池或公司行动的 PIT 建模。

### 4.3 目标与特征边界

- 目标和特征必须来自同一个已冻结 DatasetSnapshot；
- 目标不得同时出现在 features；
- features 必须去重并有稳定顺序；
- 全空、常量、非数值且无声明编码器的特征在 split 前拒绝；
- 缺失值策略必须在 `PreprocessingPlan` 中声明，不允许 `dropna()` 成为隐藏默认；
- 新协议不接受 imbalanced sampling；现有 SMOTE/over/under-sampling 属于 legacy 路径，
  分类任务立项前不得接入回归协议。

## 5. `SplitPlanV1`

### 5.1 SplitPlan 是一等 lineage 对象

SplitPlan 必须在任何模型拟合前持久化，并绑定：

```text
dataset_sha256
target ref
data_structure declaration
row identity policy
development/final assignment
CV fold assignment
group/time constraints
random seed
split policy version
split profile id/version
effective split parameters
content hash
```

相同 DatasetSnapshot、TaskSpec、split policy 与 seed 必须产生相同 SplitPlan hash。模型分支
必须引用同一个 SplitPlan，才能进行公平 Compare。

### 5.2 行身份

M0 使用：

```text
row_ref = dataset_sha256 + immutable snapshot row ordinal
```

ordinal 只在同一不可变 snapshot 内有意义。不同 dataset hash 的 row_ref 不相等，系统不得
尝试用当前行序对齐两个不同 snapshot。未来如引入业务主键，应作为新 row identity policy，
不得原地改变 v1 语义。

### 5.3 Split profile 与实际参数

M0 不把 `test_size=0.25`、`cv_folds=5` 等实现常量继续藏在代码中。每个 SplitPlan 必须
冻结完整的实际参数，例如：

```json
{
  "profile_id": "iid_holdout_kfold",
  "profile_version": 1,
  "effective_parameters": {
    "final_holdout_fraction": 0.2,
    "cv_folds": 5,
    "shuffle": true,
    "random_seed": 20260429,
    "group_column": null
  }
}
```

示例值不是产品硬编码默认。参数可以来自版本化服务器策略或用户选择，但必须：

- 在执行确认前 materialize，并显示实际值与来源；
- 通过服务器边界校验，fold 数不得超过 development 样本或 group 数允许的上限；
- 进入 SplitPlan 内容 hash、Run lineage、Report 和 Compare compatibility；
- 任一实际参数变化都生成新的 SplitPlan，不得原地修改；
- baseline、候选模型和负对照不得分别生成自己的 split；
- `strategy`、`group_column`、`time_column`、`entity_column`、`gap`、`embargo`、排序方向、
  holdout 比例、fold 数、shuffle、seed 及其来源都必须持久化；即使 temporal/panel 在 M0
  被拒绝，也必须把声明过的参数保留在拒绝 receipt 中，不得丢失后改走 random。

M0 注册表只允许两个可执行 profile：

```text
iid_holdout_kfold / v1
grouped_holdout_groupkfold / v1
```

注册接口允许未来增加策略，但未知 profile/version 必须 fail-closed。`random`、`stratified`、
`group_stratified`、`blocked_time`、`anchored_walk_forward`、`rolling_walk_forward` 不能仅凭
名字进入 M0；其中分类分层和时间 profile 分别依赖尚未交付的任务类型与可得性规则。

### 5.4 M0 支持的 split profile

#### IID

```text
development / final_holdout
development 内 KFold CV
```

#### Grouped

```text
按 group 划分 development / final_holdout
development 内 GroupKFold
同一 group 永不跨 partition 或 fold
```

#### Temporal / Panel

M0 只验证声明完整性并拒绝通用随机切分。后续 profile 才可执行 ordered、rolling、
expanding、gap、embargo 与标签可得性规则；M0 只允许声明并校验这些字段，不能因字段存在
就宣称 temporal/panel 已支持。

### 5.5 holdout 隔离

- CV、模型比较、预处理拟合和参数选择只能使用 development；
- final holdout 行不得出现在任何 CV fold；
- final holdout 只在候选模型与固定 baseline 拟合完成后评估；
- M0 不实现跨 run 的 `SEALED → UNSEALED_ONCE → CONSUMED` 状态机，因此不得宣称
  已解决反复查看 holdout 的所有问题；
- 每个 EvaluationPacket 必须记录 final holdout 被评估的事实和时间；
- rerun 若重新设计模型，必须生成新 TaskSpec 与新 EvaluationPacket，不能覆盖旧证据。

## 6. `PreprocessingPlanV1`

### 6.1 三种执行语义

共享内核必须区分以下语义，核心边界是 `date_local` 与 `period_fitted` 不能混用：

| 语义 | 示例 | 执行规则 |
|---|---|---|
| `stateless` | 固定公式、单位换算、声明式 log | 不学习数据参数；对每个 partition 确定性执行 |
| `date_local` | 同日截面 rank、同日截面 z-score、同日 winsorize | 每个日期只使用该日期当时截面；不从训练期学习跨期参数 |
| `period_fitted` | StandardScaler、imputer 统计量、PCA、特征选择 | 只在当前训练 fold 拟合，再应用到 validation/final |

M0 通用表格 UI 主要使用 `stateless` 与 `period_fitted`。注册协议和预处理执行层必须实现
并用隔离 conformance fixture 测试 `date_local`，以免未来 Quant Profile 被“一律在训练期
拟合”的错误通则阻塞；但 M0 不把 date-local 截面预测暴露成用户可执行的 temporal/panel
profile，也不据此宣称量化可用。

### 6.2 注册约束

每个 transform 必须声明：

```text
transform_id
transform_version
fit_semantics
required_columns
output_columns
determinism policy
missing-value behavior
```

规则：

- 未注册 transform 不得执行；
- 未声明 `fit_semantics` 必须 fail-closed；
- `period_fitted` transform 必须进入 sklearn-compatible fold pipeline 或等价隔离执行器；
- `date_local` transform 必须要求 time/date 列，且不得把其他日期的统计量带入当前日期；
- transform 语义变更必须升版本，历史 run 保持原解释；
- pipeline 的实际拟合 partition 与 transform 版本必须进入 PredictionPacket。

所有 imputation、MICE、均值/中位数填补、scaling、feature selection、PCA、target encoding
等 fit-state transform 必须在每一个 development training fold 内拟合，再应用到对应
validation fold；final fit 只能用完整 development partition，final holdout 只接收已冻结
状态。全数据 scaling、测试折填补和先拟合再切分都必须由负向泄漏测试拒绝。`period_fitted`
与 `date_local` 的含义不能互换：前者绑定训练 fold，后者只在同一日期局部计算。

### 6.3 `FeatureRecipeV1`

`FeatureRecipe` 是 typed、版本化、可复现的派生变量协议，不是代码执行入口。每个节点至少
记录：输入列/父 recipe、输出列与类型、操作 id/version、参数、fit scope、source artifact、
missing/outlier policy、determinism policy、recipe lineage parent 和 reproducibility metadata。

第一阶段只注册确定性操作：derived variable、recode、interaction、`log`、`ratio`。每个
操作都必须声明零值/负值/缺失/异常值行为；未知操作、动态表达式、任意代码、dataset-specific
branch、exercise branch 或未绑定输入 artifact 均 fail-closed。Recipe 的输出必须进入
`SampleSpec`/`PredictionTaskSpec` binding，不能在 UI、Agent 或报告层临时重算。

## 7. 模型、基线与样本外证据

### 7.1 模型范围

本版只复用：

```text
prediction_lasso
prediction_ridge
prediction_random_forest
```

`alpha=1.0` 等示例值不是本版重新硬编码的默认。超参数可以来自版本化服务器策略或用户选择，
但每个候选必须在执行确认前形成完整 `ModelSpec`，并展示、持久化：

```text
model_id
model contract version
effective parameters
parameter source
determinism / seed policy
```

只保存“使用了某个服务器策略”而不保存实际参数不合格。实际参数必须进入 TaskSpec hash、Run
lineage、PredictionPacket 与 Compare compatibility；参数变化必须产生新 TaskSpec/模型分支。
本版没有自动调参，也不允许 Agent 用重试搜索参数。

### 7.2 强制 baseline

每个任务必须运行简单 baseline：

```text
mean_regressor
```

候选模型不能只报告自己的 R²/RMSE；必须报告相对 baseline 的样本外增量。复杂模型未稳定
优于 baseline 时，状态只能是 `NO_INCREMENTAL_GAIN`，不能因绝对指标看起来非空而推荐。

### 7.3 样本外预测

新协议必须持久化有界的逐行预测证据：

```text
row_ref
partition (cv_validation | final_holdout)
fold_id or null
y_true
y_pred
model_id
split_plan_ref
```

前端和 Agent 默认读取汇总投影；逐行证据通过有界 artifact reader 访问，不把整表直接塞进
LLM 上下文。

### 7.4 指标

M0 回归指标至少包含：

```text
R²
RMSE
MAE
n observations
baseline delta
CV fold distribution
final holdout metric
```

CV 汇总和 final holdout 必须分栏，禁止合成一个“总分”。

## 8. 负对照

### 8.1 置换标签

在 development partition 内，以记录在 packet 中的 seed 置换目标，使用相同 SplitPlan
边界、相同模型策略和相同预处理协议重新评估。

不得在全数据置换后重新生成 partition，也不得让 final holdout 参与模型选择。

输出：

```text
observed development CV distribution
permuted-target CV distribution
metric gap
control seed / count / policy version
status
```

状态语义：

- `CONTROL_BEHAVED_AS_EXPECTED`：置换后退化；
- `NO_EVIDENCE_ABOVE_PERMUTATION_BASELINE`：真实标签没有稳定优于置换；
- `LEAKAGE_OR_PROTOCOL_FAILURE_SUSPECTED`：置换后仍表现异常好；
- `CONTROL_INCONCLUSIVE`：样本或指标不足。

真实数据上“未优于置换”不是软件失败，而是研究结论；合成已知真值 fixture 上，置换标签
必须退化，否则 release gate 失败。

### 8.2 噪声特征

在 development partition 内生成带固定 seed、与原特征同样行身份的噪声列。噪声列必须：

- 不写回用户 DatasetSnapshot；
- 只存在于负对照分支；
- 经过与真实特征相同的 period-fitted pipeline；
- 记录生成器和 seed；
- 使用 fold validation 数据上的有界、模型无关 permutation importance，报告跨 fold 的
  排名/稳定度；不使用 estimator-native impurity importance，也不引入 SHAP。

输出状态：

- `NOISE_NOT_STABLE`；
- `NOISE_COMPETES_WITH_SIGNAL`；
- `NOISE_DOMINATES`；
- `CONTROL_INCONCLUSIVE`。

Random Forest 对噪声产生非零 importance 本身不是失败；失败条件是噪声跨 fold 稳定占据主要
位置，或加入噪声后评估表现出现无法解释的系统性提升。

### 8.3 Future-shift 泄漏诱饵

M0 的发布 conformance suite 必须包含一个时间排序合成 fixture，其中某个特征通过显式
derivation metadata 声明为目标或源列的未来位移，例如 `lead(target, 1)`。验收要求：

- fixture 的数据结构是 `temporal`，不能被转换为 IID 以绕过闸门；
- 已知的 future/lead derivation 不得注册成 M0 可执行 transform；
- 请求必须在任何预处理拟合和模型拟合前，以稳定 reason code 拒绝；
- 不得产生 PredictionPacket、EvaluationPacket 或“表现异常好”的成功结果；
- 测试必须同时断言没有调用 estimator fit，而不只检查 UI 文案。

M0 的最低稳定结果可以是 `PREDICTION_SPLIT_PROFILE_NOT_SUPPORTED`；若 transform provenance
先发现显式未来依赖，可以返回更具体的 `PREDICTION_FUTURE_DERIVATION_FORBIDDEN`。两者都
表示 fail-closed，不得自动删除该特征后继续运行。

这项 conformance 不等价于完整 look-ahead detector。原始数据若没有 availability/provenance
声明，M0 不能可靠判断某列是否偷看未来，必须在报告中保留这一限制。

### 8.4 预算

负对照次数必须受版本化服务器策略约束。用户和 Agent不能请求无界 permutation、噪声列或
重试。Packet 必须记录实际预算、停止原因与是否完整执行。

## 9. v1.8.6 最小 Artifact payload 版本闸门

### 9.1 目标

本版只为新预测 packet 建立最小闸门，不宣称完成 BACKLOG 中全局
`ARTIFACT-SCHEMA-REGISTRY`。

每条新 artifact record 必须携带：

```json
{
  "artifact_id": "...",
  "artifact_type": "prediction_evaluation",
  "payload_contract": {
    "payload_schema": "workbench.prediction.evaluation-packet",
    "schema_version": 1
  }
}
```

Artifact payload 顶层也必须携带同一 `schema_version`，producer 在写入前校验 payload，
register 时验证 record 声明与 payload 一致。

### 9.2 M0 schema 集合

本版只注册以下 schema：

```text
workbench.prediction.sample-spec / v1
workbench.prediction.task-spec / v1
workbench.prediction.split-plan / v1
workbench.prediction.preprocessing-plan / v1
workbench.prediction.feature-recipe / v1
workbench.prediction.prediction-packet / v1
workbench.prediction.evaluation-packet / v1
workbench.prediction.negative-control-packet / v1
workbench.prediction.model-comparison-packet / v1
workbench.statistics.evidence-packet / v1
```

不得预先创建 Quant、Factor、Tradability、Portfolio 或 Sealed Holdout schema。

### 9.3 producer 规则

- schema id 与 version 必须在服务器 registry 中注册；
- 未知字段、缺字段、错误类型、非有限数、超限数组必须拒绝；
- 校验失败不得写 artifact index；
- payload 必须先耐久写入并计算 hash，再原子更新 index；
- producer 不能用 `artifact_type` 代替 payload schema；
- 同一 schema/version 的语义不得原地改变；破坏性变更必须升 version。

### 9.4 consumer 版本协商

Table、Report、Compare、Agent reader 必须分别声明接受的精确
`(payload_schema, schema_version)` 集合：

- 已支持版本：校验后投影；
- 未知版本：保留 artifact 身份和下载能力，但拒绝语义解释；
- 缺 payload contract：标记 legacy，不得谎称已验证；
- consumer 不得猜字段、静默删字段或把未知版本按最新版本解析。

稳定错误码：

```text
ARTIFACT_PAYLOAD_CONTRACT_REQUIRED
ARTIFACT_PAYLOAD_SCHEMA_UNKNOWN
ARTIFACT_PAYLOAD_SCHEMA_VERSION_UNSUPPORTED
ARTIFACT_PAYLOAD_VALIDATION_FAILED
```

### 9.5 与全局 Schema Registry 的关系

v1.8.6 交付后，BACKLOG `ARTIFACT-SCHEMA-REGISTRY` 仍保持 open，因为旧模型、表格、图形、
统计检验和第三方 Adapter 尚未统一迁移。后续全局 registry 可以吸收本版协议，但不得把本版
最小闸门反写成“全仓 payload 已验证”。

### 9.6 Typed receipt 与统计证据

新 ML 证据至少必须以以下 receipt/payload 组合落盘：`SampleSpec`、`PredictionPacket`、
`EvaluationPacket`、`SplitPlan` receipt、`Preprocessing` receipt、`NegativeControl` receipt
和 `ModelSelection` receipt。每个 receipt 都复用本节的 envelope、schema/version、lineage
parent、producer code version、dataset/task/split binding 和 reproducibility metadata。

统计证据片的 `evidence-packet` 使用同一版本闸门，但与 prediction model selection 保持
独立：它可以被 Table、Report 和 Agent 读取，却不能把 posthoc、效应量或正态性检验结果
自动当作模型选择依据。

## 9A. 独立统计证据片

本节限定在 `backend/workbench/statistical_tests.py` 及其对应测试文件，避免与预测主链路、
Artifact consumer 和现有估计器产生重叠 ownership。结果统一返回 test id/version、输入
变量与样本摘要、statistic、p-value、置信区间（如适用）、校正方法、effect size、warnings、
assumptions、finite/degenerate 状态和可复现 metadata；不得只返回裸浮点数。

本版独立 slice 覆盖：

- posthoc ANOVA 对比，包括 Tukey HSD 与 Bonferroni，并显式记录 family 与校正范围；
- Cohen's d、eta squared、omega squared；
- one-sample t-test、paired t-test、Wilcoxon signed-rank；
- Levene、Bartlett、Shapiro-Wilk；
- 与现有 Table、Report、Agent evidence vocabulary 对齐的 typed `evidence-packet` 投影。

实现必须保留现有检验和 FDR 行为，新增方法使用独立合成 oracle、对空/常量/非有限输入
稳定失败，并明确说明正态性、独立性、方差齐性和配对键等前提。该 slice 不被用于自动
选择预测模型，不扩展到 SEM/CFA、生存、ordered/multinomial logit，也不改变 OLS、Panel、
DID、时间序列估计器。

## 10. 历史 prediction 兼容与 Compare

### 10.1 不原地迁移

历史 `prediction_result` 没有 SplitPlan、fold assignment、payload contract、逐行预测或
负对照。系统不得修改历史 run，也不得根据旧 `random_seed` 伪造 SplitPlan。

### 10.2 legacy 状态

缺少 `payload_contract` 的旧 prediction artifact 读取为：

```text
protocol = legacy_random_split_v0
validation = payload_not_evaluated
comparability = legacy_only
```

UI 必须显示：

> Legacy evaluation — split protocol was not persisted. The result remains readable but is not
> comparable with v1.8.6 predictive-research results.

### 10.3 Compare 规则

- v1.8.6 新结果之间：只有 dataset hash、target、SplitPlan、metric protocol 与 payload
  schema 兼容时才能 Compare；
- legacy 与 v1.8.6：以 `PREDICTION_LEGACY_RESULT_INCOMPARABLE` 拒绝数值比较；
- legacy 与 legacy：保留原卡片查看，不新增“科学可比”的声明；
- 若未来需要迁移，必须生成新的 derived artifact 和 lineage edge，不能覆盖旧 artifact。

## 11. Graph 与消费者投影

### 11.1 Graph

每个 v1.8.6 预测 run 的主链至少显示：

```text
Dataset Snapshot
→ Prediction Task
→ Split Plan
→ Baseline + Candidate Models
→ Evaluation
→ Negative Controls
→ Result
```

fold、逐行预测和每次 permutation 不创建独立 Graph 节点，只作为 packet 内有界记录，避免
Graph 爆屏。

### 11.2 Table

显示：

- development CV fold 指标；
- final holdout 指标；
- baseline 与候选差异；
- 负对照结果；
- 数据结构、SplitPlan 与 schema 版本；
- 有界逐行 prediction 表。

### 11.3 Report

报告必须区分：

```text
Development evidence
Final holdout evidence
Negative-control evidence
Known limitations
```

不得把预测关联写成因果效应，不得把一次 final holdout 结果写成“已证明可泛化”。

### 11.4 Compare

Compare 默认比较相同 SplitPlan 上的 baseline 与候选，不允许只比较两个无法确认使用同一
样本划分的聚合分数。

### 11.5 Agent

Agent 只能读取已通过 schema validation 的有界投影，并必须引用：

```text
run_id
artifact_id
payload_schema/version
split_plan_ref
metric source
```

Agent 可以解释结果、指出限制和提出新 proposal；不能重定义数据结构、修改 SplitPlan、访问
任意原始表或自动执行 rerun。

### 11.6 Notebook 边界

本版不建设完整 ML 规划器。Notebook 可以承载已有 typed proposal/确认生命周期，但不要求
Agent 自动产生多个模型方案或自动调参。若提供创建入口，它必须与手动入口生成同一个
`PredictionTaskSpecV1`，不得存在第二套隐式 wire format。

## 12. 稳定失败语义

| 错误码 | 含义 | 用户可执行下一步 |
|---|---|---|
| `PREDICTION_DATA_STRUCTURE_UNKNOWN` | 未声明数据结构 | 选择 IID/Grouped/Temporal/Panel 并确认 |
| `PREDICTION_GROUP_COLUMN_REQUIRED` | Grouped 缺分组列 | 选择 group column |
| `PREDICTION_TIME_COLUMN_REQUIRED` | Temporal/Panel 缺时间列 | 选择 time column |
| `PREDICTION_ENTITY_COLUMN_REQUIRED` | Panel 缺实体列 | 选择 entity column |
| `PREDICTION_SPLIT_PROFILE_NOT_SUPPORTED` | M0 不执行 temporal/panel prediction | 使用现有时间序列能力或等待对应 profile |
| `PREDICTION_PREPROCESSING_SEMANTICS_REQUIRED` | transform 未声明执行语义 | 选择已注册 transform/version |
| `PREDICTION_MODEL_SPEC_REQUIRED` | 模型实际参数或来源未 materialize | 重新生成完整 ModelSpec 并确认 |
| `PREDICTION_SPLIT_BINDING_MISMATCH` | Task、数据和 SplitPlan 不一致 | 重新生成 SplitPlan |
| `PREDICTION_HOLDOUT_CONTAMINATED` | holdout 出现在 CV/拟合范围 | 停止运行并重新分割 |
| `PREDICTION_FUTURE_DERIVATION_FORBIDDEN` | 显式 future/lead derivation 进入 M0 | 删除未来依赖或等待时间安全 profile |
| `PREDICTION_NEGATIVE_CONTROL_INCOMPLETE` | 负对照未按预算完成 | 查看停止原因，不能宣称完整验证 |
| `PREDICTION_LEGACY_RESULT_INCOMPARABLE` | 旧随机切分结果与新协议不可比 | 以新协议 rerun |
| `ARTIFACT_PAYLOAD_CONTRACT_REQUIRED` | 新 packet 未声明 schema | 修复 producer，不写 index |
| `ARTIFACT_PAYLOAD_SCHEMA_VERSION_UNSUPPORTED` | consumer 不支持该版本 | 升级 consumer 或仅下载原始 artifact |

任何失败都必须在模型拟合或消费者解释前 fail-closed，不得回退到 legacy prediction。

## 13. 验收标准

### 13.1 契约与切分

- [ ] `SampleSpec` 是 Run、Graph、Agent、Compare、Report 共同引用的 typed persisted envelope；
- [ ] sampling / analysis / frequency weight 语义分离，声明但不支持时在拟合前 fail-closed；
- [ ] StructureSpec 与 AvailabilitySpec 均有验证状态；未知结构不默认变成 IID，缺失可得性
      reservation 不被推断为可用；
- [ ] random/grouped/temporal strategy 及 group/time/gap/embargo/seed/ratio 等参数全部
      进入可复用的 SplitPlan 或拒绝 receipt；
- [ ] `data_structure=unknown` 在拟合前失败；
- [ ] IID 必须显式确认，不能由列名或缺少时间列自动推断；
- [ ] Grouped 数据同一 group 不跨 partition/fold；
- [ ] Temporal/Panel 不会走随机切分；
- [ ] SplitPlan 在拟合前持久化且内容寻址；
- [ ] 同输入/策略/seed 生成相同 SplitPlan；
- [ ] final holdout 行不出现在 CV、预处理拟合或模型选择中；
- [ ] baseline 与所有候选使用同一 SplitPlan；
- [ ] 所有候选的实际模型参数和来源在确认前可见，并进入 TaskSpec hash。

### 13.2 预处理

- [ ] `period_fitted` 参数只来自当前训练 fold；
- [ ] `date_local` 只使用同一日期截面；
- [ ] `stateless` transform 不产生拟合状态；
- [ ] 未声明语义和未知 transform/version 均拒绝；
- [ ] transform 版本、语义和实际拟合 partition 进入 packet。
- [ ] 全局 scaling、测试折 imputation、先拟合后切分等 leakage fixture 均失败；
- [ ] `FeatureRecipe` 的输入/输出/类型/参数/version/fit scope/source artifact/lineage/
      missing/outlier/reproducibility metadata 完整，未知操作与任意 code.execute 均拒绝。

### 13.3 负对照

- [ ] 合成已知信号数据中，真实标签模型恢复信号；
- [ ] 同一数据置换标签后退化到随机范围；
- [ ] seeded noise 不会跨 fold 稳定主导；
- [ ] future-shift fixture 在 estimator fit 前被稳定拒绝，且不生成结果 packet；
- [ ] 测试不得把“所有 temporal 都拒绝”夸大成“可自动识别未声明未来泄漏”；
- [ ] 负对照预算、seed、状态和停止原因持久化；
- [ ] 真实数据无增量时诚实返回 `NO_EVIDENCE_ABOVE_PERMUTATION_BASELINE`。

### 13.4 Artifact schema

- [ ] 所有新 packet record 都带 `payload_contract`；
- [ ] payload 与 record 的 schema/version 一致；
- [ ] producer 在 index 更新前完成 payload validation；
- [ ] 未知字段、错误类型、非有限数、超限数组、未知版本均拒绝；
- [ ] Table/Report/Compare/Agent 各自声明接受版本；
- [ ] 未知版本仍可保留身份/下载，但不能被语义解释；
- [ ] 不得把本版最小闸门报告成全局 Artifact Schema Registry 完成。

### 13.4A 独立统计证据

- [ ] posthoc ANOVA、Tukey/Bonferroni、Cohen d、eta/omega squared、one-sample/paired t、
      Wilcoxon signed-rank、Levene/Bartlett、Shapiro-Wilk 有独立 oracle；
- [ ] 结果 schema、Table/Report/Agent evidence 投影包含 assumptions、warnings、effect size
      和校正范围；
- [ ] 统计片不改变既有检验、FDR、OLS/Panel/DID/时间序列行为，也不自动参与模型选择。

### 13.5 历史兼容

- [ ] 历史 run 不被修改；
- [ ] 旧 prediction 显示 legacy/payload-not-evaluated；
- [ ] legacy 与新结果 Compare 稳定拒绝；
- [ ] 旧卡片仍可读取，避免历史项目直接损坏；

## 14. 测试策略

### 14.1 先失败后通过

每个产品改动必须有一条修复前确实失败的测试证据。不能引用 baseline 已存在测试来冒充
本版修复。对旧测试若改变预期，必须保留其原本保护的独立断言。

### 14.2 独立 oracle 与合成 fixture

至少包括：

1. 已知线性信号 fixture；
2. 纯噪声 fixture；
3. 隐藏 group 重复观测 fixture；
4. 时间排序 fixture，用来证明通用 random profile 会被阻塞；
5. 带显式 `lead` provenance 的 future-shift lure，用来证明拟合不会发生；
6. 预处理 leakage fixture；
7. payload schema 旧版/未知版/缺字段 fixture；
8. legacy prediction artifact fixture；
9. sampling / analysis / frequency weight 语义冲突与不支持 adapter fixture；
10. FeatureRecipe 类型、零值/负值/缺失/异常值及 lineage fixture；
11. posthoc、effect size、one-sample/paired/Wilcoxon、variance/normality test 的独立 oracle。

负对照的 expected 不能由被测模型自己生成。已知信号、置换和噪声 fixture 的生成器、seed、
预期性质与评估实现必须分离。

### 14.3 不变量

- 预测 packet 不改变 OLS/Panel/DID/时间序列结果；
- 新 ArtifactRecord 字段不能让旧 artifact index 无法读取；
- legacy reader 不得把缺 schema 的 payload 标成 validated；
- Compare 不得因字段非空就绕过 compatibility；
- Agent 不得读取未通过 schema validation 的 payload 数值；
- 所有预算有上界；
- 同 seed 重复运行结果可复现到已声明的数值容差。

## 15. 交付顺序

```text
1  SampleSpec/Sampling/Structure/Availability + 最小 payload contract envelope + validator
2  PredictionTaskSpec + data_structure fail-closed
3  SplitPlan + development/final/CV 隔离及全部声明参数持久化
4  PreprocessingPlan 三种语义 + fold leakage negative tests
5  baseline + Prediction/Evaluation packets
6  置换标签 + 噪声特征负对照 + future-shift conformance
7  FeatureRecipe typed registry 与 deterministic operations
8  legacy reader + Compare compatibility gate
9  独立 statistical_tests.py slice 与 evidence packet
10 Graph/Table/Report/Agent 最小投影
11 真机 UI 验收 + full gate + release docs
```

依赖关系：1 是所有新 packet 的前置；2 → 3 → 4 → 5 → 6；7 依赖 1/2/4；8 依赖 3；
9 只允许修改 `statistical_tests.py` 与对应测试/投影契约；10 依赖 5/6/7/8/9；11 依赖全部。

实现计划可以把它切成多个正式 devline objective，但不能各自另造 contract，也不能先做 UI
后补 payload schema。所有阶段的生产改动必须先有本阶段真实失败测试证据。

## 16. 后续路线（不是 v1.8.6 承诺）

### 通用 ML

1. 分类、概率校准、排序与任务专属指标；
2. 扩展 Split profile registry：stratified/group-stratified、blocked time、anchored/rolling
   walk-forward、gap/embargo；
3. 有界超参数搜索与完整 Trial Ledger；
4. 模型族扩展、特征解释稳定性与 Notebook 规划；
5. 完整 Sealed Holdout 状态机。

### Quant Research Profile

1. `TemporalDataset` 与 `AvailabilityDeclaration`；
2. 特征与标签可得性、as-of join、历史股票池和公司行动；
3. `FactorSpec`、可推导 lookback/availability 的受限 Factor DSL；
4. FactorFamily / FactorSet / FactorRecord 与负对照扩展；
5. Rank IC、分组收益、稳定性、冗余和有效试验数；
6. 成本、换手、容量、可交易性与目标组合导出。

后续 Quant Profile 必须遵守以下设计不变量，但 v1.8.6 不创建这些 schema 或 UI：

- **BYOD 先行**：先用合成 fixture 和用户自带 Parquet + 数据声明，不让上层直接依赖聚宽、
  Tushare、通达信等某一家字段；数据源 Adapter 后续统一输出 `TemporalDataset`；
- **availability 证据分级**：结构化公告/生效/退市/修订时间为高等级证据；只有用户声明时
  可运行但降级为 `RESEARCH_ONLY`；未声明或不可知时阻止依赖该字段的正式研究；
- **标签可得性与 embargo 分离**：标签窗口尚未结束的样本不能训练；与验证期共享收益窗口的
  样本再由 gap/embargo 排除，不能用一个布尔字段混成同一概念；
- **股票池历史显式化**：universe 必须声明生效区间、是否包含退市资产和成分来源；只有当前
  成分或无退市历史时不得输出无保留的绩效宣称；
- **价格事实可复现**：优先保存未复权价格 + 公司行动 + as-of 调整规则；至少必须记录数据源、
  提取时间、复权方式和原始快照，不把会被未来公司行动重写的动态历史序列当唯一事实源；
- **Factor DSL 可审计**：最大回看期和 availability 传播由 AST 机械推导，不能让用户手填；
  `Factor Passport` 是既有 packet/lineage 的汇总视图，不另造事实来源；
- **批量研究不撑爆 Graph**：FactorSet 是批量主节点，单因子只有被 pin、进入组合、单独 rerun
  或正式报告时才升级为节点；因子值缓存与评估缓存必须分层，SplitPlan 只进入评估缓存键；
- **Trial Ledger 后置但不能绕过**：完整 Ledger 在规模化搜索阶段建设，必须记录失败试验并按
  dataset/universe/target/workspace 跨项目聚合；有效试验数不能直接等于 trial 行数；
- **硬闸门与研究判据分离**：未来信息、非法 split、未拟合隔离、payload 不一致等 fail-closed；
  IC、Sharpe、换手、容量、解释强弱只形成 grade/reason/evidence/recommended action，不冒充
  软件执行失败；
- **解释不冒充证据**：economic rationale 若无结构化 Hypothesis 验证，只能标为作者提供、
  未经系统验证的陈述，不参与自动晋级。

用户上传数据若只有声明、没有 PIT 证据，可以研究，但必须标记 `RESEARCH_ONLY`、
`LOOKAHEAD_RISK` 或 `SURVIVORSHIP_UNKNOWN`；不得作生产可交易性宣称。

### 永久权限边界

```text
允许：研究、模拟评估、Paper Research、目标组合导出
禁止：券商凭证、订单路由、自动下单、实盘持仓管理
```

研究 Agent 可以提出 proposal，不能获得交易权限。

## 17. 本版完成的精确定义

只有同时满足以下条件，才可宣称 v1.8.6 完成：

> Workbench 能把抽样、结构、可得性、特征 recipe 和切分冻结为 Run、Graph、Agent、Compare、
> Report 共同引用的 typed `SampleSpec`；在用户明确声明 IID 或 Grouped 数据结构后，使用
> 参数显式且持久化的 SplitPlan 将 development CV 与 final holdout 分离；按显式预处理语义
> 执行已有回归预测模型；与简单 baseline 比较；产生置换标签和噪声特征负对照；把 Task、
> Sample、Split、Preprocessing、FeatureRecipe、Prediction、Evaluation、Controls 与 Compare
> 作为带 payload schema/version 的 artifact 持久化；让 Graph、Table、Report、Compare 和
> Agent 从同一版本化证据读取结果；同时保持旧 prediction run 可读、明确未验证且不能与新
> 协议静默比较；并用 future-shift conformance 证明显式未来依赖不会进入模型拟合。独立的
> `statistical_tests.py` slice 还必须输出带假设、校正、效应量和 warnings 的统一证据 packet，
> 且不改变既有估计器或自动参与预测模型选择。

本版不得宣称：完成通用 ML、实现 Quant Research、解决所有 holdout 重用、完成全仓
Artifact Schema Registry、支持时间/面板预测、支持自动调参或具备任何实盘交易能力。
