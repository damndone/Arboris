## Chosen approach

Extend the existing committed evidence envelope with a versioned section contract, not an independent result store. Alternative A (re-enable legacy presentation reads) is rejected because it bypasses owner admission. Alternative B (a second independently committed report packet) adds synchronization and ownership failure modes without a current need. The chosen extension preserves one evidence source and separates producer, projection and rendering responsibilities.

## Result section contract

`family_evidence.structured_results` contains an exact object with `schema_version`, `contract_digest`, and `sections`. Version 1 is distinct from the enclosing envelope version. Unknown versions produce `UNSUPPORTED_VERSION`; no in-place migration or fallback. A missing extension is explicitly unavailable for structured-section requests; existing admitted numeric-only reads do not pretend to contain sections.

Each section has exactly `section_id`, `section_type`, `schema_version`, `status`, `reason_codes`, `fact_refs`, `dependency_refs`, and `content`. IDs are unique within the envelope. Section types resolve through server-owned declarations; an undeclared type is rejected rather than rendered as arbitrary JSON. The initial declarations cover model identity, regression tables, descriptive statistics, statistical tests, survey design, marginal effects, model-family evidence, diagnostics, interpretation constraints, variable importance and workflow status. Sections are independently selectable and composable; they do not encode a fixed execution sequence.

`content` is a bounded typed tree. Allowed nodes are text, boolean, null, object, list and fact reference. Nodes have exact keys for their type; object keys are unique strings, and numeric literal nodes are forbidden. Numerical results, sample counts and inferential quantities live in `numeric_facts`; a fact reference carries a fact ID and an explicit integer/number representation. Representation cannot round or truncate a value. Missing values have explicit status/reason nodes, not invented zeroes. Text is non-authoritative display data, never an instruction or HTML. Section-specific validators enforce field meaning in addition to the common tree schema.

Every reference must resolve to an admitted fact in the same envelope. Declared `fact_refs` must equal the tree's reference set. Fact provenance identifies the exact producer source selector. Persist p-values as values, including tiny nonzero p-values; do not infer them from significance labels. Confidence interval method, confidence level, reference distribution and approximate-inference labels must come from declared producer evidence. Missing method/level remains explicitly undeclared; never assume Wald/95%. Validation provenance is per fact: adding an unchecked p-value does not inherit a coefficient's oracle result.

Common hard limits: 128 sections per envelope, tree depth 16, 16384 nodes per section, 4096 UTF-8 bytes per text value, and 1 MiB canonical bytes for the complete section extension. Duplicate IDs, non-finite values, unsafe integer conversions, unknown nodes and oversize inputs fail with stable contract errors. These are admission ceilings, not permission to bypass smaller consumer budgets. Large outputs require declared partitions; they are never silently truncated into an apparently complete section.

## Owner-bound dependency integrity

The host producer snapshots the exact immutable artifacts used by each section after their final write. The dependency manifest contains version, project/run identity and unique records of artifact ID, safe project-relative path and SHA-256. Each section references only dependencies present in that manifest. The manifest is covered by the committed envelope digest, which the existing C0 commit and owner bind. It must not contain its own envelope-file digest or depend on a report/export generated from that envelope; this avoids cyclic hashes.

Artifact index contents are not digest authority. The producer validates index membership and seals the relevant index records into the manifest, excluding mutable/unrelated export entries. Consumers compare current relevant records with sealed records; adding an unrelated export does not invalidate model evidence. Removing a bound record, changing a path/type/source identity, or synchronously changing a source file and its mutable index is rejected.

All file snapshots and subsequent hash checks use the admitted host FD store, no-follow directory traversal and regular-file validation. No caller-selected absolute paths, raw pathname writer, client-provided trusted digest or LLM-provided identity is admitted. Capture checks file identity/size/timestamps around reading; an unstable capture is rejected. Consumers read section values from the immutable C0 packet, never from a dependency after validation. Integrity means valid at the checked read boundary, not a claim that local files can never subsequently change.

At every Agent, Notebook, Report and export admission, recheck the selected dependency closure. Missing files, altered bytes, symlink substitution, missing/rebound index records, foreign project/run bindings or invalid manifest cause typed unavailability with no facts/section content released for the affected selection. A request for the complete result fails closed if any required section dependency fails. A independently selected valid section may remain available and must not be presented as the whole result. Durable manifest verification must work after backend restart through the normal local authority bootstrap.

## Shared projection and export

The projection takes declared section IDs and/or fact IDs. Selection computes a fact/dependency closure before releasing content. Existing sensitivity, destination, egress receipt and token/row policies apply to all content, including labels and metadata. A section is atomic for selection: if its closure exceeds the available budget or contains a denied fact, return its explicit unavailable/redacted reason without releasing an orphan tree. Audits distinguish selected, omitted and redacted sections/facts. Local Report/export budgets may differ from remote Agent budgets only through explicit server-owned declarations, not a hidden unlimited mode.

Canonical projection identity/digest, owner-issued receipt and document-writer equality cover the selected sections, their fact values, dependency bindings and status. Adapters must not append unbound presentation fields after issuance. Agent and Notebook use the same selection/projection path; Report, HTML, PDF and XLSX render the corresponding admitted sections. XLSX creates actual section-specific tables rather than repeating the generic fact list under each name. Renderers may format values and labels, but cannot recompute statistics or fill missing results from diagnostic_summary/model_results.

For conversational use, an explicit semantic selector may resolve a server-bound model identity, optional exact terms, and declared statistic roles against those same admitted section references. It is an alternative to explicit IDs, not an authority or budget bypass. Missing/ambiguous bindings reject; absent term filtering means all matching terms, never first-N truncation. The selected facts and exact model/term/role/fact bindings enter the canonical delivery budget and receipt, together with the source closure. A semantic fact selection does not pretend to be a complete or partially rewritten section. Agent/Notebook adapters share this resolver and cannot infer identity from fact-name conventions.

## Implementation boundaries

1. A single contract module owns section validation, exact fact-reference closure and dependency manifest value types; envelope admission invokes it. Contract/declaration versions and digests change together.
2. Producer adapters in the Report stage and owner factory populate these contracts from bounded server-produced fields and seal dependencies using the existing host file store. They preserve method/validation metadata and never mint missing statistical facts.
3. The shared consumer registry and results service enforce dependency admission and budgeted section selection. Agent and Report adapters consume that projection without reading legacy presentation files.
4. HTML/PDF/XLSX writers validate the complete owner-issued projection and render only its selected content. Frontend section cards use declared fields and display missing/partial evidence explicitly.

Freeze the contract API before assigning disjoint producer and consumer/export implementation work. One owner edits the shared contract. Add exact implementation/test paths through formal rescope before edits; preserve existing dirty changes. Record meaningful failures, gaps, review and gate results via the formal CLI. No separate temporary development-line or worktree proliferation.

## Acceptance

- Positive round trip: real producer -> C0 commit -> owner -> Agent/Notebook/Report -> HTML/PDF/XLSX preserves coefficients, p-values, declared intervals, survey provenance, marginal effects, diagnostics, table labels and failed workflow state.
- Mutations: change a numeric value, fact reference, label, section status, manifest digest or writer payload; each live assertion must fail. Missing reference, foreign binding and unknown version must fail before rendering.
- Dependency attacks: altered source plus rewritten index, removed index entry, replaced file/symlink, and restart/reload are exercised with real admitted host stores. No mock-only integrity success claim.
- Privacy/budget: denied or over-budget facts cannot leak through a section; labels count toward the budget; denied remote delivery lacks section content. A legitimately bounded local selection still works.
- Statistical provenance: explicit non-Wald/non-95% intervals survive unchanged; missing provenance is unavailable, not guessed; unchecked facts do not become statistically validated.
- Regression tests retain positive numerical, escaping and export assertions. No blanket replacement with unavailable, xfail, ignored tests or raw fallback.
- Then controlled macOS full gate, fresh P1 in-app browser acceptance, separate deterministic and actual DeepSeek results, and clean candidate SHA. Linux/other hosts stay NOT VERIFIED and do not block local development. P2 stays deferred.

## Approved lossless delivery pages (2026-09-14)

The user approved section and within-section lossless pagination, retaining evidence bindings and existing delivery budgets. This adds a delivery representation, not a second evidence source or a relaxation of atomic complete-section validation. Existing non-paged projections remain unchanged. Increasing caps and truncating a section are rejected alternatives.

A versioned page stream transports the canonical UTF-8 bytes of one owner-admitted section bundle: exact section wire, referenced NumericFacts and selected dependency manifest. The bundle has an exact digest and byte length. Page metadata binds source identity/digest, section identity, consumer and destination, bundle digest, offset, total bytes, next offset and page digest. Payload chunks use canonical base64 so a boundary may fall inside a UTF-8 character without corrupting it. These transport fragments are never exposed as complete ResultSectionV1 or complete numerical evidence. Interpretation waits for reconstruction and ordinary section/fact validation, or uses the existing independently admitted bounded semantic selection.

Offsets and continuation metadata are untrusted selectors, not authority. Every request still requires the existing server-owned project/run/session/source and destination authority. Each page admission checks the original source and complete selected dependency closure; changing the source between pages rejects continuation. A source digest supplied by the client cannot authorize a read. Remote pages require the existing egress policy and an exact receipt over that page's complete payload; materialization alone never permits sending. No pre-receipt projection may leak through the public port.

The pure page contract validates exact version/keys, strict integer offsets, canonical base64, contiguous nonempty byte ranges and content digests. Its page packer counts the complete serialized page plus a caller-declared envelope reserve against the existing delivery budget, and final service/tool wrapping is checked again. A budget too small for even one byte and required identity produces explicit unavailability. Admission bounds apply before encoding/copying; no whole-project read or unbounded reassembly is permitted.

The transport encoder may retain immutable canonical bytes and an internally computed digest to avoid repeatedly hashing them merely to choose chunk boundaries; this cache does not replace current source/dependency admission. It cannot accept a caller-supplied digest as proof. The initial local adapter conservatively charges the entire selected section's existing logical row cost on each page (facts, sections, dependency records, list entries and fact occurrences). Base64 is never charged as a single statistical row. Sections exceeding the existing row cap still return explicit unavailability until a tested finer-grained row accounting contract exists; byte pagination alone does not claim to solve that separate limit.

Completeness is accumulated, never inferred from receiving a last-page flag. Receivers require the same source/section/bundle binding, exact contiguous non-overlapping coverage from zero through total bytes, and matching final digest. Skips, duplicate/overlapping pages, mixed snapshots, foreign scopes, corruption and inconsistent totals reject. Before full coverage the state is PARTIAL with received/total bytes; after complete digest and ordinary bundle schema validation it becomes COMPLETE. A selected complete section is not a claim that every section in the run was read. Run-level completeness separately requires every section in the owner-bound section directory. Missing, denied and not-applicable sections retain their explicit status.

Local Report and exports may consume a bounded sequence internally and reconstruct under explicit source-admission resource ceilings; no single delivery cap changes. Export finalization requires a complete validated collection; interruption cannot publish a partial file as a complete export. Browser state displays PARTIAL/COMPLETE and progress, never silently replacing an earlier snapshot with mixed pages. Agent/Notebook use the same service and can select small semantic facts independently; they must not send an assembled over-budget bundle to an LLM or treat a transport fragment as a statistical conclusion. Reading pages does not authorize endless automatic provider calls.

Acceptance adds byte-exact Unicode/tiny-value round trips; one section larger than the old local cap; per-page final budgets; duplicate/gap/reorder/mixed-source attacks; changed dependencies between pages; interrupted/resumed reading; and actual Report/Agent/Notebook/export integration. The retained survey fixture is the real regression target. Contract-only tests are not completion of these integration gates.

## Approved production egress authority (2026-09-18)

The user explicitly approved the production authorization supplement. Reuse the existing ContextEgressGatewayV1/materializer/issuer and compiler. The host, never a model or HTTP assertion, owns source classification and user grants. Classification binds project and immutable source/commit digest; absent classification is unknown and cannot authorize remote sending. Local admitted reads remain distinct and must not relabel unknown data as public. Classification or downgrade requires the host's administrative capability.

Grants bind project, provider configuration/destination, purpose, allowed data categories and sensitivities, issuing principal, and expiry. Revocation and host restart invalidate live sending authority unless explicitly restored from an admitted trusted store; no grant is inferred from API-key presence, compile, execution confirmation or old session history. User-authored text and workspace evidence are separate categories. This contract approval authorizes implementing grant controls, not blanket transmission of every project.

One host-injected send boundary validates the exact provider payload after message/tool conversion and configuration, including replayed history and tool output framing. Missing classification, grant, source admission or matching receipt blocks before network access. Source-bound structured evidence must use its existing remote admission, not promote a local receipt or reclassify opaque JSON as ordinary text. Grant checks run on every provider request and retry. No secrets or rejected content are written into error traces. Exact UTF-8 bytes, not character counts or NFC-normalized hash bytes, enforce delivery limits; an oversize tool result becomes explicit unavailable, never a truncated statistical result. Do not add a second planner or execution engine.

Acceptance includes real host authority, unknown/default denial, positive scoped grant, foreign provider/project/purpose rejection, expired/revoked grants, tampered exact payload, replay after revocation, original source mutation, and post-wrapper Unicode byte overflow. Mock HTTP proves boundary behavior only; actual DeepSeek and browser gates remain separate.
