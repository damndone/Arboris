## 1. 问题

产品主线是「上传数据 → 一句话说想干什么 → Agent 出方案 → 批准 → Agent 自己跑完」。
本版要修的不是一个功能缺口，而是**三个缺口加一条被违反的不变量**。

### 1.1 不变量：能力必须自然语言可达

上一版声称「全部能用自然语言调用」，实际**只核对了模型族，没覆盖数据操作族**。
结果是 `merge` / `reshape` / `subset` / feature recipe 只有 HTTP 路由和 UI，自然语言完全调不到。

这不是疏忽，是**没有机制**。能力散落在多个注册表里，而「是否可达」靠人工核对。
本版把它变成结构性约束：

> **每一个产生能力的操作，必须同时出现在 `OperationRegistry`（顶层可提议）
> 与 `WORKFLOW_STEP_SPEC_CONTRACTS`（可与其他步骤同方案）两张词表里，
> 由测试强制，缺一张即红。**

这条不变量是本版的主线。三块新能力都按它建，不再有「先做能力、以后接线」。

### 1.2 缺口一：数据管理（能力约 85%，Agent 够不着）

后端完备且会提交 lineage（`data_operations.py:508` 的 `apply_data_transform`
与 `:750` 的 `apply_feature_recipe_operation` 都会写 artifact → 写 recipe → 注册
→ 提交 graph 子节点 → 写 node_index），但不在两张词表里。

**已核实的词表现状**（问注册表本身，非 grep 字面量）：

- `OperationRegistry.operation_ids()` —— 16 条：`model.rerun` / `model.genesis` /
  `model.custom`(关) / `graph.fork` / `data.column.cast` / `data.columns.cast` /
  `code.execute`(关) / `operation.multi_step` + 8 条 workflow step 身份
- `WORKFLOW_STEP_SPEC_CONTRACTS` —— 10 条

> **注意**：常被误列的 `data.cleaning` / `analysis.explain` / `analysis.suggest` /
> `workspace.arbitrary` **均未注册**。这四个字符串来自一次 grep 字面量的盘点错误，
> 已在交接书 §3 记录，此处再次标注以免复发。

by-group 已有（`GROUPABLE_OPERATIONS`），变量标签与值标签 v1.8.7 已补。
缺通用 `tsset` 与滞后算子——见 §1.3，它已从「不做」变成硬前置。

### 1.3 缺口二：时间序列（最深，需一整层新契约）

现有 ARMA-GARCH 与 ETS 只是时间序列的一部分。缺 ARIMA/SARIMA、独立的单位根检验、
协整、VAR/VECM、Granger 因果、脉冲响应。

**ADF/KPSS 的现状要说清**：`adfuller` 确实在算，但只在
`engine/packs/arma_garch/transforms.py` 与 `diagnostics.py` **包内部**，
服务于该模型自己的平稳化决策。`contracts/model/time_series_diagnostics.py:300`
的注释写得很直白——那个契约只记录 p 值来源，**不执行 ADF 计算**。
所以「独立的单位根检验」确实是缺的。

**连带的硬前置**：ARIMA/SARIMA/VAR/VECM 都要求一个已声明的时间索引。
因此 `tsset`（时间索引 + 频率 + 面板 id）**从交接书 §8 的排除项变成本版前置**。
这是加入时间序列层的必然结果，不是范围蔓延。

### 1.4 缺口三：多元统计（完全空白，但可独立成 pack）

PCA、EFA（含旋转）、Cronbach's α 一个都没有。探针的少数命中全是子串误报
（`sem` 匹配 assemble、`cluster` 匹配聚类稳健 SE）。

好处是**不依赖回归引擎**，可以独立成 pack，与其他两块并行推进、互不阻塞。

## 2. 三个设计决策（数据管理层）

### 决策一：操作粒度 —— 每种转换一个 OperationDefinition（偏离交接书 §4 B1）

交接书 §4 B1 的方案是一个 `data.transform@v1` 用 `operation` 枚举覆盖四种。**不采纳。**

**理由**：四种转换的字段几乎不相交。`merge` 必须有
`secondary_run_id`/`secondary_node_id`/`secondary_artifact_id` 三元组 + `keys` + `how`；
`subset` 一个都不要；`reshape` 的两个方向连参数名都不同（`wide_to_long` 用
`id_columns`/`value_columns`，`long_to_wide` 用 `index`/`columns`/`values`）。

合成一份 `proposal_schema` 就只能把这些字段全标成可选。而 **LLM 读的是
`proposal_schema`**（交接书 §7.2 的教训），可选意味着模型漏填 merge 的 secondary
三元组**不构成违规**，一道校验从「schema 层当场拒」降级为「运行时才炸」。

拆开的额外收益：每个操作有自己的 `example_prompts` 与 `ui_description`，
语义锚点是合并方案的数倍——**对措辞变化的鲁棒性更强，不是更弱**。

**成本可以按掉**：所有转换操作共用 `executor_key="data.transform"`，
orchestrator 四处分发点认的是 executor_key，因此**每处仍只加一个分支**。

**五个 feature recipe 合为一个 `data.feature_recipe@v1`**：它们结构同形（都是「由若干
现有列派生一列」），底层 `FeatureRecipe` 本来就是
`operation_id`/`inputs`/`outputs`/`parameters` 的通用形状，一份 schema 能如实表达。

### 决策二：数据集发现工具 —— `list_project_datasets`

**为什么必须新造**：`inspect_project_dataset_schema`（`context_tools.py:1674`）只吃一个
`run_id`，读那一个 run 的 `staged/data_profile.json`，**不返回 `artifact_id`、不枚举节点、
不跨 run**。且现存工具**没有一个能列出项目里有哪些 run**。

所以 Agent 连「第二份数据存在」都不知道，`merge` 在自然语言下不可能被正确提出——
它会**编一个 id**（交接书 §7.3 那类事故的形状）。

```
list_project_datasets(detail_for?: [{run_id, node_id}])   # detail_for 上限 8
  → {
      datasets: [
        { run_id, node_id, artifact_id,          # 身份，永不截断
          row_count, column_count,
          columns: [名字, ...],                   # 受预算；超出报 columns_omitted
          columns_omitted: int,
          columns_without_missing: bool,
          column_details?: [ { name, dtype, unique_count, missing_rate? } ]
        }, ...
      ],
      datasets_omitted: 0,
      omitted_sections: ["raw_rows", "column_descriptives"]
    }
```

四条约束：

1. **身份永不截断。** 「不知道某数据存在」会让模型编 id；「知道存在但不清楚有什么列」
   只会让它追问一次。两种失败严重性差一个量级。
2. **分层深度。** 未点名的只给列名；`detail_for` 点名的（≤8）给 `dtype` / `unique_count`。
3. **稀疏编码，但不用隐式约定。** `dtype` 与 `unique_count` 恒出（前者决定要不要先 cast，
   后者决定 merge 是一对一还是一对多——后端就是拿它硬拦多对多的）。`missing_rate`
   仅在非零时出现，由每个数据集一个显式的 `columns_without_missing` 布尔兜底。
   **不采用「字段缺席即为零」**——隐式约定正是 §7 反复警告的形状。
4. **截断必报计数。** 静默截断是上一版截距 SE 事故（静默 `continue`）的同一种病。

**性能不是约束**：工具只读几个 JSON。唯一稀缺资源是上下文，取舍以「每 token 的
决策价值」为准。

### 决策三：diff 语义 —— 沿用 `data.schema_diff.v1`，不新造 kind

初稿曾打算新造 `data.frame_diff.v1`。**查过消费者后推翻。**

`frontend/src/lineage/detail/sections/DataColumnCastSection.tsx:193-238` 的
`ProvenanceDiff` **故意不按 `kind` 分支**（注释原话：读 present 的字段，"so a new data
operation renders without touching this"），且**已经**渲染 `row_count_before/after`、
`columns_added`、`columns_removed`、`dtype_changes`。

新造 kind 收益为零（消费方不看 kind），还会在 `AiActivityPanel.tsx:296` 显示陌生标签。
**沿用 `data.schema_diff.v1`，按操作填既有字段。**

## 3. 范围

用户决定：数据管理三个杠杆全做，另加时间序列层与多元统计 pack。

### 3.A 数据管理

**杠杆一：组合 ≫ 枚举**

交接书 §4 与 §6 之间有缺口：§6 的端到端验收要求「Agent 出**含转换步骤的方案**」——
转换与建模在**同一个方案**里，这要求进 step 词表。但 §4 的 B1/B2 只讲了顶层提议面。
**只做 B1/B2 通不过 §6。** 这正是 §1.1 那条不变量的具体表现。

组合是通用性的最大杠杆：anti-join = `merge(how="outer")` → `subset`，无需新代码。

**杠杆二：加深现有四种**

`subset` 的行筛选**只支持相等**（`data_operations.py:412` 是
`parameters.get("equals", {})`）。「只保留 2020 年以后的」「去掉收入缺失的行」现在做不了。

扩成一组**封闭**算子（不是表达式求值，安全闸门形态不变）：

```
filters: [ { column, op, value? } ]
op ∈ { eq, ne, gt, ge, lt, le, in, not_in, between, is_missing, not_missing }
```

保留 `equals` 旧形式以兼容既有手动路径与已落盘 recipe。
`merge` 增加可选 `indicator`，使 anti-join 的两步组合可表达。

**杠杆三：新增原子操作**

| 操作 | 参数 |
|---|---|
| `data.dedupe` | `columns`、`keep` ∈ first/last |
| `data.rename` | `mapping` {旧: 新}，拒绝重名冲突 |
| `data.aggregate` | `group_by`、`aggregations: [{column, func, output}]`，func ∈ sum/mean/median/min/max/count/std |
| `data.fill_missing` | 每列 `strategy` ∈ drop_rows/constant/mean/median/mode |
| `data.tsset` | `time_column`、`frequency`、可选 `panel_id_column` —— **时间序列层的硬前置** |
| `data.lag` | `columns`、`lags: [int]`、可选 `difference` 阶数 |

> `data.sort` **不做**：它是唯一对统计结果无任何影响的操作（只对时序/面板的呈现有意义，
> 而 `tsset` 已经承担了时序排序的语义）。

### 3.B 时间序列层（新契约层）

按能力分组，每组一个模型族或检验族，**全部同时注册进两张词表**。

| 能力 | 契约要点 |
|---|---|
| **单位根检验** | ADF / KPSS / PP 独立化。当前只在 arma_garch 包内部，要抽成可独立提议的检验；须保留 `time_series_diagnostics.py` 已有的 p 值来源语义（`approximate` / `unavailable`），**不得把近似 p 值当精确值报** |
| **ARIMA / SARIMA** | `(p,d,q)(P,D,Q,s)`；定阶（AIC/BIC/HQIC）；残差诊断（Ljung-Box）；**预测区间**必须与点预测同时给 |
| **协整** | Engle-Granger 两步 + Johansen（迹检验与最大特征根）；协整秩是结论，不是输入 |
| **VAR** | 滞后阶选择、稳定性（特征根模 < 1）、Granger 因果、**正交化 IRF 含置信带**、FEVD |
| **VECM** | 协整秩 + 调整系数 α + 协整向量 β；与 VAR 共用滞后阶与稳定性契约 |

**共同前置**：全部要求已 `tsset` 的时间索引。缺索引时**拒绝并给出下一步**，不猜测。

**IRF 的置信带**是这层最容易做假的地方：点估计好算，置信带要么 bootstrap 要么
渐近，两者结论可能不同。契约必须**显式记录用的是哪种**，不能只给一条带子。

### 3.C 多元统计 pack（独立，不依赖回归引擎）

| 能力 | 契约要点 |
|---|---|
| **PCA** | 相关阵 vs 协方差阵（必须显式声明，不默认）；成分数选择（Kaiser / 碎石 / 累计方差阈值）；载荷 + 得分 + 解释方差比 |
| **EFA** | 提取方法（主轴 / 最大似然）；**旋转**（varimax / promax / oblimin）；KMO 与 Bartlett 球形检验作为**前置适用性检查**；共同度 |
| **Cronbach's α** | 含 item-total 相关与「删除该项后的 α」；反向计分项须显式声明 |

**适用性检查是硬闸不是提示**：KMO 过低或 Bartlett 不显著时，EFA 结果无意义。
按现有安全闸门的风格**拒绝执行并说明**，而不是照跑再附一句警告。

## 5. 分期

每期自洽、可单独验收。**任一期结束都能收口，不留半成品。**

| 期 | 内容 | 收口价值 |
|---|---|---|
| **P1** | 四种转换 + feature recipe 注册进**两张**词表；orchestrator 四处分发；`_DATA_CHILD_NODE_OPERATIONS`；diff 填充 | 满足交接书原定全部范围 |
| **P2** | `list_project_datasets`；merge 在自然语言下可达 | merge/append 真正可用 |
| **P3** | 词表全覆盖守卫（§6 守卫 A）——**不变量落地** | 此类缺口永不再静默复发 |
| **P4** | `subset` 比较算子；`merge` indicator | 覆盖最大的单点缺口 |
| **P5** | dedupe / rename / aggregate / fill_missing / tsset / lag | 数据管理闭环 |
| **P6** | 多元统计 pack（PCA / EFA / Cronbach's α） | C 类从零到有，独立可交付 |
| **P7** | 时间序列层：单位根独立化 → ARIMA/SARIMA → 协整 → VAR/VECM → Granger/IRF | 最深缺口；内部仍可按箭头逐段收口 |
| **P8** | 前端 `changeSummary`；端到端真机 | 本版存在的理由 |

**P3 位置是刻意的**：守卫要在 P6/P7 造新能力**之前**就位，这样新能力从第一天起
就被强制上两张词表，而不是事后补。

**P6 在 P7 之前**：多元统计独立于回归引擎，风险低、可并行；时间序列层依赖
P5 的 `tsset`，必须在其后。

## 6. 测试策略

**契约层**：每个操作的 `proposal_schema` / `editable_schema` / validator / step contract。

**执行层**：四处分发点各走通一次；stale preview 被拒；安全闸门（多对多阻断、行增长上限、
append schema 不兼容、subset 行索引越界、KMO/Bartlett 不达标、VAR 不稳定、缺时间索引）各有一例。

**守卫层 —— 本版最容易做假的地方**：

- **A. 词表全覆盖（本版核心守卫）**：断言每一个产生能力的操作**同时**在
  `OperationRegistry` 与 `WORKFLOW_STEP_SPEC_CONTRACTS` 里。有意例外必须**显式列在
  测试的白名单里并写明理由**（如 `code.execute` / `model.custom` 关闭），
  **不得静默排除**。这条直接对应「上一轮核对只覆盖了模型族」。
- **B. 断言 LLM 真正读到的那份**：守卫直接读 `proposal_schema`（不是 `editable_schema`），
  断言 merge 的 secondary 三元组在 `required` 里。
- **C. 断言调用有正确结果，不是「方法存在」**：新工具走**注册的 handler** 实际调用一次，
  断言返回值形状，而非断言 provider 上有这个方法。
- **D. 两个半边都测**：既测「Agent 能提出」，也测「Agent 能读到结果」。
- **E. 按 shape 写守卫，不按族名。**
- **F. 发现工具的有界性**：构造超预算场景，断言 `*_omitted` 被如实报出，
  且数据集身份**一条不少**。
- **G. 数值正确性对外部基准**：新统计能力不接受「自洽即通过」。
  ARIMA/VAR/协整对 statsmodels 或 R；PCA/EFA 对 R `psych`；Cronbach's α 对 R。
  容差写进测试，参照 v1.5.8/v1.5.9 对 R 的做法（~1e-13）。

**真机**：真 DeepSeek，浏览器里走通端到端。确认提议前**核对提议内容与刚发的那句话
对得上**（v1.8.7 曾确认了旧提议导致验收作废）。

## 7. 验收标准

**不变量**

- [ ] 守卫 A 通过：每个能力操作都在两张词表里，例外显式白名单化
- [ ] 三块新能力（数据转换 / 多元统计 / 时间序列）各抽样验证：一句自然语言可达

**数据管理**

- [ ] 四种转换 + 五个 recipe 各能由一句自然语言提出 typed proposal
- [ ] merge 场景下 Agent **自己找到**第二份数据的三元组，不需用户报 id
- [ ] 转换与 `model.genesis` 能出现在**同一个** `operation.multi_step` 方案里
- [ ] 确认后执行产生 graph 子节点，`node_index` 有条目，lineage 可追
- [ ] `subset` 能表达「大于 / 小于 / 缺失 / 在集合内」
- [ ] 提议在面板上是人话不是 JSON dump

**时间序列**

- [ ] 单位根检验可独立提议，p 值来源语义（精确/近似/不可用）如实保留
- [ ] ARIMA/SARIMA 点预测与**预测区间**同时给出
- [ ] VAR 报告稳定性、Granger 因果、IRF **含置信带且标明 bootstrap 还是渐近**
- [ ] 协整秩由检验得出，不由用户指定
- [ ] 缺时间索引时**拒绝并给下一步**，不猜测

**多元统计**

- [ ] PCA 显式声明相关阵还是协方差阵
- [ ] EFA 的 KMO / Bartlett 是**硬闸**，不达标即拒绝执行
- [ ] Cronbach's α 含 item-total 与删除该项后的 α

**工程**

## 8. 不做什么

- `code.execute` / `model.custom` —— 用户既定决定，保持关闭
- `data.sort` —— 见 §3.A，唯一对结果无影响的操作
- anti-join / 模糊匹配作为独立操作 —— 前者由 merge + subset 组合表达；
  后者语义不确定，不适合自动执行
- C 类其余部分（聚类 / 判别 / 对应分析 / SEM / CFA）—— 本版只做 PCA / EFA / α
- A 类残余（MANOVA / Scheffé / Cramér's V / McNemar / 功效分析）
- B 类残余（Tobit / 截断回归 / Heckman / 条件 logit）；WLS 已在权重路径内部使用，
  但**未暴露为可选模型**，本版不改变这一点
- P1-4 GEE（工作相关结构）
- P2 全部（ZIP/NB、Hurdle、Beta、Matching、Synthetic Control、GMM、Spatial、Bayesian）

## 9. 已知风险

1. **体量。** 本版从「把数据管理接进自然语言」扩为「三块能力 + 一条不变量」，
   时间序列层与多元统计 pack **各自的体量与原定全版相当**，合计约为原范围的三到四倍。
   §5 的分期是为此设计的：P1–P5 已覆盖交接书全部目标，P6/P7 可择期收口。
2. **`tsset` 的连带性。** 它原在交接书 §8 的排除项里，因 ARIMA/VAR 的硬依赖被拉进来。
   若 P7 收口不做，P5 里的 `tsset` 仍应保留——它对面板数据独立有价值。
3. **`proposal_schema` 的复发风险。** 本版改的正是契约与接线，
   §7 那五次失效模式的复发概率高于平常。守卫 B 专门拦截。
4. **新统计能力的「自洽即通过」风险。** IRF 置信带、EFA 旋转、协整秩这类结果，
   自洽的错误实现完全可能全绿。守卫 G（对外部基准）是唯一可靠的拦截。
5. **`aggregate` 的行数收缩**与现有 `_enforce_growth_policy`（只管增长）方向相反，
   需确认收缩不绕过任何既有校验。
