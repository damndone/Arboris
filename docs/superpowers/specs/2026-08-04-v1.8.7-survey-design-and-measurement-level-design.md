## 0. 一句话结论

v1.8.7 是**单轴版本：复杂抽样设计**。核心判断是**引擎优先，族是声明**：

> 不按「先给 OLS 做 svy，再给 logit 做 svy」的方式一族一族推进。
> 而是**把设计方差引擎做一次**（Taylor 线性化 + 重复权重双通道），
> 让模型族通过 `ModelFamilyContract` 的一条声明接入，
> 每族的增量成本 = 一条声明 + 一个 oracle 测试。

## 1. 关键判据：什么能加抽样设计

### 1.1 错误的判据

> ~~「R `survey` 里有没有对应的 `svy*` 函数」~~

这条判据在本设计的讨论过程中被实测推翻两次。按它会误排除
分位数回归、IV/2SLS、面板 FE 和 DID——而这四类实测全部可做且可验证。

### 1.2 正确的判据

> **这个估计量是不是数据的确定性函数？**

因为**重复权重不需要估计量光滑，也不需要推导影响函数——它把整个估计量在每套权重上重跑一遍**。
只要估计量是数据的确定性函数，设计方差就能算，且能对 R `survey::withReplicates` 逐位对照。

### 1.3 实测证据（2026-08-04，宿主机 R 4.x + survey 4.5）

| 能力 | 实测结果 |
|---|---|
| 分层 + PSU + 权重（`svyglm`） | 系数/SE/`degf` 均可取得 |
| `degf = #PSU − #strata` | 162 − 3 = 159，与 `degf()` 一致 |
| lonely PSU 默认 | `"fail"`，与我们要的 fail-closed 一致 |
| lonely PSU 五策略 | `fail`(err) / `remove` 0.15640049 / `adjust` 0.15720010 / `average` 0.18059573 / `certainty` 0.15640049 —— **互相可区分** |
| 加权分位数回归点估计 | `rq(weights=)` 与「按权重展开行」逐位一致，max diff **2.2e-16** |
| 分位数回归设计方差 | `as.svrepdesign` + `withReplicates` → theta/SE 可得 |
| IV / 2SLS + 设计 | theta=−3.5987　SE=0.2463 |
| 面板 FE（组内去均值）+ 设计 | theta=−3.7296　SE=0.1477 |
| TWFE DID 交互项 + 设计 | theta=81.045　SE=39.524，**7/100 replicate 返回 NA 被丢弃** |

最后一行是重要副产品：**自助重抽样会让交互项的某个格变空**。R 的做法是警告后丢弃。
本版必须**如实报告丢弃数量与原因**，不得静默（见 §4 不变量 4）。

### 1.4 唯一仍排除的：时间序列

排除理由**不是**「没有参考实现」，而是**两个对象不组合**：

- 抽样设计描述「怎么从一个**有限总体**里抽单位」；
- 时间序列是「一个随机过程的**单条实现**」。

不存在「时间点的有限总体」被分层 PSU 抽样过。给 ARMA-GARCH 配 strata/PSU 不是难，是没有意义。

**相邻的真需求另立**：重复横截面（CPS 月度、CGSS 各期）→ 每期算设计基础估计值（带正确 SE）
→ 再把这串估计值当时间序列建模。这是两阶段架构，不是「svy + ARMA」，
写进 roadmap 单独设计，不属本版。

## 2. 为什么是这三件功能

判据：**不做就会静默出错，而用户没有能力发现。**

### 2.1 A1 现状：管道通了，估计量是空的

`strata` 与 `PSU` 在整个后端**只出现在 4 个字符串字面量里**：

```
backend/workbench/econometrics/runner.py:647
backend/workbench/engine/stages/estimation.py:365, 763
backend/workbench/predictive_research/prediction_protocol.py:151
```

`sampling_weight` 已从 `runs_routes.py:253` → `orchestrator` → `estimation.py` 全程贯通，
在 `_ols_weight_spec`（`estimation.py:358`）撞上 fail-closed。

**并且现有错误信息本身在教用户做错事**：

> `declare strata/PSU through the existing entity_col + covariance=clustered channel`

聚类稳健标准误 **不等于** 分层 + PSU 的设计方差：它忽略分层带来的方差缩减而系统性**高估**方差；
不产出设计自由度，CI 用错分布；分层与聚类是两个正交维度，用后者冒充前者是范畴错误。
**A1 必须连这句建议一起换掉。**

### 2.2 抽象层已就位

`ModelFamilyContract`（`backend/workbench/agent/workflow_contracts.py:270`）已有：

```python
allows_weights: tuple[str, ...] = ()          # {"sampling", "analysis", "frequency"}
```

「该族接受哪种权重语义」**已经是每族一条声明**。本版扩展这个声明位，
而不是在 `estimation.py` 里堆 `if family == ...`。

### 2.3 A2 现状：整数量表静默跑 Poisson

`router.py:87 detect_y_kind()`：非负整数且 `nunique ≤ 20` → `COUNT` → `poisson_rate`。
李克特 1–4 正好落进这个分支。`YKind.ORDINAL` 只有一个产生点（ordered Categorical）。
下游是通的（`v186_model_families/ordinal_logit.py:26` 已注册 ordinal 默认）。
**卡口只在 `router.py` 这一个函数里。**

**不改自动路由**，理由不是怕 golden 漂，是它不科学：同一列 `1,2,3,4` 可能是满意度打分（有序）、
就诊次数（计数）、编码地区（无序）或 4 分制绩点（准连续），**数值上完全不可区分**。
区别在测量方式里，是元数据不是数据。自动路由无论往哪边跳都会对另一半用户静默出错
——**失败模式与现状相同，只是换了受害人群**。

对标对象自己就不猜：Stata 命令即声明；SPSS 的「度量」列是用户拥有的可编辑变量属性。

### 2.4 A3 现状：三个族在自己批自己的卷子

`ordinal_logit` / `multinomial_logit` / `quantile_regression` 仅内部一致性
——用 statsmodels 复核 statsmodels 算的结果，而 statsmodels 正是执行引擎。
`survival_cox` 已对 R 验证但 R 数值硬编码在测试里，无可重跑生成脚本。

#### A1-b 方差双通道

- **Taylor 线性化** —— 光滑估计量的默认通道，与 R `survey` 默认一致
- **重复权重** —— 通用通道：BRR / jackknife / rescaling bootstrap，
  以及直接消费数据自带的重复权重

**重复权重是本版的核心引擎，不是分位数回归的专用补丁。** 它解锁所有
Taylor 线性化处理不了的非光滑估计量，且每一个都能对 `withReplicates` 逐位对照。
它本身也是必需的：NHANES、CPS 等公开调查数据**直接发布重复权重**，
官方推荐方差算法即 BRR/jackknife；不支持重复权重等于这些数据集的官方算法跑不了。

**设计自由度**：`degf = #PSU − #strata`，用于 t 临界值与 CI，必须出现在结果与导出中。

**设计效应与有效样本量**：`DEFF` / `DEFT` / Kish 有效样本量 `n_eff = (Σw)² / Σw²`。
这是 SPSS/Stata `svy` 的标准输出（Stata `estat effects`），对 R
`svymean(deff=TRUE)` 验证。实测参考值：`DEFF=1.7035`，`n=200 → n_eff=168.58`。

**这一项属于「用户不知道要问」的那类**：`DEFF=1.7` 意味着 200 人的样本，
方差表现只相当于简单随机抽样的 168 人。用户不会主动去问，但这个数直接决定结论的强度。
因此它必须**默认产出并可见**，不是可选开关。

**replicate 失败必须如实报告**：报告成功/失败 replicate 数、失败原因分类，
且失败比例超过阈值时**拒绝出结果**而非静默丢弃（见 §4 不变量 4）。

#### A1-c 族接入 = 一条声明，且组合必须正交

**这是本版最重要的架构约束。**

族 × 设计 × 方差方法是 N×M×K。若写成手写支持表，加一个估计量就要改设计层
——那不叫扩展性。三者必须**正交、自由组合**：

```
Design      strata / PSU / weights / fpc / replicate / lonely-psu / subpop   ← 独立对象
Estimator   声明了能力集的确定性估计量                                        ← 独立对象
Variance    linearization | replicate                                        ← 独立对象
```

**估计量契约是一组能力声明，不是一个函数签名**：

| 能力 | 必需？ | 解锁 |
|---|---|---|
| 确定性重估 `(data, weights) -> params` | **必需** | 重复权重方差（几乎总成立） |
| 影响函数 | 可选 | Taylor 线性化 |
| 消费设计对象（strata/PSU 结构） | 可选 | degf 感知的推断、调整 Wald 检验 |

**组合合法性由这些声明推导，不查表。** 只声明了必需项的估计量
（例如 agent 在沙箱里写出来的）自动获得重复权重方差；
声明了影响函数的额外获得线性化通道。

扩展 `ModelFamilyContract` 的声明位表达的是**该估计量的性质**
（是否光滑、是否提供影响函数、是否需要额外前提），
**不是**「它支持哪些设计」。设计支持性由性质推导得出。

**禁止在 `estimation.py` 里按族写分支。禁止手写「族 × 设计」支持矩阵。**

#### A1-c2 第二张枚举矩阵：`result_shape` 必须打开

`ModelFamilyContract.result_shape` 当前是**只有 3 个值的封闭枚举**
（`workflow_contracts.py:310`）：

```python
if self.result_shape not in {
    "coefficient_intervals", "effect_estimate_bundle", "event_study_bundle",
}:
    raise ValueError("ModelFamilyContract result_shape is invalid")
```

这是一张伪装成契约的枚举矩阵。**任何产出形状不属于这三种的能力根本注册不进来**
——PCA/EFA 的载荷矩阵与因子得分、Cronbach's α 的信度系数与分项-总分相关、
聚类的类别归属与类中心，全部被它挡在门外。
对接书所说「这批不是加模型，是加新节点类型，成本高一档」，成本高的根源就在这个枚举。

**本版必须把它改成可声明扩展。** 但要区分两件事：

- **打开** = 新产出形状能被声明、注册、投影到消费者 —— **属本版**
- **填满** = PCA / EFA / Cronbach / 聚类的实际实现 —— **不属本版**（见 §5）

打开扩展点是架构工作，填内容是枚举工作。本版只做前者，并用一个
**合成产出形状**证明它真能注册进来（验收 A1-17）。

**必须接上 v1.8.6 的最小 payload 闸门，不得留白。**
新产出形状意味着新 payload，而消费者（Table / Report / Agent）要知道 payload
长什么样才能投影。§5 排除了「全仓 Artifact Schema Registry」，
若不作处理，打开 `result_shape` 等于把那笔架构债重新打开。

v1.8.6 已解过同题：其设计 §9 建了**最小 payload 版本闸门**
（不做全仓 registry，但新 packet 必须带最小 schema 声明与消费者版本协商）。
**新 `result_shape` 走同一道闸门**：声明 shape 时必须同时声明其 payload 最小 schema
与版本，消费者按既有协商规则处理未知版本。
这既打开了扩展点，又不扩大既有架构债。

三条直接收益：

1. **扩展性** —— 加估计量不碰设计层
2. **Agent 接入** —— 能力矩阵可推导、可发现；组合不合法时返回 **typed 失败**
   （含机器可判定的 reason code 与缺失前提），agent 据此推理换路，而非撞墙
3. **自研算法** —— 沙箱内写出的估计量只要满足 `(data, weights) -> params` 契约，
   **自动获得设计方差、重复权重与 oracle 对照工装**，无需为它再实现一遍方差。
   这是组合性真正付钱的地方，也是 `V1.8.3-CAPABILITY-EXT` 的前置形状

#### A1-c3 子总体分析（subpopulation）

**这是本版判据最典型的案例，且极易被误用。**

正确做法是在**完整设计对象上取子集**（R `subset(design, ...)`、Stata `svy, subpop()`）；
错误做法是**先筛数据再建设计**（Stata `if`）。后者会**低估标准误**，
且当子总体掏空某些 PSU 时设计自由度也会变。

实测（横切分层的子集，2026-08-04）：

```
            coef(meals)      SE          degf
正确子总体  -3.450320   0.150288   124
先筛数据    -3.450320   0.149110   124
SE 相对偏差 -0.78%
```

**系数完全相同，SE 不同。** 本例 PSU 结构简单故差异仅 0.78%；
真实调查数据中差异更大且 degf 会变。

要命之处：用户先 filter 再分析，**结果看起来完全正常，系数还一模一样**，
他没有任何办法发现 SE 是错的。Stata 手册专门警告不要用 `if` 代替 `subpop()`。

本版必须：

- 提供**设计内子总体**通道（在完整设计上取子集，保留全部方差信息）
- **检测并提示**「数据已被上游筛过 + 声明了 survey design」这一危险组合，
  由 A2b 的 agent 提问覆盖（这正是「用户不知道要问」的典型）

#### A1-c4 设计下的假设检验

`svyglm` 只给单系数 t 检验。联合检验必须走**调整 Wald 检验**
（Stata `svy: test`，R `regTermTest`），分母自由度用**设计自由度**而非残差自由度。
实测：`F = 244.8471 on 2 and 157 df`（157 = 设计自由度）。

没有它，多分类变量的整体显著性、嵌套模型比较在 svy 下都做不了
——而这是 SPSS/Stata 用户的日常操作。对 R `regTermTest` 逐位验证。

#### A1-d 面板权重语义声明

面板场景存在真实的方法学分叉：**纵向权重 vs 横截面权重**（CFPS / PSID 两种都发布）。
这是**声明问题不是能力问题**——`survey_weight_frame` 必须显式声明，
未声明时 fail-closed 并说明两者差异，不默认挑一个。

#### A1-e 权重调整

事后分层（post-stratification）与校准/raking，对 R `postStratify` / `calibrate` / `rake` 验证。
**本项属最后交付块**，受 §7 退出线约束。

### A2 · 测量级别声明

沿既有 `labels` 通道（已贯通 `runs_routes.py` → `run_service` → `source.py:49` /
`cleaning.py:28` → `frame.attrs` → report / visualization）新增 `measurement_level`。

取值 `nominal` / `ordinal` / `scale` / `count` / `unspecified`（默认）。前三档对齐 SPSS 「度量」。

| 声明状态 | 行为 |
|---|---|
| `unspecified`（默认，含全部历史 run） | 路由**一字不动**，产出显式 `measurement_advisory` |
| 已声明 | 按声明路由。**这不是猜测，是执行用户声明** |

**Advisory 证据必须确定性抽取**，不得由 LLM 生成。来源：`value_labels` 是否存在及其原文与可排序性、
取值集合、水平数、是否含 0、列名与 `variable_labels` 原文、同批列形状一致性。

> **值标签是强证据。** 没有人会给「就诊次数」标上 `1=很不满意`。
> 给值贴了语义标签 ⇒ 分类；标签可排序 ⇒ 有序。这是规则不是猜测，
> 且数据里**已经有了**，只是当前无人读取。

**Agent 批量提议**：新增 typed operation `data.columns.declare_measurement`，
沿 `data.columns.cast`（`operations.py:257`，proposal schema / validator / executor /
reconciler / verification builder 全套）的批量形状。Agent 只能**引用**后端抽出的证据，
不能**生成**；存疑列老实标出，不纳入提议。

**摩擦是核心指标**：50 列问卷若要手标 50 次，结果是没人标，功能等于不存在。

### A2b · 抽样设计的前提检验与提问（第 1 层第二个实例）

A2 只覆盖了 roadmap 第 1 层四类中的「元数据补全」一类。本项补上「**前提自动检验并说人话**」，
与 A2 同一模式、同一红线，边际成本低。

**这是 SPSS/Stata 结构性做不到的一段**：它们会老老实实跑一个前提完全不满足的分析，
一声不吭；想起来做诊断是用户自己的事。

Agent 基于**后端确定性抽取的设计事实**提出质疑，典型三类：

| 触发 | 提问 |
|---|---|
| 声明为 IID / 未声明设计，但数据里存在疑似分层或 PSU 列（名称、取值基数、嵌套结构） | 「`region` 看起来是分层变量。当前按简单随机样本处理，若这是分层抽样，标准误会是错的」 |
| `DEFF` 明显大于 1 | 「`DEFF=1.7`，这份 200 人的样本方差表现只相当于简单随机抽样的 168 人。这会影响结论强度」 |
| 权重变异极大 / 存在极端权重 | 「最大权重是中位数的 N 倍，少数观测主导了估计。是否需要修剪或复核权重构造」 |

**红线不变**（roadmap §1 那把尺子）：

- ✅ **提问**：「这可能是分层变量，要不要声明」「有效样本量只有 168，注意结论强度」
- ❌ **回答/断言**：「你应该用分层设计」「你的结论不成立」

Agent 不改任何设置、不自动重跑。它把事实摊开并提问，动作由用户决定。
所有数值（DEFF、n_eff、权重分布、嵌套结构）**一律后端确定性计算**，agent 只引用。

### A3 · 外部 oracle 补齐

照仓库既有范式（`tests/fixtures/{cs_did,dcdh,sa_did,honest_did}/generate_oracle.R`），
每族交付**提交进仓库的 `.R` 生成脚本 + fixture + 逐位对照测试 + 如实声明的容差**：

`ordinal_logit`→`MASS::polr`（已知求解器差异，**如实声明容差，不包装成逐位通过**）、
`multinomial_logit`→`nnet::multinom`、`quantile_regression`→`quantreg::rq`、
`survival_cox`→补生成脚本去掉硬编码。

## 4. 工作流不变量

1. **三条系统不变量**：没有类型的内容可以解释、不能执行；没有验证的实现可以实验、
   不能产出正式数字；没有 lineage 的结果可以预览、不能成为 Workbench 结论。
2. **AI 提问不回答。** Agent 产出 typed proposal 与证据，不产出结论与数字。
3. **证据不可由 LLM 生成。** proposal 的证据字段一律后端确定性抽取，agent 只引用。
4. **fail-loud 优于静默降级。** replicate 失败数、lonely PSU、未声明的面板权重语义
   一律显式报告或拒绝；**不得静默丢弃、静默调整或静默挑默认值**。
5. **族接入靠声明，不靠分支。** 不得在 `estimation.py` 按族写 `if`。
6. **golden 0-drift 是硬约束。** 未声明 survey design、未声明测量级别的既有路径逐位不变。
7. **数值正确性必须有外部 oracle**，或用定义构造 oracle；用同一执行引擎复核不算，
   必须如实标注为内部一致性。
8. **未经明确授权，不 push / 不建 PR / 不 merge / 不 tag。**

## 7. 交付顺序、阶段门与退出线

按 ADR-PD-001。**allowlist 在 `start` 时一次列全**，`backend/workbench/*.py`
顶层文件必须在 start 时纳入，不得事后 rescope 补入。

```
块 0  A0 文档账（起手即做）
块 1  共享入参薄接线（Run API + orchestrator 字段透传，零行为）
块 2  两个枚举天花板一起拆：
        · 设计方差引擎（Taylor + 重复权重）+ lonely PSU 五策略 + degf + DEFF/n_eff
          + 子总体（设计内取子集）+ 调整 Wald 检验
        · result_shape 从封闭枚举改为可声明扩展（A1-c2），接 v1.8.6 最小 payload 闸门
块 3  ModelFamilyContract 声明位 + 首批族（OLS / logit / probit / poisson）
块 4  非光滑与复杂族（有序 / 多项 / Cox / 分位数 / IV / 面板 FE / DID）
块 5  SPSS/Stata 补齐族（双因素 ANOVA / ANCOVA / 重复测量 / Tobit / 截断 / Heckman / 条件 logit）
块 6  权重调整（事后分层 / 校准 / raking）
A2    与块 2 起并行（文件不相交，仅共用块 1 的入参接线）
A2b   块 2 完成后开始（依赖 DEFF/n_eff 的后端产出）
A3    全程独立并行
```

**块 2 是本版的架构核心，两张枚举矩阵必须在同一块里一起拆。**
理由：`result_shape` 若晚于族接入才打开，块 3–5 会先按旧枚举把族接进来，
之后再改就是返工——而返工时那些族已经有 oracle 测试钉着，改动成本高一档。

**阶段门**：每一块必须 oracle 对上 + 用户可达验收通过，才允许开下一块。
不允许「块 2 做到八成就跳块 3」。

**退出线**：块 4 / 块 5 若超出预期，**按块顺延下一版**，不交半成品。
半个设计方差引擎比没有更危险——它会让人以为方差已经对了。
顺延哪一块由人拍板，不由实现者自行决定。

**并行性判断**：A1 与 A2 都要往 Run API 与 orchestrator 加入参，
因此**块 1 必须先由一次共享的薄接线提交完成**（只加字段透传，不含任何行为），
之后 A1 / A2 才可并行。这条薄接线属 Integration 性质的机械改动。

## 8. 测试策略

- **TDD 硬要求**：先写失败测试，**贴出修复前的失败输出**，再实现。
  自查 `git log -S "def <test_name>" --oneline`（识破「拿 baseline 既有测试当修复证据」）
- **三档 oracle**：有第三方实现 → 逐位对照显式容差；无第三方实现 → 用**定义**构造 oracle；
  用同一执行引擎复核 → **不算**，如实标注内部一致性
- **fixture 纪律**：阈值要让「信号」与「错误」可区分（反面教材：v1.8.6 泄漏 run
  r²=0.988 低于 0.99 阈值而假通过）；断言用到产物路径时先打印实际路径核对

## 9. 本版完成的精确定义

> 用户能声明分层、PSU、抽样权重、fpc、lonely-PSU 策略与重复权重（含数据自带的），
> 得到 Taylor 线性化或重复权重的设计方差、正确的设计自由度与据此计算的置信区间；
> 这些数值对 R `survey` 逐位对照通过；模型族通过 `ModelFamilyContract` 的一条声明接入
> 而非按族分支，且新增一族的成本可证明为「一条声明 + 一个 oracle 测试」；
> replicate 失败、lonely PSU 与未声明的面板权重语义一律显式报告或拒绝，绝不静默；
> 用户能声明变量测量级别并据此路由，未声明时得到有确定性证据支撑的显式提示而非静默 Poisson；
> Agent 能对多列问卷产出一份摊开证据的批量提议，存疑列老实标出，一次确认即落地并留 lineage，
> 且无法把编造的证据放进提议；v1.8.6 四个模型族各有可重跑的 R 生成脚本、fixture 与逐位对照测试；
> 既有未声明路径逐位不变，golden 0-drift；完整 gate 通过且上述路径有真机验收证据。

**不可宣称**：

- 不宣称时间序列 + 抽样设计（概念不组合，见 §1.4）
- 不宣称时间维度安全——列级前视仍无法检测，顺延 v1.8.8
- 不宣称 `frequency_weight` 已对 Stata 验证（宿主机无 Stata）
- 未交付的块按 §7 退出线**如实列出**，不用「已完成」概括

## 10. 已知限制（须写进 release notes 的那些）

**「用户自己发现不了的那些」才是必须写的。**

- **列级前视无法检测。** 无 availability/provenance 声明时，系统不能判断某列是否偷看未来；
  把时间序列声明为 IID 时，一个显式未来位移的特征可跑出 r² > 0.9 而不被拦截。本版未改变
- **重复权重方差依赖 replicate 数。** 数量不足时 SE 不稳定；本版报告 replicate 数与失败数，
  但**不代替用户判断该用多少**
- **测量级别 advisory 是提示不是判定。** 系统举证，判断权在用户
- 时间序列 + 抽样设计不支持，且这是概念性的，不会在后续版本中「补上」
