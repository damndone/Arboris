# v1.8.8 Agent-chain hardening and reachability design

Status: approved design; implementation pending.

Worktree: `/Users/jiayuanren/项目规划/.worktrees/workbench-v1.8.8-p6`

Baseline: `ad51d23fb147238188eed9f9e645c02633f7d422`

## Goal

Close the three acceptance gaps left by the P7 Agent-adoption line while
preserving Workbench's evidence-first and confirmation-gated boundaries:

1. accept a real Report response without weakening citation or figure
   validation;
2. validate a Notebook option against its own artifact contract rather than
   the ambient inventory of every artifact in a run; and
3. make the remaining natural-language capability gaps and the actual Genesis
   editor consume declaration-owned contracts.

The target reachability state after the capability work is `52 / 54`: the
current eighteen real gaps become reachable, while the two reviewed closures
(`code.execute` and the legacy `data.column.cast`) remain explicitly closed.
`model.genesis` remains a workflow carrier and is not opened as an independent
natural-language mutation operation.

## Evidence that fixes the shape of the work

The live registry was queried before writing this design. The affected
capability IDs are:

- statistical tests: `test.anova`, `test.chi_square`,
  `test.correlations`, `test.evidence`, `test.fisher_exact`,
  `test.nonparametric`, `test.rank_correlations`, `test.t_tests`;
- prediction: `prediction.prediction_lasso`,
  `prediction.prediction_ridge`, `prediction.prediction_random_forest`;
- data preparation: `imputation.mice`, `resample.smote`,
  `resample.oversample`, `resample.undersample`;
- time series: `model.time_series.arma_garch`, `model.time_series.ets`; and
- selector: `model.auto`.

The current registry also confirms that only
`data.columns.cast`, `graph.fork`, `model.rerun`, and `operation.multi_step`
are natural-language-enabled top-level operations. The implementation must
continue to derive all existing IDs and values from the live declarations; it
must not add a second hand-maintained inventory.

## Non-negotiable safety and extensibility rules

- A provider response that violates a report contract is rejected. Duplicate,
  unknown, malformed, or missing figure markers are never silently stripped or
  repaired.
- Automatic retry is permitted only for an idempotent Report HTTP request after
  a classified transport failure. Typed Agent calls and any operation that can
  mutate a graph or persist a result are not automatically retried.
- Notebook artifact files remain registered and readable even when they are not
  part of the selected option's contract. Narrowing the validation projection
  is not deletion or concealment.
- A natural-language proposal still crosses the existing
  propose -> user confirmation -> execute boundary. LLM prose never chooses a
  statistical method or changes data without a typed, server-validated
  proposal.
- A new composable capability joins one generic adapter registry and one
  declaration-owned workflow contract. It must not add a per-operation branch
  to the orchestrator or runtime dispatcher.
- All numeric engines continue to be deterministic Python implementations
  validated against external references in tests. Production code does not
  invoke R or a shell.

## Self-review corrections before implementation

The first draft was too easy to read as “representative browser success plus
green registry coverage.” That would leave the known P7 acceptance gap alive.
The implementation plan must therefore include a host-side live acceptance
matrix keyed by every current P7 registry operation. For each operation the
matrix records the visible Agent proposal, the confirmation action, the durable
terminal operation state, and the resulting artifact/provenance identity. A
unit-test loop over adapters is not evidence for this matrix. Optional package
absence is an explicit, typed `blocked/optional_dependency` result with the
operation ID; it is never a silent skip or a counted success.

The matrix is separate from browser sampling: the browser path must cover every
new P5 capability and at least one operation in every P7 family, while the
full 64-operation matrix proves that the generic runtime can be driven from
real Agent requests. It is a browser-visible Workbench path, not a direct API
or adapter loop. The fixture catalog is itself typed: it may contain several
small datasets and model lineage fixtures because one universal table cannot
honestly satisfy frame, contingency-table, study-record, time-series, and
post-estimation inputs. If an operation cannot be exercised with a compatible
fixture, the handoff says so by ID and reason instead of changing the
denominator.

The self-review also fixes four semantic ambiguities:

1. the resampling adapters are prediction-data steps only. They require a
   declared discrete target and explicit feature columns, may be consumed by a
   prediction step, and are rejected as sources for econometric inference
   families; this prevents SMOTE or class rebalancing from silently changing an
   inference sample;
2. `model.auto` is an executable deterministic selector step, not a prose-only
   result. It chooses and runs a server-admitted family in one adapter call and
   persists the selected family, candidate policy, and selection evidence;
3. a Genesis draft has a two-phase editor schema: an initial server-owned
   selector/role schema before a model is chosen, then a model-family-specific
   schema after the `model_type` patch. The schema is composed from the live
   capability metadata plus the existing Genesis/model-family role contract,
   so required outcome/predictor roles are not lost merely because the general
   capability endpoint omits them. When the table patch changes the available
   columns, the server refreshes column options atomically with the draft and
   its schema hash. The wizard must hydrate and render the latter response,
   while the server rejects fields outside it; and
4. the Notebook completion outcome records the sorted ambient artifact IDs (and
   count) outside the contract projection. The files remain in the run index,
   and the outcome cannot make them disappear behind a single warning count.

These corrections keep the extensibility claim honest: future capabilities add
one declaration and adapter, while future live acceptance adds one derived
matrix row rather than another hand-written dispatch list.

## Module A — Report provider and figure binding

### Current failure

The Report route asks the model to place every figure marker. A provider can
emit `[[fig:coef_plot]]` twice, which correctly fails the strict contract; a
second attempt can then fail at the transport layer with an upstream
`ReadError`. The frontend only accepts and persists a response after the route
returns a contract-valid packet, so no report was accepted.

### Design

Split report generation into two server-owned phases:

1. the LLM produces evidence-cited Markdown and must not emit any figure
   marker;
2. the server validates the narrative for citations and quality, then binds
   the packet's supplied figures exactly once in a deterministic marker block.

The final response continues to use the existing Markdown marker format so the
review, save, and export consumers remain compatible. A narrative containing
any figure marker is a contract violation, including a duplicate or an unknown
marker. The server does not remove it; it asks for a bounded correction and
returns `LLM_RESPONSE_CONTRACT_INVALID` if the provider cannot comply.

The deterministic binding is intentionally content-light: it emits one marker
per packet figure in packet order and does not invent a visual interpretation.
The figure source and chart metadata remain the frontend/server-owned evidence.

### Transport retry

The LLM client classifies transport failures separately from non-2xx responses
and invalid response shapes. The Report route performs at most one retry for a
classified transient transport failure, with a short bounded backoff. The
retry count and terminal error class are observable in the API error details.
No provider response that made progress into a typed Agent tool call is retried
by this mechanism.

### Tests and acceptance

- report contract tests cover narrative-without-figures, deterministic binding,
  provider-emitted marker rejection, and exact-once final markers;
- route tests cover duplicate-marker correction, transport failure followed by
  success, and exhausted transient failure;
- frontend tests prove the returned server-bound markers still render and
  export;
- real acceptance requires a saved report record, not merely a provider reply
  or a green route test.

## Module B — Notebook artifact ownership

### Current failure

The Genesis/Notebook execution fallback reads the entire `artifacts_index.json`
for a run and passes it to a contract that normally declares only the primary
capability outputs. A successful OLS run therefore produces informational
`ARTIFACT_UNDECLARED` issues for cleaning records, diagnostics, figures, and
the report bundle even though those records are valid run artifacts.

### Design

Keep two explicit views of a run:

- the ambient run artifact registry, which remains the complete durable record;
- the option-owned artifact projection, derived only from the current
  `ArtifactContract.expected` identities.

When completion is called without an explicit server-owned produced-artifact
projection, the service validates the contract-scoped view. It records the
scope and ambient count in the outcome/trace so a reader can see that the
ambient registry was retained but was not misrepresented as option output.
When a caller supplies an explicit produced-artifact list, the existing strict
undeclared-artifact detection remains active. This preserves the guard for
incorrect providers and keeps the unit-level contract semantics intact.

The expected identity/type mapping continues to come from the published
capability artifact vocabulary and the option declaration. No standard list of
OLS or Genesis by-products is hardcoded into the validator.

### Tests and acceptance

- a run-wide index with the current real QA artifact shape validates without
  undeclared warnings when completion uses the contract projection;
- missing required and wrong-type expected artifacts still block the head;
- explicit produced lists still report undeclared artifacts;
- the full ambient index remains readable after completion;
- the real Notebook chain must end with a committed option and no
  `ARTIFACT_UNDECLARED` warning for the contract projection.

## Module C — Reachability adapters and Genesis editor

### Generic adapter seam

Introduce a declaration-driven workflow capability registry for the eighteen
missing IDs. Each entry owns its closed request schema, column/input
projection, input mode, deterministic adapter, result validation, and output
declaration. The workflow runtime gets one generic registry dispatch seam; it
does not learn the names of individual statistical tests, prediction models, or
preparation methods.

P7's existing registry remains covered by its current generic seam. The new
registry follows the same fail-closed shape and can be folded into a common
protocol later without making this repair depend on a broad P7 refactor.

### Statistical tests

The eight `test.*` entries call the existing statistical-test kernel through an
explicit-family adapter. They do not replace the automatic exploratory test
stage. The explicit step records its requested family, source columns,
assumptions, and correction scope. Multiple comparisons are corrected within
the declared step family; results from separate explicitly requested steps are
not silently pooled into one correction family. An unsuitable or empty source
for a requested family fails the step rather than producing an empty success.

### Prediction

The three `prediction.*` entries use the existing typed predictive-research
protocol, including split plan, sample specification, negative controls, and
OOS evaluation. Sampling and imputation remain explicit fields with the
existing safety restrictions. A prediction step is not treated as causal
inference and its artifact/result envelope says so.

### Data preparation

`imputation.mice`, `resample.smote`, `resample.oversample`, and
`resample.undersample` are dataset-producing workflow steps. Their adapters
must persist the transformed dataset, recipe/decision metadata, and source
binding so a later model step can declare and consume that producer. Unsupported
targets, insufficient classes, missing columns, optional dependency failures,
or incomplete imputation fail closed. The Agent may propose a preparation step,
but the user still confirms it before the sample changes. Resampling is not
permitted to feed `model.genesis` or another econometric inference family: the
workflow compiler rejects that edge and explains that the registered sampling
protocol is prediction-only. This is an explicit safety boundary, not a
missing consumer.

### Time series and selector

`model.time_series.arma_garch` and `model.time_series.ets` join the workflow
registry through their existing typed pack/recipe contracts and preserve their
time-index, missing-value, and transform preflight checks. They are not
pretended to be ordinary `model.genesis` families.

`model.auto` is a deterministic selector adapter. It records the selected
family and the server-owned selection evidence in the result lineage. The LLM
may state the request and rationale, but it cannot supply an arbitrary chosen
family outside the closed selector contract.

The selector's output must be a completed model result plus a selection
evidence artifact, not an unexecuted recommendation. The adapter invokes only
the server's existing auto-selection policy and refuses an Agent-supplied
family override that is not part of that policy.

### Capability inventory and P2 guard

The inventory projects each newly registered workflow capability as a real
composition path. It does not give those steps a false top-level
`proposed_by` path and does not mark them exempt. The P2 snapshot is updated in
the same capability-registration changes, with a docstring explaining that the
numeric assertion is a deliberate record of the current truth and must be
updated intentionally when a gap is closed.

The two reviewed closures remain the only exemptions. The expected final
partition is:

| partition | count |
| --- | ---: |
| direct natural-language paths | 4 |
| composition paths | 48 |
| reachable | 52 |
| reviewed closures | 2 |
| unreachability gaps | 0 |
| inventory | 54 |

### Genesis editor contract

Genesis draft creation publishes a server-owned model editor schema/hash
derived from the same capability metadata used by the capability endpoint.
Changing the selected model type refreshes the applicable schema projection;
model patches are rejected when they contain fields outside that projection or
values outside its closed options. The existing `editable_schema`,
`editable_schema_hash`, and `schema_id` fields are the bridge to the existing
draft editor and are not duplicated in a new frontend-only schema.

`GenesisWizard` consumes the server capability/model metadata for selection and
uses the draft's schema as the validation source. Specialized controls remain
where a model family needs a richer interaction, but their emitted params must
be accepted by the same server schema. Hydration of an existing draft must
occur before any empty form defaults can overwrite it.

### Tests and acceptance

- registry coverage is declaration-derived and rejects missing/extra adapters;
- generated step vocabulary, capability inventory, proposal schemas, and route
  inspection all expose the same new entries;
- each new guard is mutation-tested with an anchor check, a behavior-changing
  mutation, the exact red error, restoration, and a green rerun;
- a representative data-preparation -> model workflow proves the produced
  dataset is actually consumed, not merely registered;
- Genesis route, draft-store, and `GenesisWizard` tests exercise the actual
  editor consumer and reject a forged/unsupported field;
- P2 reaches `52/54` with zero real gaps and exactly two reviewed closures.

## Real-chain verification boundary

Automated tests establish contract coverage only. After the implementation is
green, the host environment must separately run:

1. a real Agent proposal and confirmation for a preparation -> model workflow;
2. a real Notebook execution with a clean contract projection;
3. a real Report generation that is saved and rendered/exportable; and
4. a Genesis editor upload, resume, model selection, validation, and execution
   path.

5. the complete current P7 operation matrix, with a visible proposal and
   confirmation for every registry operation and a durable result or an
   operation-specific optional-dependency block. No row may be marked complete
   from a mocked provider, a direct adapter call, or a pytest result. The
   matrix's current denominator is the live `p7_pack_registry` count of 64,
   queried again immediately before execution.

Provider failures, optional dependency skips, and browser inability to accept a
report remain explicit `NOT VERIFIED` evidence until the corresponding durable
consumer record exists.

## AI-native value to verify

The implementation must state the concrete advantage at handoff time:

- Report lets an Agent compose a citable narrative from a bounded evidence
  packet and bind the correct figures without allowing prose to change facts;
- Notebook lets an Agent propose a multi-step, user-approved preparation,
  estimation, and diagnostic chain with durable lineage rather than forcing a
  user to discover and wire every prerequisite manually; and
- the reachability work lets one natural-language request assemble data
  preparation, explicit tests, prediction, time-series analysis, and reporting
  through typed contracts. The Agent contributes discovery, rationale, and
  composition; the server still owns method validity and numerical execution.

These are the “beyond SPSS/Stata” claims for this line. If the real-chain
evidence shows only a fixed form invocation, the claim is not accepted.

## Explicit non-goals

- No direct natural-language opening of `model.genesis` as a mutation bypass.
- No silent fallback from an unavailable provider to another provider or model.
- No automatic data cleaning, automatic method substitution, or automatic
  multiple-comparison pooling chosen by an LLM.
- No change to P0 composition semantics, P1 inventory semantics, or the P7
  numerical engines beyond the adapter/contract projection needed to reach
  them.
- No push, PR, merge, tag, or release as part of this line.
