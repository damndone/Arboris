## 0. 一句话目标

把 2206 行的 `workbench/api.py`（FastAPI 承重容器）拆成**路由 / service / repository 三层**，
让"每加一个端点就往大文件叠"的累积模式结构性终结；顺带把 🔴 P1（auto-mode draft 不可编辑）
在服务层修掉。**纯搬迁 + 一个契约修复，行为对外不变——契约测试 + golden 0-drift 是硬不变量。**

## 1. 为什么这是拓展性打底（与北极星的关系）

roadmap 北极星 = 一张 lineage graph 完成所有操作（编辑/rerun/对比/AI/报告）。这些新能力
（v1.6.10+ 的图内对比 / 节点 AskAI / 引用报告）**每一个都要加 2-4 个新端点**。今天它们只能
往 api.py 叠 → 大文件继续涨、契约越糊越死。先立三层 + "不许再往大文件加"的规矩，之后每个北极星
功能都是**新 router + 新 service**，api.py 不再动。**这就是"为后期拓展性打好基础"的具体兑现。**

## 4. P1 修复（折进本版，服务层落地）

**病**：auto-mode base run → from-node draft 的 `params.model_type="auto"`；`editable_schema` 的
model_type options 只含具体家族（无 `auto`）；DraftEditorSection Save 全量回传 → `PATCH
/pipeline-drafts/{id}` 逐参数校验 → 422 `INVALID_PARAM_OPTION`。任何从 auto-mode run
（旧 Submit / API / CLI 默认）fork 的 draft 完全不可编辑。

**实际落地 = 只做 ②（根因修复）；① 经分析后不做**（决策记录见下方「① 复盘」）。

原计划 ②+①，实现时发现 ① 需要改契约、且无正确性收益：

**① 复盘（为何不做）**：当前 `PATCH /pipeline-drafts/{id}` 是**全量替换** `params`
（`patch()`: `model_node["params"] = params`）。若 FE 只回传 changed fields，`params`
会丢掉未改的键 → 触发 `MISSING_EDITABLE_PARAM`。故 ① 必须同时把后端改成**部分合并**
（replace→merge）语义——这是一个**契约改动 + 新风险**，而 ② 已在契约执行点根因修复
（全量 PATCH 现在就正确工作，且 FE/CLI/API 任一客户端都受益）。为一个 payload 优化去
destabilize 一个能正确工作的契约，违背"为拓展性打稳地基"。**决定:只做 ②**；① 作为
可选优化留档（若将来要做，须连同 PATCH replace→merge 契约一起 spec）。

**② 后端对「值未变的参数」跳过 option 校验（契约执行点根治，已实现）**：
- 落点：`workbench/lineage/pipeline_drafts.py` 的 `_validate_params()`——遍历 `params` 时，
  若 `key in source_params and params[key] == source_params[key]`（值与继承的 source 值字节相同）
  则 `continue` 跳过 `_validate_control_value`。继承值本就来自真实执行过的 run，不该用（可能更窄的）
  editable_schema options 重校验;只对**用户真正改动**的参数做 option/type 校验。
- 与客户端无关——FE/CLI/API 任一发全量参数都不再误伤。语义正确（`auto` 不进合法项，排除 ③）。
- 测试（`tests/test_pipeline_drafts_store.py`，TDD）：`skips_unchanged_inherited_param_outside_options`
  （只改 covariance,model_type=auto 未变 → ok）、`allows_changing_inherited_param_to_valid_option`
  （auto→logit → ok）、`still_blocks_changed_param_outside_options`（auto→bogus → INVALID_PARAM_OPTION）。
  既有 `blocks_invalid_select_option`（改成非法值被抓）不破。
- 真机复现验收（Phase 6 smoke）：`draft_82b538d59b5f4d0687d326842f0ccb2a` 场景 Save 成功。

## 5. 分阶段执行（阶段间过 gate，纯搬迁零行为漂移）

> 纪律：每阶段**只搬不改逻辑**（P1 除外，单列 Phase 5）；每阶段后 worktree 内跑 gate
> （`LANG=LC_ALL=en_US.UTF-8 ./scripts/gate.sh`）确认 BE 全绿 / golden 23 0-drift / FE / tsc。

- **Phase 0 baseline**：worktree 内先跑一次 full gate 存基线（证明起点绿）；确认契约 + behavior_snapshot 覆盖 23 路由的响应形状。若有端点无契约测试 → 先补最小快照再拆（护栏优先）。
- **Phase 1 repository 层**：抽 `repository/run_repository.py`（最独立、纯函数、低风险）。api.py 改为 import。gate。
- **Phase 2 results service**：抽 `services/results_service.py`（`_model_results`/issue 归一化）。gate。
- **Phase 3 run service（后台调度+上传）**：抽 `services/run_service.py`（`_submit_run`/`_bg_run`/`_write_upload`）。SSE 复用 `events.py`。gate。
- **Phase 4 router 化**：逐簇把 route def 搬进 `http/*_routes.py`，api.py→app.py 只留 `include_router`。**一次一簇**（projects → runs → graph → drafts → rerun），每簇后 gate。`api.py` 留 `from .app import app` shim 保 import 路径。
- **Phase 5 P1 修复**：在 `draft_service`/PATCH 校验点落 ② + 补 3 个测试。gate。
- **Phase 6 收尾**：full gate + 三级评审（Implementer→Test&QA→Reviewer，子代理用 opus）+ 真机 smoke（含从 auto-mode run fork draft 改 covariance 存成功）。

## 8. 风险

- **router 化易漏隐式副作用**：FastAPI route 顺序（如 `/runs/{id}` vs `/runs/batch` 的路径优先级）、
  依赖注入、`Form(...)` 解析细节。缓解：一次一簇 + 每簇 gate + 契约测试钉响应形状。
- **循环 import**：service 调 orchestrator、orchestrator 可能反向引用 → 抽层时以依赖方向为准，
  必要时用 TYPE_CHECKING / 局部 import。
- **behavior_snapshot 覆盖盲区**：若某端点响应未被快照钉住，纯搬迁可能悄悄改形状。Phase 0 先补盲区。
