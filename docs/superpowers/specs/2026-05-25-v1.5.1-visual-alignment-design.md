### 0.4 New tracks — design

#### T6 — Global Theme Toggle

**Mechanism**:
- `<html data-theme="dark|light">` (no per-route modifier classes).
- CSS variables in `:root[data-theme="dark"]` and `:root[data-theme="light"]` blocks; all OKLCH tokens (`--surface-bg`, `--surface-fg`, `--surface-muted`, `--accent-*`, `--trust-*`, `--rail-*`, `--stage-*`) get both palettes.
- Toggle button lives in `Topbar` (route `/runs/:id`) AND in `AppShell` header for `/` and `/runs` routes (so the toggle is always reachable, not only on lineage).
- Persistence: `localStorage["workbench:theme"]` = `"dark"|"light"|"system"`. Default = `"system"`, which reads `window.matchMedia("(prefers-color-scheme: dark)")` and re-evaluates on change.

**Files**:
- `frontend/src/theme/ThemeProvider.tsx` (NEW) — context + `data-theme` writer + matchMedia listener
- `frontend/src/theme/useTheme.ts` (NEW) — hook returning `{theme, effective, setTheme}`
- `frontend/src/theme/ThemeToggle.tsx` (NEW) — three-state button (Light / Dark / System)
- `frontend/src/theme/ThemeProvider.test.tsx` (NEW) — 4 tests
- `frontend/src/theme/ThemeToggle.test.tsx` (NEW) — 3 tests
- `frontend/src/main.tsx` — wrap `<App />` in `<ThemeProvider>`
- `frontend/src/styles.css` — split single-palette tokens into `[data-theme="dark"]` / `[data-theme="light"]` blocks
- `frontend/src/lineage/tokens/lineage.css` — same split
- `frontend/src/AppShell.tsx` — mount `<ThemeToggle />` in header right slot

**Token migration rule**: For every existing token currently in `:root`, create a `[data-theme="dark"]` value (preserve current OKLCH) and a `[data-theme="light"]` value (lightness flipped: L 0.14 → 0.96, L 0.78 → 0.22, etc., preserving chroma + hue). Document the mapping table in `frontend/src/theme/TOKEN_MAP.md`.

**Backward-compat shim**: Keep the `workbench-shell--lineage` class in place for one cycle (V1.5.1) but its CSS body now reads `var(--surface-*)` instead of hardcoded OKLCH. Deletion deferred to V1.5.2.

## 4. Track 1 — SSE + Progress

### 4.1 Backend contract (already exists, no BE changes)

```
GET /runs/{run_id}/events?project_root=...
```

Emits SSE frames with the following event names and JSON body shape (`RunProgressEvent`):

| event | step | message | status | terminal? |
|---|---|---|---|---|
| `step_start` | string | "Stage <name> starting" | null | no |
| `step_complete` | string | "Stage <name> done" | null | no |
| `step_blocked` | string | "<reason>" | "blocked" | no |
| `workflow_completed` | null | "Workflow completed" | "completed" | yes |
| `workflow_blocked` | null | "Workflow blocked" | "blocked" | yes |
| `workflow_failed` | null | "Workflow failed: <err>" | "failed" | yes |
| `workflow_interrupted` | null | "Workflow interrupted" | "interrupted" | yes |

All shape facts asserted by `tests/test_event_manager.py` + `frontend/src/api.test.ts:257 connectRunEvents wires step events and terminal close`. **No backend changes needed for T1.**

### 4.2 Frontend changes

#### 4.2.1 `waitForRunTerminal` internals

External signature stays:
```ts
waitForRunTerminal(projectRoot, runId, { intervalMs?, maxMs?, onTick?, signal? })
  : Promise<RunDetail>
```

New behaviour:
1. If `typeof EventSource === "undefined"` → fall through to the V1.5.0 polling path unchanged.
2. Otherwise, open `connectRunEvents(...)`:
   - On every event, call `opts.onTick?.(detail)` — but `detail` must include the latest event payload. Extend `onTick` shape: `onTick?: (detail: RunDetail, lastEvent?: RunProgressEvent) => void`.
   - On terminal event, `await fetchRunDetail(...)` once and resolve with it.
   - On `EventSource.onerror` (network drop, server gone), close the SSE handle and fall through to polling for the remainder of the wait.
3. `maxMs` cap still applies (now defaults to **30 min** since SSE doesn't burn HTTP roundtrips). Polling-fallback path keeps the 5-min default.
4. `signal` aborts both SSE and any in-flight fetch.

#### 4.2.2 Submit page progress UI

In `App.tsx`, replace the static "Running workflow — waiting for completion" string with:

```
Running workflow…
└─ <step_name>: <message>     ← from latest step_start / step_complete
```

If three seconds pass without any event, show "Connecting to event stream…" to confirm the channel is live. If the run reaches a terminal status, the existing auto-nav to `/runs/<id>?tab=lineage` fires unchanged.

#### 4.2.3 Optional: lineage page banner during in-progress run

If a user enters `/runs/<id>` before the run terminates (rare but possible via deep-link), show a thin top banner: "Run in progress · current step: <name>". Source: the same `connectRunEvents` subscription, owned by `LineageRouteContainer` (cleaned up on unmount).

|---|---|
| `frontend/src/api.ts` | `waitForRunTerminal` internals; extend `onTick` shape; new `_subscribeRun` helper composing `connectRunEvents` |

| `frontend/src/lineage/LineageRouteContainer.tsx` | Optional in-progress banner subscription |

### 4.4 Failure modes covered

| Scenario | Behaviour |
|---|---|

## 5. Track 2 — Auto-select first review node

### 5.1 Behaviour

On `LineageRouteContainer` mount **only when `?node=` is absent**:

1. Iterate `viewModel.nodes` in the order they appear in the response.
2. First pass: pick first node with `trust === "review"`.
3. If none, second pass: pick first node with `trust === "caution"`.
4. If still none: leave selection empty (drawer shows V1.5.0 placeholder).
5. When picked, call `navigate(..., { replace: true })` with `?node=<nodeKey>` appended. **Never use `push`** — this would create a useless history entry that breaks the back button.

### 5.2 Why this order

The editorial prototype enters with a review-needed card already open (per `uiux/screenshots/initial.png`). `review` is the higher-attention state (hard block); `caution` is softer (advisory). Selecting `caution` only when no `review` exists matches "open the most pressing review first."

## 8. Track 5 — Polish bundle

### 8.1 `lastRun` persistence

**Problem**: In V1.5.0, `App.tsx` holds `lastRun` in `useState`. Navigating away (e.g., `/` → `/runs/x` → back to `/`) wipes the "your last run was…" hint card.

**Fix**: Move `lastRun` into a new `AppShellContext` (or reuse the existing one if it's already a context — check during impl), backed by `sessionStorage["workbench:lastRun"]`. Restored on mount, cleared on explicit user dismissal only.

**Files**:
- `frontend/src/AppShell.tsx` (or new `frontend/src/AppShellContext.tsx` if missing)
- `frontend/src/App.tsx` (read from context instead of local state)
- `frontend/src/App.test.tsx` (test: trigger run → navigate away → back → hint card still visible)

### 8.2 `/runs` history list dark chrome

**Problem**: `/runs/<id>` is dark (V1.5.0 P1), but `/runs` history list is still V1.4 light. Jumping from lineage to history is visually jarring.

**Fix**: Extend the `workbench-shell--lineage` modifier (currently route-pattern `/^\/runs\/[^/?#]+$/`) to also match `/^\/runs(?:\/[^/?#]+)?$/`. Update OKLCH token mirrors as needed.

**Files**:
- `frontend/src/App.tsx` (regex update + code comment explanation)
- `frontend/src/App.test.tsx` (assert dark class on `/runs` route)
- `frontend/src/styles.css` (verify no breaking selectors)

### 8.3 `WORKBENCH_UI_ORIGIN` fallback

**Problem**: CLI prints `Lineage: http://localhost:5173/...` by default. If user runs CLI without `npm run dev`, the link is dead.

**Fix**: When env var unset, CLI tries to detect whether `:5173` is live (quick TCP probe with 100 ms timeout). If not, fall back to `http://localhost:8000` (BE serves the static SPA from `frontend/dist/` in production; ditto if user is running `uvicorn` alone).

**Files**:
- `backend/workbench/cli.py` (new `_resolve_ui_origin()` helper)
- `tests/test_cli.py` (3 tests: env var set wins, :5173 live wins, fallback to :8000)

**Risk**: TCP probe adds ~50–200 ms to CLI start. Mitigation: cache result in `~/.workbench/ui_origin_cache.json` with 1 h TTL.

### 8.4 DoD (Track 5 combined)

- All new tests pass (~6 added)
- Browser smoke L27–L29 (lastRun persistence, /runs dark, CLI lineage URL valid)
- No regression in baseline counts
