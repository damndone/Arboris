# Workbench v1.8.6 全范围扩展设计

> 状态：扩展设计已批准，作为 v1.8.6 全范围 Goal 的范围依据。
>
> 本文件扩展 `2026-08-01-v1.8.6-predictive-research-correctness-foundation-design.md`，不改写
> 原文，也不声称原设计从一开始就包含本文件新增的能力。原设计继续保留其历史效力；本文件
> 只记录用户在 2026-08-03 决定纳入同一交付线的扩展范围。

## 0. 扩展理由

用户决定把 v1.8.6 从「预测研究正确性地基」扩展为「地基 + 数据管理层 + 统计工具箱 +
两个新模型族及分位数回归」的完整研究工作台能力，接受工程量扩大；是否改称 v1.9.0
另行决定，不影响本文件的执行范围。

## 1. 相对原设计打开的范围

下列项目逐条覆盖原设计的「明确不做」清单；只有本文件列出的实现才可被视为本次扩展打开，
不得借此推导出更广泛的自动化能力。

### 1.1 数据管理层

- `FeatureRecipe` 从内部 typed registry 暴露为 API/UI 可达操作，并写入 Graph 节点与
  lineage；支持既有五个受限算子：interaction、log、ratio、recode、derived_variable。
- `reshape`（长宽转换）作为显式、可追溯 Graph 操作。
- `merge` / `append` 作为执行操作；键冲突、多对多、异常行数膨胀必须 fail-closed。
- `subset` 作为可追溯的行筛选操作。
- 本范围不打开任意 `code.execute`、自动特征搜索或无限操作分支。

### 1.2 权重与 survey 研究横切

- `sampling_weight`、`analysis_weight`、`frequency_weight` 三种语义贯通 API 与 UI。
- OLS 支持 `frequency_weight` 与 `analysis_weight`；`sampling_weight` 在完整分层/聚类
  语义就绪前保持 fail-closed。
- strata 与 PSU 声明复用既有 cluster 通道，不建立第二套聚类路径。
- 每个模型族通过 `ModelFamilyContract.allows_weights` 明确声明准入；未声明即拒绝。

### 1.3 新模型族与 y_type

- `y_type` 增加 `ordinal`、`nominal`。
- 增加有序 logit/probit 与多项 logit pack，输出优势比/相对风险比、边际效应和预测概率。
- 有序模型必须提供平行线假设诊断。
- 所有既有 continuous、binary、count 路由行为保持不变。

### 1.4 生存分析

- 增加 Kaplan–Meier、log-rank、Cox 比例风险模型及 Schoenfeld 比例风险诊断。
- 使用独立的 censoring、risk set、time-to-event 契约，不复用普通回归 request 形状。

### 1.5 分位数回归

- 增加 statsmodels `QuantReg` pack。
- 支持多分位点、分位点置信区间、bootstrap 和跨分位点比较。

### 1.6 统计工具箱与消费端

- 把 posthoc ANOVA、Tukey/Bonferroni、Cohen's d、eta/omega squared、one-sample/paired t、
  Wilcoxon signed-rank、Levene/Bartlett、Shapiro-Wilk 接入用户可达的统计 evidence packet。
- 增加多模型并列回归表、显著性标记和 Table 1 描述统计表。
- 变量标签和值标签贯通表格、报告和图形输出；无法保留外部格式标签时必须如实说明。

## 2. 仍然排除的范围

以下项目即使本扩展存在，也不得在 v1.8.6 中偷偷打开：

- temporal / panel prediction 的实际执行；保持 fail-closed。
- PIT 数据源、历史股票池、因子 DSL、换手/成本/容量和实盘下单。
- 超参数搜索平台、深度学习、自动特征工程。
- 完整 Sealed Holdout 状态机。
- SEM / CFA / MANOVA。
- PCA、探索性因子分析、聚类、判别分析。
- Tobit、Heckman、条件 logit、零膨胀、Hurdle。
- 动态面板 / System GMM、空间模型、贝叶斯模型。
- 倾向得分、Matching、IPW、RDD、合成控制。
- 任意第三方依赖自动安装、任意 `code.execute` 生成模型。

## 3. 工作流不变量

### 3.1 治理与注册

- 每个工作流使用独立 development line 和独立 allowlist；不得把所有扩展堆进已有冻结 line。
- 估计器注册表采用追加式注册；既有 handler 和数值路径不因新增族而改变。
- `ModelFamilyContract` 明确声明支持的权重和 split kind；未声明能力 fail-closed。

### 3.2 数据操作与身份

- 每个数据操作都产生 Graph 节点、输入边、参数/版本和可复现 identity。
- FeatureRecipe 结果 identity 不含 SplitPlan；Evaluation/Prediction packet identity 必须含
  SplitPlan。
- reshape、merge、append、subset 改变输入或行集合时，必须重新计算下游 identity 并使旧缓存
  正确失效。
- merge 多对多、键冲突、异常行数膨胀必须在产生结果前拒绝。

### 3.3 权重

- 同一数据不传权重与传全 1 frequency weight 的无权重路径结果逐位一致。
- 权重语义不能互相替代；不支持的语义在拟合前返回稳定错误码且不产生结果 artifact。
- 对外部 Stata/R oracle 的数值验证必须标注验证等级；没有 oracle 不得声称逐位一致。

### 3.4 统计 evidence

- 新统计检验不能只存在于 Python 函数和单元测试中，必须进入正常 Run 的
  `workbench.statistics.evidence-packet` v1。
- ANOVA 多分类场景必须包含 posthoc、校正范围以及 eta/omega squared；两组场景必须包含
  Cohen's d；组间比较前必须记录 Levene/Shapiro 诊断。
- 配对检验需要显式配对语义；缺少配对契约时拒绝并给出可执行下一步，不能按列顺序猜配对。
- Table、Report、Agent 只能读取 schema-validated packet，并保留 assumptions、warnings、
  effect size 和 multiple-testing correction scope。

### 3.5 新模型族

- 既有三种 y_type 的默认路由行为和 golden 数值逐位不变。
- Ordered/MNLogit、Cox、QuantReg 各自使用独立 typed request/packet，不把普通回归 spec
  强行套在不同统计对象上。
- 每个新增族的输出必须包含模型参数、关键诊断、预测/边际结果、假设和验证等级。
- 与 Stata/R 外部实现逐位验证；没有 oracle 时明确标注「仅内部一致性测试」或「未对外部实现验证」。

### 3.6 MICE

- prediction + MICE 必须在每个训练 fold 内独立拟合并应用到验证/测试 fold。
- 全表 MICE 后切分的诱饵测试必须失败；在 fold-local 实现完成前，阻断路径只能作为兜底，
  不得被 release notes 描述成已经支持 MICE。

### 3.7 用户可达性

- 每项新增能力必须能从真实 API/UI 入口触发，并在 Graph、Run Result 或 Report 中看到结果。
- 单元测试只证明内核局部正确，不能替代真实 Run、真实 artifact、Graph/Report/Agent 证据。
- 每条工作流至少有一条真实用户路径验收和一条可复现的负向边界验收。

## 4. 交付与验证边界

- 所有新增文件必须归属于明确 development line 的 allowlist。
- 每个 line 必须记录修复前失败输出、修复后测试输出、用户可感知能力、未完成项、scope 变化
  和 FMS 事件编号。
- 既有 golden 23 必须保持 0-drift；新增模型族和权重只允许增加新证据，不得改变既有估计结果。
- full gate、native browser、外部数值 oracle 和 formal FMS verification 分开报告。
- 未经用户明确授权，不 push、PR、merge 或 tag。
