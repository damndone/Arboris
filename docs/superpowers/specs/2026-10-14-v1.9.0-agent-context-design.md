# v1.9.0 Agent context: compaction, instructions, project recall

Date: 2026-10-14. Line: `v1-9-0`. Status: accepted by the user in conversation
("compaction must be done; instructions must be general; memory needs
distinguishing - reading the local project/sessions may be better").

## Why

The Agent resends the whole conversation every step. `ContextBuilder` could
read a `compaction` entry but nothing wrote one, so a long conversation ends
in a provider context-length error. The Agent has no way to receive the
person's standing conventions, and it forgets every earlier conversation in
the same project.

## References

- **pi** (`badlogic/pi-mono`, coding-agent `docs/compaction.md`): session tree
  of JSONL entries (Arboris' `JsonlSessionRepository` already follows it);
  auto-compaction when `contextTokens > contextWindow - reserveTokens`
  (16384), keeping the most recent ~20000 tokens verbatim; cuts only at
  user-turn boundaries so a tool result never loses its call; structured
  summary (Goal, Constraints & Preferences, Progress, Key Decisions, Next
  Steps, Critical Context); iterative re-summary from the previous summary;
  `CompactionEntry{summary, firstKeptEntryId, tokensBefore}`; one
  compact-and-retry on provider overflow; manual `/compact [instructions]`.
- **Codex** (`AGENTS.md` guide): instructions from a global file and from
  the project, joined general-to-specific so the more specific file wins;
  a byte limit (32 KiB). Compaction as a hand-off summary for the next model.
- **Hermes Agent** (memory docs): small curated memory files injected as a
  frozen snapshot at session start; a separate, unlimited session archive
  searched on demand (`session_search`, SQLite FTS5) that returns stored
  messages. Its own docs note memory clutter and that long-lived chats make
  memory rarely useful.

## Decisions

### 1. Compaction (statistics-aware)

- Standing messages are never summarized: the latest protocol, identity,
  focus, instructions, recall index and Workbench context. Only the
  conversation (user, assistant, tool) is compacted.
- Trigger before each model step when the estimated context exceeds
  `window - reserve` (reserve 16384). Window = the configured model's
  declared context window, else an assumed 64000 tokens (stated in the
  status, never presented as the model's real window). Also: manual compact
  with optional focus instructions, and one compact-and-retry when the
  provider rejects the request for length.
- Keep the newest ~20000 tokens verbatim, cut at a user message.
- Summary sections for analysis work: Research question and goal; Data and
  variables in use (with ids); Analyses done and their results (each number
  with the run/model/artifact/step id it came from); Decisions and the
  person's preferences; Proposals (id and state); Open questions and next
  steps.
- **Numbers in a summary are evidence on later turns**, so the summary is
  checked with the same numeric grounding as replies, against the messages
  it replaces. One rewrite is requested on failure; a summary that still
  contains unsupported numbers is kept but marked unverified and excluded
  from numeric evidence, so later answers must re-inspect.
- Entry: `compaction{summary, first_kept_entry_id, tokens_before,
  tokens_after, trigger, verified, unverified_numbers, model}`. Nothing is
  deleted; the UI shows a marker and the summary.

### 2. Instructions (general, layered)

Joined general-to-specific, each a frozen snapshot at session start:

1. Arboris analysis guide (built in, read-only): principles that hold from a
   two-variable regression to time-series forecasting, quantitative strategy
   research and machine learning - estimand first, design before method,
   assumptions checked not assumed, honest validation (out-of-sample,
   time-ordered, no look-ahead), uncertainty and multiplicity reported,
   reproducibility.
2. Personal instructions: `~/.config/econometrics-workbench/AGENTS.md`
   (language, reporting conventions, significance level) - across projects.
3. Project instructions: `<project>/AGENTS.md` - the research question, data
   dictionary, domain context, agreed methods. The same file other agents
   (Codex, Claude Code, pi) read in that folder.

32 KiB total; truncation is stated, not silent. A generic template (same
sections for any kind of analysis) and a "draft from this project" that
fills in datasets and variables without a model.

### 3. Memory: project recall, not global memory

Automatic cross-project memory stays off: projects differ, and a lesson from
one is noise or bias in another. Instead, like Codex/Claude Code reading the
local workspace:

- A new conversation receives a short index of this project's earlier
  conversations (title, date, chapters, last summary line).
- Read-only tools search this project's conversations and read one around a
  hit (Hermes `session_search`, scoped to the project).
- Stable personal preferences live in the personal instructions file, which
  the person writes - explicit, inspectable, never inferred.
- The existing domain memory (default off, Notebook) is unchanged.
