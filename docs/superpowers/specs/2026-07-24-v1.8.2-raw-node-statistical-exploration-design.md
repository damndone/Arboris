# v1.8.2 Class 3 Stata workflow design

日期：2026-07-24  
状态：范围已扩展，等待用户复核
开发线：`v1-8-2-raw-statistics`  
基线：`418b040b766cc929447b38f7f14e00531168ec7c`

## 1. 摘要

Workbench 在 v1.8.2 内完成一套可追溯的 Class 3 Stata 教学工作流。用户
选中 Graph 中的 Raw data 节点，在右侧面板中构建多个 AND 筛选条件，先
预览和保存描述性统计，再计算相关矩阵，随后创建派生指标、绘图、进入
已有 OLS 模型能力，并查看 residual/fitted diagnostics，最后导出完整报告。

切片只是内部实施顺序，产品上必须形成一条完整的：

```text
先探索 -> 再变换 -> 再建模 -> 再诊断 -> 再报告
```

Raw data 是不可变事实源；typed transform、model、plot、diagnostic 和
report 都是带 source、scope、参数和 fingerprint 的证据对象。用户不需要
编写 Python，也不需要手动维护 Stata 日志文件。

## 2. Do-file 到 Workbench 的映射

| Do-file 能力 | v1.8.2 对应能力 |
|---|---|
| `use`, `clear` | Project/Raw data 生命周期；Raw artifact 不可变 |
| `log using`, `log close` | 自动 Run log、analysis transcript 和事件证据 |
| `summarize`, `misstable`, `corr` | Raw data 上的 Statistical exploration |
| `summarize, detail` | Detail 模式和百分位数 artifact |
| `gen small_school...` | Typed percentile-derived transform |
| 分组 `summarize` | 共享 scope 的 grouped descriptive statistics |
| `twoway scatter` | Plot explorer 和 figure artifact |
| `reg` | 复用现有 OLS Model Draft/Run |
| `_b`, `_se`, `e(N)` | 现有模型结果 adapter 展示 CI 和有效样本量 |
| `predict residuals` | Model diagnostics residual artifact/plot |
| `predict fitted_values` | Model diagnostics fitted artifact/plot |
| `translate ... PDF` | 完整 Analysis Report/PDF artifact |

## 3. 范围与非目标

### 目标

- Raw data 节点提供模型前筛选、描述统计、缺失值和相关矩阵；
- 支持多个 AND 条件；
- 支持基础统计和 `summarize, detail`；
- 支持基于 p25/p75 创建 typed indicators；
- 支持带 scope 的散点图；
- 复用现有 OLS 执行能力，补齐 N、95% CI、模型比较显示；
- 支持 residual/fitted diagnostics；
- 自动保留日志、图形和 PDF 报告；
- 所有结果在 Graph 中可见、可重读、可导出。

### 非目标

本版本不新增新的回归引擎或模型家族，不提供 OR 条件组、多级分组、任意
Python/R 编辑器，也不让 Agent 自主编写和执行统计程序。`code.execute`
继续是受风险授权保护的高级 DataFrame 变换，不是教学工作流主入口。

## 4. 用户流程

```text
选择 Raw data 节点
  -> Statistical exploration
  -> 添加 AND 筛选条件
  -> Summarize / Detail / Missing / Correlation
  -> 根据百分位创建 typed derived variables
  -> 保存 spending scatter plots
  -> Continue to model selection
  -> 复用现有 OLS Model Draft / Run
  -> 查看 N、CI、model compare
  -> residual/fitted diagnostics
  -> Report / log / PDF export
```

## 5. 交互设计

### 5.1 Raw data 右侧面板

Raw data 节点详情中新增位于模型操作之前的 `Statistical exploration` 区域，
顶部显示 source、read-only 状态、当前 scope、筛选后行数和 data freshness。
它既支持 Genesis 上传后的 zero-run Raw artifact，也支持已有 Run 中的 Raw
data 节点。

### 5.2 AND 筛选器

每个条件行包含 column、operator、value editor 和 remove。首版支持
`equals`、`in`、`>=`、`<=`、`is_missing`、`is_not_missing`。所有条件固定
显示 AND，通过 `Add AND condition` 增加条件。无匹配行阻止统计执行并给出
修正入口；空值条件不能静默转成普通比较。

每次条件变化都显示 filtered rows 和变量缺失概况。筛选 spec 会被所有
后续统计、绘图和模型 draft 复用。

### 5.3 Descriptive statistics

卡片包含：

- `Group by (optional)`：首版允许一个列，例如 `year`；
- `Variables`：默认选中所有可做数值统计的列；
- Obs、Mean、Std. dev.、Min、Max；
- `Detail` 开关；
- Preview、Save result、Export CSV/XLSX。

分组长表至少包含 `group_values`, `variable`, `obs`, `mean`, `std_dev`,
`min`, `max`。Obs 按变量分别计算非缺失值，因此同组不同变量的 Obs 可以
不同，匹配 Stata `summarize`。

Detail 模式增加 `p1`, `p5`, `p10`, `p25`, `p50`, `p75`, `p90`, `p95`,
`p99` 和可选 IQR。百分位数必须绑定当前 filter scope、group_by 和变量。

### 5.4 Correlation matrix

Correlation 与 Descriptive statistics 同属 Statistical exploration，但保持
独立动作，共享当前 filter scope。默认使用所有选中的数值列、Pearson 和
listwise，输出带 `variable` 行标签的 pooled 矩阵，匹配 Stata `correlate`。

Correlation 不自动继承 group_by；若用户要得到逐年份矩阵，必须显式创建
新的统计操作，避免一次操作产生六个难以阅读的矩阵。Spearman、Kendall、
pairwise 作为后续高级选项。

### 5.5 Typed percentile-derived variables

用户从已保存的 Detail 统计结果点击 `Create derived variable`，选择 source
column、p25/p75 threshold、output name 和显式 predicate，例如：

- `small_school = totreg <= p25`；
- `large_school = totreg >= p75`；
- `poor_school = pfl >= p75`；
- `least_poor_school = pfl <= p25`。

系统生成版本化 typed transform spec 和新的 Transform node，而不是隐藏执行
Python。节点记录 percentile source artifact、threshold value、scope、
predicate、missing policy 和 output schema。上述变量是 fixture，不是硬编码
业务规则。

### 5.6 Plot explorer

Plot explorer 可以挂在 Raw data scope 或 Model diagnostics scope，包含 x、y、
可选分类着色、有效 Obs、缺失处理、Preview、Save figure 和 Export PNG/SVG。
图形 artifact 记录 plot spec、source fingerprint 和 scope。v1.8.2 至少覆盖
`adj_dppupil_comp` 对 `pfl`、`totreg` 的散点图，并允许保存多个不同图形。

### 5.7 OLS 接线与置信区间

不新增 OLS engine，复用现有 Model Draft/Run。v1.8.2 补齐：

- 模型继承 Raw scope 或 typed Transform node；
- 结果显示 `e(N)` 对应的有效样本量；
- 每个系数显示 estimate、standard error、95% CI；
- model result 记录 y、x、covariance、scope 和 source fingerprint；
- 第二个模型通过 Graph fork/compare 添加 `pfl`，不覆盖第一个模型；
- CI/N 由同一模型结果 artifact 提供，前端不自行制造模型证据。

### 5.8 Residual/fitted diagnostics

模型完成后提供 Diagnostics：

- 生成 residual 和 fitted-value 的只读派生 artifact；
- residual 对 `pfl`、`pblack` 的散点图；
- fitted 对 `pfl` 的散点图；
- 每张图保留 model id、source scope 和 model result fingerprint；
- 临时列的显示或删除不改变原始模型和 Raw data。

### 5.9 日志、报告和 PDF

Run 自动生成事件日志和 analysis transcript。Report/PDF 汇总数据源、筛选、
统计表、派生变量 recipe、图形、OLS 结果、CI、诊断和 gate 状态。用户不需要
执行 `log close` 或手动调用 `translate`；导出是 Run 的可见 artifact，而不是
终端副作用。

## 6. 数据与证据契约

### 6.1 StatisticalExplorationSpecV1

```json
{
  "schema_version": "statistical-exploration.v1",
  "source_run_id": null,
  "source_node_id": "...",
  "source_artifact_id": "upload_or_raw_data",
  "source_sha256": "...",
  "filters": [
    {"column": "year", "operator": "in", "values": [1998, 2002]},
    {"column": "boro", "operator": "equals", "value": 2}
  ],
  "filter_logic": "AND",
  "action": "descriptive_stats",
  "group_by": ["year"],
  "variables": ["bdsnew", "year", "middle"],
  "method": "stata-summarize-compatible",
  "missing_policy": "variablewise",
  "output_format": "table"
}
```

zero-run Genesis artifact 的 `source_run_id` 为 null；已有 Run 的 Raw 节点填写
实际 run id。`source_node_id` 和 `source_artifact_id` 始终必填，并由 resolver
确认 artifact 属于当前项目和源节点。Correlation 使用相同结构，将 action
改为 `correlation_matrix`、group_by 置空、method 设为 `pearson`、missing_policy
设为 `listwise`。

### 6.2 Graph 结果

统计结果不是 dataset transform child，使用明确的 analysis result node 或
等价的 analysis artifact：

- kind：`statistical_analysis`；stage：`exploration`；parent：Raw data；
- payload：结果 artifact；
- annotations：完整 spec、source fingerprint、operation id、created_at；
- status：preview、materialized、stale、failed。

Graph 表达 Raw → Descriptive、Raw → Correlation 两条独立证据边。保存统计
结果不能造成“数据发生改变”的 downstream invalidation。

Typed 派生变量必须是 transform node；Plot、Model、Diagnostic、Report 各自
拥有独立 artifact 类型和 source binding。

### 6.3 Stale

源 artifact SHA、schema fingerprint 或过滤值字典变化时，保存结果标记 stale
但保留原 spec 和结果。用户通过 `Re-run` 重新验证，不覆盖旧结果。

## 7. 后端实现边界

新增或扩展受控服务，职责限定为：

1. 验证 StatisticalExplorationSpecV1 和 typed filter evaluator；
2. 从 zero-run upload 或 run-backed Raw artifact 读取只读 DataFrame；
3. 计算基础/detail/grouped statistics 和 correlation；
4. 生成 preview、确定性 fingerprint、result artifact 和 Graph record；
5. 通过 typed operation 生成 percentile-derived variables；
6. 通过显式 plot spec 生成 figure artifact；
7. 复用现有 OLS result，提供 CI/N reader 和 model compare binding；
8. 从完成的模型生成 residual/fitted diagnostics；
9. 汇总 log、tables、figures、models、diagnostics 到 report/PDF；
10. 检查 source freshness，不修改 Raw data。

这些能力不能通过拼接用户 Python 字符串实现，也不能把统计探索复用成
`code.execute` 的任意数据变换。

## 8. 测试与验收

### 后端

- AND filters：equals、in、数值范围、missing；
- 零行、非法列、非法类型、重复条件；
- grouped/detail statistics 的 Obs、sample SD、percentiles；
- Pearson listwise correlation fixture；
- source SHA stale 阻断；
- preview/materialize fingerprint 一致；
- Raw 未被写入，exploration 不触发模型 invalidation；
- p25/p75 transform threshold、scope、schema 可追溯；
- plot spec 和有效 Obs 可追溯；
- OLS CI/N 与已有模型 artifact 一致；
- residual/fitted 只依赖已完成模型；
- report/PDF 包含所有上游 artifact。

### 前端

- Raw 节点显示统计探索面板，模型节点显示 diagnostics；
- AND 条件增删和类型化编辑；
- summarize、detail、correlation 共享 scope、独立结果；
- derived-variable preview/confirm/stale；
- Plot explorer source/scope 选择；
- OLS CI/N/model compare visible reader；
- residual/fitted 不被当成原始列；
- report reader 读取完整 Class 3 artifact pack。

### 浏览器验收

使用真实 CSV 完成：

1. Raw 节点设置六个年份和第二个 AND 条件，核对 filtered rows；
2. 按 year 生成 summarize/detail，核对 1998 年 bdsnew 等 Stata fixture；
3. 生成 pooled correlation；
4. 由 p25/p75 创建四个 typed indicators；
5. 保存 spending/pfl、spending/totreg 两张图；
6. 运行 `adj_dppupil_comp ~ pblack` 和添加 `pfl` 的第二个 OLS；
7. 核对两个模型的 N、CI 和 Graph fork；
8. 生成 residual/fitted 图；
9. 导出含 log、tables、figures、models、diagnostics 的 PDF；
10. 修改源数据后确认旧结果 stale。

完整 gate 必须通过，且 v1.8.1 tag、release notes、release train 文档和
`integration/v1.8.1` worktree 保持不变。

## 9. v1.8.2 内部切片顺序

所有切片都属于 v1.8.2，顺序只是为了保持每一步可验证：

1. 前置统计：filter、summarize、detail、missing、correlation；
2. 数据与图形：percentile-derived variables、group summarize、scatter；
3. 模型接线：复用 OLS，补齐 CI/N、model compare；
4. 诊断与交付：residual/fitted、log、report、PDF。

每个切片完成后都必须在 Graph 中可读取，并通过对应 backend、frontend 和
browser evidence gate；版本结束时只接受完整 Class 3 workflow 闭环。

## 10. 后续演进

后续版本再增加 OR 条件组、多级分组、Spearman/Kendall、pairwise missing
policy、分布图和 Agent 生成 typed statistical option。Agent 仍必须经过
preview、证据绑定和用户确认，不能直接生成或执行任意代码。
