# v1.8.2 Raw-node Statistical Exploration Design

日期：2026-07-24  
状态：设计已获用户确认，等待 spec 复核  
开发线：`v1-8-2-raw-statistics`  
基线：`418b040b766cc929447b38f7f14e00531168ec7c`

## 1. 摘要

Workbench 需要在模型选择之前提供一等的统计探索能力。用户选中
Graph 中的 Raw data 节点，在右侧面板中构建多个 AND 筛选条件，先预览和
保存描述性统计，再计算相关矩阵，最后带着相同的数据范围进入模型选择。

统计探索是只读的：Raw data 仍是不可变事实源，不生成伪清洗数据节点，
也不要求用户编写 Python。它既要支持 Genesis 上传后的 zero-run Raw artifact，
也要支持已有 Run 中的 Raw data 节点。筛选条件、分组列、变量选择、统计
方法、缺失值策略、源 artifact 指纹和结果 artifact 都必须进入可追溯的统计
分析记录。

## 2. 问题与目标

### 当前问题

v1.8.1 的运行报告内部已有描述统计和相关性产物，但它们依附于一次模型
运行。当前用户若要完成“按年份 summarize、六年 pooled correlation”的
任务，只能借助 `code.execute` 编写 Python，把统计结果转成新的数据节点。
这暴露了三个问题：

1. 模型前探索被错误地放进模型运行之后；
2. 统计意图被表现成高风险数据变换，而不是只读分析；
3. 教学用户必须理解 Python 和 DataFrame 才能完成基础统计任务。

### 目标

- Raw data 节点选中后，右侧直接出现 Statistical exploration 区域；
- 支持多个 AND 条件，至少覆盖分类值、数值比较和缺失值条件；
- 支持按一个分组列生成逐组描述统计；
- 支持当前筛选数据的 pooled correlation matrix；
- 描述统计默认提供 Obs、Mean、Std. dev.、Min、Max；
- 相关矩阵默认使用 Pearson + listwise，匹配 Stata `correlate`；
- 结果可预览、保存、导出，并挂在 Raw data 节点的证据链下；
- 统计结果可以作为后续模型决策的上下文，但不替用户自动选择模型。

## 3. 非目标

本版本不包括：

- OR 条件组；
- 多级或交叉分组统计；
- 任意 Python / R 代码编辑器替代方案；
- 由 Agent 自主编写统计程序并直接执行；
- VIF、残差诊断等模型后诊断；
- 将 Raw data 修改为筛选后的新数据集。

`code.execute` 继续作为高级、受风险授权保护的 DataFrame 变换能力，
不是本功能的主入口。

## 4. 用户流程

```text
选择 Raw data 节点
  -> 右侧 Statistical exploration
  -> 添加 AND 筛选条件
  -> 查看筛选后行数和缺失概况
  -> Descriptive statistics：可选 group_by，预览/保存
  -> Correlation matrix：选择变量，预览/保存
  -> Continue to model selection
  -> 模型 draft 复用同一 data scope
```

用户可以只执行其中一个动作，也可以先保存描述统计再保存相关矩阵。
两者共享筛选上下文，但生成两个独立的结果 artifact，避免把两个不同的
统计结果塞入一个难以解释的复合表。

## 5. 交互设计

### 5.1 Raw data 右侧面板

在 Raw data 节点详情中新增位于模型操作之前的 `Statistical exploration`
区域，顶部固定显示：

- source：Raw data 节点名称、行数、列数；
- state：read-only；
- scope：当前筛选条件；
- filtered rows：筛选后总行数；
- data freshness：源 artifact 是否仍与统计记录一致。

### 5.2 AND 筛选器

筛选器由条件行组成，每行包含：

- column；
- operator；
- value editor；
- remove。

首版支持：

- `equals`；
- `in`（从低基数列的已知值中多选）；
- `>=`、`<=`；
- `is_missing`、`is_not_missing`。

所有条件固定显示 `AND`，通过 `Add AND condition` 增加条件。UI 不提供
隐藏的默认筛选，也不把空值条件静默转换成普通比较。每次条件变化都重新
计算 preview，并显示筛选后行数；无匹配行时阻止统计执行并给出修正入口。

### 5.3 Descriptive statistics

该卡片包含：

- `Group by (optional)`：首版允许一个列，例如 `year`；
- `Variables`：默认选中所有可做数值统计的列，支持移除；
- 固定统计量：Obs、Mean、Std. dev.、Min、Max；
- `Preview summarize`；
- `Save result` 和 `Export CSV/XLSX`。

分组结果以长表展示，至少包含：

`group_values`, `variable`, `obs`, `mean`, `std_dev`, `min`, `max`。

没有 `group_by` 时返回一个 pooled 总结。Obs 按变量分别计算非缺失值，
因此同一组中不同变量的 Obs 可以不同，行为与 Stata `summarize` 一致。

### 5.4 Correlation matrix

该卡片与 Descriptive statistics 同属 Statistical exploration，但保持独立
操作。它共享当前 filter scope，默认：

- method：Pearson；
- missing policy：listwise；
- variables：所有选中的数值列；
- 输出：带 `variable` 行标签的矩阵。

首版不把 `group_by` 自动套用到 correlation。若用户想得到逐年份矩阵，
必须显式创建新的统计操作；这避免一次操作产生六个矩阵而不易阅读。

UI 应明确说明：当前相关矩阵是在筛选后的 pooled 数据上计算。后续可以
增加 Spearman、Kendall 和 pairwise 作为高级选项，但不得改变默认
`correlate` 语义。

### 5.5 进入模型选择

统计探索区域底部提供 `Continue to model selection`。点击后打开模型配置，
同时携带当前 `data_scope_id`。模型表单显示：

- 使用的 Raw data 节点；
- 当前筛选条件；
- 已生成的统计证据链接；
- 一键返回统计探索修改范围。

模型选择仍由用户完成。系统可以提示高相关变量或缺失风险，但不能把
描述统计结果自动解释成模型推荐或自动执行模型。

## 6. 数据与证据契约

### 6.1 StatisticalExplorationSpecV1

建议新增版本化 typed spec：

```json
{
  "schema_version": "statistical-exploration.v1",
  "source_run_id": null,
  "source_node_id": "...",
  "source_artifact_id": "upload_or_raw_data",
  "source_sha256": "...",
  "filters": [
    {"column": "year", "operator": "in", "values": [1998, 2002]},
    {"column": "boro", "operator": "equals", "value": 2}
  ],
  "filter_logic": "AND",
  "action": "descriptive_stats",
  "group_by": ["year"],
  "variables": ["bdsnew", "year", "middle"],
  "method": "stata-summarize-compatible",
  "missing_policy": "variablewise",
  "output_format": "table"
}
```

`source_run_id` 对 zero-run Genesis artifact 为 `null`；已有 Run 的 Raw
节点填写实际 run id。`source_node_id` 和 `source_artifact_id` 始终必填，
并由 resolver 确认 artifact 属于当前项目和源节点。

`correlation_matrix` 使用相同结构，将 `action` 改为
`correlation_matrix`，`group_by` 为空，`method` 为 `pearson`，
`missing_policy` 为 `listwise`。

### 6.2 结果与 Graph

统计结果不是 dataset transform child。建议增加一种明确的分析结果节点
或等价的 analysis artifact 记录：

- node kind：`statistical_analysis`；
- stage：`exploration`；
- parent：Raw data node；
- payload：结果 artifact；
- annotations：完整 spec、source fingerprint、operation id、created_at；
- status：`preview`, `materialized`, `stale`, `failed`。

Graph 必须能表达：Raw data → Descriptive statistics，以及 Raw data →
Correlation matrix 两条独立证据边。保存统计结果不应使模型 downstream
变成“需要重新运行”的假失效状态，因为它没有改变数据。

### 6.3 Stale 与重新验证

如果源 artifact 的 SHA、schema fingerprint 或过滤值字典发生变化，已保存
结果标记为 `stale`，但保留原 spec 和结果。用户可以 `Re-run exploration`
重新验证，而不是覆盖旧结果。

## 7. 后端实现边界

新增统计探索服务，职责限定为：

1. 解析并验证 `StatisticalExplorationSpecV1`；
2. 从 zero-run upload artifact 或 run-backed Raw data artifact 读取只读
   DataFrame；
3. 以 typed filter evaluator 执行 AND 条件；
4. 计算描述统计或相关矩阵；
5. 生成 preview 与确定性 result fingerprint；
6. materialize 结果 artifact 和 Graph evidence record；
7. 在源数据变化时执行 stale 检查。

它不复用 `code.execute` 的任意代码路径，也不修改 Raw data。统计计算应
直接使用受控的 pandas/statistical helpers，并为 Stata 兼容语义建立独立
测试，而不是在测试中拼接 Python 字符串。

## 8. 测试与验收

### 后端契约

- AND filters：equals、in、数值范围、missing 条件；
- 过滤后零行、非法列、非法值类型、重复条件；
- 分组描述统计的逐变量 Obs 和 sample standard deviation；
- pooled Pearson listwise correlation 与固定 fixture 对齐；
- source SHA 不一致时 stale 阻断；
- preview 与 materialize 结果 fingerprint 一致；
- Raw data 未被写入或改变；
- 结果节点不触发模型 downstream invalidation。

### 前端

- Raw data 节点才显示统计探索面板；
- AND 条件增删和类型化编辑；
- summarize/correlation 共享 scope、独立结果；
- 空结果、stale、错误和保存状态；
- 进入模型配置时 scope 和证据链接保留；
- 结果读者能读取版本化统计 packet，而不是只显示旧模型表格。

### 浏览器验收

使用真实 CSV 完成：

1. 从 Raw data 节点打开面板；
2. 设置 `year in {1998, 2002, 2006, 2010, 2014, 2016}`；
3. 添加第二个 AND 条件并确认行数变化；
4. 按 `year` 预览描述统计，核对 1998 年 `bdsnew` 等 fixture 数值；
5. 在同一 scope 生成 pooled correlation matrix；
6. 保存两个结果并在 Graph 中看到两条 evidence 边；
7. 进入模型选择，确认 scope 和结果链接仍在；
8. 修改源数据或过滤值字典后确认旧结果显示 stale。

完整 gate 仍需通过，且 v1.8.1 tag、release notes、release train 文档和
`integration/v1.8.1` worktree 保持不变。

## 9. 演进路径

v1.8.2 只实现确定性的显式 UI。后续版本可以在同一
`StatisticalExplorationSpecV1` 上增加：

- Spearman/Kendall；
- pairwise missing policy；
- 多级分组；
- 频数、分位数、分布图和缺失模式；
- Agent 生成 typed statistical option，但必须经过 preview、证据绑定和
  用户确认，不能直接生成或执行任意代码。

这样可以把“先探索、再建模”变成 Workbench 的稳定主路径，同时保持
Graph、Artifact、Draft 和 Run 的事实源边界不被破坏。
