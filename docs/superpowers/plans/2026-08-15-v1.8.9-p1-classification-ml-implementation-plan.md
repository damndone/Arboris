# Workbench v1.8.9 P1 Classification ML Core Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development or superpowers:executing-plans. Follow TDD and the frozen Contract Lock; this line must not modify central Agent/Notebook routing or UI mount points.

**Goal:** 在统一、可扩展的分类任务契约上实现无泄漏、可比较、可校准、可解释的分类 ML 核心，并以 Logistic Regression 与 Random Forest 两个 adapter 证明“增加模型不改变编译器、运行时和消费者”的扩展路径。

**Architecture:** 分类核心由 typed task/split/preprocessing/model/evaluation/policy contracts、adapter registry、artifact persistence、Graph lineage、EvidenceEnvelope projection 和 package-local provider declaration 组成。模型选择、阈值决策与 final holdout 严格分离。该线只发布能力和 renderer contribution；Agent、Notebook、Report mount 与中央 catalog 切换由 `v1-8-9-agent-notebook-cutover` 单独完成。

**Tech Stack:** Python 3.14、pandas、NumPy、scikit-learn、pytest、Workbench predictive_research/Graph/evidence contracts、React/TypeScript/Vitest。

## Contract and ownership boundaries

- 输入：Contract Lock C0；Workflow Truth、Evidence Core、Agent Compiler Core 的 C1 兼容矩阵。
- 只消费公开 contract facade；不 import sibling line 的私有模块。
- 本线不依赖 Data Consumer Core，因此可与其并行。
- 本线不得修改中央 Agent/Notebook routing、`frontend/src/report/ReportView.tsx` 或 canonical section registry。
