> Spec：`specs/2026-07-22-v1.8.1-agent-notebook-analysis-option.md` §12、§4.0、DEC-CTX-001。
> 前置：Gate 1（RunFamily）已完成 —— `run_family_id` / `active_head_run_id` 是
> `NotebookPlanningContextV1` 的必填字段，没有它编译不出来。

> 不做通用 Context DSL（spec §12.2 的排除清单逐条有效）。

## 为什么是它，而不是"再加个检索"

v1.8.0 真机上 Agent 三次拿不到时间序列摘要，报 `tool_output_budget_exceeded`。
当时的单点修法是 `recipes/arma_garch.py: _bounded_comparison()`——把 4 个 row-id
列表换成一个计数。**那个修法是对的，但它只修了一处。** Gate 2 是把它变成通用工序。

实测（v1.8.0 ARMA-GARCH run，见 spec §12.3 校准表）：

```
artifacts_index.json   59 个 artifact / 22 KB   = 单工具预算(8192)的 2.7 倍
model_results/*.json   11.5 KB                  = 单个就超预算
graph.json             11 节点 / 10.9 KB
```

**缺的从来不是检索能力，是有界投影。**

## 验收步骤的写法约定（同 Gate 1，强制）

每步验证断言**具体内容**，不得只断言存在性：

- ❌ "上下文已编译" → ✅ "`generation_context_hash` 两次编译逐字节相等，
  且 `omissions` 含 `{section: artifact_summaries, included: 5, available: 59}`"
- ❌ "预算生效" → ✅ "序列化后长度 ≤ 24576，且 59 个 artifact 中恰好 5 个带
  详细摘要、其余按 type 聚合成 12 个计数条目"

## Task 3：两个 fingerprint（spec §4.0 的命门）

**目标**：generation hash 与 freshness fingerprint 各司其职，且**不会自引用**。

- [ ] **Step 1: 写失败测试（自引用）**：编译上下文 → 生成 3 条 sibling option →
      重新编译 → 断言这 3 条的 `freshness_dependency_fingerprint` **全部未变**
      （即它们仍 fresh）。这条是本 Task 的命门：
      `existing_option_summaries` 属于 generation hash，**不得**进 freshness。
- [ ] **Step 2: 写失败测试（白名单）**：逐项改动 spec §4.0 白名单里的字段
      （Analysis Contract revision / dataset profile revision / run_family_id /
      active_head_run_id / 选中文本 hash），断言 fingerprint **每一项都变**；
      再逐项改动黑名单字段（compiled_at / trace_id / token 数 / budget_report /
      omissions / sibling option），断言 fingerprint **一项都不变**。
- [ ] **Step 3: 运行**，确认失败。
- [ ] **Step 4: 实现** `freshness_dependency_fingerprint`——**只**读白名单字段，
      与 `generation_context_hash` 走**不同**的输入集合。
- [ ] **Step 5: 与既有 stale 机制对齐**：确认 `agent/proposals.py: confirm()`
      的比对字段与本 fingerprint **不冲突**（Gate 1 已证明 `context_fingerprint`
      与 `active_head_run_id` 是既有比对项，本 fingerprint 是其超集）。
- [ ] **Step 6: 运行聚焦测试**并确认通过。

## 不做的事

- **不**做向量检索 / 语义搜索 / 跨项目上下文发现（DEC-CTX-001 明确排除）。
- **不**做通用 Context DSL——只有 `notebook-plan/v1` 一个 profile。
- **不**动 `recipes/arma_garch.py: _bounded_comparison()`——它已经是对的，
  Gate 2 是把同样的思路通用化，不是重构既有单点修复。
- **不**改任何既有数值产物；golden 必须 0-drift。

## 风险

| 风险 | 缓解 |
|---|---|
| 两个 hash 被实现成一个 | Task 3 Step 1 的自引用测试 + Step 2 的黑白名单逐项断言 |
| 预算默认值拍脑袋 | Task 6 Step 1 打印实际用量；spec §12.3 已用真机数据校准过一轮 |
| "必须完整保留"的项被预算误伤 | Task 2 Step 2 用极小 budget 专测 |
| 编译器成为绕不过去的瓶颈但仍被绕过 | Task 5 Step 3 的结构测试 |
| 上下文快照泄露越权数据 | Compiler 是统一入口（spec §12.1），权限过滤在此收敛 |
