# v1.8.12 第 5 步计划：CLI 由目录生成（V1812-CLI-FROM-CATALOG）

验收（objective）：命令行完成负二项 NB1 → Wald → 导出 Stata 脚本，并在本机用 Stata 实跑通过。用户 2026-10-08 同意本机跑 Stata。

## 现状

- `workbench run` 手写 40 多个参数，直接调用 `orchestrator.run_workflow`，绕过 HTTP 用的 `_submit_run`。
- 结果：缺 `model_options`、加权、预测数据结构、统计检验、分组运行等参数；`run_inputs.json` 等提交记录与界面运行不同。
- 没有后估计和脚本导出命令。

## 设计

1. **运行请求字段表** `backend/workbench/run_request.py`（只依赖标准库）：
   - 每个字段写一次：名称、默认值、类型、说明、CLI 可重复、JSON 文档。
   - `POST /runs` 的表单签名由它生成（OpenAPI 不变，由生成类型的漂移测试守住）。
   - 表单组装与解析（`model_options`、`labels`、`statistical_tests`）由路由与 CLI 共用。
2. **`workbench run`**：
   - 选项由字段表生成，保留原有调用方式（`PROJECT DATA Y --x ...`、`--survey-replicate-weight`）。
   - 经与 HTTP 相同的 `_submit_run` 提交，等运行结束；stdout 只输出 run_id，失败返回非 0。
3. **`workbench postestimation <op>`**：
   - 子命令与选项由后估计操作的步骤合同生成；为避免启动时导入统计库，合同数据移入轻量模块。
   - 执行走与 Agent 相同的工作流引擎（`compile_workflow` + `WorkflowExecutor`）；来源指纹用源数据工件的 SHA-256。
4. **`workbench export-script` / `export-targets`**：调用与 HTTP 相同的脚本导出服务；`--output` 把脚本包写到指定路径。
5. **`workbench models [MODEL]`**：列出能力目录（模型类型、参数、`model_options` 字段）。
6. 每条命令都记入分析台账，与界面操作一致。
7. **NB1 原生导出**（实施中发现）：v1.8.11 只验证了 NB2，NB1 退回结果侧车，Stata 并不真正重估。
   - 补 Stata（`nbreg …, dispersion(constant)`）与 Python（`loglike_method="nb1"`）原生翻译，用模型与后估计 oracle 在真实 Stata / Python 中执行验证。
   - R 没有参照级 NB1 估计器，保持侧车并写明原因。

## 测试

- CLI 与 HTTP 对同一组参数产生相同的工作流参数（同一提交路径）。
- 字段表与 `POST /runs` 的 OpenAPI 表单一致。
- 后估计子命令覆盖每个登记的操作。
- 导入 CLI 不加载 pandas / numpy / scipy / statsmodels / fastapi（启动预算 < 0.5 s）。
- 端到端：NB1 → Wald → 导出 Stata 包 → `stata-mp -b do` 实跑，脚本内的数值自检通过。
