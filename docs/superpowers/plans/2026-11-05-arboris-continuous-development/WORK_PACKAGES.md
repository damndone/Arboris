## 3. 三项方法的精确产品边界

### T1：局部水平状态空间

输入：时间列、观测列、噪声方差 Q/R、初始状态与方差、预测步数、留出范围。所有时间/缺失约定可见；规则频率存在断档时不得因删行把时间压缩。

输出：过滤状态、创新及方差、对数似然、预测均值、状态区间与观测预测区间的区别、留出指标、基准预测、真实引擎/构建和数据身份。大数组作本地列式/二进制结果，仅有限摘要进入 Agent。

Q/R、初始状态与方差须在查看最终 holdout 前固定并记录来源。看过留出结果后反复改参属于探索比较，不能继续称为未使用的最终测试集。区间标明条件于指定参数和初始状态，不包含参数选择/估计的不确定性；T1b 估参也必须仅用每折训练数据。

先完成固定参数模式；后续 **T1b** 追加原生 Q/R 参数估计、平滑与局部趋势，分别验证优化收敛和边界。固定参数模式可以正式可用，但名称和说明必须准确，不能标“自动参数估计”。

测试入口：现有 `tests/test_native_time_series.py`；新增方法场景纳入 `tests/test_native_research_workflow.py` 的实际执行，而不仅是 validate/catalog；浏览器完成选列→运行→图表→重开→改参重跑。

### M1：原生 Ridge

输入：目标列、特征列、alpha、截距/缩放规则、冻结的训练/验证/测试划分；时间或分组数据按其结构分割。模型只使用训练部分学习标准化和填补参数。

时间预测还须冻结每个特征/标签的可获知时间及标签覆盖期间。每折按训练截止时点检查，隔离跨入验证/测试期的重叠标签；必要的间隔和排除规则随结果保存。不支持的时点场景明确拒绝，不能把简单时间排序当作已消除泄漏。已有 predictive_research 只作为复用基础，仍需验证这项语义。

输出：原单位系数/截距、预测、训练与样本外误差、基准预测、分割与预处理证据、真实原生身份。误差是预测表现，不包装为因果效应或传统回归显著性。

优先复用 `predictive_research`，避免独立维护第二套只按行号切分的 holdout 产品。宽表、秩亏、极端尺度和 alpha=0 的支持策略必须明确。

测试入口：`tests/test_native_ridge.py`；独立 SVD/解析小例；交换单位、改变测试后缀等性质测试；训练参数不能被未来/测试数据改变。自动调参 **M1b** 另设训练内交叉验证，不碰最终测试集。

### Q1：离线组合回放

输入：带可获知时间的冻结信号/权重、对应收益期间、初始资金、费用和再平衡假设。首版只声明实现真正支持的 long-only/现金/模拟成交范围。

输出：逐期持仓、现金、成交名义量、费用、收益和净值，回撤/风险摘要，完整假设与数据版本。资金费、借券成本、滑点、交易费未实现时明确标示不适用或未建模，不默认为零然后声称已扣齐所有成本。

时间规则必须防止用该期收盘后才知道的信号在同一期间获得收益。独立有理数会计 oracle 检查现金/资产/费用恒等式；未来权重或收益变化不得回写历史结果。组合回放不等同于盘口成交模拟，不能证明实际能成交。

首版校验 signal_time < execution_time < end_time 和期间连续性；输入者给出的时间戳不能证明数据在历史上确实可得。保留 `supplied_values_order_only` 与 `source_vintage_verified=False` 等真实状态，在 GUI、报告、Agent 摘要中显示。历史时点数据版本验证作为独立后续门，未通过时不能声称消除了全部前视偏差。

测试入口：`tests/test_native_quant_replay.py` 和同一 workflow 的实际产物；浏览器显示假设、扣费前后结果、账本下载与重开。

## 4. 产品与 Agent 的故障矩阵

| 触发 | 期望行为 |
|---|---|
| 同一提交的网络重传/确认两次 | 同一幂等键返回同一合法 run/attempt，不执行两次；指纹不作为跨执行意图的去重键 |
| 用户明确要求重新运行同样参数 | 建立新执行意图和新 attempt，保留旧结果；缓存复用必须显式记录 |
| 用户关闭窗口 | 运行按既有后台规则继续；重开恢复同一 run/attempt |
| 计算已完成，HTTP 响应丢失 | 从 receipt 和结果恢复，不能重新计算/重复提交副作用 |
| domain effect 已提交，图投影未写完 | 对账并修复投影，不能回滚成“从未执行” |
| 取消与完成同时发生 | 有确定状态规则；取消未完成不显示已停止；不会发布半成品成功节点 |
| 租约到期，但旧进程仍在运行 | fencing 拒绝旧 owner 再提交；新 owner 先对账，不双执行 |
| 失败后改参重试 | 新 attempt 链接旧失败；重新校验参数、plan/version、来源指纹和权限；改参使旧预览/确认失效，不继承单次高风险授权；旧终态不原地改回 running |
| 事件重复、乱序或缺失 | 按稳定序号恢复；必要时重新取快照，图与 journal 一致 |
| 文件/数据在批准后改变 | 源指纹重校验，拒绝使用旧批准执行新内容 |
| 原生库缺失或不兼容 | 清楚提示；仅合同允许的回退才可发生，并记录实际引擎与原因 |
| 原生自检或数值输出失败 | 保留失败，不能把参考引擎跑通当作本次原生成功 |
| Agent 引用错误结果/编造数字 | 完成门拒绝，读取绑定 producer 的真实结果后再说明 |
| 自定义能力未通过 admission | 保持原权限/沙箱，不为满足 GUI 覆盖绕过准入 |

图必须区分“计划中的执行节点”和“实际生成的数据/模型节点”；用稳定 ID 连接两者，不能预先制造看似已完成的结果。

图状态至少覆盖：待计划/等待确认/排队/依赖阻断/运行/停止中/等待对账/恢复中/完成/失败/已取消。等待确认可审阅与确认，依赖阻断可查看上游，运行可请求停止，对账中禁止盲目重放，失败可查看证据并发起新的修正尝试。后端状态与图形映射建立逐项 fixture。

取消验收沿用已批准长计算 ≤2 秒门，在声明工作量域证明信号确实进入原生计算、辅助线程退出、原异常传回，返回后不再发布新产物或持续写文件。冷加载、自检及不可抢占调用如未覆盖须单列，不用 Python 提前取消冒充原生计算取消。

## 6. 后续任务卡固定字段

| 字段 | 必填内容 |
|---|---|
| identity | 稳定 task ID、所属 release/line、parent、attempt、owner/session |
| lease | token/epoch、expires_at、last_heartbeat、host_id、session_id、pid/进程启动时间；提交带当前 revision 与租约身份 |
| authorization | 本次用户指令/既有 objective 的具体授权和仍适用限制 |
| baseline | 完整 SHA、共享合同版本、必要输入摘要、交接状态 |
| scope | 精确允许/禁止路径；共享文件 owner；受保护例外 |
| dependency | 所需任务及其具体通过证据；可并行部分 |
| deliverable | 用户能完成的操作；对应模型/operation ID；实际产物 |
| numerical_contract | 方法定义、参考实现、适用域、分指标误差与失败条件 |
| verification | 本地测试、独立验证、浏览器、Agent、资源门，各自命令/证据路径 |
| lifecycle | ready/claimed/implementing/verifying/reviewing/integrated/accepted，或具体阻塞类 |
| handoff | patch/commit 身份、已通过与未通过、日志、下一动作、恢复方式 |

任务卡存储与正式 FMS 分离：卡用于协调，关键 FAILURE/ERROR/GAP/REVIEW/GATE/STATE_CHANGE 经正式 CLI 单写入版本线。版本关闭前执行 verify 与重新生成 retrospective；不能用初始旧 retrospective 里的“无失败”代表当前状态。

首期运行队列规划使用当前版本工作树 `local/development-queue/v1-9-1/queue.json`，协调者单写、原子替换，保留 schema_version/revision/摘要；恢复前与实际会话和进程核对。该队列尚未部署，不能以本文存在就声称无人值守调度已在运行。
