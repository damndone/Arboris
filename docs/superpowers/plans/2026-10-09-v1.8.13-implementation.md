## 手动合同接入摘要（供 v1.9.0 使用）

本线新增六个 HTTP 操作：`GET /operations`、`POST /operations/run`、`GET /runs/{run_id}/manual-reports/draft`、`POST /runs/{run_id}/manual-reports`、`GET /runs/{run_id}/manual-reports`、`GET /runs/{run_id}/manual-reports/{report_id}/export`。生成类型为唯一前端文件改动。所有项目接口仍传 `project_root` query。旧 HTTP 类型本批生成 diff 为 640 insertions / 0 deletions。

操作请求示例（实际 id 从图/目录读取，示例标识不是已有数据）：

```json
{"request_id":"manual-summary-1","mode":"preview","target":{"kind":"dataset_node","run_id":"RUN_ID","node_id":"stage:source","artifact_id":"raw_dataset"},"steps":[{"step_id":"summary","operation_id":"statistical.explore","spec":{"operation":"summarize","selected_columns":["income"]}}]}
```

响应返回 `preview_id`、`fingerprint`、`revision`、`confirmation_required`、`status`、`steps`。确认只传 `request_id`、`mode: "confirm"`、服务器返回的 `preview_id` 与 `fingerprint`；不能重传 target/steps 改写已固定计划。纯读取允许 `execute`；修改会要求确认。结果引用按 `run_id` 与 `artifact_id/node_id` 返回，多步失败保留逐步状态。request_id 复用同语义返回原结果，不同语义或 adapter 来源冲突 409。

报告：先 GET draft 获得 `source_fingerprint`、`facts[].id` 与 `figures[].artifact_id`，POST 用户自选的合法 `mrpt_…` id、title、text、所选引用（可选 parent_report_id）。用户只能改正文/标题/选引用，不能上传替代数值；保存与导出重新检查证据。历史记录作者 user、draft_origin deterministic，不冒充模型。导出 html/docx/tex/pdf-print。

目录覆盖 live 注册身份及专用入口，未配置模型也可读；graph.fork 的原专用路由与 analysis-loop 手动提案不再构造模型适配器。模型创建按声明确认；自定义能力指向 Notebook 既有 confirm-and-execute，必须有 admitted binding 与 trusted gateway。GET 当前只预检 dataset source 归属，返回 needs_parameters；模型/上传目标与具体参数、列和执行准入在 POST preview 验证。复杂嵌套声明保留 JSON object/list 控件，不宣称前端全表单已完成。UI 点选验收需 v1.9.0 明确采用合同后另验。
