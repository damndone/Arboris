# v1.8.9 P0 Evidence/Report Hardening remediation-7 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Wire the real server-owned Report admission into the orchestrator-to-ReportStage path and fail closed before ARMA-GARCH raw deliverable construction when admission is missing.

**Architecture:** Keep the existing exact-object owner/projection admission as the only ReportStage capability.  The orchestrator will adapt an already server-owned persistence/receipt into an issued projection before it invokes the traced pipeline, placing the exact pair in `ctx.artifacts`; ReportStage will run one admission gate before selecting either the standard or ARMA report builder.  If the production seam is in `backend/workbench/orchestrator/__init__.py`, the formal line will be explicitly rescoped to that exact file before the implementation edit.

**Tech Stack:** Python 3, pytest, FastAPI/Workbench orchestration services, formal `scripts/devline_control.py`, SHA-256/diff checks.
