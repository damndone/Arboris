# v1.8.8 Planner Evaluation and Quality Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use inline TDD execution with the formal devline `v1-8-8-planner-evaluation-quality`. Every production change must follow a red-green-refactor cycle and every material gate must be appended through `scripts/devline_control.py`.

**Goal:** Add a declaration-derived planner evaluation layer, a successful Hurdle negative-binomial generic workflow fixture, declaration-checked P7 handler maps, and focused warning cleanup without weakening fail-closed or provenance contracts.

**Architecture:** The evaluation package is test/benchmark infrastructure only. It projects live `CapabilityContract`, operation, workflow-step, schema, and artifact declarations into ordinary-language cases, then scores typed outcomes from the existing Notebook composition or Chain/Node direct seam. Production planner code gains only the closed typed refusal terminal needed to distinguish a deliberate refusal from provider failure. Hurdle and P7 changes stay inside their existing pack/runtime seams; warning fixes are limited to Workbench-owned call sites.

**Tech Stack:** Python 3, pytest, pandas/statsmodels/scipy, existing Workbench typed proposal and workflow contracts, TypeScript/React/Vitest, JSONL benchmark evidence, formal devline CLI.
