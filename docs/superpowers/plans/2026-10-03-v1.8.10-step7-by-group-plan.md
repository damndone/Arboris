# v1.8.10 第 7 步：按组执行组合子（计划）

依据：objective 第 7 步、设计文档 §3.5“按组分别执行”。

## 架构

- 组合子核心 `backend/workbench/combinators/by_group.py`：
  - 分组：显式的分组列；缺失值自成一组 “(missing)”；组按取值排序；默认最多 50 组，超过就拒绝，并建议改用交互项或多层模型。
  - 子集语义按能力声明：`subset`（先筛选再分析）、`domain`（复杂抽样的域估计：保留全部数据，只把本组标为子总体）、`unsupported`（拒绝）。模型族在有抽样设计时一律走 `domain`；没有设计的族走 `subset`。
  - 样本不足：门槛从检查库的 CheckSpec 读取（每个参数至少 10 行；二元结局每个参数至少 10 个较少类事件）。低于门槛的组标为“无法估计”，写明行数、参数数、门槛与出处，不做拟合。拟合失败的组同样标为“无法估计”，并附原因。
  - 开放清单 `BY_GROUP_OPEN`：只有声明了子集语义、并且通过通用不变性测试的能力才开放。
  - 跨组多重比较校正：Holm 与 Benjamini–Hochberg，对各组同一项检验的 p 值做校正。
- 输出：集合信封（第 1 步的 `workbench.result_collection.v1`），每组一个成员。写在 `model_results/collections/` 下，不放进 `model_results/*.json`，因为有读取者会把那里的每个文件都当成结果。
- 模型（OLS、logit、probit、Poisson）在运行内执行：运行请求带 `by_group: {column}`，估计阶段对每组调用该族自己的拟合，结果 id 为 `<模型>_g01` 等，每组都有自己的结果和推断核心（每组都可以单独做后估计）。报告回归表与表格视图本来就支持多模型并排。
- 组间差异检验（复用第 2 步）：在合并样本上加入分组与全部自变量的完全交互（生成实际的交互列，用同一族的拟合与协方差，包括抽样设计），对推断核心做 Wald：(a) 所有交互项联合为 0（各组系数整体相同）；(b) 每个自变量与组的交互联合为 0（该自变量的作用在各组是否相同）。自变量含分类项时，第一版不提供这项检验，写明原因。
- 统计检验（描述统计、t 检验、卡方、相关）：Agent 的 `test.<族>` 工作流步骤加可选字段 `by_group`，对每组子集分别运行，结果附跨组 Holm/BH 校正后的 p 值。
- 台账：每组的每项检验都计入推断检验数，报告披露的检验数随之增加。
- Agent：
  - `model.genesis` 加 `by_group` 字段；说明文字从开放清单生成。
  - 系数投影带分组信息与组间差异检验。
  - 数字核对增加一条检查：结果里有组间差异检验时，回复若出现组间比较的说法（不同、更大、更高……），必须引用这项检验的统计量或 p 值；不合格就退回模型改写。

## 子步骤

1. 7a 核心 + 模型按组（subset）+ 集合信封 + 显示 + 不变性测试（OLS、logit、probit、Poisson）。
2. 7b 组间差异检验（交互项 + Wald），对照 R（`anova` / `car::linearHypothesis`）。
3. 7c 抽样设计下的域估计，现场对照 Stata `svy: regress …, subpop(if g == k)`。
4. 7d 统计检验按组 + Holm/BH + 台账计数。
5. 7e Agent 字段、投影、数字核对扩展。
6. 7f 浏览器验收三个场景，提交。

## 结果（2026-10-03）

### 实现与对照

- 7a 模型按组：OLS、logit、probit、Poisson。每组用该族自己的拟合函数，结果 id 为 `ols_1_g01` 等，各有自己的推断核心。缺失值自成一组；低于检查库门槛的组列为“无法估计”，写明行数、参数数和出处；最多 50 组。通用不变性测试：四个族的每一组都等于“先筛选再单独运行”（系数、标准误、p 值、区间、协方差矩阵，1e-9）。集合信封里每组的 nobs 是模型实际使用的行数（浏览器验收发现最初记成了组的总行数，已修）。
- 7b 组间差异检验：合并样本 + 分组与全部自变量的完全交互，同一族、同一协方差，对推断核心做 Wald（所有组项；每个自变量的交互项）。四个族都与 R `car::linearHypothesis` 一致（OLS 用 HC1 + F，其余用卡方，1e-6）。自变量含分类项时，这项检验暂不提供，并写明原因。
- 7c 抽样设计下的域估计：每组保留全部行，用指示列声明为子总体（与已有的 subpop 取交集）。每组的系数、标准误、设计自由度与现场运行的 Stata `svy, subpop()` 一致；差异检验的 Wald 统计量 W 与 Stata `test` 一致。设计方差只对 OLS 实现，其他族在有设计时按组执行会被拒绝。
- 7d 统计检验按组：`test.t_tests`、`test.chi_square`、`test.correlations` 加 `by_group` 字段，并通过不变性测试；每项检验附跨组的 Holm 和 BH 校正 p 值（与 R `p.adjust` 一致）。`statistical.explore` 的 `group_by` 改由组合子分组：缺失值成组，最多 50 组。
- 台账与披露：步骤按实际检验次数计数（`LedgerStep.tests`，由步骤的 `row_counts.ledger_count` 上报）；报告披露在生成时读取运行的集合信封，按已估计组数计入模型分析数，因此界面、Agent、Notebook 各条路径都一致。
- Agent：`model.genesis.by_group` 字段，说明文字从开放清单生成；与多重插补同用、分组列也是模型变量、未开放的族，都在计划阶段拒绝。Agent 读的三份投影（结果摘要、系数查询、检验结果）都带组名、无法估计的组和差异检验。检验结果改用专门的紧凑投影：通用预算原来会整组丢掉（缺失组那一行最先被裁）。数字核对新增“组间比较”检查。

### 顺带修复的已有缺陷

- 单次运行声明子总体（subpop）时，结果包里的系数是全样本的，标准误却是子总体的（v1.8.7 起存在；对照 Stata：0.5992 对 0.9150）；R² 等也来自全样本。现在点估计取设计引擎在子总体上的估计，与 Stata 一致；全样本的拟合统计量不再报告。
- 抽样设计下的多约束 Wald 检验改用 Korn–Graubard 调整的 F（Stata 在 svy 之后的默认做法）；单个约束时结果不变。

### 浏览器验收（carData::SLID，加拿大 1994 年安大略省劳动收入调查，7425 行）

- 场景 ①：在 Notebook 里用中文请求“按 language 分组，对每组估计同一个 OLS 模型：wages 对 education 和 age”。各组系数和标准误与 R 分组回归（HC1）完全一致，样本量为 3244 / 259 / 484；缺失语言的 27 行列为“无法估计”（每个参数 9 行，低于 10）。表格视图的列标题写明组，表下写明“并排的列不是差异检验”，并列出三项组间差异检验。报告披露的模型分析数按组计入。
- 场景 ②：在按性别分组的运行上问“男女的教育回报一样吗？”。Agent 引用交互项 Wald：F(1, 4008) = 2.31，p = 0.129（R：2.3105，0.1286），结论是没有可检出的差异，并说明并排的系数和置信区间重叠都不能作判断依据。
- 场景 ③（Stata `svy, subpop()`）由自动测试现场调用 Stata 核对。
- 验收中发现并修复：
  1. Agent 把“wages 对 education、age”理解成两个模型，在单模型方案里塞进工作流的 `branches`；规划校验没有拒绝未知字段，物化时才失败。现在规划和物化共用同一份允许字段清单 `NOTEBOOK_GENESIS_MODEL_PARAMS`，未知字段在规划阶段就退回，并说明原因。
  2. 按组方案的预期产物仍是 `ols_1`，而按组运行不产生它。现在改为 `by_group_collection`，并在产物词表里登记（规划和选项服务共用 `by_group_artifact_types`）。
  3. Genesis 草稿的参数清单里没有 `by_group`，物化时报 `NON_EDITABLE_PARAM`。
  4. 表格视图的回归表不显示组名、无法估计的组和差异检验。
- 记下未修的模型措辞问题：Agent 说 Holm 校正后“该值不变”，含糊不清（Holm 校正后为 0.129，等于原始 p）。

### 待决定

- 抽样设计下系数 t 检验的自由度：现在沿用 R `survey`（设计自由度 − 参数数 + 1，v1.8.7 的对照）；Stata 用设计自由度（PSU 数 − 层数）。两者相差“参数数 − 1”，系数和标准误不受影响。
