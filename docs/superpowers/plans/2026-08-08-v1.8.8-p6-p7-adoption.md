# v1.8.8 P6/P7 Capability Adoption Plan

## Goal

Adopt every statistical capability present in the frozen P7 source into the
P3 Workbench seam. A capability is complete only when its typed request is
declared, visible to every Agent consumer, admitted by the reachability
inventory, routed through the generic workflow executor, and proven to execute
successfully on a bounded fixture. The final browser and human natural-language
workflow remains a later P7 acceptance gate.

## Non-negotiable boundaries

- P3's `WorkflowStepContractRegistry` remains the declaration source for
  workflow admission and all compatibility projections. No second inventory
  or hard-coded pack-ID list may be introduced.
- Pack capabilities are composable workflow steps. They are not top-level
  proposals unless a separate live declaration explicitly enables that surface;
  `top_level_exposure_note` must remain distinct from reachability exemptions.
- `proposed_by=()` plus `composable_as=(operation_id,)` is valid only when the
  `operation.multi_step` route actually exposes and executes the step.
  Reachable pack capabilities must not carry an exemption reason.
- The existing four-way orchestrator dispatch is not extended with one branch
  per statistical operation. One generic, declaration-driven pack dispatcher
  and typed adapter registry is the only new runtime seam.
- Frozen P7 numerical code is copied selectively from the source; source-side
  deletions and changes to P0/P1/P2, shared stages, report plumbing, survey
  mathematics, frontend, and Agent foundations are not merged.
- Runtime code remains free of R, shell, `eval`, `exec`, dynamic imports,
  formulas, callbacks, arbitrary paths, and Agent-generated code. External
  oracles remain test-only.
- A missing adapter or unsupported input shape is a loud, stable rejection;
  it may not fall through to a different operation, drop a frame, or return a
  successful-looking empty result.

## Architecture

1. Selectively bring the frozen P7 contract and pack modules into the P6
   worktree and prove that their existing focused tests still pass on the P3
   foundation.
2. Add a typed P7 pack-adapter registry. Each pack family owns its adapter
   declarations, while the registry derives the complete operation set from
   the frozen contract collections and checks that every declared ID has one
   handler, one input mode, one result validator, and one bounded column
   extractor. The registry is the only operation-to-handler lookup.
3. Generate `StepSpecContract` entries from that registry. Frame-native packs
   consume a resolved `step_frame`; non-frame packs use an explicit typed
   payload adapter or declare `consumes_input_frame=False`. The editable schema
   remains closed and operation-specific enough for a planner to produce a
   valid request.
4. Add one generic workflow-runtime dispatch key for P7 packs. It validates
   the typed request, calls the registered adapter, validates the frozen result
   envelope, and persists a bounded result artifact with source/step
   provenance. It never mutates a dataset unless the adapter's declaration says
   so; P7 packs in this line are read-only statistical evidence.
5. Verify the three vocabulary consumers, OperationRegistry, capability
   inventory, P2 reachability truth, workflow execution, and result projection
   together. A new declaration injected in a test must appear automatically;
   replacing the derived projection with a pre-injection constant must make the
   same test fail.

## Required mutation evidence

Every new assertion needs an anchored behavior-changing mutation. At minimum:

1. Remove one generated enum and show the exact schema assertion fails.
2. Replace registry-derived operation projections with a pre-injection tuple and
   show the injected operation is absent from all three vocabulary consumers.
3. Change a pack inventory entry to `data_operation` and show the expected
   `pack` assertion fails.
4. Remove one adapter or change its dispatch key and show the exact operation
   fails closed rather than executing another handler.
5. Change result artifact provenance or envelope validation and show the
   corresponding integration test fails.

Each harness must first assert its anchor exists, assert the file hash changes,
prove the mutated behavior actually differs, print the real pytest error, then
restore the original bytes/hash and rerun the green test. A no-op mutation is
not evidence.

## Explicitly not claimed by this plan

- Browser UI acceptance, host-device Agent conversation, proposal freshness
  against a newly typed natural-language message, and the final human chain
  are P7's later acceptance boundary.
- This line does not add new statistical methods or change the frozen P7
  estimands/limitations. It only makes the already-frozen operations callable
  through Workbench's typed Agent seam.
- Full release, merge, push, tag, and publish remain unauthorized.
