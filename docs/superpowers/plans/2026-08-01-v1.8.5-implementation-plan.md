# v1.8.5 实施计划：Typed Memory 与模型族契约

> 范围权威：`docs/superpowers/specs/2026-07-31-v1.8.5-typed-memory-and-model-family-design.md`。本文件只描述实施顺序与验收证据；不扩展版本范围。

## 目标与边界

交付两条彼此独立、最终在 Notebook/Agent 汇合的能力：

1. 使被批准的跨项目记忆能以受控的 `suggest_default` 改变**待确认**的 typed proposal 默认值，同时保留来源、失效降级与 gate 可见性。
2. 以 `ModelFamilyContract` 取代 workflow 的 OLS 特例，让既有 `cs_did`、`sa_did`、`dcdh` 通过 typed workflow 到达 Notebook、Draft、执行和结果展示。

不新增估计器、不改变现有估计器数值、不加入语义/向量检索、不允许记忆执行代码或绕过 Proposal/Risk 确认。

## 执行顺序

### 1. 模型族契约核心（纯重构）

- 在 `backend/workbench/agent/workflow_contracts.py` 定义不可变的 `ModelFamilyContract` 注册表，并将 `model.genesis` 的字段/分支校验委托给契约。
- 在 `backend/workbench/agent/workflow_runtime.py` 将每个分支执行收敛为：查契约 → 验证 spec → 构造参数 → 执行 → 按声明的 artifact/result-shape 准入。
- 先为 `ols`、`panel_ols` 编写回归测试，证明原参数、残差诊断、CI 准入和 Panel FE/Dummy-FE 的 `1e-8` oracle 不变；再改生产代码。
- 验证：`tests/test_workflow_runtime.py tests/test_panel_covariance.py`、golden 23 的 0-drift。

### 2. DID 工作流准入

- 为 `cs_did`、`sa_did`、`dcdh` 声明各自所需的 entity/time/cohort 或 treatment-path 参数、已注册的主 artifact、以及 effect/event-study result shape。
- 在 `workflow_contracts.py` 与 `agent/notebook/planning_agent.py` 明确拒绝缺字段或错误字段，并给出可执行的下一步；不退化为 OLS。
- 在 `agent/notebook/materialization.py` 以模型族契约验证和写入参数，避免 OLS 专用 normalize/字段规则误套到 DID。
- 测试先行：每族各一条 composed workflow → typed option → 确认 → 执行 → Table/Report 可发现的验收；另加“DID 被当作 coefficient intervals”与“EventStudyBundle 被要求 CI”两条拒绝测试。
- 验证：`tests/test_workflow_runtime.py tests/test_did_runner.py tests/test_did_wiring.py tests/test_cs_did_wiring.py tests/test_notebook_planning_agent.py tests/test_notebook_routes.py`，以及 golden 23 0-drift。

### 3. Typed Memory 契约与兼容读入

- 在 `backend/workbench/domain_memory/contracts.py` 为内容 revision 增加 `project_domain_fact`、`apply_mode`、`vocabulary_version`、`verifier`、`last_validated_at`。
- 新的写入采用 content contract v2；读取现有 v1 journal 时映射为安全默认：`inform_only`，且没有 verifier 时不能影响默认值。旧持久化不会被重写。
- `MemoryCandidate`、`DomainMemoryService.approve_candidate` 和前端 contracts/API 同步传递新增字段；默认关闭，候选/批准仍需用户明确操作。
- 测试先行：v1 读取兼容、v2 hash/字段完整性、未注册 apply_mode/verifier 拒绝。

### 4. 记忆作用面与来源不变量

- 将 runtime retrieval 输出扩展为可审计的 `apply_mode`、词汇表、验证状态和降级理由。
- 为 Notebook proposal 构造添加一个严格的 default-application boundary：
  - `inform_only` 绝不修改字段；
  - `suggest_default` 仅能修改契约允许且当前 evidence 已验证的默认字段；
  - 每个被修改字段都写入 `memory_id`/`revision` provenance；来源不完整即拒绝；
  - 不接触 evidence、admission、排序、authorization 或 validation bypass。
- 前端在 Draft/Notebook 显示“来自记忆的建议”及其 revision，但不制造第二套确认按钮。
- 测试先行：所有不变量、来源缺失 fail-closed、现有记忆默认无效果、用户确认仍不可跳过。

### 5. 双层有效性执行者

- `retrieve_domain_memory` 在返回前执行：过期、词汇表不匹配 → omission；验证已超窗口 → 保留为 `inform_only` 并标出降级原因。
- `scripts/gate.sh` 添加不阻塞 preflight，列出已批准记忆的即将过期、过期、缺 verifier 与验证过期项；产品 correctness 仍只依赖 runtime fail-closed。
- 测试先行：每种 omission/降级和 gate 输出都先在未实现时失败；过期项不得让 gate 失败。

### 6. 集成、浏览器与收口

- 用本机 Workbench 做真实 Notebook 流程验收：memory provenance 可见且需要确认；三类 DID 均可提交并展示自己的结果包。
- 运行有界回归、前端测试、TypeScript、golden，再在非嵌套 Seatbelt 环境停止 Vite 后运行 full gate。
- 通过 CLI 为每个 material failure/gate/state change 追加 FMS 事件，最后 `verify --all`、`index --all`、生成 retrospective；更新现有 release notes/BACKLOG/handoff，不新建零散说明文档。

## 证据纪律

- 每项生产行为先添加会失败的测试，保留失败输出；实现后重跑相同测试。
- 任何“已有行为”按 verified-preexisting 记录，不把旧测试当作本版修复。
- 结论区分：实现并测试、浏览器验收、完整 gate、发布状态。未做的项保持 `NOT VERIFIED`。
