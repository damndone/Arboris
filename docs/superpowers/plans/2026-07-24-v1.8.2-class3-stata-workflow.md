# Feature Name

v1.8.2 Class 3 statistical exploration and OLS diagnostics workflow

# Goal

Deliver the complete Class 3 workflow in Workbench v1.8.2: Raw Data node
exploration with bounded AND filters; year-wise descriptive statistics;
missingness and pooled correlation; detailed summaries and typed percentile
group definitions; scatter plots; reuse of the existing OLS model path with
visible sample size and confidence intervals; residual/fitted diagnostics; and
durable transcript, HTML, PDF, and XLSX report artifacts.

The workflow must be usable from the Raw Data node before a model is chosen.
It must keep Graph/RunFamily/Draft/Run/Artifact as the sources of truth. A
statistical exploration is a read-only typed operation over a fingerprinted
dataset context; it is not a second execution state and it must not mutate the
raw dataset or silently execute arbitrary Python. Existing OLS execution is
reused; no new regression engine is introduced.

# Architecture

1. Add one backend statistical-exploration service and typed HTTP route family.
   The service resolves the source artifact through the existing data-node
   binding rules, validates a typed operation spec, applies all filters as an
   ordered AND predicate, and computes deterministic pandas/statsmodels-free
   exploration results. It persists an immutable JSON result plus a compact
   transcript under the source run's durable artifact area, keyed by the
   source SHA, operation spec, and result schema version. Repeated requests
   with the same fingerprint reuse the same artifact; a changed source or spec
   yields a new artifact.
2. Extend response-time dataset decoration so Raw Data nodes advertise the
   available exploration artifact records without rewriting graph.json. The
   frontend resolves the artifact identity from the decorated node, never from
   display text or an Agent response.
3. Add the Raw Data detail section under a new “Statistical exploration” group.
   The section owns filter rows, operation selection, variable selection, and
   result tabs. Filter rows are typed from the source schema and can be added,
   removed, and combined with AND. The UI shows exact row counts and missing
   policies for every result.
4. Add typed derived-variable requests for p25/p75 thresholds. The derived
   definition stores source artifact fingerprint, source column, percentile,
   threshold, and comparison direction. It is revalidated on each execution;
   stale definitions are retained and shown as stale rather than silently
   changing. Derived variables remain data-operation artifacts suitable for a
   later OLS Draft.
5. Reuse the existing OLS Draft/model route and result normalization. The
   exploration panel can hand a bounded filtered context and selected typed
   columns into the existing OLS form, but it does not run a model implicitly.
   The existing normalized OLS result contract is verified and extended in
   place only to expose finite-sample N, coefficient 95% confidence intervals,
   residuals, and fitted values as already-produced model artifacts.
6. Reuse the existing visualization, report view-model, report HTML, PDF, and
   XLSX export seams. Exploration results and model diagnostics are added as
   typed sections/artifacts; raw data and full artifacts are never copied into
   global Agent context.

# Tech Stack

Python 3, FastAPI, Pydantic, pandas, NumPy, statsmodels (existing OLS path),
matplotlib (existing visualization path), Jinja2, reportlab, React, TypeScript,
Vitest, pytest, the repository's existing `gate.sh`, and the in-app browser.
