# Workbench v1.8.9 P0 Agent Compiler Core Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 建立从研究意图到服务器编译工作流的可信边界，让 Agent 能自由组合全部已准入能力，但不能伪造 identity、权限、风险或执行授权。

**Architecture:** 从 Contract Lock C0 消费只读 planning/Port/Failure/Provider contracts，在现有 registries 外侧增加 path-aware Manifest/Descriptor、typed AnalysisIntent、server compiler、CompilationRecord store 和 shadow-equivalence kernel。Provider/Notebook/orchestrator/routes/runtime cutover 后置给单一 Cutover line；本线只产出可独立测试的 core 和 package-local provider refs，不修改共享执行控制面。

**Tech Stack:** Python 3.14 dataclasses、JSON canonical hashing、FastAPI、pytest、现有 Agent Core/Orchestrator/Notebook planner/workflow contracts。

- [ ] **Step 2: 实现 FailureEnvelope**

字段固定为 failure class、stable reason code、capability/step identity、evidence refs、retryable、safe remediation choices、confirmation requirement、partial outputs/trust。mutation 不可自动 retry；同一 plan 无新证据不得无限重复。

- [ ] **Step 3: 实现 compile pipeline**

固定顺序：schema validation → descriptor/full-contract resolution → server source/column binding → DAG/port compatibility → preconditions/freshness → risk/resource budget → canonical existing workflow projection → PlanDiff → CompilationRecord。

`semantic_plan_hash` 基于用户确认的 canonical methods/options/source commitments/contract/catalog/policy snapshot，不包含时间戳、provider prose 或尚未解析的执行 identity。`execution_instance_hash` 在上游完成后加入服务器解析的真实 run/node/artifact digest；两者都调用 `sha256_canonical()`，不实现第三套 canonical JSON。

- [ ] **Step 4: append-only CompilationRecord authority**

`compilation_store.py` 只由 server compiler 写入 CompilationRecord；绑定 principal/project、semantic hash、PlanDiff、contract/catalog/policy snapshot 和 source commitments。module-private constructor、客户端 marker 或回传完整 CompiledWorkflow 不构成 authority。Cutover route 未来只接受 `compilation_record_id + confirmation_ref`；本线用 store API 测试此边界，不修改 route/runtime。
