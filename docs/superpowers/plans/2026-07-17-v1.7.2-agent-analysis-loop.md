# v1.7.2 Agent Analysis Loop Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 在一个已成功完成的 OLS source run 上，完成 `inspect → diagnose → PlanDiff → confirm → child rerun → ValidationPacket → ComparePacket → explain` 的确定性、可恢复、可审计闭环。

**Architecture:** 先在后端新增独立的 `analysis_loop` 确定性域，负责 source/cluster/target preflight、canonical hash、fingerprint、packet 持久化、验证、比较和结论分类；现有 Agent 只提交不可信 intent，并读取这些结构化结果。`model.rerun` 继续复用 v1.7.1 的 proposal/confirmation/claim/lease/effect/commit/reconcile 生命周期，Analysis Loop 只在 canonical proposal 和 child 生命周期边界挂接，不绕过现有执行状态机。

**Tech Stack:** Python 3、FastAPI、Pydantic、pandas、statsmodels、现有 JSON/JSONL append-only stores、React、TypeScript、Vitest、pytest、现有 `scripts/gate.sh`。
