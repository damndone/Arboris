# v1.8.1 前置项 1 — RunFamily 升为一等身份 · 实施计划

> Spec：`specs/2026-07-22-v1.8.1-agent-notebook-analysis-option.md` §2.3、DEC-NB-002。
> 范围：**只做 RunFamily**。Notebook 与 Option 对象不在本计划内，等本计划落地后另出。
> 前置：无。本计划是 v1.8.1 其余所有工作的前置。

## 为什么先做这个

`run_family_id` 目前是**派生**的：`agent/chains.py: legacy_family_anchor()` 调
`scan_family()` 找到根 run，拼成 `legacy-family:<root_run_id>`。这满足不了
DEC-NB-001 的"Notebook 可以先于任何 Run 存在"。

而且它涉及**迁移既有数据**——顺序错了会让历史 run 读不出 family。因此单独成计划、
按序执行，而不是和 Notebook 混在一起。

## 验收步骤的写法约定（本计划强制）

> 上一份 `v1.8-deliverables-closeout-plan.md` 的 Task 1 Step 1 写的是
> "an XLSX workbook with the eight named non-empty sheets"。这条**通过了**，
> 而其中三张表仍然不可用——`Rolling forecasts` 只有 18 列里的 2 列。
> **"存在"和"非空"是会被字面满足的验收。**

因此本计划的每一步验证必须断言**具体内容**，不得只断言存在性：

- ❌ "family 记录已创建" → ✅ "family 记录的 `run_family_id` 等于 `<具体值>`，
  且 `legacy_anchor_run_id` 为 `<具体 run>`"
- ❌ "迁移后 id 不变" → ✅ "迁移前后对同一 run 调用读取路径，返回的字符串
  **逐字节相等**（`assert before == after`，不是 `startswith`）"

## Task 1：RunFamily 持久化实体

**目标**：一个可以先于任何 run 存在、身份不编码 run 的 family 记录。

**契约**：

```
RunFamily
---------
run_family_id        str   新建为 run-family:<uuid>；旧数据保留 legacy-family:<root_run_id>
project_id           str
created_at           str
created_by           str
origin               enum  notebook | run_adoption | legacy_migration
legacy_anchor_run_id str?  仅旧数据
```

- [ ] **Step 1: 写失败测试**：新建 family 后，`run_family_id` 匹配
      `^run-family:[0-9a-f-]{36}$`，**不含任何 run id 子串**；`origin="notebook"`；
      `legacy_anchor_run_id is None`。再断言同一 project 连续建两个 family 得到
      **不同** id。
- [ ] **Step 2: 运行** `pytest tests/test_run_family_store.py -q`，确认失败原因是
      模块不存在，而非断言写错。
- [ ] **Step 3: 实现** `workbench/lineage/run_family.py`：`RunFamilyStore`，
      沿用既有 JSONL append-only 约定（同 `agent-sessions/`、operation records），
      落在 `workbench/run-families/<run_family_id>.jsonl`。
- [ ] **Step 4: 实现 `create_family()`**，`origin` 必填。**禁止**从任何 run 参数
      推导 id——测试须证明函数签名不接受 run id。
- [ ] **Step 5: 运行聚焦测试**并确认通过。

## Task 2：run ↔ family 成员关系持久化

**目标**：新建 run 的 family 归属被**写下来**，不再事后推导。

- [ ] **Step 1: 写失败测试**：新建 run 时传入 `run_family_id`，从
      `run_manifest.json`（或成员索引）读回的值与传入值**逐字节相等**；
      并断言此路径**未调用** `scan_family()`（用 monkeypatch 让 `scan_family`
      抛异常，若被调用则测试失败）。
- [ ] **Step 2: 运行**聚焦测试，确认当前实现会调用 `scan_family()` 而失败。
- [ ] **Step 3: 实现**成员关系持久化，写入 run 创建路径。
- [ ] **Step 4: 实现读取优先级**：
      ```
      persisted 存在  → 用持久化值
      persisted 缺失  → legacy_family_anchor() 计算，记兼容性告警
      新建 run 无 persisted → 拒绝（RUN_FAMILY_REQUIRED）
      ```
- [ ] **Step 5: 写测试钉住"fallback 不得成为新写入路径"**：对一条**新建**
      且未提供 family 的 run，必须抛 `RUN_FAMILY_REQUIRED`，**不得**静默走
      `legacy_family_anchor()`。这条是本 Task 的命门。
- [ ] **Step 6: 运行聚焦测试**并确认通过。

## Task 3：既有数据迁移

**目标**：所有历史 run 获得持久化 family 记录，且**对外可见的字符串一字不变**。

- [ ] **Step 1: 写失败测试**：用真实历史 run 目录做 fixture（**从
      `/private/tmp/wb-v18-dofile-repro` 或 examples 下的真实 run 复制，
      不手写 fixture**——见本计划开头的约定），断言：
      迁移前调 `legacy_family_anchor(run)` 得到 `S_before`；迁移后调**新读取路径**
      得到 `S_after`；`assert S_before == S_after`（逐字节，不是前缀匹配）。
- [ ] **Step 2: 写第二条失败测试**：一条 family 下有多个 run（含 rerun/fork 产生的
      child）时，迁移后**全部**成员的 `run_family_id` 相同，且等于迁移前各自的
      推导值。
- [ ] **Step 3: 运行**，确认失败原因是迁移未实现。
- [ ] **Step 4: 实现迁移**：扫描既有 run → 按 `legacy_family_anchor()` 分组 →
      为每组创建 `RunFamily`（`origin="legacy_migration"`，
      `legacy_anchor_run_id=<root run>`）→ 写成员关系。
      **`run_family_id` 沿用原字符串，不重新生成。**
- [ ] **Step 5: 实现幂等**：重复迁移不产生第二份记录、不改变任何 id。
      测试须连跑两次迁移并断言结果字节相同。
- [ ] **Step 6: 运行**全部迁移测试并确认通过。

## Task 6：收口

- [ ] **Step 1: 跑 spec §9.1 的六条验收测试**，逐条对照：
      ```
      1 无 Run 的 Notebook → family 已持久化，active_head = null
      2 首个 Option 执行  → 新 Run 继承 notebook.run_family_id
      ```

## 不做的事

- **不**创建 Notebook 对象（Task 6 Step 1 因此 deferred）。
- **不**给 `run_family_id` 加 Notebook 侧 UNIQUE 约束——
  "一 Notebook 一 family" 不反推 "一 family 一 Notebook"（spec §2.4）。
- **不**改动任何既有 run 的数值产物；golden 必须 0-drift。
- **不**删除 `legacy_family_anchor()`，只降级其职责。

## 风险

| 风险 | 缓解 |
|---|---|
| 迁移中断留下半迁移状态 | Task 3 Step 5 的幂等；append-only 不就地改写 |
| 新读取路径在旧数据上回退失败 | Task 2 Step 4 的三级优先级 + 兼容性告警 |
| family 变更意外影响数值 | Task 6 Step 3 的 golden 0-drift 断言 |
| 手写 fixture 与真实 run 结构不符 | Task 3 Step 1 强制用真实 run 目录复制 |
