# v1.7 Agent UI usability implementation plan

**Goal:** Make the existing v1.7 Agent surface operable and legible without
changing the confirmed Agent Harness architecture.

**Boundaries:** Keep one `AgentSurfaceProvider`, the Graph composer as the
only input, the bottom Agent page as a terminal projection, and the existing
provider update/refresh HTTP contracts. Do not modify adversarial review files.

## Task 1: Lock the UI contracts with RED tests

- AgentPanel renders no textarea, model selector, or context button.
- Assistant Markdown renders as elements and does not expose raw heading or
  emphasis markers.
- Pending proposal content is bounded separately from the transcript and
  confirmation remains available.
- Composer context control opens a readable popover and has a circular ring
  contract.
- App chrome removes the visible title and places theme control beside the
  Home/Workbench tabs.
- Provider model records expose display labels and request IDs; changing a
  model persists through the existing update seam.

## Task 2: Implement the Agent surface correction

- Remove the bottom-panel `AgentComposer` mount.
- Add the terminal message projection and proposal action rail.
- Reuse `frontend/src/report/markdown.tsx` for assistant content.
- Replace the decorative context button with a controlled popover and stable
  equal-size ring geometry.
- Keep status/error/event cursor visible without stealing transcript space.

## Task 3: Make LLM Settings and model selection truthful

- Use `{display_name, request_model}` records in the Agent selector.
- Make Settings model mapping editable, refreshable, and visibly successful or
  failed; add/remove model rows where the existing editor cannot do so.
- Preserve the active provider and default model contract on reload.
- Verify the connected DeepSeek provider exposes its Flash and Pro records;
  if the upstream model list does not return them, surface the exact provider
  response/error rather than silently inventing options.

## Task 4: Compact the application chrome

- Remove the visible application title from the top chrome.
- Move `ThemeToggle` into the Home/Workbench navigation row.
- Preserve mobile wrapping, keyboard access, and route semantics.

## Task 5: Verification

- Run focused Vitest/TypeScript checks after each frontend slice.
- Browser-verify light/dark themes, long Markdown, proposal confirmation,
  context popover, reload, and DeepSeek model switching when configured.
- Run `bash scripts/gate.sh --quick`; at stage close run full
  `bash scripts/gate.sh`, `git diff --check`, and protected-file checks.
