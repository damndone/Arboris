# v1.8.10 第 8 步：焦点上下文（执行记录）

依据：objective 第 8 步（`V189-DATA-TAB-AGENT-SCOPE`）、设计文档 §8.4。这是 v1.9.0“只有一个 Agent”的地基。

## 问题

- Agent 的作用范围由面板自己根据图上的选中项推断。选中的节点不属于当前运行时，它退回当前运行的头节点：在图上点选 `iv_2sls`，显示的仍是 `ols_robust`（2026-10-01 在界面里看到，场景 ④）。
- Data 页把正在查看的数据集放在自己的局部状态里，Agent 看不到；没有选中节点时就落到项目级 Agent，而项目级 Agent 只有只读工具，用户请求做描述统计时得到“无法运行分析”（场景 ③ 的死路）。

## 实现

- `frontend/src/workbench/agent/focus.ts`：`FocusRef`（类型 + id + 运行）与焦点提供者注册表，覆盖五种焦点：项目、数据集、节点、方案、报告。每种一个提供者，解析出 Agent 的角色、作用的运行、作用的节点和显示标签。以后新增焦点类型只需加一个提供者。
  - 节点：按节点所在的运行解析。当前运行包含该节点时用当前运行；否则用该节点所在运行族的头运行，标签显示为 “Run xxx · 节点名”。
  - 数据集：在指定运行里找到对应的数据集节点（如 `stage:raw`），交给节点提供者。
  - 运行栏上的 `run:<id>`：该运行的头部模型节点。
  - 森林里找不到的选中项（草稿节点）：沿用当前运行的链，不带节点，与以前一致。
- 页面声明焦点：工作台状态新增 `agentFocus` / `setAgentFocus`。Data 页在显示期间声明 `{kind: "dataset", id: <数据集节点>, runId}`，离开时清除。
- 先后顺序：在运行栏切换运行之后，旧的详情标签页不能压过新运行（已有测试固定的行为）；在切换运行之后再点选另一运行的节点，则以节点为准（场景 ④）。用“哪个最后变化”来区分；首次渲染时以运行为准。
- Agent 面板改为从注册表解析：会话角色、`chain_id`、`run_id`、上下文包、存储键和标签都来自解析结果，不再各自推断。
- 后端：创建 Agent 会话时可以带 `focus`（类型、id、运行、标签），写入会话事件，并作为一条消息告诉模型“这次对话作用于哪个对象”。

## 浏览器验收（2026-10-03，示例数据 `iv_returns_to_schooling.csv`：一次 OLS、一次 iv_2sls）

- 场景 ①：在 Data 页查看原始数据时，Agent 标签为 “Dataset · Raw input data”。问“对 wage 做描述统计”：Agent 直接在 `stage:raw` 节点上运行了只读的描述统计，无需确认，并记入分析台账。
- 场景 ②：回到图上选中 OLS 模型节点，标签为 “Current chain · ols_robust (primary)”。问“对 educ 和 age 的系数做联合检验”：在 `model:ols_1` 上运行只读的 Wald 检验，F(2, 297) = 408.1。
- 场景 ③：上面两条路径都没有出现“项目级 Agent 只读、无法运行分析”。离开 Data 页、空白画布时仍是项目级 Agent（跨运行概览）。
- 场景 ④：当前运行为 OLS 时，在图上点选 iv_2sls 节点，Agent 标签为 “Run dde8793f · iv_2sls (primary)”，会话绑定到 iv 运行的链。
