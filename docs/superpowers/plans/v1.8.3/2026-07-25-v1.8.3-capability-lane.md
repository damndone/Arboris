# Workbench v1.8.3 Capability Lane Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use `subagent-driven-development` for B0 versus CORE, then `executing-plans` for the serial Capability phases. Do not parallelize phases that share Capability Factory state.

**Goal:** Build a general, isolated, evidence-gated capability production path from sealed custom runtime through `model.custom` Notebook execution.

**Architecture:** B0 defines the model-agnostic runtime ABI and containment. CORE defines the sole trusted local profile/project identity. CF1–CF3B progressively add resolution, immutable dependency bundles, independent validation, exact implementation registration, and scoped admission. CF4 enters the existing Draft/Run/Graph/Artifact path without bypassing confirmation or inventing consumer semantics.

**Tech Stack:** Python stdlib, FastAPI, canonical JSON, append-only/content-addressed stores, existing Agent risk and Notebook contracts, React/TypeScript, pytest, Vitest.

---

## Shared lane constraints

- Package roots: `backend/workbench/custom_capability/`, `backend/workbench/identity/`, and `backend/workbench/capability_factory/`.
- Package-local trace declarations live in `capability_factory/trace_contracts.py`; Core Trace registration is deferred to Integration.
- Capability routes may be implemented and tested unmounted; `backend/workbench/app.py` is deferred to Integration.
- Shared `NotebookSurface.tsx` and `notebook.css` are deferred to Integration.
- Every formal line freezes a compact temporary objective from its phase below and supplies the exact phase path allowlist to `devline_control.py start`; no per-phase objective file is retained.
