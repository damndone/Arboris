## 1. Why this hotfix exists

V1.5.0 shipped 5 user-visible bugs that block sign-off:

1. **Forced light → dark navigation** discards V1.4 result summary and visually jars
2. **Overview tab white-on-white** under dark route shell (functionally broken)
3. **History → run_id click cannot reach Lineage tab** (regression — only the post-run auto-nav path was wired)
4. **`lastRun` lost on tab switch** — local `useState`, not persistent
5. **Lineage nodes locked** (`nodesDraggable={false}`) — prototype expectation is free-drag

These bugs were missed because the V1.5.0 browser smoke checklist (L1–L20) covered lineage canvas internals + simple visibility, **not** cross-page UX continuity or the Overview tab's appearance under the new dark shell. Process gap; smoke checklist extension is part of this hotfix.

---

## 2. Scope guardrails

**In scope**: Bug fixes for the 5 issues above. Minimum-viable changes to restore acceptable UX. No new features. No architectural refactor.

**Out of scope** (defer to V1.5.1 or later):
- Prototype-style force-directed graph engine (still React Flow + dagre)
- LeftRail, Topbar, SSE upgrade (V1.5.1)
- Multi-tab drawer, AskAI, anything from spec §17 Q1–Q6 (V1.5.2)
- "While we're here" refactors

## 3. UX decisions (pre-locked)

| Decision | Choice | Reason |
|---|---|---|
| Post-run navigation | **Stay on Submit page**; render V1.4-style result summary inline; show prominent `✓ Run completed — Open Lineage →` button | Direct response to user feedback: "看不到原本 submit 界面可以呈现的结果" |
| Dark shell scope | **`?tab=lineage` query param scope**, not route scope | Overview tab returns to V1.4 light shell (its native form), Lineage tab keeps V1.5.0 dark editorial surface |
| History → run navigation | Replace inline `selectedRunId` state with `navigate(\`/runs/${id}?project_root=...&tab=overview\`)` | Unifies History entry path with post-run entry path; both land on `/runs/:id` |
| `lastRun` persistence | `sessionStorage["workbench:lastRun"]` (same approach planned for V1.5.1 T5.1) | Survives navigation without server-side state |
| Node drag | `nodesDraggable={true}` + verify React Flow default `edgeType` renders bezier | One-line fix; physics deferred |

## 4. Fix breakdown

### HF1 — Remove forced auto-nav; render inline result on Submit

**Problem**: [App.tsx:217-231](frontend/src/App.tsx#L217) `navigate(\`/runs/${result.run_id}?tab=lineage\`)` runs unconditionally after run terminates. User loses Submit context + cross dark/light boundary.

**Fix**:

1. **Remove the `navigate(...)` call** in the Submit `handleSubmit` flow. Keep `setLastRun(result)` and `setActivity("Workflow completed")` unchanged.
2. **Embed `<RunResultView />`** below the existing Submit form when `lastRun` is set:
   ```tsx
   {lastRun && (
     <section className="last-run-result" aria-labelledby="last-run-heading">
       <header className="last-run-header">
         <h2 id="last-run-heading">Last run · {lastRun.run_id}</h2>
         <button type="button" onClick={() => navigate(`/runs/${lastRun.run_id}?project_root=${encodeURIComponent(projectRoot)}&tab=lineage`)}>
           Open Lineage →
         </button>
       </header>
       <RunResultView projectRoot={projectRoot} runId={lastRun.run_id} onError={setError} />
     </section>
   )}
   ```
3. **Owner**: FE
4. **Effort**: M (60-90 min)
5. **Touched files**:
   - `frontend/src/App.tsx` (remove nav, add inline result section)
   - `frontend/src/App.test.tsx` (update test that asserted auto-nav; add test for inline result render + "Open Lineage" button click → nav)
   - `frontend/src/styles.css` (style `.last-run-result` header)
6. **DoD**:
   - After run completes, URL stays at `/`
   - V1.4 result panel (coefficients, trust, diagnostics) renders inline
   - "Open Lineage" button navigates to `/runs/:id?tab=lineage`
   - 2 updated/new App.test.tsx assertions pass
7. **Smoke L30**: After `workbench run`, Submit page shows result summary inline; clicking "Open Lineage" enters dark view.

### HF2 — Scope dark shell to `?tab=lineage` only

**Problem**: [App.tsx:698](frontend/src/App.tsx#L698) `isLineageDetailRoute = /^\/runs\/[^/?#]+$/.test(location.pathname)` triggers dark shell for the entire `/runs/:id` route, including the Overview tab. Overview content uses light `.result-panel`/`.summary-list` styles, but inherits the dark shell's white `--label`, producing white-on-white text.

**Fix**:

1. **Change the boundary check** in App.tsx:
   ```ts
   const tabParam = searchParams.get("tab") ?? "overview";
   const isLineageDarkScope =
     /^\/runs\/[^/?#]+$/.test(location.pathname) && tabParam === "lineage";
   ```
2. **Update the className**:
   ```tsx
   className={\`workbench-shell${isLineageDarkScope ? " workbench-shell--lineage" : ""}\`}
   ```
3. **Verify** Overview tab on `/runs/:id?tab=overview` renders with V1.4 light styling (no white-on-white).
4. **Code comment** explaining the parameter-scoped (not route-scoped) decision.
5. **Owner**: FE
6. **Effort**: S (30 min)
7. **Touched files**:
   - `frontend/src/App.tsx`
   - `frontend/src/App.test.tsx` (add tests: `/runs/:id?tab=overview` has no dark class; `/runs/:id?tab=lineage` has dark class)
8. **DoD**:
   - Overview tab on `/runs/:id?tab=overview` matches V1.4 visual baseline
   - Lineage tab on `/runs/:id?tab=lineage` retains V1.5.0 dark chrome
   - 2 new App.test.tsx assertions pass
9. **Smoke L31**: Navigate `/runs/:id?tab=overview` → text readable (no white-on-white); switch to Lineage → dark chrome activates.

### HF4 — `lastRun` survives navigation via sessionStorage

**Problem**: `lastRun` in [App.tsx](frontend/src/App.tsx) `useState`; unmount discards it. After running, switching tabs, or refresh, user cannot find the run again easily.

**Fix**:

1. **Persist `lastRun`** via sessionStorage:
   ```tsx
   const [lastRun, setLastRunState] = useState<RunCreateResponse | null>(() => {
     try {
       const raw = sessionStorage.getItem("workbench:lastRun");
       return raw ? JSON.parse(raw) : null;
     } catch { return null; }
   });
   const setLastRun = useCallback((r: RunCreateResponse | null) => {
     setLastRunState(r);
     try {
       if (r) sessionStorage.setItem("workbench:lastRun", JSON.stringify(r));
       else sessionStorage.removeItem("workbench:lastRun");
     } catch { /* ignore */ }
   }, []);
   ```
2. **No new context** needed (sessionStorage is already global; keeping the state local + persistent is simplest for hotfix scope).
3. **Owner**: FE
4. **Effort**: M (45 min)
5. **Touched files**:
   - `frontend/src/App.tsx`
   - `frontend/src/App.test.tsx` (test: trigger run → sessionStorage populated → simulate navigation → still set on remount)
6. **DoD**:
   - After a successful run, `sessionStorage["workbench:lastRun"]` contains the run JSON
   - On Submit page remount, the inline result panel (HF1) renders the persisted run
   - 1 new test passes
7. **Smoke L33**: Run → navigate to History → click Submit tab → Last run result still visible.

> Note: this is the same fix planned for V1.5.1 T5.1. Doing it here means V1.5.1 T5.1 is no-op; T5.1 will be replaced with a different polish item OR removed.

### HF5 — Unlock node dragging + verify bezier edges

**Problem**: [GraphCanvas.tsx:474](frontend/src/lineage/graph/GraphCanvas.tsx#L474) `nodesDraggable={false}`. User can pan the background but not move individual cards.

**Fix**:

1. **Set `nodesDraggable={true}`**.
2. **Verify React Flow edge default**: confirm `edgeType` resolves to bezier (`"default"` in RF v11 = bezier). If not, set `defaultEdgeOptions={{ type: "default" }}` explicitly.
3. **Add `onNodeDragStop`** handler if needed to persist positions (V1 scope: in-memory only; don't persist to localStorage in hotfix).
4. **Owner**: FE
5. **Effort**: S (30 min)
6. **Touched files**:
   - `frontend/src/lineage/graph/GraphCanvas.tsx`
   - `frontend/src/lineage/graph/GraphCanvas.test.tsx` (verify drag handler attached; existing tests should keep passing)
7. **DoD**:
   - In dev server, dragging a card moves it; edges re-route smoothly (RF handles this automatically when nodes move)
   - No regression in existing GraphCanvas tests
8. **Smoke L34**: In Lineage view, click and drag any card → card follows cursor → connected edges re-route as curved bezier.
