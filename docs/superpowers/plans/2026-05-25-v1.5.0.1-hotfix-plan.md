## 1. Why this hotfix exists

V1.5.0 shipped 5 user-visible bugs that block sign-off:

1. **Forced light → dark navigation** discards V1.4 result summary and visually jars
2. **Overview tab white-on-white** under dark route shell (functionally broken)
3. **History → run_id click cannot reach Lineage tab** (regression — only the post-run auto-nav path was wired)
4. **`lastRun` lost on tab switch** — local `useState`, not persistent
5. **Lineage nodes locked** (`nodesDraggable={false}`) — prototype expectation is free-drag

These bugs were missed because the V1.5.0 browser smoke checklist (L1–L20) covered lineage canvas internals + simple visibility, **not** cross-page UX continuity or the Overview tab's appearance under the new dark shell. Process gap; smoke checklist extension is part of this hotfix.

---

## 2. Scope guardrails

**In scope**: Bug fixes for the 5 issues above. Minimum-viable changes to restore acceptable UX. No new features. No architectural refactor.

**Out of scope** (defer to V1.5.1 or later):
- Prototype-style force-directed graph engine (still React Flow + dagre)
- LeftRail, Topbar, SSE upgrade (V1.5.1)
- Multi-tab drawer, AskAI, anything from spec §17 Q1–Q6 (V1.5.2)
- "While we're here" refactors

## 3. UX decisions (pre-locked)

| Decision | Choice | Reason |
|---|---|---|
| Post-run navigation | **Stay on Submit page**; render V1.4-style result summary inline; show prominent `✓ Run completed — Open Lineage →` button | Direct response to user feedback: "看不到原本 submit 界面可以呈现的结果" |
| Dark shell scope | **`?tab=lineage` query param scope**, not route scope | Overview tab returns to V1.4 light shell (its native form), Lineage tab keeps V1.5.0 dark editorial surface |
| History → run navigation | Replace inline `selectedRunId` state with `navigate(\`/runs/${id}?project_root=...&tab=overview\`)` | Unifies History entry path with post-run entry path; both land on `/runs/:id` |
| `lastRun` persistence | `sessionStorage["workbench:lastRun"]` (same approach planned for V1.5.1 T5.1) | Survives navigation without server-side state |
| Node drag | `nodesDraggable={true}` + verify React Flow default `edgeType` renders bezier | One-line fix; physics deferred |

4. **Code comment** explaining the parameter-scoped (not route-scoped) decision.
5. **Owner**: FE
6. **Effort**: S (30 min)
7. **Touched files**:

### HF4 — `lastRun` survives navigation via sessionStorage

**Problem**: `lastRun` in [App.tsx](frontend/src/App.tsx) `useState`; unmount discards it. After running, switching tabs, or refresh, user cannot find the run again easily.

**Fix**:

1. **Persist `lastRun`** via sessionStorage:
   ```tsx
   const [lastRun, setLastRunState] = useState<RunCreateResponse | null>(() => {
     try {
       const raw = sessionStorage.getItem("workbench:lastRun");
       return raw ? JSON.parse(raw) : null;
     } catch { return null; }
   });
   const setLastRun = useCallback((r: RunCreateResponse | null) => {
     setLastRunState(r);
     try {
       if (r) sessionStorage.setItem("workbench:lastRun", JSON.stringify(r));
       else sessionStorage.removeItem("workbench:lastRun");
     } catch { /* ignore */ }
   }, []);
   ```
2. **No new context** needed (sessionStorage is already global; keeping the state local + persistent is simplest for hotfix scope).
3. **Owner**: FE
4. **Effort**: M (45 min)
5. **Touched files**:
   - `frontend/src/App.tsx`
   - `frontend/src/App.test.tsx` (test: trigger run → sessionStorage populated → simulate navigation → still set on remount)
6. **DoD**:
   - After a successful run, `sessionStorage["workbench:lastRun"]` contains the run JSON
   - On Submit page remount, the inline result panel (HF1) renders the persisted run
   - 1 new test passes
7. **Smoke L33**: Run → navigate to History → click Submit tab → Last run result still visible.

> Note: this is the same fix planned for V1.5.1 T5.1. Doing it here means V1.5.1 T5.1 is no-op; T5.1 will be replaced with a different polish item OR removed.

### HF5 — Unlock node dragging + lock bezier edges + preserve drag positions

**Problem**:
- [GraphCanvas.tsx:474](frontend/src/lineage/graph/GraphCanvas.tsx#L474) `nodesDraggable={false}` — drag disabled at React Flow level.
- [GraphCanvas.tsx:268-393](frontend/src/lineage/graph/GraphCanvas.tsx#L268-L393) `rfNodes = useMemo(...)` recomputes dagre positions on every view-model change. **If we only flip `nodesDraggable=true`, the next selection change (which mutates the `related` set) will re-run the memo and snap dragged cards back to dagre.** Drag would be effectively useless.
- Edge type currently falls through to React Flow default. Prototype defaults to `bezier`. While RF v11's `default` resolves to BezierEdge, this is an implicit dependency on RF internals — pin it explicitly.

**Prototype reference**: `uiux/app.jsx:4-12` `TWEAK_DEFAULTS = { layout: "free", edgeStyle: "bezier", ... }`. The prototype's empty-drawer hint at `panels.jsx:469` explicitly tells users: "单击 = 打开详情 · 右键 = 菜单 · **拖拽 = 重排**" — drag is part of the contract.

**Fix**:

1. **Move from `useMemo` to `useNodesState`** in GraphCanvas:
   ```tsx
   const seededNodes = useMemo(() => buildSeededNodes(model, ...), [model, ...]);
   const [rfNodes, setRfNodes, onNodesChange] = useNodesState(seededNodes);
   // Re-seed only when seed identity changes (new graph load), not on selection
   useEffect(() => { setRfNodes(seededNodes); }, [model.id /* or stable graph fingerprint */]);
   ```
   - The `useEffect` must depend on a **graph-identity** key, not the seeded array itself. Use `model.run_id` + `model.nodes.length` as a coarse fingerprint, OR pass the run_id from `useLineage` directly. Selection/related-set changes must NOT re-seed.
   - Decorations driven by selection (related, dim, selected flags) must move out of node `data` initialization into a separate `useMemo` that maps over `rfNodes` and overrides `data` per render without resetting positions. Or use React Flow's `selected` state instead of custom flags where possible.

2. **Pass `onNodesChange` to ReactFlow** so RF can update positions on drag.

3. **Set `nodesDraggable={true}`**.

4. **Pin edge type**: `defaultEdgeOptions={{ type: "default" }}` immediately after `nodesDraggable`. Explicit, future-proof.

5. **Optional drag-end persistence**: out of hotfix scope. In-session memory is enough — refresh loses positions, same as prototype.

6. **Update empty-drawer hint** (DetailDrawer empty state): add "拖拽节点 = 重排" to match prototype contract.

7. **Owner**: FE
8. **Effort**: **M (60-90 min)** — was originally S; expanded after prototype review found the useMemo trap.
9. **Touched files**:
   - `frontend/src/lineage/graph/GraphCanvas.tsx` (state refactor)
   - `frontend/src/lineage/graph/GraphCanvas.test.tsx` (test: drag changes RF position; selection change does not reset positions)
   - `frontend/src/lineage/detail/DetailDrawer.tsx` (empty state hint text — if a hint already exists)
   - `frontend/src/lineage/detail/DetailDrawer.test.tsx` (update if hint text asserted)
10. **DoD**:
    - In dev server, dragging a card moves it; edges re-route smoothly
    - **Clicking a different node after dragging does NOT snap dragged cards back to dagre positions**
    - Edges visibly bezier (not orthogonal step / not straight)
    - Empty drawer hint mentions drag
    - 1 new GraphCanvas test (drag position persists across selection)
    - All existing GraphCanvas tests still pass (decorations test may need adjustment if it asserted node `data` shape)
11. **Smoke L34**: In Lineage view: drag card A → moves; click card B → card A stays moved; verify edges are bezier (curved, not stepped).

## 12. Prototype review notes (2026-05-25)

Reviewed `uiux/handoff/prototype.html` + `uiux/app.jsx` + `uiux/panels.jsx` + `uiux/graph.jsx` + screenshots `initial.png` / `v2.png` / `v3.png` / `cleaner.png` before execution. Findings:

1. **Prototype defaults are dark + free layout + bezier edges + multi-tab** (`TWEAK_DEFAULTS`). V1.5.0 implemented dark only on `/runs/:id` route shell (with the white-on-white bug HF2 fixes); used dagre with locked nodes; single-tab drawer. Free + bezier alignment is HF5's responsibility; multi-tab + theme defaults remain V1.5.x.

2. **Prototype's drawer has many sections V1.5.0 doesn't ship**: AskAI, ReportComposer, EditableOps, CodeBlock, downstream usage list, sample preview table, histogram. V1.5.0 ships only header/title, trust banner (no action buttons), lineage chain, basics, decision, raw JSON modal. Gap acknowledged; NOT in hotfix scope — these depend on BE features or V1.5.x sections.

3. **Empty-drawer hint text** ("拖拽 = 重排") confirms drag is part of the user contract — HF5 must enable it.

4. **No "Submit page" exists in prototype** — the prototype IS the run view, with the user assumed to have already submitted. Our app's Submit/History/Lineage three-route shape is an additional layer the prototype doesn't model. HF1's "render inline result on Submit" is therefore a workbench-app-specific UX bridge, not a prototype mirror. The CTA "Open Lineage →" gets the user to the prototype-shaped surface.

5. **Top-bar Graph/Table/Pipeline tabs** in prototype are visible but Table and Pipeline appear non-functional in screenshots. V1.5.1 T4 plans to render them disabled with "Coming in V2.0" — alignment is correct.

No hotfix-scope items missed by the original plan after this review except the HF5 useMemo trap (now corrected).
