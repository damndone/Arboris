# v1.8.10 第 1 步：结果信封与推断核心（实施计划）

依据：objective 第 1 步；设计文档 §3.2。分五个子步骤，每个子步骤先写失败测试，走完实现 → 测试审查 → 评审之后单独提交。

## 摸底结论（2026-10-02，在 worktree 上实际运行）

| 族 | 拟合对象 | 结果里有没有协方差 |
|---|---|---|
| OLS、logit、probit、Poisson、负二项 | statsmodels 结果对象 | 没有，只有逐项标准误 |
| IV 2SLS | linearmodels `IVResults` | 没有 |
| 有序、多项、分位数回归、Cox | 运行时内部用 statsmodels（OrderedModel、MNLogit、QuantReg、PHReg），拟合对象不返回 | 没有 |
| CS、SA（DID） | 无拟合对象；完整结果在 `cs_did.json` 等文件 | 只有总体 ATT 的标准误 |

- 结果在估计阶段落盘（`engine/stages/estimation.py` 调用 `_write_model_result`），此时拟合对象还在内存里。
- Agent 按 `FAMILY_EVIDENCE_PROJECTIONS` 读取 5 个族的额外字段，DID 三族没有声明。
- 前端至少有 8 个各自的数字格式函数，规则不一致；报告回归表直接 `String(value)`。

## 1a 推断核心

- 新合同 `contracts/model/inference_kernel.py`：`workbench.inference_kernel.v1`。
  - 字段：参数名与参数值；协方差矩阵（k ≤ 500 时完整保存，否则只存关注参数并写明范围）；参考分布（t 或 z）与自由度；对数似然；样本量；估计样本指纹；协方差估计方法。
  - 提供的接口列表（`coef_vcov`、`loglik`），以及缺失接口的原因。
- 按接口抽取，不按族名：凡是带有 `params` 和 `cov_params()` 的拟合对象都能抽取。v1.8.6 的运行时调用同一个函数，交出自己的核心。DID 族交出总体 ATT 的 1×1 核心。
- 落盘为 `model_results/kernel_<model_id>.json` 并登记成 artifact。
- 测试：
  - 已登记的每个模型处理器跑完后，都有核心文件；接口为空时必须写明原因；
  - 参数名与结果包的系数名一致；
  - OLS 和 logit 的协方差与 statsmodels 直接计算的结果一致到 1e-10。

## 1b 信封声明

- 新登记表 `contracts/model/result_envelope_registry.py`。每个族一份声明：
  - 合同名、结果形状、核心来源；
  - 给 Agent 的投影字段及上限，替代 `FAMILY_EVIDENCE_PROJECTIONS`，边界函数原样迁移；
  - 报告段落。
- 补上 CS、SA、dCDH 的声明：总体 ATT 及区间、按时期的事件研究（有上限）、事前检验、honest DID 摘要。
- 测试：
  - `MODEL_FAMILY_CONTRACTS` 与模型处理器中的每个族都有声明；
  - Agent 投影代码里不出现族名；
  - 消费者不按路径直接读取结果包。

## 1c 消费者同源

- Agent：`inspect_result_summary` 通过登记表读取，DID 族可读。
- 报告：回归证据表和 DID 段落都从声明读取。
- Notebook：引用同一份投影。
- 数字格式：新建共享模块 `frontend/src/format/numbers.ts`。
  - 估计值约 4 位有效数字，绝对值 ≥ 1000 时取整并加千分位；
  - p 值写成 `< 0.001`，否则保留 3 位小数；
  - 报告回归表、Table 页、运行结果页都改用它。
- 测试：
  - 前端单测：p = 0 显示为 `< 0.001`，0.9928945017762245 显示为 0.9929；
  - 后端测试：Agent 读 CS 节点能拿到 ATT 和区间。

## 1d 集合信封

- 合同 `workbench.result_collection.v1`：成员键（组值或插补序号）、每个成员的状态（成功 / 无法估计 + 原因）、可选的合并结果、组合子参数与随机种子。
- 本步只建合同和校验；第 5、7 步才产出集合。

## 1e 验收

- 浏览器：
  - 选中 CS 节点问整体 ATT 和置信区间，回答与结果面板一致；
  - 加入报告后有 CS 段落；
  - Notebook 引用同一数字；
  - 有序 logit、Cox 各做一次同样的场景。
- 性能：读取单个结果 < 1 s；推断核心文件在 k ≤ 500 时 ≤ 2 MB。
