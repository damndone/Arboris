# Workbench v1.8.3 Memory Lane Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use `executing-plans` and complete `MEM1 → MEM2 → MEM3` serially in one Memory-owned worktree.

**Goal:** Add rebuildable project context and opt-in cross-project domain memory that improves retrieval and analysis preparation without becoming a hidden fact source or authority path.

**Architecture:** MEM1 builds a derived Project/RunFamily context index. MEM2 adds one scoped candidate/content/approval store and bounded retrieval. MEM3 adds a contained candidate-only curator and user-governed review/conflict lifecycle. All identity comes from CORE; shared Context Compiler, Trace, application, and Notebook mounting are deferred to Integration.

**Tech Stack:** Python, FastAPI route modules, append-only/content-addressed stores, existing Graph/Trace/Option facts, React/TypeScript, pytest, Vitest.

**Execution control:** [`2026-07-25-v1.8.3-execution-control.md`](./2026-07-25-v1.8.3-execution-control.md)

---

## Shared lane constraints

- Consume CORE `LocalProfileIdentity` and `ProjectIdentityRevision`; never generate a second local or project identity.
- Domain-memory use and iteration are independent and default off.
- Candidate, content revision, approval/current grant, source-access binding, retrieval, and usage are distinct records.
- Memory may add context or checks only. It cannot recommend a capability, change ranking evidence, admit an implementation, authorize an option, or dispatch a run.
- Package-local trace declarations live in `domain_memory/trace_contracts.py`; Core Trace registration is deferred to Integration.
- Pure projections are built here; edits to `agent/context_compiler.py`, `app.py`, `NotebookSurface.tsx`, and `notebook.css` are deferred to Integration.
- Every formal line freezes a compact temporary objective from its phase below and supplies the exact phase path allowlist to `devline_control.py start`; no per-phase objective file is retained.
