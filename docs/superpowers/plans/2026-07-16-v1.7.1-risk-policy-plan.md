## 11. Agent reliability and evidence slice (v1.7.1 amendment)

This amendment follows the existing Agent Harness design and does not reopen
P-CE1, P-SBX2, V11, V7, time-series integration, or a general memory/RAG/Skill/Hook runtime.

### 11.1 Contract-only additions

- Keep session JSONL as short-term context truth; events remain observation/replay only.
- Keep the existing 24,000-character context packet and 4,000-character question limits.
- Reject oversized context explicitly; do not silently truncate message/tool-result blocks.
- Document progressive disclosure as Level 0 project summary, Level 1 node/run summary,
  Level 2 schema/diagnostics/result summary, Level 3 bounded evidence, Level 4 operation
  contract, Level 5 proposal/confirmation.
- Keep `agent/v1` as the current protocol version and make clear that prompt text never grants
  backend permission.
- Document reload/recovery semantics: durable session entries and events are replayable, but
  canonical graph/run/operation state is always re-read from backend stores.

### 11.2 Minimal runtime guard

Files:

- `backend/workbench/agent/core.py`
- `tests/test_agent_harness_foundation.py`

Tasks:

- Add a positive `max_consecutive_identical_tool_calls` budget field with a safe default of `2`.
- Canonicalize each tool id and JSON argument object before execution.
- Count only consecutive identical calls within one prompt/continue command.
- After the second completed identical call, persist a terminal assistant error
  `repeated_tool_call_limit`, emit `loop_guard`, and mark the session `blocked`.
- Keep tool results durable before entering the terminal error path so reload does not leave a
  dangling assistant tool call without a result.
- Do not add parallel execution, retries, token accounting, or cost accounting.

Tests first:

- Add a fake adapter that emits the same read-only tool call repeatedly.
- Verify the first two calls execute, the third model request is never made, the session is
  `blocked`, the terminal error is durable, and one `loop_guard` event contains the tool id and
  repetition count.
- Verify a changed argument resets the consecutive counter.
