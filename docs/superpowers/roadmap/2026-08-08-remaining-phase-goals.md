## 0. 三条北极星（一切取舍由它们裁决）

用户反复强调的三条，此处写成**可判定**的形式。每个阶段的验收都要能对上。

### ① AI-native：能发挥 LLM/Agent 长处的地方要**超过** SPSS/Stata

**但超越的形式只能是**：Agent **提议** → 人**批准** → 理由**入 lineage**。

**永久不做**（违反基石，无论多方便）：

- Agent 自主选择统计方法而不告知理由
- 自动修数据
- 用 LLM 的判断替代数值检验

**可判定**：每个阶段必须能指出「这一段在哪里超过了 SPSS/Stata」，并且那个超越点落在上面这个形式里。答不出来的阶段就是在单纯追赶，要在计划里如实标注。

### ② 准确性与安全性是基石，优先于一切

任何为了灵活性而**削弱确定性契约、绕过安全闸门、或让错误结果能静默通过**的设计，一律否决。

事故原型（记住这个形状）：一次名字不匹配静默 `continue`，标准误用了 **0.7804** 而不是正确的 **1.5955**——**run 成功、报告正常、全套测试绿**。

**可判定**：新统计能力**不接受「自洽即通过」**，必须对外部基准（statsmodels / R，容差参照 ~1e-13）。R 只在测试中调用，**生产代码零 shell/R**。

### ③ 模块化与可组合：像编程一样自由组合，不是固定公式 + 死流程

**衡量标准（设计文档自己定的，不放宽）**：

> 接入第 N+1 个能力应只需实现契约 + 写能力本身，**不需要改 orchestrator 的四处分发**。
> 做不到就说明契约没抽对。

**终局**：**自然语言可调用 Workbench 的全部能力。**

**今天的诚实数字**：**34 / 54 = 63%**（含经 `operation.multi_step` 的组合路径）。
剩下 20 条里 2 条有意关闭、**18 条是真缺口**。

## 1. 阶段依赖与并行安排

```
P2 ──→ P3 ──→ ┌─ P4  数据管理接入
   串行   串行  ├─ P5  18 个可达性缺口补齐        ← 三者可并行
                └─ P6  P7/P8 的 29 个能力接入
                        │
                        └──→ P7  前端 + 真机端到端   ← 必须最后
```

**为什么 P2 / P3 必须串行且在最前**：它们改的是**所有后续阶段都要站在上面的那一层**。
P2 定义「什么叫可达」，P3 定义「怎样接入」。这两件事定错，后面三个并行阶段会各自
按错的地基建一遍——P0 的组合 seam 就是这个风险的实例（如果 seam 做错，
后续九个任务全要重排）。

**为什么 P4 / P5 / P6 可以并行**：它们动的是**不同的能力族**（数据操作 / 存量缺口 /
新 pack），共用同一个 P3 的接入面，互不写同一批文件。**前提是 P3 真的把接入面抽对了**——
如果三个阶段各自都要改 orchestrator，那它们就不可并行，而这本身就是 P3 失败的信号。

**建议**：P4/P5/P6 并行时用 **subagent-driven**，每个族一个 worktree，
按协议 §4.1 的循环各自走审查。

**为什么 P7 必须最后**：真机验收要验的是「一句话能不能调到能力」，
前面任何一个阶段没接完，这条验收都说明不了问题。

## P2 — 让「全部能力可达」成为一条会红的断言

### Goal

**把「自然语言可调用全部能力」从一句宣称变成一条会失败的测试。**

今天这句话是宣称：上一版声称做到了，实际只核对了模型族。P1 造出了清单（54 条），
但**没有任何东西在断言它**。P2 补上那个断言。

### 必须先修的前置

**`CapabilityContract.is_reachable` 是乐观的**——它只看 `proposed_by` / `composable_as`
非空，**不看那条路径自然语言走不走得通**。

已核实：自然语言可提议的 operation 只有 **4 个**（`data.columns.cast` / `graph.fork` /
`model.rerun` / `operation.multi_step`）。**`model.genesis` 的
`natural_language_enabled=False`**，而 22 个模型族的 `proposed_by` 全指着它。

不修这个，守卫会对 5 条走不通的路径判绿。

> ⚠️ 算可达率时**必须算上组合路径**。只算直接提议会得出 4/54 = 7%，与真相差九倍。

### 验收即断言

- [ ] 可达性判定认得 `natural_language_enabled`，并区分「直接提议」与「经组合可达」
- [ ] 守卫**从统一能力清单枚举**，对每条能力断言：可达，或带**陈述的豁免理由**
- [ ] 守卫**在能力层**而非操作层——`model.genesis` 一个操作承载 22 个族，
      按操作写的守卫在第 23 个族够不着时照样绿
- [ ] 有意豁免**显式白名单化并写明理由**，不得靠缺席表达
- [ ] **元测试防漂移**：注入一个假能力 → 守卫自动把它算进分母
- [ ] 18 个已知缺口在守卫下**如实变红**（不是被 xfail 掩盖）——
      P2 的产物是一条红线，不是一片绿

### 一个明确的设计选择留给 Codex

18 个缺口一次性变红，会让 CI 长期红。三种处理：

1. 守卫报告数字并**钉死当前值**（像 P1 那条测试），修好一个就更新一次记录
2. 守卫对已知缺口列**时限白名单**，逾期变红
3. 先补完 P5 的缺口再上守卫

**给出你的选择与理由。** 不许选「标 xfail」——那等于守卫白做。

### AI-native 落点

守卫本身不是 AI-native 的。但它是**唯一能让「Agent 能力全集」这个承诺可信**的东西——
SPSS/Stata 没有「Agent 可达性」这个概念，所以这一段是**为超越铺路**而非超越本身。
如实标注。

## P3 — 让第 N+1 个能力的接入成本显著低于第 N 个

### Goal

**一个能力只需实现契约，接入自动发生。**

这是用户三条北极星里第三条的核心，也是整个 v1.8.8 真正的地基产物。

**今天的成本**（接入一个能力要手工接的线）：

```
OperationDefinition  →  StepSpecContract  →  orchestrator 四处分发
      ↓                       ↓                      ↓
proposal_schema        produces_dataset        validate / prepare
editable_schema        consumes_input_frame    execute / reconcile
example_prompts        replayable_by_recipe
vocabulary_builder            ↓
      ↓              workflow_step_vocabulary（三个消费者！）
diff_builder_key
verification_builder_key
```

**漏一处的后果都是静默的**：漏 step 词表 → 不能组合；漏 vocabulary 渲染 →
chain agent 一个字看不到；漏 `produces_dataset` → 下游读原始表还报成功。

### 验收即断言

- [ ] **守卫 H**：接入一个新能力**没有改动 orchestrator 的四处分发**。
      这条把「拓展性」从口号变成会失败的测试
- [ ] 一个能力的**全部接入点从一份声明派生**——不是手工维护 N 份
- [ ] `workflow_step_vocabulary()` 的**三个消费者**（`planning_agent` / `inspect_operation_contract` /
      **`agent_routes.py` 逐键渲染**）自动都拿到新能力。第三个是踩过的坑
- [ ] **元测试**：注入一个假能力 → 它在所有接入点上自动出现，**不改任何测试**
- [ ] 用 **P7 的 29 个能力之一**做真实检验：接入它没改四处分发。
      改了就说明契约没抽对，**回来改契约，不要绕过**

### 明确的非目标

不要为了「通用」而把 `proposal_schema` 松成 `object`。**契约要封闭**——
一个能力的参数集合必须是封闭值集（`Literal` / `frozenset`），
否则 LLM 发不出正确字段，而这正是 v1.8.7 栽过的地方。

**通用的是接入机制，不是参数类型。**

### AI-native 落点

这是**最直接的一段**：接入成本降下来之后，「用自然语言调用全部能力」从
「每个能力都要人工接线」变成「注册即可达」。SPSS/Stata 的能力清单是编译进产品的，
不存在这个问题也不存在这个能力。

## P4 — 数据管理接入（本版最初的存在理由）

### Goal

**「上传数据 → 一句话 → Agent 出含转换步骤的方案 → 批准 → 跑出模型结果」全链路打通。**

后端早已完备（`apply_data_transform` / `apply_feature_recipe_operation` 都会写 artifact、
写 recipe、提交 graph 子节点、写 node_index），缺的只是接入。P3 之后这一段应该很便宜。

### 范围

- 四种转换：`merge` / `append` / `reshape` / `subset`
- 五个 feature recipe：`interaction` / `log` / `ratio` / `recode` / `derived_variable`
- **`list_project_datasets` 发现工具**——没有它 `merge` 在自然语言下不可能被正确提出，
  Agent 连「第二份数据存在」都不知道，会**编一个 id**。形状见设计文档 §决策三
- **`subset` 的比较算子**：今天只支持相等（`parameters.get("equals", {})`），
  「只保留 2020 年以后的」「去掉收入缺失的行」做不了。扩成一组**封闭**算子
  （`eq/ne/gt/ge/lt/le/in/not_in/between/is_missing/not_missing`），不是表达式求值
- **新增原子操作**：`dedupe` / `rename` / `aggregate` / `fill_missing` / `tsset` / `lag`
  （`data.sort` **不做**——唯一对统计结果无影响的操作，且 `tsset` 已承担时序排序语义）

### 验收即断言

- [ ] 每种转换与每个 recipe 各能由**一句自然语言**提出 typed proposal
- [ ] merge 场景下 Agent **自己找到**第二份数据的 `(run_id, node_id, artifact_id)`，
      不需用户报 id
- [ ] 转换与 `model.genesis` 能出现在**同一个** `operation.multi_step` 方案里
      （P0 的 seam 支持这个，但**从未真机验证**）
- [ ] 确认后执行产生 graph 子节点，`node_index` 有条目，**血缘指向真实上游**
- [ ] 提议在面板上是人话不是 JSON dump
- [ ] `subset` 能表达「大于 / 小于 / 缺失 / 在集合内」

### 操作粒度（已定，不要改）

**每种转换一个 `OperationDefinition`**，不要合成一个用 `operation` 枚举区分的。
理由见设计文档 §决策二：四种转换字段几乎不相交，合成一份 schema 只能把
merge 的 secondary 三元组标成可选，而 **LLM 读的是 `proposal_schema`**——
可选意味着模型漏填**不构成违规**，一道校验从 schema 层降级到运行时。

共用 `executor_key` 即可，四处分发点各仍只加一个分支。

### AI-native 落点

**前置诊断即提议**：SPSS 要求用户自己知道数据是宽表、需要先 reshape。
Agent 有了发现工具可以自己看出来，并**主动把转换作为方案第一步提出，附上理由**。
这是本阶段的超越点。

## P5 — 补齐 18 个可达性缺口

### Goal

**把「自然语言真实覆盖率」从 63% 推到接近 100%，剩下的必须是带理由的有意关闭。**

### 缺口清单（P1 已精确定位）

| 族 | 数量 | 说明 |
|---|---|---|
| **统计检验** | 8 | 相关 / 秩相关 / t 检验 / ANOVA / 非参 / 卡方 / Fisher / evidence。**一个都点不了名**——它们是按列类型自动跑的 pipeline stage，没有任何 operation 能调用 |
| **预测模型** | 3 | Lasso / Ridge / RandomForest。**Agent 要不了一个 Lasso 预测** |
| **数据准备** | 4 | MICE + SMOTE/过采样/欠采样。**Agent 无法决定缺失值是丢弃还是填补——即无法影响它所估计的样本** |
| 时序族 | 2 | ARMA-GARCH / ETS 能手动跑，**进不了 multi_step 方案**（无 workflow 准入契约） |
| selector | 1 | `model.auto` |

**其中「数据准备」这一族最要紧**：它决定模型到底看到哪些行。Agent 影响不了它，
就意味着 Agent 报出的任何结果都建立在一个它无法参与的样本决策上。

### 验收即断言

- [ ] 每一族都能由自然语言点名调用
- [ ] 统计检验能作为 step 参与组合（而不只是自动跑）
- [ ] 两个时序族有 workflow 准入契约，能进 multi_step 方案
- [ ] P2 的守卫在本阶段结束时**全绿**，且剩余豁免项各有陈述的理由

### 一个必须正面处理的问题

**8 个检验族目前是「自动跑」的 pipeline stage。** 让它们「可点名」不等于
「取消自动跑」——两种模式要能共存，而且**语义要说清**：用户点名要一个 t 检验，
和系统自动跑出一堆检验，是两件不同的事，结果的可信度与多重性校正也不同。

**这一条涉及统计正确性，不要只当接线做。** 多重比较的问题在自动跑时是隐含的
（跑了 8 族检验而不校正），点名调用时反而更干净。在计划里写清你的处理。

## P6 — P7/P8 的 29 个能力接入

### Goal

**Codex 已在独立 worktree 完成的 29 个统计能力，按 P3 的契约接入并变为自然语言可达。**

内核形状 `fit_x(frame, columns, *, 封闭 Literal 参数) -> dict` 与 workflow executor
传 `step_frame` 吻合，契约模块自称「未来的 CapabilityContract seam」——形状是对的。

### ⚠️ 接入前必须重做的核验

**8 月 7 日那份「纯新增、merge 干净」的结论已经过期。** 现在是
**104 新增 + 16 修改 + 50 行删除**，修改了共享引擎路径
（`imputation.py`、`engine/stages/{estimation,diagnostics,imputation}.py`、
`orchestrator/_report_build.py`、`report_view_model.py`）以及 golden 测试与契约样本。

merge 目前仍干净（`git merge-tree` exit 0），但**风险性质变了**。重验，不要引用旧结论。

### 已定位的四个坑

| 坑 | 处理要求 |
|---|---|
| `power_analysis.py` 有 `CONTRACT` 但**无 `*_OPERATION_IDS`** | 按命名约定枚举会**静默漏掉它**。且它的能力空间是 3 designs × 4 targets 的**组合**，「补齐 frozenset」要先决定补 2 条还是 12 条 |
| multivariate 的 8 个 id 拆在**两个** frozenset 里 | 只查「存在 `*_OPERATION_IDS`」的元测试仍漏 5 条 |
| 「都消费输入帧」**只有 23/29 成立** | roc 收两个序列、categorical 收计数表、meta 收 study 记录、power 不吃数据。`combine_effects(studies: Any = None)` 的 `Any` 最坏——标成 `consumes_input_frame=True` 而不写适配层，**DataFrame 会被当 `studies` 吞掉而不报错** |
| 接入顺序 | 29 条一次性变红**不是「期望的红」**——那是「工作没做完」被写成「产品有窟窿」，且无可操作性，最可能被标 xfail，那 P2 就白做了。**分批**，每批在同一个 commit 里既加能力又给出可达性状态 |

### 验收即断言

- [ ] 29 个能力（含 power_analysis 的真实条数）全部在清单里，可达或带理由豁免
- [ ] **接入过程未改 orchestrator 四处分发**（P3 的守卫 H 检验）
- [ ] 数值正确性对外部基准（statsmodels / R），**生产代码零 shell/R**
- [ ] 6 个「不消费输入帧」的能力有**显式适配层或显式声明**，不许靠 `Any` 蒙过去

### AI-native 落点

**假设违反的自动串联**：SPSS 会照跑并把诊断塞进输出末尾，用户不看就不知道。
这 29 个能力里有多处硬闸可以做成「拒绝 + 提议」：

- VAR 特征根模 ≥ 1 → 明说不稳定，提议差分或改滞后阶，**而不是照出一份错报告**
- EFA 的 KMO 过低 / Bartlett 不显著 → **拒绝执行**并说明
- 协整秩为 0 → 已经是 `rejected`，不强行拟合（Codex 做对了）

**关键分寸**：诊断结论是**拒绝或提议**，不是自动改。自动改违反基石。

## 3. 一句话

**每一个真问题都是「今天无害、换个条件就静默出错」的形状，而且没有一个会让当时的测试变红。**

所以全部流程重量压在两件事上：**让断言证明自己是活的**，和**先问谁真的会读这份东西**。
