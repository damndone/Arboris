## What was implemented

### One shared natural-language execution boundary

- `AgentNotebookRuntimeV1` composes the provider catalog, trusted executor
  registry, capability catalog, compiler and typed evidence committer.
- The shared compiler accepts the same structured semantic intent for both
  Agent and Notebook entrypoints. Natural language is normalized into this
  intent before compilation; it is not allowed to directly choose a Python
  callable, module path, provider or artifact path.
- Compilation remains previewable and typed. Confirmation and execution use
  server-retained records and receipts rather than client-shaped authority.
- A Notebook compile request delegates to the same compiler with
  `entrypoint="notebook"`; it does not maintain a second capability table.

### Correctness and security boundaries

- Real HTTP routes use an application-instance authority store. A custom
  FastAPI app must be explicitly bootstrapped; an unbound app/runtime fails
  closed instead of falling back to a module-level fixture.
- The host supplies the server-owned identity resolver. Agent HTTP requests
  must match the resolved actor, session and canonical project; Notebook
  requests are bound to the persisted Notebook/project identity.
- A provider result cannot be marked completed with an arbitrary evidence
  string. Completion requires a persisted typed receipt matching actor,
  session, project, compilation record, execution instance and the canonical
  digest of the dispatched result.
- Classification artifacts are registered into `artifacts_index.json` with a
  typed payload contract and content digest. The download boundary recomputes
  the file hash and returns a typed integrity failure without returning the
  body when the digest is missing, malformed or mismatched.

### Data consumption and result evidence

- The report consumer only reads indexed classification artifacts and accepts
  the strict v1 evidence packet contract. It does not treat arbitrary JSON as
  evidence.
- Invalid, duplicate, unavailable or failed classification evidence is
  represented as an explicit `UNAVAILABLE` packet. If no classification item
  is indexed, no fabricated classification panel is mounted.
- The renderer allowlists known scalar evidence fields and does not stringify
  unknown nested objects, so raw payloads or secret-like fields cannot appear
  as a report result by accident.

## Natural-language capability status

The shared compiler path is now implemented for Agent and the new Notebook
cutover adapter: a natural-language request can be normalized, previewed,
confirmed and executed through the same typed operation boundary when the
host has supplied the provider runtime and identity resolver.

This does not yet mean that every historical Notebook route or every legacy
workflow runtime has been migrated. Confirmation and execution remain
server-controlled operations, and this worktree has no browser-visible or
real-provider acceptance evidence.

## Known limits and next integration slices

1. Production startup must inject real `ProviderRuntimeContributionV1` values
   and a host-owned identity resolver. The default unbound state returns a
   typed `503` rather than inventing a provider.
2. Direct Python route-function calls without a `Request` remain a legacy
   compatibility/testing seam. The real HTTP authorization path is bound to
   the app instance and host resolver; remove or gate the direct seam in a
   later integration line.
3. The protected lower-level persistence register still accepts a supplied
   digest for compatibility. The HTTP consumer independently rehashes bytes
   and fails closed; a future persistence line should make digest computation
   internal to registration.
4. C0 authority, compilation and confirmation stores remain process-local.
   Restart durability, one-time receipt consumption and multi-worker
   coordination need the persistence foundation line.
5. The historical Notebook/planner and protected workflow runtime paths are
   not globally migrated. The shared bridge is additive and does not claim a
   unique choke point for every existing execution path.
6. Browser acceptance, external-provider calls, host-level sandbox acceptance,
   merge, push, tag, release and deployment were not performed.
