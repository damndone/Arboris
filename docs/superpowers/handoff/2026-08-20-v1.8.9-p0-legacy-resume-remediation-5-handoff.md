## Implementation

`WorkbenchOrchestrator` no longer constructs a raw `ProposalStore` by default or
exposes an explicitly supplied raw store through its public `proposal_store`
attribute. `create_proposal()`, `revise_proposal()`, and `decline_proposal()`
obtain a live `ProposalStoreCapabilityV1` and repository-root identity before
registry reads or any proposal/repository/event write. Raw, reconstructed,
cross-scope, and tampered stores fail with typed
`LegacyProposalWriteBoundaryError`; stale revision replay remains a typed
proposal conflict. Existing data-operation read bookkeeping retains a private
raw-store compatibility input without making it a proposal writer.

All Agent proposal creation, revision, decline, and chain-turn routes now pass
the route-owned capability explicitly. The predecessor direct-confirm negative
fixture was migrated to create its setup proposal through that capability and
still proves the legacy confirm boundary has no proposal or operation-record
side effect.
