## Delivered in this local slice

- Agent, Notebook, Report, and shared projection consumers now project only
  from `ServerOwnedEvidenceProjectionSourceV1`, which reloads the live
  `EvidencePacketStoreV1` packet through the `EvidenceRegistryV1` admission
  and registry receipt on each projection.
- `ConsumerProjectionRegistryV1.project(...)` no longer exposes or uses a raw
  `PersistedEvidenceEnvelopeV1` projection path; caller-constructed persisted
  envelopes fail closed at the production boundary.
- `ServerOwnedEvidenceProjectionSourceV1` now requires a non-empty SHA256
  envelope digest, binds source/policy/live packet digest exactly, and rejects
  `object.__new__` slot-cloned sources through host-issued source admission.
- Sensitivity is bound to a server-issued immutable policy; caller attempts to
  downgrade restricted evidence to public/internal fail before facts are
  projected.
- Report canonical projection reloads the live packet/registry admission and
  does not trust mutable `_canonical_record`/`_canonical_artifact` caches.
- Report request identity is no longer a caller-controlled same-value fact
  source: caller-created `ReportEvidenceRequestIdentityV1` values are rejected,
  while the owner rebuilds/reissues its exact server-admitted identity after
  cache tamper.
- Remote projection audit/evidence wire retains the validated egress receipt
  id and digest after the existing egress receipt seam passes.
- Persisted evidence projections now carry data snapshot reference/digest,
  reject cross-artifact and cross-admission identity, reject caller-supplied
  raw rows, reject unknown fact identities, and propagate
  `UNAVAILABLE`/`DEGRADED`/`BLOCKED` without inventing facts.
- Notebook and Agent use the same projection registry seam; Notebook only
  wraps the already-typed server projection.
- Report UI accepts only a runtime-validated typed projection, rejects raw
  payloads/missing or unknown renderers/wrong consumer contracts, and visibly preserves
  facts, intervals, caveats, availability, validation provenance, lineage,
  identity, and data snapshot identity.
- Coverage raw keys retain direct/composable path class and keep blocked rows
  in the denominator.

## Review finding status

### P0 — server-owned persistence authority: closed in focused tests

The direct `PersistedEvidenceEnvelopeV1` production projection path was removed
from the shared registry. Production projection now requires the live
server-owned source capability, registry admission, registry receipt, host
authority, exact source issuance, source/policy/live packet digest match, and
Report owner identity admission.

### P1 — declaration and audit completeness

- The current provider catalog schema cannot declare accepted evidence/envelope
  refs, fact kinds, redaction budgets, ordering, renderer version, or ownership
  of unreachable/exempt rows. Consumer defaults must not be treated as the
  final product declaration.
- Remote egress receipts are validated and their receipt id/digest are now
  retained in the projection audit/evidence wire.
- Coverage currently reports declared direct/composable paths; it does not
  synthesize explicit unreachable/exempt raw-key rows.
- The existing `factTable.ts` and `FamilyEvidence.tsx` still contain duplicate
  frontend validation paths; consolidation is a follow-up maintainability task.
