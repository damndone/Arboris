# v1.8.9 Central Evidence Consumer Mount Handoff

## Scope

Formal line: `v1-8-9-central-evidence-consumer-mount`  
Baseline: `91ee6a05eab2a1892844c8a3057e1e607359a29e`  
Worktree: `workbench-v1.8.9-hardening-integration`

This line mounted the already-persisted C0 typed evidence into the central
results response and into the Agent/Notebook persisted-evidence readers. It did
not add an estimator or weaken the existing strict model-result artifact
binding.

## Implemented

- `GET /runs/{run_id}` now returns `results_evidence` from the server-owned C0
  packet, registry, receipt, and the `results` projection declaration.
- The route returns a separate `results_evidence_receipt` and keeps legacy
  `model_results`, `statistical_evidence`, and table compatibility fields
  visibly non-authoritative.
- Missing owner capability, foreign project root, stale/tampered packet, and
  invalid identity return an explicit unavailable/degraded typed packet with no
  facts and no raw model-result fallback.
- `read_persisted_consumer_evidence_for_run` is the shared service entrypoint;
  Agent and Notebook wrappers select only their declared consumer id and cannot
  inject a registry, path, raw result packet, provider, or alternate model.
- Agent result, diagnostics, and statistical-evidence tools now carry the
  shared `persisted_evidence` packet alongside the legacy bounded compatibility
  projection. The old projection remains separate and does not create or
  authorize evidence.
- The Report path continues to require exact owner-issued projection,
  artifact admission, registry receipt, and canonical digest. Its current
  boundary suite is included in the final focused gate. No separate Report
  calculation path was introduced.
