## Exact implementation tip

`backend/workbench/repository/run_repository.py` now validates indexed artifact
paths with a server-owned bounded grammar: ASCII components matching
`[A-Za-z0-9._-]{1,128}`, at most 64 components, and at most 512 bytes. It
opens the run root and every path component with `O_NOFOLLOW`, traverses only
through directory descriptors, opens the final artifact once, uses `fstat` to
require a regular file, and hashes bytes from that same descriptor. The old
`is_file()`/`resolve()` then path-hash sequence is gone from artifact-index
validation, so a replacement with an external symlink fails closed.

Missing or unreadable `artifacts_index.json` remains
`ARTIFACTS_INDEX_UNAVAILABLE` / HTTP 503. Malformed or invalid indexes,
missing/non-regular/unreadable artifacts, path/type/digest/duplicate violations,
and content mismatches remain `ARTIFACTS_INDEX_INVALID` / HTTP 500. HTTP invalid
responses contain no raw exception and no `groups`. Canonical `formal_output`
and the typed classification producer plus Agent/Notebook/Report projections
remain valid. The report producer was not changed.

The existing artifact-type compatibility allowlist was not expanded. Bounded P2
follow-up: audit producer vocabulary drift or establish a server-owned registry
in a separately scoped line; remediation-13 does not copy more constants into
the security validator.
