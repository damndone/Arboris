## What was closed

### 1. Report consumes only completed server evidence

Report dependency validation now requires the compiled dependency set, a
unique persisted admission and completion for every dependency, and a matching
server-owned artifact row for every completed artifact. The report receives a
bounded projection of those completion records rather than trusting caller
supplied status, artifact IDs, row counts, or metadata.

### 2. Child-run model artifacts are frozen before result admission

`model.genesis` produces child runs. Every artifact returned by a child run is
now registered against the active workflow receipt with its path, digest,
inode identity, producer, expected output set, and source/model branch
provenance before the typed model result can be admitted. A valid model result
therefore cannot be rejected merely because it lives in a child run, while a
caller-supplied foreign artifact still fails closed.

### 3. Post-estimation and custom producer outputs use the same bridge

Joint F tests, White tests, stationary-point results, and other workflow-owned
post-estimation artifacts now use the common runtime artifact registration
bridge. The authorized custom capability test path explicitly calls the
receipt-bound formal artifact port; writing a public index row alone is not
considered evidence.

### 4. Formal output commit is rollback-safe under parent replacement

The formal writer rechecks its parent identity after the atomic replace. If a
parent is moved during the commit race, a newly created destination is removed
through the held directory FD before the typed path-change error is raised, so
the deterministic probe leaves no outside file.

### 5. Adversarial assertions reflect the tightened boundary

Concurrency probes accept either duplicate-execution refusal or restart-
authority refusal, both of which reject the losing worker. Public artifact
index rewrites are tested as non-authoritative after admission; content or
symlink tampering still fails against the frozen server row. Error assertions
accept the stable typed boundary codes rather than relying on one historical
message wording.

### 6. File-level replacement and rollback are fail-closed

The formal output target now records the final-file inode, rejects a filename
replacement before server admission, and preserves an existing destination by
an same-directory hard-link backup until the receipt-bound registry/index
transaction succeeds. A failed transaction restores the previous content; a
newly created file is removed only when its inode still matches the target.
Repeated pending runtime writes for one path close and roll back the superseded
target instead of leaking its descriptors.

The public index writer also checks its pre-read inode before replacing the
index, so a concurrent legacy/index writer cannot be silently overwritten.
