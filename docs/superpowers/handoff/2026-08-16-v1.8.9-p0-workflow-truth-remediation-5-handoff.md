## What was closed

### 1. Host authority is fail-closed at the package boundary

`issue_server_evidence_port()` no longer accepts a caller-selected path, FD,
socket, mapping, or configuration as the production workflow trust root. The
public `host_endpoint` compatibility argument is an explicit rejection path.

The package now has a typed `WorkflowHostEndpointV1` boundary and a private
deployment resolver seam. The default resolver raises
`WORKFLOW_EVIDENCE_HOST_ENDPOINT_REQUIRED`; it does not derive an endpoint from
request data and does not mint a hidden Python host token. The issued port
holds a duplicate of the supervisor-provided workflows-directory FD and
rechecks its device/inode identity before authority or evidence operations.

This is intentionally a **fail-closed package boundary**. A production server
must wire the resolver from its deployment-owned supervisor/host adapter. A
test fixture may replace the seam only to model that external boundary; that
fixture is not production acceptance evidence.

### 2. Completion consumes a server-owned artifact admission registry

After an admitted step returns a typed result, the server port admits each
artifact into a per-port registry bound to the exact receipt, workflow, step,
run, path, digest, and producer. Completion and replay require that registry
entry; a matching public `artifacts_index.json` row alone is insufficient.

Foreign-run model artifacts additionally require validated persisted branch
provenance: workflow/step identity, source run and source artifact, source
digest, model run, model artifact, expected artifact set, and the branch's
durable model evidence. Forged same-run registry rows and forged foreign-run
branch metadata are rejected before a completion record is appended.

### 3. Formal report/export writers are receipt-gated before IO

HTML, PDF, and XLSX writers now require the active server-issued receipt before
loading/rendering a formal output target. They write through an admitted
temporary file opened relative to the validated parent FD, fsync it, and commit
with `os.replace(..., src_dir_fd=..., dst_dir_fd=...)`. The report collection
JSON uses the same path boundary.

The runtime-owned workflow artifact producers covered in this line (numeric and
prepared datasets, named tests, ETS/capability results, post-estimation, P7,
and node indexes) use the same helper. Parent components are opened/created
relative to a held run FD with `O_NOFOLLOW`; root, parent, and final destination
device/inode identity is rechecked before read, open, and commit. A symlink or
parent replacement fails with `WORKFLOW_ARTIFACT_PATH_CHANGED` and does not
leave an outside artifact behind.

Existing receipt, post-estimation, restart, evidence-lock, FD/inode, and
no-write behavior was retained and exercised by the focused suite.
