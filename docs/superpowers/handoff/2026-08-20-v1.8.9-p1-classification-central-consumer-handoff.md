# Workbench v1.8.9 P1 Classification Central Consumer Handoff

## Scope

- Formal line: `v1-8-9-p1-classification-central-consumer`
- Baseline: `91ee6a05eab2a1892844c8a3057e1e607359a29e`
- Integration worktree: `workbench-v1.8.9-hardening-integration`
- Source implementation commits: `39e76303`, `a94a6f88`, `186d4886`, `bb6b0c9b`

This line connects the already-persisted classification evidence to one
server-owned consumer facade. It does not add model families or alter fitting,
split, CV, holdout, calibration, threshold, or explainability semantics.

## Delivered

- Agent, Notebook, and Report classification reads use the same central
  provider-owned wrapper/projection adapter.
- The central API accepts only an opaque server-issued run capability. Raw
  paths, project roots, packets, provider objects, registries, and model
  inputs are rejected at that boundary.
- The HTTP run-detail route resolves the run once, mints the capability from
  that resolved run, and uses the same capability for the Report projection.
- The indexed artifact, receipt, server identity, fold/C0 and evidence status
  checks remain fail-closed. Missing index is typed `unavailable`; valid
  degraded evidence retains its blocked reasons; tampered and foreign evidence
  never falls back to raw JSON.
- Legacy package-level Path callers are compatibility adapters only: they mint
  a central capability before reading and cannot call the low-level projection
  directly. Capability records use weak keys so completed reads do not retain
  run roots indefinitely.
- Run detail now declares classification evidence authority as
  `server-owned`.
