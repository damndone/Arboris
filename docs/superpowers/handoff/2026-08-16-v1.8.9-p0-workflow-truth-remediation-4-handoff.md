## 本轮已收口的四个问题

### 1. 所有写入 helper 统一 receipt-gated

receipt-gated callback 在执行前安装唯一的 write context；所有会创建、注册或持久化正式 artifact 的 helper 都先验证：

- host-issued `EvidencePersistencePort`；
- 当前 `WorkflowAdmissionReceipt`；
- receipt 对应的完整 draft/step snapshot；
- workflow、target、scope、plan、step contract 没有发生 TOCTOU 变化。

因此直接调用 report、joint F test、White test、quadratic stationary point、model/post-estimation、dataset、exploration、data-management、imputation、resampling、prediction、time-series、P7 和 capability-result helper，会在任何 artifact 写入前以 `WORKFLOW_ADMISSION_RECEIPT_REQUIRED` 失败。

### 2. completion 不能消费另一个 run 的 artifact

completion 现在把 artifact 的 `run_id` 与 admitted target 的 `run_id` 绑定。跨 run 的 model branch 只有在 branch proof 同时证明 workflow、step、source run、source artifact 时才允许；普通合法 registry artifact 不能越过这个边界。

同时继续校验 project/run 所有权、registry 唯一性、相对路径、symlink/traversal、文件存在性、registry digest、binding digest 和 step producer proof。

### 3. 去掉内部伪 host key，改成真实宿主 endpoint 依赖

生产入口不再自行创建内部 host capability。新的发行边界是：

```text
issue_server_evidence_port(project_root, host_endpoint)
```

`host_endpoint` 必须由真实宿主提供，并包含：

- 与 `project_root` 一致的项目绑定；
- 实际打开的 `project_root/workbench/workflows` 目录 FD。

发行时会验证 FD 是目录、对应当前 workflows 目录，并持有该 FD 的副本。直接调用 `EvidencePersistencePort(project_root)`、缺失 endpoint、错误目录 FD、路径替换后的旧 endpoint，以及 `object.__new__` 伪造 port 都 fail-closed。

`WorkflowExecutor.execute(..., host_endpoint=...)` 与 `execute_workflow(..., host_endpoint=...)` 已提供明确接线参数；如果既传 `evidence_port` 又传 endpoint，会拒绝冲突输入。

这意味着当前没有真实宿主接线时，执行会明确返回 `WORKFLOW_EVIDENCE_HOST_ENDPOINT_REQUIRED`，不会回退到内部假 key，也不会把测试 adapter 当作生产 authority。

### 4. lock 与真实写入使用同一稳定目录域

workflow transaction 锁定 admitted directory inode；append 使用同一个 locked directory FD、`dir_fd`、`O_APPEND`、`O_NOFOLLOW`，并对文件和目录 fsync。替换 workflows path 后，FD/inode 校验会以 `WORKFLOW_EVIDENCE_PATH_CHANGED` fail-closed，不能形成第二个写入域。
