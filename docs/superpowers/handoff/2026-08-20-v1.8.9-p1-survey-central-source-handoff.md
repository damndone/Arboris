# v1.8.9 P1 Survey central source handoff

## Scope and root cause

The existing Survey model-result artifact had a server-owned manifest, file
digest, and `result_binding`, but Agent and Notebook had no shared,
capability-only consumer source. The new source adapter validates that existing
identity before issuing an opaque snapshot. It accepts the established
`ols_robust` persisted identity as the OLS family without changing estimator or
variance semantics.

## Implemented

- `survey_projection_adapter.py` issues weakly-held opaque receipt and source
  handles, accepts only Agent/Notebook catalog declarations, and preserves
  validated/degraded/unavailable status plus reason and bounded design metadata.
- `survey_consumer_service.py` accepts only a server-issued run capability,
  validates exactly one indexed Survey model artifact and its binding digest,
  then projects through the source handle. Paths, raw packets, and forged
  capabilities fail closed.
- Agent and Notebook use that same central service. `survey.json` declares the
  provider contribution and required Agent/Notebook projections.
