## Outcome

Remediation-5 replaces package-local Python proof roots with an explicit host
authority channel. Evidence accepts only a live Unix stream socket supplied by
the host boundary; it does not issue a local signing secret or infer authority
from a caller-shaped Python object. A missing or malformed handle fails closed
with `EVIDENCE_HOST_AUTHORITY_REQUIRED` before registry admission, persistence
admission, or projection success.

## Implemented controls

- `backend/workbench/evidence/authority.py` defines the external channel
  request binding and newline-delimited canonical JSON operations:
  `session`, `issue`, and `validate`. Requests bind purpose, scope, owner PID,
  session, root FD/device/inode when applicable, subject object identity, and
  payload digest. The module contains no trust secret or proof key.
- Registry construction, registry receipts, persistence admission, and
  projection views/outcomes all consume host-issued opaque proofs through that
  channel. The public factory and direct constructors fail closed without a
  host handle.
- Registry, persistence, and projection no longer use module globals as proof
  keys. Their capabilities reject `copy`, `deepcopy`, pickle, and reconstructed
  object forms; `object.__new__` field copies fail before durable reads/writes
  or consumer-visible success serialization.
- Remediation-4 FD-root identity, path, lock, concurrency, and orphan rollback
  behavior remains in place. The test host is outside the Evidence module and
  is only a socket peer fixture; it is not a production fallback.

## Host protocol integration dependency

The current Workbench host runtime does not yet provide the production
authority channel or resolver. The integration owner must pass a real
host-owned Unix stream socket to `create_server_evidence_registry` and
`EvidencePacketStoreV1.admit`, implement the `session`/`issue`/`validate`
protocol, and keep the channel outside untrusted caller construction. No
handle means fail closed. This package-local line does not claim host wiring,
catalog denominator, consumer/runtime migration, provider execution, browser
acceptance, full gate, or release readiness.
