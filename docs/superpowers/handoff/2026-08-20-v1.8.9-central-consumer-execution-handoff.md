## Implemented in this line

1. The shared server bootstrap can compose data and classification host ports
   into the same declaration-derived Agent/Notebook runtime. A missing port
   remains explicitly unavailable; a wrong port type or catalog digest is
   rejected.
2. The data host port now accepts only a typed server-issued record authority,
   fixes operation/version/source identities to the issued port, verifies the
   exact `OperationRecord` object and complete scope/snapshot/source claims,
   adapts the generic compiler request to a typed request, and rejects nested
   raw/path/rows payloads.
3. The classification host port now binds actor, project, session, snapshot,
   model, expiry, read-only effect, and required evidence to the issued input.
   It validates lowercase SHA-256 digests, accuracy bounds, canonical result
   digest, and result identity against the issued input. Logistic Regression
   and Random Forest remain the only host-port model adapters in this slice.
4. Both host paths return bounded identity/metric summaries. Raw frames,
   feature matrices, rows, and filesystem paths do not cross the generic
   provider boundary.

## Known limits and next line

- The central HTTP/Notebook/Report consumer mount still needs a separate line:
  package-local projection helpers are not proof that `/runs`, Notebook, and
  Report production routes consume the persisted evidence.
- `backend/workbench/prediction.py` still uses the legacy classification
  identity registry and passes its caller-owned frame into the package-local
  classification protocol. This line intentionally did not modify that path;
  migrate it in a separately scoped line before calling it the host-port
  production entrypoint.
- The record authority is currently an in-process typed mapping. Durable
  cross-process issuance and resolver wiring are not verified.
- Browser acceptance, real provider startup, cross-process behavior, full
  repository gate, merge, tag, release, and deployment remain `NOT VERIFIED`.
- `.sav/.zsav/.dta` interchange remains an optional-dependency boundary; no
  native file-format dependency was added here.

## Safe continuation

The next implementation line should mount persisted consumer evidence through
the central Agent/Notebook/Report production path, with a separate formal
scope for `runs_routes.py`, Notebook service/context tools, and the Report
view model. It must preserve the current fail-closed host-port contracts and
prove the complete natural-language -> compile -> proposal -> confirmation ->
execute -> evidence -> consumer rendering path before any release claim.
