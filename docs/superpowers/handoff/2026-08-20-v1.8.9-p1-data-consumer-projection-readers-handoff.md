# v1.8.9 P1 Data Consumer Projection Readers Handoff

## Delivered

- Added `DataConsumerRunCapabilityV1`, an opaque server-issued run handle
  bound to one project identity, session identity, run, and live data catalog.
- Added one central bounded data projection reader. It reads only committed
  `OperationRecord` output ports and emits operation, execution, artifact,
  source, snapshot, catalog, and evidence-digest facts. It never reads a
  dataframe or returns a filesystem path/raw evidence packet.
- Agent and Notebook now expose explicit capability-only data evidence readers
  that delegate to the same central service. The old C0 evidence compatibility
  readers remain separate and are not treated as data-operation authority.
- The Report run surface now includes `data_consumer_evidence`, its
  server-owned authority marker, and a typed projection receipt. Without an
  admitted server identity it returns `UNAVAILABLE`.
- Data-operation confirmation now writes server-owned project/session/snapshot
  and source identity claims into both sides of the durable OperationRecord so
  later consumers can bind to the exact operation context.

## Explicit limits

- The reader consumes already committed data-operation evidence; it does not
  invent or execute new operations. Existing workflow/runtime paths that create
  legacy records without the new identity claims remain explicitly unavailable
  until migrated.
- Browser acceptance, real external-provider startup, cross-process authority,
  full host startup, full repository gate, merge, tag, release, and deployment
  acceptance are **NOT VERIFIED**.
- `.sav/.zsav/.dta` remain typed `optional_dependency` unavailable when
  `pyreadstat` is absent.
