## Implementation

`backend/workbench/repository/file_integrity.py` is the single repository/file-integrity seam. It applies the server-owned bounded ASCII relative-path grammar, opens the run root and intermediate directories with `O_NOFOLLOW|O_DIRECTORY`, fstats every directory and final descriptor, rejects non-regular files, and reads/hashes bytes from the same owned FD with before/after inode and size checks.

The artifacts-index validator, `GET /runs/{run_id}/artifacts/{artifact_id}`, and classification consumer artifact/receipt reads all use that seam. Generic downloads return bytes from the opened descriptor in a plain `Response`; they no longer use a path-backed `FileResponse` after a path probe. Classification downloads return only the validated wrapper. Classification identity, receipt, split/fold/OOF/holdout, weights, calibration, threshold, evidence, and Agent/Notebook/Report typed projections were preserved. The report producer and protected predecessor formal records were not changed.

The live HTTP replacement probe lets list validation complete, then replaces the main classification artifact before the wrapper's second safe-open call. The callback actually ran twice for the target path; the second call observed the replacement and returned `ARTIFACT_PATH_INVALID` with no 200 wrapper, artifact facts, receipt, or content digests. Direct artifact and receipt consumer callbacks were patched on the live helper with `raising=True`, executed (`observed["calls"] > 0`), and failed closed before projection. Non-race symlink, missing, non-regular, digest mismatch, duplicate, path/type, and index-status behavior remains covered by the production/HTTP focus.

The artifact allowlist was intentionally unchanged. Producer-vocabulary drift is a bounded P2 follow-up for a separately scoped compatibility audit or server-owned registry; no additional constants were copied into this security seam.
