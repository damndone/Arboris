# Workbench v1.8.9 P0 Legacy/Resume Hardening Handoff

Line: `v1-8-9-p0-legacy-resume-hardening`
Base SHA: `05362b5697e10eb25fd219da003641f96eeec082`

## Delivered

- Historical Agent proposal confirmation no longer instantiates the legacy
  `WorkbenchOrchestrator`. It resolves the route-owned canonical actor,
  session, and project before any compiler lookup, then requires one
  server-owned `AgentNotebookCompilerV1` compilation record and retained
  confirmation bound to proposal id/revision/fingerprint, operation,
  semantic plan hash, and canonical scope. Absent or mismatched handles fail
  closed while preserving the legacy response envelope.
- Historical Notebook v1.0/non-materializable `confirm` and
  `confirm-and-execute` routes, plus direct service callers, now refuse before
  the old service/run authority with the typed
  `NOTEBOOK_LEGACY_COMPILATION_REQUIRED` response. The existing composed
  workflow cutover refusal uses the same code; compatibility response shape
  does not restore execution authority.
- Resume now requires persisted admission status to be exactly `admitted`.
  Every completed step is rebound to its sealed server completion, unique
  admission, persisted artifact admission, and frozen server artifact registry
  before dependency callbacks or new writes. Persisted artifact IDs, output
  bindings, lineage, and row counts must match.
- Completion seals are checked before result/row-count conversion. Malformed
  completion row counts, output bindings, lineage, attempts, and result
  metadata become typed `WorkflowExecutionError` values rather than leaking
  `ValueError` or other conversion exceptions.
- `model.custom` branches require an explicit server-owned
  `server_model_declarations[step_id]` branch-producing declaration. Family,
  outcome, predictors, and covariance are compared exactly; absent or forged
  declarations fail closed. Existing `model.genesis`/non-OLS protections remain
  intact.

## Post-review remediation

- A retained historical compilation record is now atomically bound to the
  first proposal id, revision, fingerprint, operation, semantic-plan hash,
  confirmation id, and canonical actor/session/project scope. A second
  proposal cannot reuse that record and reach `compiler.execute`.
- Historical non-`graph.fork` reconcile requests fail closed with
  `AGENT_LEGACY_RECONCILE_COMPILATION_REQUIRED` before constructing the old
  `WorkbenchOrchestrator`.
- Persisted row counts are parsed as bounded non-negative integers before
  state rehydration; booleans, floats, strings, non-finite values, and
  arbitrary-precision integers become typed `WorkflowExecutionError` values.
- Server model declarations are part of the compiled workflow binding. The
  custom gateway cannot be called until the exact step has a server-owned
  branch-producing declaration; inherited runtime fixtures were updated to
  compile that declaration instead of injecting it after compilation.

## Compatibility and limits

Legacy response keys remain explicit, but response compatibility does not
restore execution authority. Browser-visible acceptance, provider/external
runtime acceptance, the full repository gate, independent spec re-review,
release/tag/merge, and Report or estimation integration are `NOT VERIFIED` in
this package-local line. An inherited materialization test still asserts the
now-prohibited direct v1.0 `service.confirm` execution, and the broader
workflow seam suite still has 21 stale fixtures missing `active_head_run_id`;
neither is used as focused P0 acceptance evidence.

No Report, estimation, provider, browser fixture, or release file is in scope.
