## Implementation

`backend/workbench/http/runs_routes.py` now owns
`_parse_artifact_range_header`. The generic
`download_artifact_endpoint` no longer calls or references Starlette's private
`FileResponse._parse_range_header`, and it does not construct a path-backed
response. The parser bounds the Range header to 64 KiB and the range count to
64 before materializing ranges, preserves byte suffix/open-ended ranges,
single-range and multipart-range merging, and keeps explicit malformed `400`
and unsatisfiable `416` responses.

The existing generic artifact stream remains the same-FD bounded
`StreamingResponse` path: 64 KiB maximum chunks, 512 MiB maximum artifact
size, descriptor-owned generator cleanup in `finally`, and fail-closed
read-time device/inode/size checks. `If-Range` accepts the existing ETag or
`Last-Modified` value and falls back to a full `200` stream when stale. MIME
`Content-Type`, attachment `Content-Disposition`, `Content-Length`,
`Accept-Ranges: bytes`, `Last-Modified`, and ETag remain present.

`FileResponse` remains imported only for unrelated existing report/export
endpoints (`get_report_endpoint` and `export_result_table_endpoint`). The
generic artifact route itself has no `FileResponse` or private range-parser
reference. The list/index/classification consumer seams, 500/503 boundaries,
and typed contracts were not changed. The remediation-15 residual whole-body
`consumer_projection` consumer is unchanged and explicitly outside this
generic-download line.
