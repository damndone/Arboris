## 结论

本开发线完成了 v1.8.9 P1 的“数据消费层基础”切片：数据来源、类型、敏感性、过滤、操作描述、预览/确认和受限上下文出口现在有了可验证的契约。实现仍然保持在包内边界，没有把尚未完成的生产级 Agent/Notebook 自然语言执行接入中央注册表或执行器。

## 已实现

### 数据正确性与安全边界

- 增加有内容哈希、运行/节点/产物身份和 schema/metadata revision 的 `DataProfileV1`。
- 区分 observed、declared、inferred metadata；未知或受限敏感性默认不向消费方泄露样本值和分位数。
- 增加封闭的 typed filter AST，支持比较、集合、区间、缺失值以及布尔组合；有深度、节点数、列表长度和整数位数限制；不使用 `eval` 或 pandas `query`。
- 数据操作 manifest 现在包含完整 descriptor、输入/输出端口、风险与确认级别、预览/确认引用、重放身份、请求 schema digest 和输出身份字段。
- provider descriptor 绑定 live manifest/registry surface 的实际摘要；当前只用于发现和契约校验，不是运行时加载器。
- `project_root` 基础校验拒绝 symlink，并要求存在 `runs` 目录。

### 数据消费与操作流程

- 提供 profile、manifest、metadata-loss preview、operation preview/confirm 的 HTTP 路由。
- profile 路由从服务端 run 输入读取标签，避免客户端伪造来源标签。
- FeatureRecipe/Transform 的确认流程增加本地 ProposalStore 校验：绑定来源身份、预览指纹、来源/辅助数据哈希和 active chain head；确认时要求 human UI actor。
- 增加有界的 C0 ContextEgress：服务端拥有 dataset identity，拒绝字符串身份、直接传入 ContractRef、敏感/未知列和 remote raw；原始行只允许明确的本地安全类型并受预算限制；instructions 为不可变 JSON-compatible 结构。
- metadata-loss 目前是预览契约，能说明目标格式会丢失哪些元数据；实际导出和确认仍留给后续 exporter 线。

### UI 与 Agent/Notebook 适配面

- 增加 schema-driven 的通用 `DataOperationsSection` 和严格 manifest parser，支持以后按 descriptor 自动生成控件，不把操作名称写死在 UI 组件里。
- UI 目前未挂载到中央 `sectionRegistry`，因此本线没有改变现有页面行为。
- 增加 draft-only Agent/Notebook provider/operation fixtures，供发现、契约和后续适配使用；`execution_allowed=false`，没有生产级自然语言执行入口。
