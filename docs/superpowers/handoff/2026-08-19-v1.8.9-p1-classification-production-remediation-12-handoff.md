## Exact implementation tip

`backend/workbench/repository/run_repository.py` now imports the existing
`sha256_file` helper. After canonical record shape, digest, and normalized path
validation, `_validate_artifact_record` resolves the indexed path, requires
`Path.is_file()`, hashes the actual bytes, and requires exact equality with the
indexed lowercase SHA-256. Missing, non-regular, unreadable, and content-
mismatched artifacts raise the existing validation path and are mapped by
`_read_artifacts_index` to `ARTIFACTS_INDEX_INVALID` / HTTP 500. The index read
boundary catches `OSError` separately and maps an absent or unreadable
`artifacts_index.json` to `ARTIFACTS_INDEX_UNAVAILABLE` / HTTP 503; malformed
JSON remains `ARTIFACTS_INDEX_INVALID` / HTTP 500. The HTTP route therefore
cannot group or serve records before these repository checks complete.

The valid `formal_output` fixture writes real `{}` bytes and records
`sha256(b"{}")`; controlled monkeypatches exercise unreadable index and
unreadable regular-artifact behavior without relying on root chmod semantics.
Existing canonical type, required-field, duplicate, path-containment, digest
shape, malformed JSON, and classification identity/projection coverage remains
unchanged.
