## Outcome

The Report consumer now has a fail-closed typed evidence boundary. An indexed
post-estimation artifact without an explicitly parseable committed
`EvidenceCommitBindingV1` and matching `EvidenceEnvelopeV1` produces a typed
`UNAVAILABLE` projection with a reason code. A malformed or digest-mismatched
canonical pair produces a typed `BLOCKED` projection. Neither path copies raw
result fields or recursively extracts scalar leaves.

The run detail route exposes `report_evidence`. `ReportWorkspaceContext` parses
that server-owned projection, builds citable post-estimation facts only from
its bounded typed facts when status is `available`, and passes the projection
through the real `ReportView` to `FamilyEvidence`. The renderer shows status,
envelope digest, commit/provenance and bounded facts. The old model-result and
artifact props remain available for legacy direct callers, but the real
ReportView path does not pass or render them as FamilyEvidence.

The follow-up hardening removes the report-local binding/envelope fake ports.
`ServerOwnedReportEvidencePersistenceV1` accepts only exact
`EvidencePacketStoreV1`, `EvidenceRegistryV1`, and a registry-issued
`EvidenceRegistryReceiptV1`, plus a run-scoped owner identity. Its bound read
first resolves the requested artifact through the registry, then loads the
commit and packet through the real store and rechecks the commit, artifact,
complete C0 content hash, admission ref, receipt, and run identity before the
typed consumer projection can select facts. `runs_routes` injects only the
configured server-owned capability; missing or wrong-run capability is typed
fail-closed. A run index may carry only the commit/admission/content identity;
the canonical binding/envelope is loaded from owner persistence. If a copied
binding/envelope pair is placed under a foreign artifact id, the registry
rejects it as `EVIDENCE_ADMISSION_NOT_FOUND`. Multi-artifact bundles now expose
no facts when their top-level identity is not a single canonical projection.
