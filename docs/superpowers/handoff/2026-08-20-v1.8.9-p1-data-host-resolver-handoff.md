# v1.8.9 P1 Data Host Resolver Handoff

## Delivered

- Added `ServerOwnedDataConsumerHostResolverV1` and the application bootstrap
  seam `data_project_root`.
- The server binds one absolute project root, project identity, session
  identity, and live catalog digest at bootstrap. Agent/Notebook runtime input
  remains an opaque identity mapping; rows, frames, paths, and raw payloads
  are rejected.
- Durable data operation records are matched by exact scope, run, snapshot,
  operation, and optional source identities. Missing, stale, ambiguous,
  incomplete, or malformed state returns a typed unavailable/error result.
- Completed records are rehydrated only into
  `DataConsumerRuntimeOutputV1`; the generic provider boundary receives no
  operation paths, rows, or evidence packet.
- The builtin data provider now declares one identity-bound projection for
  each of Agent, Notebook, and Report. Coverage tests include the additional
  declarations.

## Explicit limits

- This line resolves already committed data-operation evidence; it does not
  claim that the generic provider can invent or execute a new data operation
  without a separately compiled/confirmed operation record.
- Agent/Notebook/Report data projection readers and Report/HTTP/frontend data
  consumer mounting remain the next P1 integration slice.
- Browser, real provider, cross-process authority, full host, full repository,
  merge, tag, release, and deployment acceptance are **NOT VERIFIED**.
- `.sav/.zsav/.dta` remain typed `optional_dependency` unavailable when
  `pyreadstat` is absent.
