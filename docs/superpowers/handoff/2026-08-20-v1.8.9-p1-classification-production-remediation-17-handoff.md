## Implementation

`backend/workbench/http/runs_routes.py` retains a Workbench-owned
`_parse_artifact_range_header`; the generic artifact route does not call
Starlette's private `FileResponse._parse_range_header` and does not construct a
path-backed response. The parser retains the 64 KiB header and 64-component
bounds, suffix/open-ended ranges, single-range and multipart handling, and the
existing malformed `400` and unsatisfiable `416` boundaries.

Range components now require strict ASCII decimal grammar. A malformed
component or malformed range-set, including `garbage`, `+1-2`, an empty
component, or reversed bounds, is rejected as malformed and is never silently
dropped. Syntactically valid but unsatisfiable components are filtered only
when another syntactically valid component is satisfiable, so
`bytes=0-1,999-1000` for a ten-byte file returns `[(0, 2)]` and `206`; `416` is
returned only when every valid component is unsatisfiable. A bounded decimal
conversion failure also maps to the same malformed boundary instead of leaking
a conversion exception.

The existing generic artifact stream remains the same-FD bounded
`StreamingResponse` path: 64 KiB maximum chunks, 512 MiB maximum artifact
size, descriptor-owned generator cleanup in `finally`, and fail-closed
read-time device/inode/size checks. Single and multipart ranges, `If-Range`,
MIME `Content-Type`, `Content-Disposition`, `Content-Length`,
`Accept-Ranges: bytes`, `Last-Modified`, ETag, and the existing 400/416
semantics remain covered. `backend/workbench/repository/file_integrity.py` is
unchanged in this line.

The list/index/classification consumer seams, 500/503 boundaries, and typed
contracts were not changed. The remediation-15 residual whole-body
`consumer_projection` consumer is a separate path and remains explicitly out
of scope.
