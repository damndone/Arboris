## Implemented

### One typed Agent/Notebook semantic boundary

- `AnalysisIntentV1` is the only semantic input accepted by the new compiler.
  It has a closed effect/sensitivity vocabulary, server-neutral intent identity,
  data snapshot binding, resource budget and explicit clarification fields.
- Unknown intent fields are rejected. Raw prompt/code/path-like payload keys do
  not become durable plan configuration.
- `CutoverCapabilityCatalogV1` derives capability descriptors from the provider
  catalog and joins every declaration to a trusted runtime contribution.
  Discovery is identity/catalog based; no model-family or capability-prefix
  switch was added.
- `TrustedExecutorRegistry` accepts only server-composed opaque executor IDs,
  checks owner/signature/effect/contracts and performs a one-to-one catalog join.
  Provider manifests cannot import a module path or supply a callable.

### Server-owned planning, confirmation and evidence

- `AgentNotebookCompilerV1` implements:
  `AnalysisIntent -> clarification -> CompilationRecordV1 -> preview/PlanDiff ->
  server confirmation -> ExecutionAdmissionV1 -> trusted provider dispatch ->
  evidence commit -> completed`.
- The semantic plan hash is separate from the execution-instance hash.
- Execute accepts a server record ID and a server-issued confirmation receipt;
  client-shaped compiled workflows and forged confirmation dictionaries are
  rejected.
- Data snapshot changes, actor/session/project mismatches and missing evidence
  prevent completion.
- `CutoverOperationStoreV1` is a typed monotonic lifecycle projection with
  race/terminal/evidence checks.
- The planning/admission effect vocabulary bridge is explicit: `read` maps to
  `read_only`, model effects map to the model-fit admission class, and invalid
  effect changes remain rejected.

### HTTP and Notebook adapters

- `backend/workbench/http/agent_routes.py` exposes server-bound compile,
  confirm and execute endpoints under `/agent/cutover/...`.
- Startup must explicitly register a compiler for a `(project_ref, session_ref)`
  scope. An unbound scope returns a typed 503; there is no legacy fallback.
- Confirmation objects are retained server-side and are never accepted from a
  client as authority. Actor, session and project scope are checked against the
  compilation record.
- `NotebookAnalysisRecipeV1` stores the shared intent, compilation record,
  semantic hash, diff, confirmation/operation/artifact/evidence references and
  rerun prerequisites. `NotebookSharedPlannerV1` delegates to the shared
  compiler instead of maintaining a second capability table.

### Typed UI evidence mounts

- `sectionRegistry` now has a declaration-derived `dataConsumerEvidence`
  section and stable renderer identity
  `renderer:data-consumer-evidence.v1`. It renders only approved status,
  evidence-grade and lineage fields; unknown shapes show `UNAVAILABLE`.
- `ReportView` has a typed classification-evidence mount. It accepts only
  `workbench.prediction.classification-evidence` schema version 1, supports the
  known persisted envelope shapes, and never dumps arbitrary payload JSON.
- Existing registry identity/order tests were updated append-only to include the
  new declaration.

## Explicit limits / follow-up boundaries

These are deliberate fail-closed boundaries and are not hidden fallbacks:

1. The default HTTP process does not invent provider runtime contributions. The
   fixture runtime is injected by tests; production startup still needs a
   server-composed provider binding. An unbound runtime returns `503`.
2. The historical `/notebooks` route still uses the legacy
   `NotebookPlanningAgent`/`NotebookService` lifecycle. The new shared seam can
   be called with `entrypoint="notebook"`, but this line does not claim that all
   historical Notebook callers are migrated.
3. `workflow_runtime.py` still contains a protected direct
   `execute_with_context()` caller. Therefore this line does not claim a unique
   global ExecutionAdmission choke point for every historical runtime path.
4. Existing C0 compilation/confirmation/egress stores are process-local in this
   seam. Durable restart recovery and one-time receipt consumption require the
   foundation integration line.
5. The report mount consumes an explicitly supplied
   `familyEvidenceArtifacts.classification_evidence` packet. The existing
   ReportWorkspaceContext artifact loader does not yet discover that new packet
   automatically; adding that loader and the actual legacy DataOperations
   adapter is a follow-up integration slice. Missing data is shown as
   `UNAVAILABLE`, never recomputed.
6. No statistical formula, model fitting, provider benchmark or external call
   was added in this cutover line.
