## 0. 一句话

`merge` / `append` / `reshape` / `subset` 与 feature recipe 的后端**已经完备且会提交 lineage**，
但**没有注册成 Agent 操作**，所以自然语言够不着。本版把它们接进去。

**为什么要紧**：产品主线是「上传数据 → 一句话说想干什么 → Agent 出方案 → 批准 → Agent 自己跑完」。
只要数据需要先 reshape 或 merge 才能建模，这条链**在第一步就断**——用户得手动去 UI 做完转换
再回来找 Agent。v1.8.7 的发布说明已把这条写进「已知限制」，本版是它的兑现。

**缺的不是能力，是注册。** 这一点决定了工作量分布：不写统计代码，写契约与接线。

## 3. 现状事实（已核实，别再重新考古）

**后端完备。** `apply_data_transform` 与 `apply_feature_recipe_operation` 都会：写 artifact →
写 recipe json → `_ensure_registered_artifact` → 提交 graph 子节点 → `_ensure_node_index_entry`。
lineage 是完整的。

**Agent 操作词表**（`OperationRegistry.operation_ids()` 的真实输出，共 16 条）。
其中**顶层可提议**的只有 8 条：

```
model.rerun   model.genesis   model.custom(关)   graph.fork
data.column.cast   data.columns.cast   code.execute(关)   operation.multi_step
```

另外 8 条是 workflow step 身份（`statistical.explore` / `statistical.derive_boolean` /
`statistical.derive_numeric` / `statistical.derived_group_summarize` / `model.joint_f_test` /
`model.white_test` / `model.quadratic_stationary_point` / `report.compose`），
它们注册是为了让 dispatcher 能校验和执行，**不是独立的提议面**——
拿它们去 `inspect_operation_contract` 会被 `context_tools.py:1368` 明确拒绝。

> 别用 grep 字符串字面量来盘这张表。本文初稿就是这么盘的，多算进了
> `data.cleaning` / `analysis.explain` / `analysis.suggest` / `workspace.arbitrary`
> 四个**根本没注册**的字符串。用 §9 的命令问注册表本身。

**`operation.multi_step` 的 step 词表**（`workflow_contracts.workflow_step_vocabulary()`）只有十个：

```
statistical.explore   statistical.derive_boolean   statistical.derive_numeric
statistical.derived_group_summarize                model.genesis
model.joint_f_test    model.white_test             model.quadratic_stationary_point
report.compose        model.custom
```

→ **数据转换在两张表里都不存在**。这是全部的缺口。

**发现工具的缺口是真的，且已精确定位。** `inspect_project_dataset_schema`
（`context_tools.py:1674`）只吃一个 `run_id`，读的是**那一个 run** 的
`staged/data_profile.json`，返回列名/dtype/缺失率/唯一值数。它**不**枚举项目里有哪些数据集节点，
**不**返回 `artifact_id`，**不**跨 run。而 `merge` / `append` 需要
`secondary_run_id` + `secondary_node_id` + `secondary_artifact_id` 三元组。
**Agent 目前无从得知第二份数据在哪。** 这是本版必须新造的东西，不是补个字段。

**一条容易误判的**：仓库里有 `inspect_repeated_measures_recipe` 和
`frontend/src/workbench/repeatedMeasures/`，那是**用 LMM 做重复测量**的 recipe，
不是经典 RM-ANOVA。别把它当成「重复测量已经有了」，也别当成 bug。

## 4. 要做的事（六块）

### B1 — 两个 OperationDefinition

在 `agent/operations.py` 注册：

- `data.transform@v1` — 覆盖 `merge` / `append` / `reshape` / `subset`
- `data.feature_recipe@v1` — 覆盖五个 recipe

每个都要有：`proposal_schema`（**LLM 实际读的那份**）、`editable_schema`、`validator`、
`vocabulary_builder`（把 merge 的 key 契约、append 的 schema_policy 等封闭值集讲清楚）。

⚠️ **`scope_requirements` 必须含 `"chain"`**，理由见 `operations.py:245` 那段注释。
⚠️ **`proposal_schema` 与 `editable_schema` 是两份东西**，v1.8.7 在这上面栽过（§7.2）。

### B2 — orchestrator 接线

`agent/orchestrator.py`：新增 `_data_transform_spec` / `_prepare_data_transform_effect`
（及 feature recipe 的对应物），并在**四处**分发点各加一个分支。
把两个新 operation_id 加进 `_DATA_CHILD_NODE_OPERATIONS`（第 81 行）。

### B3 — 发现工具（本版技术难点）

新增一个工具，让 Agent 能回答「这个项目里有哪些数据集节点、各有什么列、它们的
`(run_id, node_id, artifact_id)` 是什么」。没有它，`merge` 在自然语言下**不可能**被正确提出。

设计要点：
- 有界（v1.8 系列反复被摘要超预算咬过，参考现有工具的 `[:64]` 截断与 `omitted` 计数）
- 返回的 id 三元组必须是**能直接填进 spec** 的，不是让模型拼
- 工具**描述**要写明边界——模型只看得到描述

### B4 — diff / verification builder

复用 `data.schema_diff.v1`（`orchestrator.py:978` 附近）还是新造一个 kind，自行判断。
merge / append 改变的是**行数与来源**，reshape 改变的是**形状**，schema diff 未必说得清——
这是需要设计判断的地方，别无脑复用。

### B5 — 前端

`AgentPanel.tsx` 的 `changeSummary` 加分支，让新提议读起来是人话而不是 JSON dump。
UI 字符串**全英文**。

### B6 — 测试

- 契约层：两个 operation 的 schema / validator / vocabulary
- 执行层：四处分发各走通一次，含 stale preview 被拒
- **消费者守卫**：见 §7，这是本版最容易做假的地方
- 真机：真 DeepSeek 一句话 → 提议 → 确认 → 执行 → lineage 子节点，浏览器里走一遍

## 7. v1.8.7 的教训：验证的不是消费者读的那份 ⚠️

同一个失效模式在上一版复发**五次**，**每次全套测试都是绿的**。逐条抄在这里，因为本版
（改的是契约与接线，不是算法）**极易复发**：

1. 我验证了 `RunForm`，用户实际打开的是 `GenesisWizard`
2. 我对齐了 `editable_schema`，**LLM 读的是 `proposal_schema`**——模型根本发不出那些字段，
   而我自己写的一致性测试读的也是错的那份
3. 我测了 provider 方法存在、`ToolDefinition` 引用了它，而**注册的 handler 每次 live 调用都
   TypeError**（相对 import 深一层 + 少传一个参数）；DeepSeek 撞了两次自己绕开了，没有任何测试发现
4. 我测了「Agent 能提出」，没测「Agent 能读到结果」——两个半边，只做了一半
5. 守卫按族名写，实际该按 shape 写

**规则**：写守卫时先问一句「**谁真的会读这份东西**」，然后让测试走那条路径。
不要断言「方法存在」，要断言「调用它有正确结果」。

另一个只有**真机浏览器 run** 才抓到的：截距项因名字不匹配（`Intercept` vs `(Intercept)`）
被静默 `continue`，SE 用了朴素值 0.7804 而不是 R 的 1.5955。测试全绿、run 成功、报告正常。
**所以 §6 里的端到端真机验收不是走过场。**

还有一条流程坑：我曾在面板里**确认了错的（旧的）提议**，导致那一轮验收作废。
真机验收时，确认前核对提议内容与你刚发的那句话对得上。

## 8. 本版不做什么

- `code.execute` / `model.custom`（Agent 自研能力）——用户既定决定，保持关闭
- 通用 `tsset` 与滞后算子——是数据管理的缺口，但属于时间序列线，不在本版
- C 类多元统计（PCA / EFA / Cronbach's α / 聚类 / 判别 / SEM）——完全空白，是候选的 v1.8.9
- P1-5 时间序列（ARIMA/SARIMA、单位根、协整、VAR/VECM、Granger、IRF）——缺口最深，量最大，另开
