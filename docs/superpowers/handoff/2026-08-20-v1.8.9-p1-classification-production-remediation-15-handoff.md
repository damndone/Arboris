## Implementation

`backend/workbench/repository/file_integrity.py` remains the single server-owned
path/open/fstat seam. It now declares `MAX_ARTIFACT_STREAM_CHUNK_BYTES = 64 KiB`
and `MAX_ARTIFACT_STREAM_BYTES = 512 MiB`. Generic download hashing and body
iteration use the same safely opened descriptor, bounded `os.pread` chunks, and
stable device/inode/regular-file/size checks. Oversized files, short reads,
read-time size changes, and iterator errors fail closed. The stream generator
closes the descriptor in `finally` on success, normal exhaustion, hash/open
failure, and read failure.

`GET /runs/{run_id}/artifacts/{artifact_id}` now returns a
`StreamingResponse` for generic artifacts and restores the compatibility
surface: MIME `Content-Type`, attachment `Content-Disposition`, exact
`Content-Length`, `Accept-Ranges: bytes`, `Last-Modified`, and ETag. It
supports single and multipart byte ranges, `If-Range` fallback, explicit 400
malformed-range responses, and 416 unsatisfiable-range responses with
`Content-Range: bytes */size`. It does not call `read_bytes_and_sha256`, use a
path-backed `FileResponse`, reopen the path, or build a whole response body.
Existing classification wrapper routing, index/list validation, typed consumer
seams, digest/path/type/duplicate/non-regular checks, and 500/503 boundaries
remain unchanged.
