## Corrections

- Completion v2 contains counts and a versioned int64-position byte fingerprint,
  not positional JSON arrays. Panel evidence publishes vectorized descriptive
  summaries and residual fingerprints, not all residuals/group rows in JSON.
- Array fingerprints bind version, dtype and shape plus C-order bytes. Strided
  arrays are streamed in bounded contiguous buffers; no full Python scalar
  expansion. This deliberately creates a new fingerprint version, not a claim
  that the old canonical-JSON hash is byte-identical.
- Source binding reads the import registration and fingerprints live columns;
  it does not decode a second source or compare two copied frames. LMM retains
  its admission-gated writer and execution validation.
- AR is absent from the default IV path and is explicitly not computed. The
  machine completion gate continues to withhold complete weak-IV inference.
  The explicit library entry is `first_stage_strength(context, spec,
  compute_ar=True)` (or the direct AR functions). No model call is involved.
- IV diagnostics reuse the first-stage computation already in the checks receipt.
- Replay fixtures retain one KM, one RMST and one log-rank. Gzip archives bind
  their packed checksum and decode to the original registered-byte checksum.
  Full originals remain in ignored local storage; tolerances are unchanged.

## AR authorization and arithmetic boundary

The authorization is the human reply to `call_1176e84630e2473297ec40585bf190b4`:
“扩大本版范围，补齐 AR 置信集合的全局认证”. It authorizes that scope exception,
not unconditional AR computation on ordinary IV fits. The date in the objective
is a recorded decision date; the quoted reply identifies the actual authority.

The proposed NumPy QR/sufficient-statistics implementation performs exact
rational/Sturm algebra only on the small reduced polynomial. It explicitly
reports `input_topology_certified=False` and arithmetic over **rounded sufficient
statistics**, not exact original-observation rationals. Ill-conditioned designs
are withheld. Acceptance of this narrower on-demand experimental scope is
pending the user's explicit choice. The prototype is saved outside production
as `local/perf-regression-2026-10-20/ar-vectorized-proposal.patch` (SHA256
`cc4f999a536fcc85b0bf88ebeb7c7bba670b7560411ebab9113ec8baed7b6170`).
Production keeps the previous exact-input implementation on explicit requests;
vectorized exact-input reduction is not being claimed as implemented.
The existing R/Stata numeric tolerances and the exact hand example remain fixed.

## Compact JSON investigation — no serializer change

`artifacts.write_json` still uses `indent=2`; this investigation does not change
it or rewrite historical artifacts.

| Identity / reader | Consequence of compact serialization |
|---|---|
| `artifacts.register_artifact` / `sha256_file` | Every changed artifact byte digest changes, even when parsed values agree. Index records must bind the bytes actually written. |
| Native completion `diagnostic_artifact_sha256`, source SHA and LMM `terminal_sha256` | Re-serialization invalidates existing byte bindings. Referencing companions cannot be retained unchanged. |
| Pinned FD readers, terminal receipts and content-addressed diagnostic paths | Byte digests, receipt identity and digest-derived paths must remain consistent; the LMM writer uses its own contract and must not be implicitly reformatted. |
| `agent.context_compiler.read_completion_artifact` and result adapters | They parse JSON independently of whitespace, but verify the registered raw-byte digest first; changed files with an old index fail verification. |
| Approval/evidence packets and persisted provenance referencing artifact SHA | New artifact hashes propagate into their bindings; old approvals must not be silently rebound. |
| `sha256_canonical(payload)`, canonical plan/operation/research-specification fingerprints | Unchanged when the parsed values and canonical algorithm are unchanged. File-byte hashes and canonical object hashes are distinct. |
| Replay fixture manifests, byte-identity tests and exports containing evidence SHA | Raw checksum manifests and displayed references need the corresponding new hashes; never regenerate historical evidence to hide a mismatch. |

An in-memory formatting-only comparison (no file rewritten) on a repaired panel
run gave primary JSON 1909→1533 bytes, completion 3094→2537, index 8798→6703.
Both byte hashes changed in each comparison. These small artifacts do not show
an across-the-board 2x saving: the saving depends on nesting and row counts.
A future decision could apply compact JSON to **new writes only**, retaining
old readers and hashes. That serializer change requires the user's decision.
