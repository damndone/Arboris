### Finding 11 in detail

`scripts/evidence_identity.py` (stdlib only) builds one key from:

- the working tree as it is on disk: every tracked and untracked-not-ignored file, so staged,
  unstaged and new files all count;
- the test interpreter, OS and architecture;
- every installed distribution, compared with `constraints/python-environment.lock`, with
  missing, unlisted and different versions listed;
- dependency locks (pyproject, npm, Cargo), native build receipts (`verify_build` for every
  module and variant) and tool versions;
- the caller's test selection, inputs and threshold version.

`key_sha256` changes when any of these changes. It is used in three places:

- **Gate.** `init` digests the tree and `finish` records the key and digests it again. A tree
  that changed during the run fails the gate. An unreadable identity, or a lock mismatch,
  marks `evidence_status: incomplete` and leaves the test verdict alone.
- **`perf_1m --ab`.** The key is recorded for both lanes with threshold version 2 (footprint
  gate, RSS reference). The run fails when the candidate tree changed during it.
- **`perf_native_io`.** Same as `perf_1m --ab`. Since the review, this script already failed
  the whole run on a worker failure and archived that sample (`preserve_failed`).

Not done: an offline rebuild of the environment. The lock pins versions; reinstalling from it
needs the package index or a wheelhouse, which this change does not provide.

### Review fixes (self-review)

- Finding 8: a caller's `estimator_factory` was identified by its qualified name only. Two
  closures of one factory with different parameters shared an identity, so the cache could
  return the wrong model. Now the factory builds the estimator once and the identity records
  its type and `get_params(deep=True)`. Without `get_params`, the instance attributes are used
  (its repr if it has none). A value whose repr holds a memory address never matches, so that
  model is recomputed rather than reused. A first version used the repr for every
  estimator without `get_params`; `test_identity_cache_graph_v186` caught that this broke
  cache reuse for a stable custom estimator. The
  production path passes no factory; the built-in parameter table stays, guarded by its
  parity test.
- Finding 7: the index was invalidated only when the log got shorter. A log deleted and
  written again by another stream (run deletion uses its own instance) reused stale offsets.
  The index now also resets when the file's inode changes. Known limit: a filesystem that
  reuses the inode at once (common on ext4, not APFS) defeats the inode check, and a
  same-or-longer rewrite on such a filesystem would still be missed.
