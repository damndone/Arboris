# v1.8.12 第 6 步验收：合同分层（V1812-CONTRACT-LAYERING，P2）

日期：2026-10-08。分支 `workbench-v1.8.12`，devline `v1-8-12`。

## 问题

模型族合同表（`ModelFamilyContract`、`MODEL_FAMILY_CONTRACTS`）定义在 `agent/workflow_contracts.py`，下层反向依赖 Agent 层：

- engine（能力目录、估计阶段）、orchestrator、admission 都要导入它。
- 运行事件 `events.py` 与 `exploration_log.py` 的 JSONL 存取工具也在 `agent/storage.py` 里。

分层守卫测试先写，重构前列出 12 处向上导入：

| 模块 | 导入 |
|---|---|
| `engine/capabilities.py`（3 处） | `agent.workflow_contracts.MODEL_FAMILY_CONTRACTS` |
| `engine/stages/estimation.py`（2 处） | 同上 |
| `orchestrator/__init__.py`（1 处） | 同上 |
| `admission.py`（2 处） | 同上 |
| `events.py`（2 处） | `agent.storage` |
| `exploration_log.py`（2 处） | `agent.storage` |

## 实现

- **`contracts/model/family.py`**（新，950 行）。从 `agent/workflow_contracts.py` 按 AST 精确搬出 39 个顶层定义：
  - `ModelFamilyContract` 及其构建器、校验器类型。
  - 各族的参数构建器、数据与选项校验器。
  - `MODEL_FAMILY_CONTRACTS`、`MODEL_FAMILY_SPEC_FIELDS`、`model_family_contract`、`family_context_columns`。
  - 两个封闭取值集 `WORKFLOW_SPLIT_KINDS`、`DID_MODE_VALUES`。
  - 跨包调用的私有 `_validate_family_options` 改为公开的 `validate_family_options`。
  - `agent/workflow_contracts.py` 从 4165 行降到 3207 行。
- **留在 Agent 层**：
  - Genesis 运行级参数 `genesis_run_params`。
  - 多重插补与分组运行的运行级校验。
  - Notebook 常量与 `notebook_workflow_capability_ids`（它读 Recipe 合同，属于工作流层）。
- **`contracts/model/result_shapes.py`**：结果形状注册表随合同表下移（`git mv`）。
- **`contracts/common/errors.py`**：`OperationValidationError` 移到这里。
  - `agent/operations` 与 `workbench.agent` 继续导出同一个类，所有 `except` 不受影响。
- **`workbench/jsonl_store.py`**：原 `agent/storage.py`（`git mv`）。
  - `events.py` 与 `exploration_log.py` 原先为避开 agent 包初始化的循环才延迟导入，现改为普通顶层导入，并删去过时注释。
- **导入改写**：所有导入方都改为直接从新位置导入，共 13 个后端文件与 20 个测试文件，混合导入按名拆分。
  - 用同一个按模块解析的 AST 改写工具完成，不留兼容转发层。
  - 一处测试原先打桩旧模块路径（`test_pipeline_drafts_genesis`），改为打桩 `family`，否则测试会悄悄失效。

**4 个失败**：

1. **族名棘轮**：`agent/workflow_contracts.py` 的 26 处族名都是合同表里的声明，随表移入 `contracts/model/`（族自有层）。基线同步删去该条，总数 165 → 139。
2–4. **`test_devline_enforcement` 三项**：它们以子进程启动 `scripts/devline_control.py`，找不到 `workbench`。
   - 原因：共享虚拟环境的 editable 安装（`__editable__.local_econometrics_workbench-0.1.0.pth`）仍指向 2026-10-07 已存档移除的 `workbench-v1.8.6` worktree。
   - 这暴露了一个更早就存在的问题：在此之前，凡是不自带 `PYTHONPATH` 的子进程测试，导入的都是 **v1.8.6 的代码**，并不是当前分支。
   - 修复：`tests/conftest.py` 让本仓库的 `backend` 排在每个子进程 `PYTHONPATH` 的首位。
   - 新增 `tests/test_subprocess_imports_this_checkout.py`：先写失败（`ModuleNotFoundError`），修复后通过。
   - 共享虚拟环境本身未改动，它由所有 worktree 共用，不应指向其中任何一个。
