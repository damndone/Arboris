## Stata oracle (Stata 18 MP, batch mode)

On Stata's own `auto.dta`: `regress` (coefficients, SE, R², N), `vce(robust)` (HC1), `logit`
(coefficients, SE, log likelihood), `ttest, unequal`, `summarize, detail` (percentiles, variance,
skewness, kurtosis), `tabulate`, `recode`, and the labels Stata saved — all within 1e-6 relative
(logit SE 1e-4). Stata opens what Workbench exports in formats 117, 118 and 119, with Unicode
variable and value labels and declared missing codes. The user's own 19 `.dta` files (local only,
never committed) summarize identically: N, mean and sd of every numeric variable.

Found by the oracle: `summarize_detail` had no variance, skewness or kurtosis; the default `.dta`
was format 119, which Stata 14 cannot open (now 118, Stata's own default).

## Baseline regression (the 17 step-7 cases plus the two-turn case, with confirmation)

18/18 pass their checks; every executed operation completed except one, which exposed a bug:

- **Identical rows were dropped by the automatic cleaning stage.** A women-only logit on three
  columns (union, education, female) had 24 distinct combinations among 176 respondents; cleaning
  dropped the other 152 as "duplicates" and the run was refused for too small a sample. In survey
  and micro data identical rows are distinct people; neither Stata nor SPSS drops them. Fixed:
  rows are kept and a `DUPLICATE_ROWS_KEPT` notice tells the user; removing true duplicates is an
  explicit Dedupe, recorded in the ledger. Present since early releases.
- The integrity rule made the Agent question an explicit request to keep ages 25–55 instead of
  proposing it. Relaxed: an explicit request with no result-seeking motive is proposed as asked
  (the confirmation and ledger record it); a change the Agent suggests still needs its reason.

- **A missing covariate crashed any survey-design regression** (found while re-fixturing a test
  after the duplicate fix). The design variance used every row while the point estimate used
  complete cases. Fixed: both use the complete-case sample (Stata's `svy` default); standard
  errors equal R `survey::svyglm` to 12 digits, and the pre-filtered-design notice counts the rows
  lost to missing values.
- The Cox oracle fixture had been computed in R on `unique(df)` to match the duplicate dropping;
  it is now `coxph` on all 64 rows (agreement ~1e-15).

Re-run after both fixes: the women-only logit completes with N = 176 and the education
coefficient and SE equal statsmodels exactly; the age-restricted OLS is proposed directly and
completes.

## Follow-up: numbers the Agent may not compute, provider retries, SPSS oracle

**Numeric check** (`agent/numeric_grounding.py`). The Agent had rounded 0.09849 to
0.099 and written 5.1234 − 4.0221 as 1.100. It now has a `calculate` tool for
arithmetic, and every decimal in a reply is checked before it is shown: it must
equal a number the model was given, correctly rounded to the digits written, or
a `calculate` value whose operands are themselves supported. A failing reply is
withdrawn (kept under Reasoning) and rewritten once; a rewrite that still fails
is shown with a warning naming the numbers; a check that cannot run says so.

Found while verifying it live:

- after a withdrawn draft, DeepSeek answered HTTP 400: in thinking mode a
  second answer inside a turn that used tools requires the private
  `reasoning_content` to be sent back. The rewrite request is now a new
  user-role turn (never shown as the user's words). Forced-failure live run:
  3/3 rewrites completed;
- "p … 远低于 0.05" was flagged: worded thresholds (低于, below, less than, …)
  are now recognised like `<`;
- hexadecimal ids such as `1e99999999` parsed as numbers and overflowed; the
  evidence parser now ignores digits attached to letters;
- **grouped statistics never reached the Agent**: `summarize` by group was
  projected as `"[omitted: nesting limit]"`, so "mean wage by sex" could not be
  answered and the Agent fell back to proposing a `data.aggregate`. Grouped
  results are now lifted one level and kept in full (UI-saved and Agent-run
  alike);
- the eval harness scored a turn that ended in a provider error as a pass; it
  now fails.

Live, DeepSeek, each case ×3: read_coef, explain, describe, female_compare,
ttest_gender, multi_tests, en_ttest, multi_turn, and two new arithmetic cases
(wage gap in levels and percent; ratio and difference of two coefficients) —
all pass, no unsupported number in any reply; `calculate` was called 16 times in the last two runs.

**Provider retries.** The 9 `LLMUpstreamError`s in the earlier evaluations had
no HTTP status (dropped connections, truncated streams). Tool-bearing Agent
requests were never retried, on the belief that a provider could cause a side
effect; it cannot — tools run only after Arboris receives the call. A request
that fails before any output is now retried twice (1 s, 3 s), typed or not;
each retry is a `provider_retry` event and shows in the activity line. Auth and
request rejections are not retried.

**SPSS oracle** (`tests/test_spss_oracle.py`). R `foreign` — an SPSS parser
independent of ReadStat — against Arboris: the SPSS-written files shipped with
`foreign`, a `.sav` Arboris writes (Unicode labels, user-missing codes, a
300-character string), and locally the public GSS 2022 release (1,297 variables,
4,149 respondents, 3.0 M user-missing codes): N, mean, SD, variable labels and
value labels agree on every variable.
