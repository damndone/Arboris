# OLS 内存：整表逐格指纹与整表复制（2026-11-03）

基线 `0f6e4d79`，修改后为本提交。原始数据 `local/perf-evidence/ols-memory-20261103/ab.txt`（git 忽略）。

## 发现

- `run_ols` 没收到数据集快照时，会把整张表（包括模型不用的列）逐格转成规范化 JSON 算数据集指纹。产品主流程会传快照；
  Agent 后估计时的重新拟合（`workflow_runtime_parts/models.py`，算出的结果整份丢弃）和自动选模型失败后退回 OLS（`engine/stages/estimation.py`）没有传。
- `run_ols` 开头整表复制，模型不用的列也复制。

## 改动

- 两处调用都传入手头已有的数据集标识（退回 OLS 用与主流程相同的上传哈希和产物 id）。
- 只复制拟合读到的列（公式列、权重列、HAC 时间列），缺失的列仍交给公式报错。
- `scripts/lint_rules.py` 新规则 `ols-call-dataset-snapshot`：后端每处 `run_ols` 调用都要传 `dataset_snapshot`。
- 回归测试：多出的不用列（含缺失值）不改变系数、标准误、样本。

## 前后对比

100 万行，y、x1、x2 加 30 列不用的列；每次新进程，两边都加载同一份原生库，交替跑 5 对；“新增内存”是拟合前后峰值 RSS 之差。

| 场景 | 改前 | 改后 |
|---|---:|---:|
| 重新拟合 / 退回 OLS（之前不传快照） | 33.38 s [32.99–33.72]，2,655 MiB | **2.18 s** [2.15–2.21]，**601 MiB** |
| 主流程（传快照），30 列不用的列 | 2.22 s，835 MiB | 2.19 s，**601 MiB** |
| 主流程，没有多余列 | 2.20 s，743 MiB | 2.18 s，710 MiB（噪声内） |

三种场景前后系数和标准误逐位相同。第七轮 55 题回放结果不变（唯一差异仍是预期的 070）。
