# v1.8.12 第 8 步验收：公式项名的引号转义（V1811-PUBLIC-TERM-QUOTE，P2）

日期：2026-10-08。分支 `workbench-v1.8.12`，devline `v1-8-12`。计划：`archive/plans/2026-10-08-v1.8.12-step8-term-quote.md`。用户 2026-10-08 裁定第 8 步本版只做本项。

## 问题

公式用 `Q(<Python 字面量>)` 引用列名，各处用 `repr(column)` 生成：

- 普通列名：`Q('x')`。
- 列名含单引号：`Q("o'brien")`。
- 同时含两种引号或含反斜杠：带转义，如 `Q('a"b\'c')`。

反向解析却散落在 7 处后端代码和 1 处前端代码，都靠剥引号字符或正则：

| 位置 | 修复前的结果 |
|---|---|
| `econometrics/normalize._public_term` | 转义不还原：`both \' and " quotes`、`back\\slash` |
| `egress._TERM_RE`（外发脱敏） | 只认单引号形式，`C(Q("o'brien"))[T.Alice]` 不被识别，分类取值 `Alice` 原样外发 |
| `term_parser`、`checks/context`、`term_labels`、`diagnostic_summary` | 转义不还原；列名含 `:` 时被当成交互项拆开 |
| 导出的 Python 脚本 `wb_public` | 只认单引号形式 |
| ANOVA 包 | 自己拼 `Q('{column}')`，列名含单引号时公式语法错误，拟合失败 |
| 前端 `runResult.tsx` | 自动虚拟编码提示里的列名带转义 |

**影响范围（实测核实）**：运行流水线的清洗步骤会把所有列名规范为 `[0-9a-z_]`（`cleaning.normalize_column_name`）。

- 用含 `'`、`"` 与两者兼有的列名分别从主流程（CLI `workbench run`）和“从数据节点建模”入口实跑，系数名都已是 `o_brien_score`、`tenure_years`、`C(Q('owner_s_region'))[T.south]`。
- 所以在现有产品流程里，带引号的项名不会出现，上述外发漏隐去**目前无法经正常运行触发**，属于潜在缺陷。
- 直接调用估计函数或能力包、以及今后任何保留原列名的新入口，都会触发。本步按纵深防御修复。
- 也因此，浏览器里造不出这类项名，本步用测试和上述实跑验收，不做浏览器场景。

## 实现

- **`workbench/formula_terms.py`**（新，只依赖标准库），作为唯一实现：
  - `quote_column`：生成 `Q(repr)`。
  - `unquote_column`：只接受整个 `Q(<字符串字面量>)`，用 `ast.literal_eval` 还原。
  - `public_term`。
  - `categorical_level`：处理 `C(Q(...)[, 对比])[T.水平]` 与裸 `C(x)[T.水平]`。
  - `STRING_LITERAL` / `QUOTED_COLUMN` 正则片段，供需要在长文本里查找的外发脱敏使用，匹配到的字面量交给 `literal_value` 解码。
- **7 处后端读取方**改为调用它。
  - `term_parser` 对非单列的分类项（如 `C(np.log(x))[T.a]`）保留原解析作为回退。
  - `term_labels` 不再把含 `:` 的单列引用当交互项拆开。
- **生成端统一为 `quote_column`**：OLS 等的 `_formula_term`、工作流运行时、LMM 包（输入、结果、运行器）、ANOVA（原用未转义拼接）。
  - MANOVA 保留它的 `json.dumps` 引号：公式文本记录在它的结果信封里，测试把这一格式固定为结果合同。
  - JSON 字符串也是合法的 Python 字面量，统一读取函数照样能读回，有测试守住。
- **导出的 Python 脚本助手 `wb_public`**：用 `ast.literal_eval` 还原，脚本仍不依赖 Workbench。
- **前端**：新增 `frontend/src/format/formulaTerms.ts`，按 `repr` 的转义规则解码，`runResult.tsx` 改用它。
- **分层守卫**：`formula_terms.py` 列入下层模块。

## 发版前自审补充（R1-4）

- **问题**：正则能匹配、Python 却无法解码的字面量（如 `Q('bad\N')`）原先会让读取函数抛 `SyntaxError`。
- **修复**：
  - 读取函数现在把它视为“不是列引用”。
  - 外发脱敏把它的取值隐去，并按原文记入审计，因为无法证明它不是受保护列。
- **测试**：先写失败测试；第一次修复仍外发了取值（没有登记隐去），被测试抓住后改正。
