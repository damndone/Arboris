# v1.8.12 第 1 步验收：本地 API 安全（V1812-LOCAL-API-SECURITY，P0）

日期：2026-10-07。分支 `workbench-v1.8.12`，devline `v1-8-12`。原始日志与浏览器探针页留在本机 ignored `local/v1812-step1/`，本文件只记结论与可复核的数字。

## 实现

纯 ASGI 中间件 `backend/workbench/http/local_request_guard.py`，在任何路由、请求体、上传读取之前判定：

| 规则 | 适用 | 拒绝码 |
|---|---|---|
| Host 只认 `localhost` / `127.0.0.1` / `[::1]`（任意端口）＋ `WORKBENCH_ALLOWED_HOSTS`；缺 Host、畸形 Host 均拒 | 所有请求 | `LOCAL_REQUEST_HOST_REJECTED` |
| 带 `Origin` 时必须是本服务自身（同源）或允许的 UI 源：默认 `http://localhost:5173`，加 `WORKBENCH_UI_ORIGIN`、`WORKBENCH_ALLOWED_ORIGINS`；回环源自动覆盖同端口的另两个回环名；`null` 拒 | **所有方法** | `LOCAL_REQUEST_ORIGIN_REJECTED` |
| `Sec-Fetch-Site: cross-site` | POST / PUT / PATCH / DELETE（WebSocket 握手按改状态处理） | `LOCAL_REQUEST_CROSS_SITE_REJECTED` |

- 拒绝返回 403，`details` 为空，不回显允许列表；从不发 CORS 头。
- 每次拒绝写入用户级外发审计 `~/.workbench/egress_audit.jsonl`（`kind: local_request_rejected`）；每 60 秒最多 100 条，超出部分计数，下一条记录带 `suppressed_before`；头部值截断到 256 字符。防止恶意页面刷盘（本机磁盘余量约 8 GB）。
- 不带 Origin 的客户端（CLI、脚本、curl）与同源 UI 读请求（浏览器不带 Origin）不受影响。

### 与 objective 的偏差（加严，已验证）

objective ② 只要求改状态请求校验 Origin。实测 Vite 5.4.21 默认对任意 localhost 源开放 CORS（包括 `/api` 代理），且代理原样转发浏览器 Origin：另一个本机端口的网页可经 Vite 代理**读取**后端响应（下表探针 D）。因此 Origin 校验扩展到所有方法。同源 UI 读请求不带 Origin，不受影响。

### 有副作用的 GET（objective ③）

以真实项目（完成的 OLS run + notebook）逐个调用全部 47 个 GET 路由，对项目目录与临时 HOME 做文件快照比对：

| 路由 | 写了什么 | 改正 |
|---|---|---|
| `GET /notebooks/{id}/options` | 每次追加 `context.compiled` trace 事件、写 context blob、首次改 `notebook.jsonl` | 改为 `POST`（保留“显示时记录编译上下文”的溯源语义，纳入 Origin 校验）；前端 `listNotebookOptions` 同步改 |
| `GET /agent/sessions/{id}`（不存在的会话） | 建 `agent-sessions/`、`agent-events/` 空目录 | 先用不建目录的仓库查会话，404 前不建任何东西 |
| `GET /data-operations/column-cast/{record_id}` | 建 `operation-records/` 空目录 | `OperationRecordStore(create=False)`（同文件兄弟路由已如此） |
| `GET /domain-memory/candidates` 等 | 首次读取创建偏好锁文件 | 锁文件改在启动构造偏好存储时创建 |

接受的例外：读取一个 manifest 仍为 `running`、但 worker 已死的 run 时记为 `interrupted`（崩溃对账，写入的是服务器自有事实，run id 不可猜）。

回归：`tests/test_get_routes_are_read_only.py` 枚举所有已注册 GET 路由（含今后新增的），任何写盘即失败。

## 浏览器与外来网页验收

环境：后端 `127.0.0.1:8032`（`WORKBENCH_ALLOWED_ORIGINS=http://127.0.0.1:5192`），Vite `:5192` 代理，外来网页 `http://localhost:9999`。

**正常界面（浏览器经 Vite，页面源 `http://localhost:5192`，由回环别名覆盖）**：新建项目 → 上传 `forest_min.csv` → OLS 拟合（R² = 0.9841）→ Agent 节点会话执行联合 Wald 检验（F(2, 37) = 1238.1，HC1，产物 `post_estimation/workflow_postestimation_wald_*.json`）→ 导出 Stata 脚本包（9 个文件的 zip）→ 打开 Notebook（`POST …/options` 200，trace GET 200）。全程无一次守卫拒绝。

**外来网页 `:9999` 的 7 次尝试，全部被拒、目标目录保持为空**：

| 探针 | 浏览器侧 | 后端 |
|---|---|---|
| A `no-cors` text/plain POST `:8032/projects` | 不透明响应 | 403 ORIGIN |
| B CORS JSON POST `:8032/projects` | 预检被拒，fetch 失败 | 403 ORIGIN（OPTIONS） |
| C CORS GET `:8032/llm/config` | fetch 失败 | 403 ORIGIN |
| D CORS GET 经 Vite `:5192/api/llm/config` | **Vite 放行 CORS，页面读到的是 403 体，而非配置** | 403 ORIGIN |
| E CORS JSON POST 经 Vite `/api/projects` | 读到 403 体 | 403 ORIGIN |
| F multipart 表单 POST `:8032/runs` | iframe 显示 403 | 403 ORIGIN |
| G urlencoded 表单 POST 经 Vite `/api/projects` | iframe 显示 403 | 403 ORIGIN |

**DNS rebinding 模拟（curl 伪造 Host）**：`Host: attacker.example:8032` 的 GET、`Host: rebind.attacker.example` 的 POST 均 403 HOST，未建项目。**无 Origin 客户端**：`GET /health` 200，`POST /projects` 200 且项目建成。

## 给后续版本的注意

- 各 worktree 的 Vite 跑在非 5173 端口时，后端必须设 `WORKBENCH_ALLOWED_ORIGINS`（本地 launch 配置 `backend-v1812` 已示范），否则界面写请求会 403。
- 会话令牌仍不做（用户决定）；触发条件见开工交接归属表 V1812-SESSION-TOKEN。
