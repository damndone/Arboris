## 怎么做成模块化

后端（类型从领域对象派生，不复制字段）：
- 处理函数只写返回注解；`TypedAPIRoute` 把注解登记进 OpenAPI，并关闭运行时响应校验，线上返回逐字节不变。
- `view_of(源类型, 名称, omit=, inline=, stored=, **调整)` 从 dataclass 或 pydantic 模型派生响应类型；嵌套的 dataclass 自动转成视图（`viewed`），序列化与字段不一致处用 `define_view` 一次声明（如导航引用无原因时省略 `reason`）。
- 取值集合写成 `Literal`，校验逻辑与响应类型都从它读，例如 `ExplorationOperation`、`ContentClass`、`SensitivityLevel`、`PreviewStatus`、`PacketStatus`、`ApplyMode`、`ConfigSource`、`NavigationKind`。

测试期强制：
- conftest 中间件对每个 2xx JSON 响应按声明严格校验，多字段、少字段、类型不符都让测试失败。所有现有 HTTP 测试因此都是合同测试。联合类型违约时报告最接近的分支和失败的关键字。
- `tests/test_api_types_drift.py`：生成文件必须与后端一致；每个操作必须声明响应。
- `tests/test_canonical_wire_fixtures.py`：v1.8.1 的 6 个规范夹具按声明严格校验，前端测试读取它们时使用对应的生成类型。

前端：
- `apiTypes.ts` 提供 `Schema<名称>`、`ResponseOf<路径, 方法>`、`RequestOf<路径, 方法>`；API 函数写路径即得到请求与响应类型。
- `apiTypeProvenance.test.ts` 用 TypeScript 编译器解析每个导出的 API 函数的 `Promise<T>`，逐字段判断是否声明在生成文件里（别名、`Pick`/`Omit` 都看穿），不维护名单。客户端自己组合的结果需列入豁免并写理由；豁免过期也失败。
- `apiFixtures.ts`：测试夹具构建器，默认值等于后端总会发的字段。
