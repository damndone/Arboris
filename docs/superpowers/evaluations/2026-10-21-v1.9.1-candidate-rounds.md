leverage.goal 查明的问题（离线复现，均已修复并附测试）：

1. **确认时 HTTP 500**：6 个 `operation.multi_step` 提案的 target 指向 `model:ols_1`；提案阶段放行了，确认时工作流编译要求数据集节点，抛出 `DataColumnCastValidationError` → 500，记录一直 pending，Agent 却被告知"已执行"。它合成了 3 次报告，没有一份真实存在。修复（`73443261`）：提案阶段把模型节点按谱系绑定到它唯一的输入数据集（附说明），其他非数据集节点直接拒绝并列出可选数据集节点；确认阶段源节点无法解析时，把操作记为 failed 并如实告知 Agent。
2. **缺敏感性拟合时没有可执行的下一步**：完成检查的 next_step 先要求合成报告，可报告无法覆盖之后才补的拟合。修复：完成检查从主模型自己的设定（run_inputs）推导出可照抄的 `sensitivity_options`（工作流 target + steps，每个都先通过 `validate_model_genesis_spec`）。一类是去掉一个非焦点自变量；OLS 有高 Cook's 距离时，另给一类：按能唯一标识行的列，排除超过诊断自身阈值的行，再重拟合。缺敏感性拟合时 next_step 改为先拟合、后合成报告。选用哪一项，或另给设定，仍由 Agent 决定。
3. **补了子集重拟合后主模型变得有歧义**：直接在计划数据源上的拟合，和在派生子集上的拟合，被当成了两个并列的主模型候选，于是什么都不绑定。修复：点估计不同的几个拟合中，若只有一个直接拟合在数据源上，就绑定它为主模型，子集重拟合归入敏感性（Agent 点名主模型时仍以其选择为准）。
4. **"部分完成"说明叠加、语言错误**：回答开头照抄了上一条说明，又被再加一条；续接回合没有人的原文，中文任务里出现英文说明。修复：发布前去掉回答里已有的说明，续接回合沿用人最近一次的请求文本。
