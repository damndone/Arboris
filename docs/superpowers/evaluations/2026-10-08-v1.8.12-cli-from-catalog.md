# v1.8.12 第 5 步验收：CLI 由目录生成（V1812-CLI-FROM-CATALOG，P1）

日期：2026-10-08。分支 `workbench-v1.8.12`，devline `v1-8-12`。计划：`plans/2026-10-08-v1.8.12-step5-cli-from-catalog.md`。

## 问题

- `workbench run` 手写 40 多个参数，直接调用 `orchestrator.run_workflow`，绕过 HTTP 的 `_submit_run`。
  - 缺 `model_options`、三种加权、预测数据结构、统计检验、分组运行等参数。
  - `run_inputs.json`、分析台账与界面运行不一致。
- 没有后估计、脚本导出、模型目录命令。

## 实现

- **运行请求字段表** `backend/workbench/run_request.py`（只依赖标准库）：
  - 每个字段只写一次，包括名称、默认值、类型、说明、可重复、JSON 文档。
  - `POST /runs` 的表单签名由它生成；`workbench run` 的选项也由它生成。
  - 两者共用 `form_from_request` 把提交值组装成服务表单，并预先解析 `model_options` / `labels` / `statistical_tests`。
  - OpenAPI 与生成类型只多了字段说明（68 行 `description`），漂移测试守住。
- **`workbench run`**：
  - 选项由字段表生成，旧调用方式不变（`PROJECT DATA Y --x …`、`--survey-replicate-weight`）。
  - JSON 选项可以内联，也可以写 `@文件`。
  - 模型类型在建运行前就由引擎白名单校验。
  - 经与 HTTP 相同的 `_submit_run` 提交，订阅事件流等运行结束。
  - stdout 只输出 run_id（`RUN_ID=$(workbench run …)` 契约不变），进度与 Lineage 链接走 stderr；运行未完成时退出码为 1。
- **`workbench postestimation <op>`**：
  - 每个登记的后估计操作一个子命令，选项由步骤合同生成。
  - 步骤合同数据移到轻量模块 `contracts/model/postestimation_steps.py`，Agent 侧改为引用它。
  - 执行与 Agent 相同：`compile_workflow` + `WorkflowExecutor`。
  - 源数据节点：取谱系图中指向该模型节点的数据集节点（如 `e:cleaned-model-primary` 的 `stage:cleaned`），再经工作流运行时同一个解析器复核 SHA-256。
  - 模型节点按设计从不记录 `parent_stage_id`（只有变量节点有），所以不能用它。Agent 合同里“在模型的父数据阶段上规划”指的就是这条边。
- **`workbench export-script` / `export-targets`**：调用 HTTP 同一脚本导出服务，`--output` 把脚本包复制出来。
- **`workbench models [MODEL]`**：列出能力目录；带模型名时给出参数和 `model_options` 字段。
- **记账**：每条命令都记入分析台账（`source` 标明 CLI），与界面操作一致。
- **生成方式**：用 Typer 公开 API 构造生成的函数签名，与路由的签名生成同一思路。
  - 不用外部 click 对象：typer 0.26 自带一份 click 副本，两边的异常类型不通用。
  - 命令在首次使用时才构建，启动不导入统计库与 Web 框架。

### 顺带补齐：NB1 原生脚本导出（Stata、Python）

验收要求在 Stata 里实跑 NB1。v1.8.11 只验证过估计离散度的 NB2，NB1 会退回“Workbench 结果侧车”，Stata 并不真正重估。

- 本步补上 NB1 的原生翻译：
  - Stata：`nbreg …, dispersion(constant)`。
  - Python：statsmodels `loglike_method="nb1"`，Newton 法，信息矩阵用观测信息。
- 两者与 Workbench 拟合同一个似然；仓库已有 NB1 的 Stata 参照（`fixtures/count_models/reference-v3/stata_nb1`）。
- **R 仍走侧车**：R 没有参照级的 NB1 估计器，手写似然等于引入一个需要单独验证的新估计量。原因写进导出覆盖说明，`--require-native` 会明确拒绝。
- 固定 alpha 仍需要 Workbench（原测试改为锁定这一条）。

## 验收（命令行真实运行）

数据：600 行 NB1 计数（`delta = 1.5`，固定种子）。证据保存在本机 `local/v1812-cli-acceptance/20261008/`：数据、Wald 输出、导出结果、脚本包、do 文件、**脱敏后**的 Stata 日志。仓库里不放日志，也不写原始日志哈希。

```
workbench create <dir> proj
workbench run proj counts.csv y --x x1 --x x2 --model-type negative_binomial --model-options '{"dispersion": "constant"}'
workbench postestimation wald proj <run_id> --model-ref model:negative_binomial_1 \
    --constraints '[{"terms":{"x1":1},"value":0},{"terms":{"x2":1},"value":0}]'
workbench export-script proj <run_id> --target artifact:<wald_artifact> --language stata --require-native --output out/
cd bundle && stata-mp -b do analysis.do
```

| 环节 | 结果 |
|---|---|
| 拟合 | 2.4 s，退出 0，stdout 只有 run_id |
| Wald | χ²(2) = 147.972，p = 7.38e-33 |
| 导出 | `fully_native: true`，三步（清洗、NB1、Wald）均为 native |
| Stata 实跑 | 退出 0；19 项自检全部通过：列名核对，以及 N、系数、标准误、z、p 和 Wald 的 χ²、p、df |
| Stata 输出与 Workbench 一致 | `nbreg y x1 x2, dispersion(constant)` 后 `test` 得 χ²(2) = 147.97 |

导出包与 do 文件的 SHA-256：

- 脚本包 `analysis-stata.zip`：`e21b28b09dd66f88198ffa37873e38f3b6804cac897924a977065a75d9f3f414`
- `analysis.do`：`c74d09b3e6053f3946d0551eb95332c275bcc25944cbba38bb65f8392a560f65`

交叉核对：单约束 x1 = 0 的 Wald χ²(1) = 134.720。它等于 Stata 日志里 x1 的 z = 11.6069 的平方。

**错误路径**（均为明确信息与非 0 退出码）：

- 模型节点不存在：2。
- 约束里的项不是模型参数：1，并列出模型的参数。
- JSON 无效：2，指出位置。
- `@文件`：读取正常。
- 未知模型类型：2，列出受支持类型。
- R 要求原生：2，说明 R 没有参照级 NB1。

**性能**：`workbench --help`、`run --help`、`postestimation --help` 均为 0.11 s（预算 0.5 s）。

**日志中的 `r(199)`**：来自本机全局 `/Applications/Stata/profile.do`（“command window is unrecognized”），发生在 `do analysis.do` 之前，与导出脚本无关。回归测试只检查 `do analysis.do` 之后的部分。
