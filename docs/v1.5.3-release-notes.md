# V1.5.3 Release Notes — Foundation Hardening

> Branch: `workbench-v1.5.3` (off `workbench-v1.5.2`).
> Theme: pay down the state-machine debt the V1.5.2 handoff flagged, and
> finish the interaction surfaces the registries reserved — **zero new
> backend**. This unblocks the AI (V1.5.4) and editable/rerun (V1.5.5)
> versions by collapsing selection to a single source of truth first.

## What shipped (9 items)

### State machine — single source of truth
- **F1 `setFocusOnly`** — new Provider dispatch that sets `focus` +
  `pinned=0` WITHOUT touching tabs/active/selected. The "look at A,
  highlight B's upstream" case now works: the drawer stays on A while
  the graph highlights B's upstream. The three `focusUpstream` action
  surfaces (ContextMenu, WorkbenchTopbar, NodeActionMenu) were rewired
  off `selectByCanvasClick` (which wrongly moved selection).
- **F2 retire `useTabs`** — deleted `useTabs` + `useSelectedNode` (−672
  lines). They were a *second* URL writer running outside
  `WorkbenchStateProvider`, feeding `LineageContext` and racing
  `commit()` on `?tabs=`/`?active=`. `TabState` moved to its natural
  home in `tabsSchema.ts`.
- **F3 `selectedKey` single source** — `LineageContext` is now produced
  by a new **`LineageBridge`** that sources ALL selection state from
  the Provider. `commit()` is the sole URL writer; the documented
  same-tick clobber bug is structurally gone. Auto-select (first
  review/caution node on load) migrated into the bridge with its focus
  semantics made explicit. 8 lock-in tests pin the invariant.

### Interaction surfaces
- **F4 ⌘K focus guard** — new shared `workbench/keyboard.ts`
  `isEditableTarget()`; ⌘K no longer hijacks typing in an
  input/textarea/select/contenteditable. Reused by F6 and F7.
- **F5 search-cursor highlight** — a 6th highlight tier. The ⌘K palette
  now publishes the *current* result's nodeKey (Tier 3 `searchCursorKey`)
  and the graph renders it as a stronger amber ring/glow above the
  other (dimmer) hits, so ↑/↓ navigation is visible on canvas.
- **F6 shortcut dispatcher** — `actionRegistry` gains a structured
  `keys` field (separate from the display `shortcut` string) +
  `matchesKeys`/`actionForShortcut`. A single window listener
  (`useGlobalShortcuts`) runs the matching action against the selected
  node, reusing the F4 guard. `copyNodeId` is bound to ⌘⇧C as the first
  binding; the full keymap is deferred to owner review.
- **F7 command palette** — ⌘⇧P palette over the long-reserved
  `command-palette` surface. Lists node-scoped actions (10 actions
  added to the surface), runs them against the selected node, greys +
  guards disabled placeholders in both DOM and JS (so keyboard-Enter is
  safe), and shows an empty-state when nothing is selected.

### Housekeeping
- **F8 sessionStorage namespace** — the last `lineage:`-prefixed key
  (`legacy-hint-dismissed`) migrated to `workbench:` with a one-time
  forward migration, so a previously-dismissed hint doesn't resurface.
- **F9 isolated venv** — this worktree now has its own `.venv`
  (python3.11), no longer sharing v1.5.1's. Per the version-isolation
  rule, every worktree gets its own venv going forward.

## Architecture after this version

```
WorkbenchRouteContainer
  └── <WorkbenchStateProvider>          ← single URL writer (commit)
        └── <LineageBridge model={m}>   ← derives LineageContext from Provider
              └── <WorkbenchShell>
                    · useGlobalShortcuts() (F6)
                    · <SearchPalette/> ⌘K   <CommandPalette/> ⌘⇧P (F7)
```

## Back-compat & migration
- Legacy `?node=` URL parse preserved in `tabsSchema` (still tested).
- `LineageContext` interface shape unchanged — zero consumer edits; the
  bridge is a drop-in source swap.
- F8 migrates the old sessionStorage key transparently on first read.

## V1.5.3 explicitly DOES NOT ship
- No new backend routes. `/llm/chat`, partial/full rerun, editable-ops
  submit are still **not** present — disabled action placeholders
  (askAiAboutNode, rerunFromNode, markNeedsReview, rerun,
  generateReport) remain greyed.
- No Monaco editor, no real Table/Pipeline views, no bottom-panel
  splitter drag / Shell sandbox.
- The shortcut keymap is intentionally minimal (one demo binding) —
  awaiting owner review (handoff A.5 #3).
