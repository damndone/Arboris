# Workbench v1.8.3 — Capability Factory 与受控 Agent 扩展

v1.8.3 将 Agent 从“只编排已内置分析”扩展为受控的 **Capability
Factory**：它能解析统计能力需求、比较可信实现、准备并验证依赖与
Adapter，再把已准入的能力接入既有 Notebook、Draft、Run、Graph、Artifact
和 Report 生命周期。它不是允许 Agent 在 Workbench 主环境中随意
`pip install` 或执行任意代码的开关。

## 本版本交付

- **通用能力解析与准入。** `CapabilityRequirement`、profile、bundle、证据、
  admission 和 resolution binding 是分离且版本化的对象。原生实现、已注册
  第三方实现、Agent 生成 Adapter 与 Agent 自研算法通过同一优先级和
  fail-closed 生命周期进入候选集。
- **安全的依赖三平面。** 依赖解析/获取、quarantine 组装、验证和分析执行
  分离；主 Workbench 环境不动态安装包。锁、哈希、平台、安装树、SBOM、
  policy 与扫描结果都绑定到 bundle identity。
- **本机 experimental 供应链扫描。** 新增可钉扎的外部 scanner worker：
  只读取 sealed tree 的 `*.dist-info/METADATA`，不导入候选包代码；固定查询
  OSV 漏洞服务，执行管理员许可证 allowlist，并将许可证、漏洞、SBOM、
  构建、policy 与时效窗口绑定。过期、未来日期、哈希漂移或结果不匹配都会
  阻止执行。Agent 不能指定 scanner 命令或批准自己的结果。
- **Adapter 与算法验证晋级。** 自研/生成实现必须经过服务端 protocol、
  独立 oracle、holdout、attempt ledger、证据等级与 admission；作者自测
  不能单独把实现提升为可信。
- **`model.custom` 全链路控制面。** Notebook 推荐、用户选择、Proposal/Risk
  授权、确定性 Draft materialization、execution receipt、唯一 reservation、
  supervisor、Artifact contract 与 Graph/Report 消费已贯通。未支持的 consumer
  slot 显式拒绝，不能错误复用 OLS 的诊断或图表解释。
- **本机 Darwin experimental 执行。** 当服务端显式安装 gateway、依赖 bundle
  已准入且用户确认高风险 `experimental_confirm_and_execute` 时，生成的 Python
  Adapter 可通过 Seatbelt containment 执行；没有这些条件时保持 fail-closed，
  不退回到弱隔离或主进程执行。
- **双层记忆。** Project/RunFamily 可重建工作索引与默认关闭的跨项目领域记忆
  已接入 Notebook。候选、批准、来源访问、scope、冲突、失效与审阅分离；
  记忆不能改变 evidence、admission、推荐排序或执行授权。
- **工作流与可观测性。** `WORKFLOW_STEP_SPEC_CONTRACTS` 继续作为可组合
  workflow 的字段、拒绝消息和 Agent 词表来源；Capability Factory 与 memory
  Trace catalogs 已注册到应用启动路径。

## 验证证据

- 本机真实宿主完整 gate：backend **4141 passed, 8 skipped, 1 xfailed**；
  golden/invariants **23 passed**；frontend **169 files, 1430 tests**；
  TypeScript 通过。
- 当前 macOS 主机重新验证了两条真实 containment 路径：
  `test_authorized_notebook_gateway_runs_real_local_darwin_adapter` 与
  `test_model_custom_route_runs_generated_adapter_through_local_experimental_gateway`
  均通过。
- 本地 scanner worker 以只含 package metadata 的临时 fixture 成功取得真实
  OSV 响应；没有安装依赖、读取项目数据或使用 LLM API key。
- in-app browser smoke 已覆盖普通 Notebook 的推荐、用户确认、Draft、Graph、
  Report 与 OLS 执行流程。`model.custom` 的浏览器点击式 E2E **未单独验收**；
  其服务端 HTTP E2E 已通过，二者不混称。

## 明确不宣称

- 产品包不内置、生成或保存生产 authority signing key。生产部署必须提供
  `AttestationAuthorityPort`、key provider、当前 trust/revocation state 与
  execution-result attestation source；缺失时 production runtime 不启用。
- 本机 Darwin 路径是 **experimental/local** 证据，不等同于 Linux、其他 macOS
  版本、容器、VM、多用户部署或 hostile third-party package 的全面认证。
- scanner worker 是本机受控基线，而非完整企业许可证法务判定或集中式
  attestation 服务；部署方可以替换为自己的已钉扎 scanner，但必须维持相同的
  hash、绑定、时效与 fail-closed 契约。
- Agent 不会因为用户提出某个模型就自动下载并运行未知包。新的 dependency、
  code、admission 或高风险执行仍需相应的服务端准入与用户 Proposal/Risk 授权。
