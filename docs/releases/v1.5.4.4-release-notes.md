## What shipped

IV/2SLS — present as a tested estimator in `econometrics/runner.py` since V1.5.3.x but unreachable from the GUI — is now a first-class, end-to-end model. It was the last of the three stranded capability families found in the V1.5.4.2 audit (prediction/ML and panel entity-time shipped in V1.5.4.2).

### 1. IV estimation, explicit-only
`iv_2sls` registers into `CORE_PACK` via a `_fit_iv_2sls` adapter. It is **explicit-only** — registered in `MODEL_REGISTRY` but never in `DEFAULT_BY_Y_TYPE`, so it can never be auto-selected (endogeneity is a modeling assumption, not inferable from data). Estimates `y ~ exog [endog ~ instruments]` with a chosen covariance type.

### 2. Fail-loud spec validation
`validate_iv_spec` enforces, before estimation: at least one endogenous regressor and one instrument; the order condition (`#instruments ≥ #endogenous`); a strict partition (no column in two roles, no duplicate within a bucket, none equal to `y`). Violations raise `IVSpecError` (a `ValueError`) that rides the existing failure path to a structured `MODEL_FIT_FAILED`.

### 3. Diagnostic trio (makes IV trustworthy)
For IV runs only, `DiagnosticsStage` writes an `iv_diagnostics` artifact with plain-language verdicts:
- **Weak instruments** — first-stage F per endogenous regressor (rule-of-thumb F > 10 → strong).
- **Endogeneity (Wu-Hausman)** — `p < 0.05` → endogeneity confirmed, IV warranted; else "OLS is consistent and more efficient".
- **Overidentification (Sargan)** — only when over-identified; just-identified renders an honest "not applicable".

### 4. Foolproof input UI
When IV is selected, `RunForm` reveals `IVControls`: a **role-assignment** table where each candidate column gets exactly one role (exogenous control / endogenous / instrument) — overlap is structurally impossible — plus a live **identification badge** (under / just / over-identified) and an IV covariance selector. The result view renders `IVDiagnosticsCard` (the trio + identification badge, expanded by default, statistics and color-coded verdicts shown together).

### 5. One-click recovery — first real `rerun_actions` consumer
On an IV failure (under-identified / spec incomplete), the `FailureCard` now offers a one-click **"Switch to OLS"** — dogfooding the V1.5.4.3 `RerunAction` → `RERUN_ACTION_REGISTRY` socket with its first production registrant. The action is scoped (`applies_to=["iv_2sls"]`) so it surfaces only for IV failures (non-IV recovery sets are byte-identical → golden 0-drift), and `register_pack` now fail-louds on duplicate rerun keys.

### 6. Supporting
- **Capabilities manifest 4-way sync:** `iv_2sls` added to the manifest with `requires: ["endog","instruments"]`, a new `"IV"` group, the drift-guard test, the contract schema/sample, and the frontend `ModelGroup` union.
- **Canonical example + how-to:** `examples/datasets/iv_returns_to_schooling.csv` (valid-by-construction instruments) + `docs/iv-2sls-howto.md`, since valid instruments are hard to supply ad hoc.
- **V1.5.4.3 debt cleared:** `REGISTERED_PACKS` restore fixtures on the pack tests; the frontend type gate now covers `vite.config.ts`/`vitest.setup.ts`; the rerun key-dedup guard.

## Backward compatibility / behavior freeze

`iv_2sls` is explicit-only and new — the validation helper, estimation adapter, diagnostics branch, rerun action, and manifest entry are all inert unless a run requests `iv_2sls`. Every current golden is byte-identical (the only golden change is the additive `iv_2sls` characterization snapshot). The "Switch to OLS" rerun action is scoped to IV, so existing failure-recovery action sets are unchanged. Frontend changes for non-IV models are byte-identical (RunForm sends the same payload; result views fetch no `iv_diagnostics`).

## Notes / known minor (non-blocking)

- IV runs emit both the generic per-model diagnostics artifact (VIF/validity) and the rich `iv_diagnostics` artifact; the latter is what the result card renders.
- The IV input model treats X as "all involved variables" — the user puts controls + endogenous + instruments into X and tags roles; the frontend posts `x = exog` (X minus endogenous minus instruments) so the backend partition never overlaps.
