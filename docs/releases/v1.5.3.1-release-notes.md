# V1.5.3.1 Release Notes

**Backend-only release - no frontend changes.**

## Overview

V1.5.3.1 expands the econometric modeling capabilities of the Local Econometrics Workbench with explicit model types, prediction-only machine-learning artifacts, MICE imputation preprocessing, and imbalanced-sampling support. All new features are backend-only; the frontend UX is unchanged.

## Explicit model types

You can now request a specific model type instead of relying on automatic y-type detection.

| model_type | engine | y requirement | extra |
|---|---|---|---|
| `auto` (default) | statsmodels | auto-detected | n/a |
| `ols` | statsmodels | continuous | n/a |
| `logit` | statsmodels | binary (0/1) | n/a |
| `probit` | statsmodels | binary (0/1) | n/a |
| `poisson` | statsmodels | non-negative integer counts | n/a |
| `negative_binomial` | statsmodels | non-negative integer counts | n/a |
| `panel_ols` | linearmodels | continuous + entity/time | `panel` |
| `glm:binomial` | statsmodels | binary | n/a |
| `glm:poisson` | statsmodels | count | n/a |
| `glm:negative_binomial` | statsmodels | count | n/a |

The default `auto` mode still routes conservatively to OLS / Logit / Poisson based on the detected y type. It will never automatically select `probit`, `negative_binomial`, `glm:*`, `panel_ols`, or any prediction model.

Unsupported model types (e.g. `probt`, `glm:bad`) and unsupported GLM families produce structured `UNSUPPORTED_MODEL_TYPE` / `UNSUPPORTED_GLM_FAMILY` errors before any model artifacts are written. No OLS fallback occurs for explicitly requested models that fail to fit.

## Prediction-only ML artifacts

Three prediction model types are available when the `ml` extra is installed:

| model_type | engine | extra |
|---|---|---|
| `prediction_lasso` | scikit-learn | `ml` |
| `prediction_ridge` | scikit-learn | `ml` |
| `prediction_random_forest` | scikit-learn | `ml` |

Prediction outputs are isolated under `prediction_results/` and are clearly marked:

> Prediction results are not causal effects and are not regression inference.

- No prediction metrics appear in econometric claims, diagnostic summaries, or causal narratives.
- No full prediction arrays, fitted model objects, or `.pkl` files are persisted.
- Prediction models are supplementary - a prediction failure does not block the econometric workflow.

Enable via config:

```yaml
prediction_enabled: true
prediction_model_type: prediction_lasso
prediction_cv_folds: 5
```

Or pass `model_type="prediction_lasso"` directly to `run_workflow`.

## Imbalanced sampling (prediction-only)

Three sampling methods are available when the `imbalanced` extra is installed:

| method | extra |
|---|---|
| `smote` | `imbalanced` |
| `oversample` | `imbalanced` |
| `undersample` | `imbalanced` |

Sampling is **prediction-only** - it cannot be applied to econometric inference models. Continuous targets are explicitly rejected.

Enable via config:

```yaml
prediction_sampling_method: smote
```

## MICE imputation

Multiple Imputation by Chained Equations (MICE) is available as a preprocessing step when configured:

```yaml
imputation_method: mice
imputation_m: 5
imputation_max_iter: 10
```

**Important:** V1.5.3.1 persists **one** imputed dataset (`imputed_dataset.parquet`). It does **not** produce pooled estimates (Rubin's rules), pooled standard errors, or pooled confidence intervals. The output is a single completed dataset suitable for downstream modeling, not a full multiple-imputation analysis.

A summary artifact records the imputed columns, iteration counts, and warnings for auditability.

## Extended statistical tests

New test procedures available (no additional extras required):

- Spearman rank correlation
- Kendall's tau
- Mann-Whitney U test
- Kruskal-Wallis test
- Fisher's exact test
- Benjamini-Hochberg FDR correction (applied to p-value batches)

## Structured model failure issues

All model failures now produce structured `errors.json` entries with consistent evidence:

```json
{
  "code": "MODEL_FIT_FAILED",
  "severity": "BLOCKER",
  "message": "...",
  "evidence": {
    "model_type": "probit",
    "model_id": "probit_1",
    "engine": "statsmodels",
    "step": "estimation",
    "y": "outcome",
    "x": ["x1", "x2"],
    "root_cause": "..."
  }
}
```

Error codes: `UNSUPPORTED_MODEL_TYPE`, `UNSUPPORTED_GLM_FAMILY`, `PANEL_FIELDS_MISSING`, `MODEL_FIT_FAILED`, `OPTIONAL_DEPENDENCY_MISSING`, `PREDICTION_FAILED`.

## Installation

```bash
pip install -e ".[dev]"          # base + test tooling
pip install -e ".[panel]"       # + linearmodels (panel_ols)
pip install -e ".[ml]"          # + scikit-learn (prediction_*)
pip install -e ".[imbalanced]"  # + imbalanced-learn (smote/oversample/undersample)
pip install -e ".[imputation]"  # statsmodels (already in base; listed for explicitness)
```

Combine extras: `pip install -e ".[panel,ml,imbalanced,imputation]"`

## What this release does NOT include

- No frontend changes (no new UI, no new routes, no new components)
- No causal inference claims
- No model `.pkl` / `.pickle` artifacts
- No full prediction or residual arrays persisted
- No pooled multiple-imputation estimates (MICE persists one dataset only)
- No classification prediction models (all prediction is regression)
- No automatic advanced-model routing in `auto` mode
