# Workbench v1.8.0 Release Notes

Released 2026-07-22 from commit `93f437d`. Independent acceptance and a Stata
do-file browser reproduction both ran before release and both found defects;
those are listed below with what they were, because the gates they contradicted
had been recorded as passing.

Release gate on the release tree: backend 2956 passed / 8 skipped, golden and
invariants 23 passed with zero drift, frontend 1294 passed across 150 files,
`tsc --noEmit` clean.

## Scope

v1.8.0 introduces the generic ARMA–GARCH Volatility Workbench for a user-selected time column and numeric value column. It supports explicit transform confirmation, manual ARMA/ARCH/GARCH orders, bounded automatic candidate search, frozen training-only selection, independent rolling evaluation, structured artifacts, graph lineage, Agent-assisted typed reruns, and durable manual-versus-auto comparison.

The known-truth acceptance example is `examples/datasets/VIXCLS.csv`. The browser evidence used the original 2,610-row file, recorded the explicit exclusion of 68 missing VIX observations without changing the source, and produced a 2,542-observation analysis view.

## Verified candidate behavior

- Manual and bounded automatic ARMA/ARCH/GARCH flows complete for VIXCLS, preserve training/evaluation separation, and retain acceptance warnings rather than hiding them.
- The visible result path exposes 17 structured `ts.chart.*` artifacts and 18 panels, including conditional variance, standardized residual, squared standardized residual, and squared mean-residual series.
- The Agent can inspect a failed run, propose registered typed changes, require confirmation, and create an auditable child run. A real DeepSeek V4 Pro session was used only as browser evidence; no provider secret is recorded here.
- Compare is a project-forest object, does not write either source run's `graph.json`, checks frozen sample membership, and returns `COMPARABLE_WITH_NO_AUTOMATIC_WINNER` when the evidence does not justify a winner.

The detailed run IDs, metrics, chart inventory, screenshots, failure history, and exact browser-gate evidence are in [the VIX browser reproduction handoff](../superpowers/handoffs/2026-07-21-v1.8-vix-browser-reproduction.md).

## Scope boundary: not a numerical Stata replication

The Stata reference uses joint ARMA(1,1)-GARCH(1,1) conditional maximum likelihood. v1.8.0 estimates cases with MA order above zero sequentially (ARMA first, ARCH/GARCH second). It therefore does **not** claim numerical parity for joint parameters, joint log likelihood, or joint AIC/AICc/BIC.

The release wording is intentionally limited to:

`REFERENCE_SEMANTICS = "directional_or_workflow_regression"`

Joint ARMA(p,q)-ARCH/GARCH MLE is a dedicated follow-up work package with a Stata oracle, explicit conditioning rules, LL/IC, convergence, and forecast-parity acceptance. See `V1.8-JOINT-ARMA-GARCH-MLE` in [BACKLOG.md](../superpowers/followups/BACKLOG.md).

## Delivery

ARMA–GARCH runs generate run-owned HTML and PDF from their registered `ts.*`
evidence plus an eight-sheet Excel workbook. Newly generated DeepSeek reports
persist as immutable run-owned `ai_report_<id>` artifacts with their full fact
snapshot; browser local storage is a convenience cache only, and historical
browser-only text is not retroactively recreated. Compare distinguishes data and
sample changes from split-contract changes. The Agent audit export aggregates
parent session, operation record, child session and terminal result as JSON,
Markdown or HTML.

## What acceptance found before release

Independent acceptance and the do-file reproduction each rejected claims this
document previously carried. Recording them because "the sheet is non-empty" and
"exports as three formats" were both true and both insufficient.

**Deliverables were lossy while passing their own check.** Every workbook sheet
was non-empty, which is what had been verified. Three were unusable anyway.
Rolling forecasts exported 2 of 18 columns — no timestamps, no observed value,
no conditional mean — because the exporter was written against guessed key names
and the two that happened to match defeated its fallback, so a reader could not
reconcile the reported RMSE or coverage. Volatility candidates listed no
candidates at all, only search metadata. Diagnostics, and the run-owned HTML and
PDF, carried ADF alone, omitting the Ljung–Box, ARCH-LM, Jarque–Bera,
Shapiro–Wilk, Shapiro–Francia and residual-exceedance results that produce the
visible acceptance warnings — the verdict shipped without its evidence. The test
fixtures used the same guessed schema as the exporter, so implementation and
test agreed with each other while both disagreed with the artifacts.

**Compare was unreadable on the surface users reach.** The human-summary work
covered the durable time-series comparison, not the inline node-versus-node
Compare in the node drawer, which rendered two roughly 900-character
`model_options` JSON blobs joined by an arrow. Diffs now expand nested objects to
leaf paths.

**The HTML audit export was Markdown in a `<pre>`.** Nothing tested the
rendering, only the JSON and Markdown payloads, so the three-format claim was
true by name only.

**The Agent's summary tool exceeded its output budget, for the third time by a
third route.** statsmodels emits a NumPy DeprecationWarning on every ARIMA fit
and it was captured verbatim into every candidate record — wasted budget, and it
reads to a user as though the model had a problem. Separately, a fixed row cap
cannot bound a variable-width payload. Library-upkeep warnings are now filtered
at the capture sites and candidate tables are bounded by bytes as well as rows.

**`propose_operation` failed on its first call every turn**, because field paths
are advertised in dotted form while a patch must nest them as objects. The
vocabulary now carries a worked example whose correct and incorrect halves are
both executed against the real validator.

None of these were visible to the deterministic suite. Each needed a live
provider turn or a real automatic search over real data.

## Stata do-file reproduction

The user's own VIXCLS do-file was reproduced end to end through the visible UI
with a live DeepSeek V4 Pro session. Data handling matches: 68 missing
observations explicitly excluded leaving 2,542, trading-observation index,
log-difference-percent transform, source file unchanged. Within the do-file's own
eight ARMA candidates, BIC selects the ARMA(1,1) with no constant that the
do-file chose, and AICc minus AIC is at most 0.010 as its own check anticipated.
The variance candidate set matches ARCH(0) plus ARCH(1..10) plus GARCH(1,1).
Diagnostics line up including ARCH-LM at lag 10 and the standardized-residual
exceedance rate of 131 of 2,520; persistence 0.7752 and half-life 2.7226 match
hand calculation. Parameters are bit-identical to the earlier VIX run, so
determinism holds across projects.

Three differences are conventions, not defects, and are recorded so they are not
relitigated: automatic mode selects by an AICc-led basis where the do-file's
stated rule is BIC-first; the rolling window defaults to 20 origins against the
do-file's last 20 percent, over a user-settable `validation_n`; and under
sequential estimation ARMA-only and ARMA-GARCH share the same conditional mean
exactly, so only interval width differs, where Stata's joint `arch` would give
slightly different mean parameters.

Details in [the do-file reproduction handoff](../superpowers/handoffs/2026-07-22-v1.8-stata-dofile-browser-reproduction.md).

## Other known limitations

- The system does not invent a future trading timestamp when it cannot infer one safely.
- VIX acceptance may report visible warnings, including residual autocorrelation and normality rejection under normal innovations.
- Browser screenshots and provider sessions are QA evidence; they are not substitutes for run-owned, durable exports.
- Driving the UI with browser automation requires real keyboard input for React-controlled inputs; setting a DOM value directly leaves the submit button disabled.
