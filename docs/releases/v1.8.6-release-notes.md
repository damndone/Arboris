# Workbench v1.8.6 — 发布说明

> 状态：已发布（tag：`v1.8.6`）。以下内容只描述已实现并有验证证据的能力。

## 相较 v1.8.5 的主要变化

- **预测研究正确性基础。** 预测流程现在使用显式的 SplitPlan、最终 holdout、baseline、负对照和证据投影；未知数据结构、未声明的 split/权重语义不会静默回退到旧的随机切分路径。
- **四类新模型族。** 普通 Run、Genesis 和 Agent 可达 `ordinal_logit`、`multinomial_logit`、`survival_cox`、`quantile_regression`。结果包含与模型族对应的概率/比值比/相对风险比、边际效应、生存曲线与 log-rank、分位数与跨分位数比较等证据；缺少生存事件列等必要输入会明确拒绝。
- **统计检验补完并接入普通流程。** ANOVA 事后比较（Tukey/Bonferroni）、Cohen's d、eta squared、omega squared、Levene/Bartlett/Shapiro-Wilk 在普通 Run 中**自动产出**，并投影到报告、表格、Agent 结果和 XLSX 导出。单样本 t、配对 t 与 Wilcoxon 符号秩需要**显式声明检验目标**（见下），因为配对关系无法从列顺序推断。
- **三种权重语义显式化。** `frequency_weight` 已从 API/Genesis 入口贯通并按**观测频数语义**执行；`analysis_weight` 在 OLS 中通过加权最小二乘执行；`sampling_weight` 在完整 strata/PSU 设计语义落地前保持 fail-closed，并给出复用现有 `entity_col + covariance=clustered` 通道的下一步，不会被静默当成频数权重。
- **FeatureRecipe 与数据操作可达。** 派生变量/重编码以及 merge、append、reshape、subset 等受限数据操作已通过 API、界面和 Graph 节点入口暴露；从可物化的数据节点可直接启动现有 OLS 生命周期，并在 child run 中保留 source run/node/artifact/hash lineage，形成可回溯的 merge → reshape → derive → model 链；未知算子、键冲突、多对多膨胀和非法参数保持拒绝。当前数据节点模型桥接只覆盖数值 OLS。
- **变量和值标签。** Run API 接受严格的 `variable_labels` / `value_labels`；标签会进入数据上下文、报告表格、图形坐标/分类刻度和 XLSX 导出。没有标签时使用明确的列名 fallback，不伪造用户标签。
- **报告审阅工作区。** Report 页面提供工作区级 `Report review` 标签，支持 Float/Pin/Collapse 与不可变 revision；报告正文可改，run、事实表、模型结果、诊断 artifact 与 lineage 不可改。

## 行为变更（升级前请注意）

- **PDF 与 XLSX 改为按需导出。** 已完成的 run **不再自动携带** `report_pdf` 与 `tables_xlsx` 产物；展示型导出改由用户显式触发。这是有意的产品决定，不是缺陷。依赖「跑完即有文件」的既有习惯或脚本需要相应调整。
- **单样本/配对检验需要显式声明。** `/runs` 新增 `statistical_tests` 表单字段：

  ```json
  {"paired_columns": [["before", "after"]], "reference_means": {"score": 6.0}}
  ```

  未声明即不产出这些检验。畸形声明以 `STATISTICAL_TESTS_PAIR_INVALID` /
  `STATISTICAL_TESTS_REFERENCE_MEAN_INVALID` fail-closed，**不按列顺序猜测配对**。

## 独立验收发现的缺陷与修复

候选版本冻结后由一次独立验收（重跑全量测试 + 对 statsmodels 取数值对照 + 真实 DeepSeek 浏览器验收）发现并修复。这些缺陷都不会让测试变红、也不会让流程报错——它们产出的是**看起来正常、实际错误或不可达**的结果，因此原有的确定性闸门一条都没抓到。

### 1. `frequency_weight` 执行的是分析权重语义（正确性缺陷）

`frequency_weight` 与 `analysis_weight` 此前都走 `smf.wls`。系数恰好一致，但标准误、残差自由度和 nobs 描述的是一个从未被观测到的样本。240 行、权重合计 486 的数据上：

| | se(education) | nobs |
|---|---|---|
| 修复前 | 0.037086 | 240 |
| 展开行 oracle | 0.023903 | 486 |
| 修复后 | 0.023902943 | 486 |

加权 run 的每一个 p 值和置信区间此前都是错的。修复：频数权重声明「这一行被观测了 w 次」，因此按定义重复该行执行，使 nobs、自由度和三种协方差估计量**按构造正确**。同时拒绝分数计数、限制展开样本量、为重复行标识加后缀；全 1 权重路径逐位不变。

### 2. 预测指标不计权重（正确性缺陷）

R² 与 RMSE 在全部六个计算点（OOS、开发期 CV、baseline、两个负对照、置换特征重要性）都未加权，加权 run 报告的是一个不存在的样本的表现。已改为加权 R² / RMSE。

### 3. 有序 logit 的阈值标签指向不存在的水平

水平为 1..4 时输出 `"0/1"`、`"1/2"`、`"2/3"`，而 `outcome_levels` 是 `["1","2","3","4"]`。已改为按声明水平命名（`"1/2"`、`"2/3"`、`"3/4"`）。

### 4. 多方程族把已估计的变量报成被丢弃

多项 logit 与分位数回归的系数名形如 `<equation>:<term>`，丢弃变量检查做精确键匹配，于是把每个**已估计出系数**的预测变量都报成「因完全共线被丢弃」。已改为识别方程前缀。

### 5. Agent 读不到统计证据（可达性缺陷）

一次已持久化 138 条统计证据的 run，Agent 仍回答项目中没有 ANOVA 事后比较。两处可达性问题：有界投影按前 N 条取样，而成对 Cohen's d 条数高一个数量级，事后比较与效应量一条都进不了预算（已改为按检验族轮转）；Global Agent 运行在另一套七个工具上，其中没有统计证据入口（已新增 `inspect_project_statistical_evidence`，`ToolDefinition` 同时补上 `description`）。

真实 DeepSeek 端到端验证：Agent 现在调用该工具，报出 `anova_posthoc:wage:region` 的 statistic `0.30106559564465674`、p `0.82461235192019`，与持久化证据包逐位一致，并主动更正了自己先前的结论。

- **future-shift 泄漏诱饵此前完全缺失。** 设计 §8.3 整节规定的发布级验收一行未写。已补：时间序列结构 + 显式未来位移特征的请求必须在任何拟合前被拒绝，测试同时断言 **estimator 从未被调用**（设计明确要求，不能只查 UI 文案），且不产生任何 packet。

## 已知限制与明确不宣称

- **有序 logit 不会被自动选中。** 整数编码的量表（如 1–4 的李克特）被判定为**计数型**并自动路由到 Poisson，而非 `ordinal_logit`。这符合「既有 continuous/binary/count 路由行为保持不变」的设计不变量，但意味着**想用有序模型必须显式指定 `model_type=ordinal_logit`**；仅当因变量本身是有序分类类型时才会被自动识别。问卷数据最常见的形状恰是整数编码，使用者需自行判断。
- **`sampling_weight` 与分层/PSU 未实现。** `strata` 与 `PSU` 目前只出现在错误信息中，没有实现。这意味着**需要复杂抽样设计的调查数据（如 CGSS/CFPS/CHARLS/NHANES）在本版中不能得到正确的方差估计**。`sampling_weight` 保持 fail-closed 而非静默降级为其他权重语义。
- **MICE 的实际边界。** 通用 Run 的全表 MICE 路径工作正常（实测 80 行数据全部保留、`mice_summary.json` 与 `mice_decisions.json` 齐全）。prediction 通路使用折内 IterativeImputer：插补器在每个训练 fold 内拟合，分别应用到验证/测试 fold；非数值缺失特征、超过配置缺失率、fold 过小等前提不满足时 fail-closed。此前版本说明称通用全表 MICE 为「能力回退」，与实测不符，已更正。
- **列级前视无法检测。** 没有 availability/provenance 声明时，系统不能判断某列是否偷看未来。把时间序列数据声明为 IID 时，一个显式未来位移的特征可以跑出 r² > 0.9 的结果而不被拦截。设计已声明这一限制，`test_future_shift_leakage_decoy_v186.py` 将其钉为可见的已知行为，待 provenance 检测落地后应收紧为拒绝。
- **外部标签格式不宣称自动保留。** 可验证的是 Run/API 显式 `labels` 及其报告、表格、图形消费；`.dta`/`.sav` 等外部格式的标签自动保留不属于本版交付。
- **数据节点模型桥接范围有限。** 当前入口只启动数值 OLS；其他模型族仍通过普通 Run/Genesis/Agent 入口使用。
- temporal / panel prediction 的实际执行、PIT/quantile 全面研究套件、自动调参、深度学习和任意代码执行仍不属于本版本交付。
- 本地单元/集成测试不等于「所有族都已通过外部 oracle」。见下节验证等级。
- 完整 gate 已通过；报告审阅工作区（Report review 标签、Float/Pin/Collapse、跨 Notebook → Graph → Table 保持、显式导出、顶部 revision 编辑入口）已完成原生浏览器验收，记录见 `report-review` 验收事件 **015、019、021**，本轮又复核了悬浮标签脱离右侧标签栏、Pin、Collapse/Expand 与 Dock 回归。

## 模型族验证等级

- `ordinal_logit`：**仅内部一致性测试**；后端契约/运行/消费者测试通过，原生浏览器模型节点重跑已完成；阈值标签缺陷已修复。没有把 R `polr` 的求解器差异包装成逐位 oracle 通过。
- `multinomial_logit`：**仅内部一致性测试**；后端契约/运行/消费者测试通过，本轮未做原生浏览器运行；R `nnet::multinom` 对照用于发现并修复基准类别标签错位，但当前优化结果不宣称逐位复现。
- `survival_cox`：**Cox 系数、标准误、p 值和置信区间已对 R `survival::coxph` 做字段级验证（`1e-14` 跨语言浮点容差）**；RunForm 配置 `event_column=event` 的原生浏览器运行已完成并生成 `survival_evidence`。这不扩展为整个 survival packet 的外部逐位 oracle 声明。
- `quantile_regression`：**仅内部一致性测试**；后端契约/运行/消费者测试通过，本轮未做原生浏览器运行；不宣称与 R `quantreg::rq` 逐位复现。
- `frequency_weight` OLS：修复后与**行展开 oracle** 逐位一致。行展开是频数权重的定义，但**不是第三方实现**；对 Stata `[fweight=]` 的外部验证仍未完成。
- 独立验收中对 ordinal/multinomial/Cox/quantile 的数值复核使用 statsmodels，而 statsmodels 正是执行引擎，因此属内部一致性验证，不构成外部 oracle。
