# Workbench v1.8.5 — Typed Memory and Model-Family Contracts

v1.8.5 把两类容易被 Agent 混用的东西收敛成服务端契约：记忆只能在明确的
作用模式和有效性边界内提供建议；Notebook 的模型族、参数、能力和产物必须来自
同一份已发布注册表。重点不是增加一长串模型名称，而是让同一类错误在入口统一
修复、统一拒绝、统一显示。

## 本版本交付

- **Typed Memory。** 记忆带有 `apply_mode`、`vocabulary_version`、verifier、
  `last_validated_at`、source binding 和 revision。运行时会拒绝过期、无效或
  无法绑定来源的记忆；`inform_only` 与 `suggest_default` 的作用边界保持显式。
- **本机记忆管理。** 自动建立本机持久化库；Settings 支持全局库、项目库、项目
  是否使用全局库、候选生成、审核、归档和删除确认。全局记忆不会自动进入项目，
  必须在项目内明确启用。
- **模型族契约。** OLS、`panel_ols`、GLM/DID 家族及 ETS、ARMA/GARCH Recipe
  通过统一的 family/recipe contract 发布能力、参数和结果词表；Notebook 不再把
  OLS 的 covariance 或分支字段复制到不接受它的模型。
- **Notebook 规划入口统一化。** 服务器负责补齐 option envelope 中的稳定 ID、
  evidence 引用、能力 ID、数据源 pin、执行 preconditions 和已发布 expected
  artifacts。模型仍然负责选择方法、变量和解释；服务器拥有的事实不再由模型
  自由猜测。
- **错误类别收敛。** source upload 未 pin、旧的 capability label、未知 option
  字段、错误的 OLS `branches`、跨族 covariance、虚构 artifact ID 和空能力目录
  均由同一条 registry-driven canonicalization/admission 路径处理，不靠为每个
  模型再加一个特例。
- **可观察失败。** provider 上游不可用仍然 fail-closed，并通过
  `NOTEBOOK_PLANNING_UNAVAILABLE` 暴露；它与本地契约拒绝分开，不伪装成规划成功。

## 明确不宣称

- `LLMUpstreamError` 仍可能由外部 provider、网络或上游限流触发；本版本只保证
  它不会被误报为可执行规划，也不保证外部服务永远可用。
- 不引入任意代码执行、任意依赖安装、原始数据自由读取或新的自动执行面。
- 机器学习、量化研究和超参数搜索不属于 v1.8.5 范围。
- 未把一次真实 provider 成功扩大解释为所有模型族的浏览器级统计正确性；复杂模型
  仍需各自的数值 oracle 和端到端验收。

## 后续边界

下一阶段应优先在现有契约上建设通用预测/机器学习底座，再把量化作为更严格的
时间可得性、面板和可交易性 profile；不应重新分叉一套 Notebook、Memory 或
Proposal/Risk 生命周期。
