# Workbench v1.8.2 — Raw-node statistics and Agent-composed workflows

v1.8.2 adds a pre-model statistical exploration surface on the immutable Raw
data node, and makes the Agent able to compose a multi-step statistical
workflow over it from one natural-language request. A user can now go from an
uploaded table to grouped descriptives, correlations, percentile-derived group
comparisons, scatter plots, regressions and a report without writing code and
without choosing a model first.

## Highlights

- **Raw-node statistical exploration.** Compose AND filters, preview and
  persist grouped descriptive statistics, detailed Stata-convention
  percentiles, missing-value tables, and a pooled correlation matrix. Every
  persisted result retains its source node, filter specification, grouping,
  quantile method, missing-value policy, selected variables, and artifact
  references.
- **Agent-composed workflows.** `operation.multi_step` accepts a plan the Agent
  writes: an arbitrary DAG of typed steps with `depends_on`, executed in
  topological order under one confirmation. Steps that fail block their
  dependents rather than being skipped, and a resumed workflow reuses the steps
  that already completed.
- **Derived model terms.** A model branch may declare `categorical` columns for
  dummy expansion (lowest sorted level held out as the reference) and
  `polynomials` for powers. Terms are materialized into a content-addressed
  augmented dataset before estimation; the original upload is untouched.
- **Published step vocabulary.** `inspect_operation_contract` answers for
  `operation.multi_step` and publishes the exact spec fields, required keys and
  closed value sets for every composable step, so a plan is written against the
  contract rather than guessed at.
- **OLS model-options contract.** OLS now owns a typed `model_options`
  envelope, so a Notebook or rerun patch that sets `covariance` changes the fit
  instead of binding successfully and leaving the standard errors alone.
- **Table view scoped to the selected lineage chain**, with an inline figure
  gallery and confidence intervals in the coefficient table.

## Removed

The multi-step workflow was first built to answer a single course exercise, and
that exercise had been encoded in the server: a named preset whose bindings
were its variables, a fixed set of its survey years, a diagnostics gate keyed
to its column names, a UI placeholder suggesting those years, and a report line
that named the exercise to every future user.

The preset compile path and its bindings are gone. An Agent-composed step list
is now the only accepted form of `operation.multi_step`, so no assignment can
be privileged over another. `tests/test_no_exercise_specific_naming.py` scans
product source and fails if a specific assignment, dataset column, or panel is
named again. Two reads of legacy persisted context keys remain, each marked
`# legacy-compat`, so a Draft created before the rename still resumes instead
of re-estimating under a new identity.

## Verification

The release candidate `f66823e` passed the full gate on a host with no
competing dev server:

- Backend: 3618 passed, 8 skipped, 1 xfailed.
- Golden / invariants / snapshot: 23 passed, 0 drift.
- Frontend: 163 test files, 1419 passed.
- TypeScript check: passed.

Two independent Stata computer exercises were driven end to end against a live
DeepSeek-backed Agent on freshly created projects, from a single
natural-language request through confirmation to execution:

- **Exercise 1** (grouped descriptives, pooled correlations, missing-value
  check, detailed percentiles, quartile-derived group comparisons, scatter
  plots, two regressions): every step completed. Group counts, per-year means,
  percentiles, missing counts and both regressions were checked against an
  independent statsmodels/pandas computation and matched to every printed digit
  — for example the simple regression's coefficient 11.547073, standard error
  3.289359, p 0.000452, R² 0.002991, 95% CI [5.0981, 17.996], n 4110.
- **Exercise 2** (year dummies, a polynomial in enrollment, a middle-school
  dummy, borough dummies): the four coefficients on the demographic share
  reproduced the assignment's published answers exactly: -10.407611, 5.927226,
  6.486635 and 8.041094.

Exercise 1 was re-run after the preset removal and produced identical
coefficients, with the Agent choosing a different plan shape than before (two
single-branch model steps instead of one two-branch step).

## Not claimed

- **Interaction terms cannot be expressed.** A branch may declare linear
  predictors, categorical expansions and polynomial powers; there is no
  interaction syntax. The Agent states this boundary rather than approximating
  one.
- **Custom estimators are not supported.** A model that Workbench does not
  already implement cannot be added by the Agent. `code.execute` remains
  registered but is not natural-language reachable, and its signature is
  DataFrame-to-DataFrame, which cannot express an estimator. The design for a
  `model.custom` contract is recorded in
  `docs/superpowers/specs/2026-07-25-model-custom-contract-design.md` and is
  not implemented.
- **No browser smoke was run for this release.** The Agent workflow was
  verified through the HTTP API against a live model, not through the in-app
  browser.
- Custom or Agent-authored statistical code is not part of this release, so no
  claim is made about sandboxed execution of it beyond the existing
  `code.execute` surface unchanged from v1.8.1.
