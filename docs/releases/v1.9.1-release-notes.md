## 版本定位

v1.9.1 把 Agent 做成“研究版的 Claude Code”：由你选择 **Ask every step（每步都问）** 或 **Auto within plan（计划内自主执行）**；
计划始终可见、可以编辑；随时插话纠正、中断、整段撤回；关掉窗口后回合照样在后台运行。不接模型时，全部功能仍可手动完成。

## Agent

- **两种执行模式**：Ask 下确认之后 Agent 自动接着做，不需要说“继续”；Auto 下批准计划一次，计划内的只读与派生步骤直接执行。改原始数据、导出、外发和登记的高风险操作在两种模式下都逐次批准，这条安全底线不受任何项目规则影响。
- **项目权限规则**：设置页可按操作类别或具体操作写 allow / ask / deny，保存前校验、按文件版本防并发覆盖；deny 优先，安全底线高于一切规则。
- **计划**：有向无环图、版本与差异、执行前预检、你可编辑；批准即记为预先设定（`criteria_fixed`），之后新增的步骤标为探索性，报告分两节。
- **纠正与恢复**：插话（steer）、追加（follow-up）、中断、对话与谱系一起撤回；斜杠命令；回合持久化，服务重启后从断点继续且不重复执行。
- **完成前自检**：按剧本检查方法、诊断、稳健性、数字可追溯与结论边界；缺项时给出可执行的修复步骤，有界地自动补完，不需要你催。
- **方案比较**：结果盲的方案比较取代旧 Plans 视图；Notebook 页与旧外壳退休，18 项功能逐项迁移到新位置。
- **工具接口**：读取类工具并行；合同按需读取，常用步骤的字段直接写在协议里；错误信息附可照用的正确写法；请求准入按本回合实测耗时判断。
- **扩展**：项目技能、外部工具、钩子三个插槽与内置技能；外部工具输出受外发管控。
- **可观测性**：每步耗时、token、缓存命中与原始 usage，界面有本次任务的用量明细；未发送的请求单独列出。
- **无界面运行**：`workbench agent run` 输出事件流；评测走同一入口，回归用录制回放（零调用）。

## 分析能力

- **原生数值核心（Rust / C++）**：时间序列（ACF/PACF、AR 到 ARIMA/SARIMAX、ETS/Holt-Winters、VAR/VECM、ARCH/GARCH 系列）、岭回归与弹性网、决策树与随机森林（保存的森林可对新数据预测，分类器给出概率与标签）、带费用的组合回放；手动与 Agent 走同一入口，每个方法有独立数值对照。除下面“行为变化”一节的面板固定效应外，默认路径的估计、标准误和检验统计量与 v1.9.0 逐位一致（golden、invariants、snapshot 零漂移）。
- **可选快速引擎**：IV 等估计可选原生快速路径，默认仍是参考路径。
- **OLS 不满秩**：像 Stata 一样省略不可识别的项并在原样本上重拟合，列出省略项。
- **IV**：结果、内生或工具变量缺失时按 Stata 逐行删除；单内生变量 AR 置信集合全局认证。

## 行为变化（重跑已有分析时数值会变）

### 面板固定效应按声明的列来加

- **以前**：`panel_ols` 只声明了个体列（例如 `entity_col = firm`）、没声明时间列时，引擎仍会用自动识别出的时间列（例如 `year`），同时加上时间固定效应。结果文件里会写 `time_col: year`，但这不是用户要求的设定："仅个体固定效应"和"个体 + 时间固定效应"得到的结果完全相同。
- **现在**：只要声明了任一面板列，就严格按声明来，没声明的那一列不加效应。两列都没声明时，仍和以前一样用自动识别的两列。
- **对已有结果的影响**：
  - 已保存的结果不会变。
  - 重跑"只声明了个体列"的设定时，会从双向固定效应变成单向（个体）固定效应，系数和标准误都会变。例如评测任务 `panel_fe`：培训效应 0.5137（双向）→ 0.5161（单向），真值 0.5。
  - 只声明了时间列、并使用默认聚类标准误的设定，以前会悄悄按自动识别的个体列加效应并聚类；现在会提示 `PANEL_CLUSTER_ENTITY_REQUIRED`，要求给出聚类变量或个体列。
- **不受影响**：DID 系列（`did`、`cs_did`、`sa_did`、`dcdh`）需要同时有个体和时间结构，仍会用自动识别补齐没声明的那一列；数据层面的时间序列诊断和图表也照旧使用识别出的时间列。
- 证据：`tests/test_panel_declared_effects.py`，各设定的系数都与直接调用 linearmodels PanelOLS 一致（相对误差 1e-12）；发现经过见 `docs/superpowers/evaluations/2026-10-21-v1.9.1-candidate-rounds.md` 的"推理回传轮"。

## 性能

- 1M 行“导入 + OLS”：3.67 s（v1.9.0 约 26 s，目标 ≤ 8 s）。
- 对 v1.9.0 的资源对照（2026-11-19 同一干净提交，按置信区间判定）：OLS、面板、DID、IV 的耗时为 v1.9.0 的 0.17–0.47 倍；OLS 与 DID 内存为 0.76 与 0.68 倍；写盘字节持平。面板与可选 IV 的内存未判定。
- Agent：QRData 每题请求中位 6 → 4，墙钟中位 215 s → 44 s（同一线路、同一驱动）。

## 已知限制

- **正式评测没有跑完**：开发集 198 位置、pass³、留出、外部（BLADE、DiscoveryBench、红牌、Huntington-Klein）、Agent 论文复现和消融，均转为 v1.9.2 的第一个里程碑。本版不宣称达到 objective 的任何评测目标。
- **“需要说继续”没有降到 0**：这是 objective 的安全底线之一，只能靠真实模型测量；本版开发哨兵 5 个位置每个 1 次、Auto 1 次，v1.9.2 列为硬门。注入、越权、数字核对和“确认后说只读”四项在离线测试中为 0，真实模型红队未做。
- **请求体偏大、被拒偏多**：每任务 prompt 中位远超 30 万 token；QRData 哨兵工具被拒率 11.5%（目标 ≤ 3%），以模型写错参数格式为主。
- **资源**：面板与可选 IV 的内存比值置信区间跨过 1.05，未判定（不是退步）；原生长计算在同步合同阶段不可抢占，中断达不到 ≤ 1 s。
- **真机场景**：三条浏览器真机场景（IV Ask、面板 DID Auto、开放问题）未做；关窗后系统通知的可见性未在真机验证。
- **评测线路**：真实调用只用 NVIDIA 免费线路（`nemotron-3-ultra`），与立项时的 DeepSeek V4.1 Flash 不同；v1.9.0 基线在 DeepSeek 上测，跨线路比较只作参考。
- 只在本机 macOS 验证。完整遗留清单见 `docs/superpowers/followups/BACKLOG.md` §0.0.1。
