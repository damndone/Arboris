# V1.5.0 Release Notes — Lineage UI/UX Integration

**Status**: Complete. FE 329/329, BE 617/617, browser smoke verified
2026-05-25 against a fresh v3 run.

V1.5.0 is the first end-to-end pass of the editorial lineage view.
After running `workbench run`, the user lands directly on a dark
canvas with stage-coloured nodes, a detail drawer driven by a
section registry, screen-space hover tooltips, and a tri-state
related-set highlight. Everything is wired to the V1.5.0 graph
adapter so backend schema changes after V1.5.0 stay localised.

## What shipped

### Architecture

- **Adapter layer** (`frontend/src/lineage/api/graphAdapter.ts`):
  backend `GraphResponse` (schema v1/v2/v3) → V1.5.0 `GraphViewModel`.
  Single boundary for backend shape changes. Forward-compat slots
  (`runtimeMs`, `stats`, `artifacts`, `coefficients`, …) declared on
  `GraphViewNode` but unused by V1.5.0.
- **Backend graph schema v3** (`backend/workbench/graph_model.py`):
  `Stage` enum, six orchestrator stage-tag sites, every factory
  registered in `STAGE_BY_DECISION_ID`.
- **Section registry** (`frontend/src/lineage/detail/sections/`):
  declarative section pipeline. Drawer composition is one
  `sectionRegistry.ts` constant; adding a section in V1.5.x is a
  two-line change (new file + registry append).
- **LineageContext** + `useLineage()`: implicit dependency injection
  point for every interior surface that needs the view model.

### Components

- `lineage/graph/GraphNode.tsx` — editorial card with 8px left
  stage bar, kind eyebrow, serif title, optional REVIEW / CAUTION
  trust badge. Tri-state (`selected` / `related` / `dim`) driven by
  GraphCanvas-computed `related` set.
- `lineage/graph/GraphTooltip.tsx` — screen-space portal to
  `document.body`, 240 ms hover delay, zoom-independent position.
- `lineage/graph/GraphCanvas.tsx` — React Flow host, dagre layout,
  fold/expand for variable clusters, T8.6 canvas chrome (toolbar,
  status badge, stage legend, scoped Controls restyle).
- `lineage/detail/DetailDrawer.tsx` — registry-driven sections:
  TrustBanner, LineageChainSection, BasicsSection, DecisionSection
  (plus header + Actions menu + Raw JSON modal hookpoint).
- `lineage/decisions/decisionRegistry.ts` — humanised decision
  metadata for the 6 V1.4.0 decision IDs; survives unknown ids
  via the `humanize(...)` fallback.

### Product path

- **CLI**: `workbench run …` now prints a copyable lineage URL:
  `Lineage: http://localhost:5173/runs/<id>?project_root=…&tab=lineage`
  Origin overridable via `WORKBENCH_UI_ORIGIN`.
- **Submit page**: clicking "Run workflow" auto-navigates to the same
  URL (P0). Works for both `status=completed` and `status=blocked`.
- **Route-scoped dark chrome** (P1): `/runs/<id>` flips AppShell
  header + outer Submit/History tabs + inner Overview/Lineage tabs
  to the dark editorial surface. Submit (`/`) and History (`/runs`)
  intentionally stay on the V1.4 light surface.

### Tokens

`frontend/src/lineage/tokens/lineage.css` — full OKLCH palette,
dark default + light theme override:
- 8 `--stage-*` colours
- 3 trust tokens (`--ok`, `--review`, `--caution`)
- `--ink` (editorial stroke) ≡ `--tint` (accent fill) in V1.5.0 —
  separate tokens kept so they may diverge in V1.5.x without
  churning consumers.
- 3 font stacks (serif / sans / mono) with Chinese fallback
  (Songti SC, Noto Serif CJK SC, PingFang SC).

## What was explicitly deferred

These are V1.5.1+ scope and intentionally absent:

- Left rail with stage navigation + counts
- Top-row workspace breadcrumb / search / Rerun / Generate Report
  buttons
- Bottom terminal panel
- Trust banner inline action buttons (rerun-to-here, mark-bad-
  decision, AskAI)
- Multi-tab drawer
- Drawer header breadcrumb chip path

The lineage canvas + drawer interior matches the design intent at
V1.5.0 scope. Outer-shell structural items above are tracked under
V1.5.1.

## Known cosmetic items (not blocking)

- Status badge can overlap synthetic group nodes on a narrow canvas.
  T8.6a follow-up; cosmetic, doesn't affect functionality.
- Drawer header path is flat text, not a breadcrumb chip set. The
  same information is visible, just less visually structured than
  the design reference.

## Migration / breaking changes

- `Inspector.tsx`, `LineageTab.tsx` deleted (subsumed; see commit
  `8503c03` for the equivalence proof). External consumers should
  not exist — these were internal to the lineage module.
- `dpRegistry.ts` → `decisions/decisionRegistry.ts`. The exported
  symbol `getDPDisplay` is unchanged — symbol rename to
  `getDecisionDisplay` deferred to V1.5.1.
- `NodeCard` / `NodeTooltip` / `GraphCanvas` moved under
  `lineage/graph/`. Imports inside the lineage module updated; no
  public API change.
- `frontend/dist/` is now gitignored. If you previously had local
  build output committed, it has been untracked.

## Sign-off

V1.5.0 ships the lineage UI/UX integration end-to-end. The outer
workspace shell (left rail / terminal / topbar workspace context)
remains V1.4.1-shaped; that's the V1.5.1 scope.
