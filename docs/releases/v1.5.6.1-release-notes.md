# V1.5.6.1 — cs_did 变量聚类（variable clustering）

补完 v1.5.6 里被搁置的 CS DID **变量聚类**路径。0 新依赖、点估计冻结，
golden 仍 0-drift（既有 18 + 新增 1 条聚类 golden）。

## 做了什么

- **完成休眠的 cs_did 变量聚类路径。** 此前 CS DID 只能按 entity 聚类；
  `cs_cluster_var` 形参虽已贯通端到端，但实际聚类逻辑被 defer。本版把它接通：
  现在可以选任意一列做 one-way 变量聚类。
- **单行约定（single row convention）。** 影响函数（influence function）始终在
  **entity 级**计算；只有在两个方差步骤——解析 CRVE 标准误 + multiplier
  bootstrap——才按 cluster 做 rowsum。点估计与四种聚合完全不受影响。
- **确定性 CRVE oracle。** 用 R `did` / `DRDID` 的影响函数构建确定性聚类稳健
  方差 oracle，逐元素校验到 **1e-8**。
- **恢复 cluster-var UI 选择器。** 前端 CS DID 面板重新暴露 cluster 列选择器；
  留空 = 按 entity 聚类（默认）。
- **诚实的 metadata。** 结果带 `n_units` / `n_clusters` / `cluster_level`
  三项，如实反映聚类维度。
- **坏聚类列的结构化失败。** 缺失、不存在、或只有单一取值（单一 cluster）的
  聚类列，返回结构化 `MODEL_FIT_FAILED`，不再悄悄给出误导性的标准误。
- **golden 0-drift。** 既有 golden 一字不动；新增 1 条 additive 聚类 golden
  (`cs_did_clustered`) 钉死聚类 run 的形状（点估计 ATT 与非聚类一致，确认聚类
  只动 inference）。

## 为什么安全

- 点估计路径不变：聚类只进入两个方差步骤，ATT(g,t) 与聚合逐字不变。
- 影响函数仍在 entity 级生成，cluster rowsum 只在方差计算时叠加。
- CRVE oracle 锁死在 R `did`/`DRDID` 参考夹具上（1e-8）。
- multiplier bootstrap 已 seed，聚类 golden 在两次运行间稳定（已验证无漂移）。
