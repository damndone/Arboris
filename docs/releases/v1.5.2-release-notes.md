# V1.5.2 Release Notes — Workbench Spine

**Status**: Complete. FE 518/518, BE 621/621, frontend unit tests
green; backend baseline preserved from V1.5.1.

V1.5.2 is an **extensibility-scaffolding release**. It does not ship
new product capabilities by itself; it establishes the stable
contracts that V1.5.3+ (Editable Ops, Code Editor, AI, Report,
Table/Pipeline) all plug into.

The user-visible change is small but real:
`/runs/<id>?tab=lineage` lands on a new run-level Workbench shell
with a view switcher (Graph / Table / Pipeline), a right-click
context menu on graph nodes, a ⌘K search palette, a bottom panel
with live Logs, three new DetailDrawer slots, and a 5-level graph
highlight model. The underlying spine is what V1.5.3+ will hang
real backends off.

## What shipped

### Architecture (`frontend/src/workbench/`)

The new `workbench/` directory houses the cross-view layer that
sits above `lineage/`. Plan §2 layout (final):

```
WorkbenchRouteContainer
  ├── WorkbenchStateProvider          (cross-view state, URL writes)
  ├── LineageContext.Provider          (back-compat for V1.5.0/1.5.1)
  ├── WorkbenchTopbar                  (view switcher + action slot)
  ├── RunHistoryRail   WorkbenchMain   DetailDrawer   ← flex row
  │   (240px)          (flex:1)        (320px, conditional)
  ├── BottomPanel                      (auto height, splitter)
  └── portals: ContextMenu, SearchPalette, RawJsonModal
```

`GraphView` is now slim — only canvas + legacy banner + view-local
fold state. `TableView` / `PipelineView` ship as real empty-state
views consuming the same `selected / focus / search / action`
contract; V1.5.3+ can fill them without touching state / URL /
drawer / search wiring.

### State & URL (plan §6, §7, §18)

`WorkbenchStateProvider` owns the §7 transition table. Every state
change goes through one `dispatch.*` method; each method writes the
URL via a single internal `commit()` that combines tabs slice + URL
slice + one `setParams` call. (Two back-to-back `setParams` overwrite
each other in React Router 6.)

URL three-tier:

| Tier | Lives in | Contents |
|---|---|---|
| 1 | URL search params (shareable, refresh-restorable) | `view / tabs / active / q / panel / panelOpen / focus / pinned` |
| 2 | `sessionStorage` keyed by runId | viewport, expandedGroups, splitter height, layout, legacy-hint dismissal |
| 3 | Memory only | hover, search cursor, context menu, Ask-AI stream buffer |

`selectedKey` is *derived* from `activeTabId` — never stored
separately. `focusKey` is independent (plan §7's "right side
reading A, middle pinning B's upstream" scenario).

Legacy `?node=` URLs migrate to `tabs=<node>&active=<node>` on
read; URL writer drops `?node=` going forward.

### Registries (plan §4, §11, §12)

Three registries share one `RegistryEntry<TContext>` base:

| Registry | File | V1.5.2 contents |
|---|---|---|
| `sectionRegistry` | `workbench/registry/sectionRegistry.ts` | 7 sections: trust / askAi / operation / code / lineage / basic / decision |
| `actionRegistry` | `workbench/registry/actionRegistry.ts` | 12 actions: 7 live (openDetail / pinTab / copy{NodeId, AsJson, LineagePath} / focusUpstream / pinUpstream), 5 disabled placeholders (askAi / rerun{FromNode} / markNeedsReview / rerun / generateReport) |
| `bottomPanelRegistry` | `workbench/registry/bottomPanelRegistry.tsx` | Logs (live SSE), Shell / Pending / Timeline (disabled placeholders) |

Actions filter by `surface`: `graph-context-menu` / `drawer-header-menu` /
`topbar` / `shortcut` / `command-palette`. The right-click menu, the
drawer's "Actions ⌄" button, and the topbar's right-side action slot
all consume the same registry.

### RunSnapshotAdapter (plan §5)

`workbench/RunSnapshotAdapter.ts` is the index/projection layer over
`GraphViewModel`: `nodeByKey`, `nodesByStage`, `decisionsByNode`,
`variables`, `models`, `searchIndex`, `upstreamOf`, `downstreamOf`,
`lineagePathTo`. Mirrors `pathBuilder.MAX_HOPS=100` + lex-smallest
tiebreaker so Drawer chips, canvas highlight, and AI scope all walk
the graph the same way.

### Components

- `workbench/views/GraphView.tsx` — slim canvas view. Reads
  focus / search / context-menu state from `useWorkbenchOptional()`
  (degrades to no-op outside the provider for bare-mount tests).
  Owns expandedGroups + layout (Tier 2 sessionStorage).
- `workbench/views/TableView.tsx`, `PipelineView.tsx` — empty
  "coming in V1.5.3 / V2.0" surfaces. Both display the current
  `selectedKey` to prove they share the workbench selection.
- `workbench/WorkbenchTopbar.tsx` — view-mode tabs +
  registry-driven action buttons.
- `workbench/WorkbenchMain.tsx` — view dispatcher; mounts exactly
  one of GraphView / TableView / PipelineView per `state.view`.
- `workbench/ContextMenu.tsx` — portal context menu, driven by
  `actionsForSurface("graph-context-menu", ctx)`. Closes on
  Escape / outside-click / scroll; repositions when clipped.
- `workbench/BottomPanel.tsx` — tab strip + body. Active tab from
  `state.bottomPanel.id`; open/close from `state.bottomPanel.open`.
  Splitter height from Tier 2 sessionStorage (fixed 240px in V1.5.2;
  drag handle lands V1.5.3 alongside Shell panel).
- `workbench/SearchPalette.tsx` — ⌘K palette. Input is local
  state — typing does NOT write `?q=` until Enter/click commits via
  `dispatch.selectBySearchCommit`. Up/Down navigates results;
  Escape closes without touching selection/focus.
- `workbench/panels/LogsPanel.tsx` — subscribes to existing
  `connectRunEvents` SSE for live progress events.

### DetailDrawer extension slots (plan §13, §14)

Three new sections registered at V1.5.0-reserved slots:

| Slot | Section | When it renders |
|---|---|---|
| 20 | `AskAISection` | always — visible "AI is coming" surface |
| 30 | `OperationSection` | when `node.editableSchema` non-empty (read-only in V1.5.2) |
| 40 | `CodeSection` | when `node.code.body` present (read-only in V1.5.2) |

No section fakes backend capability. Ask AI's CTA is `disabled`
with a tooltip pointing at V1.5.3.

### Graph highlight model (plan §8)

`GraphNodeState` extended from 3 to 5 states:

| Priority | State | Rendering |
|---|---|---|
| 1 (highest) | `selected` | `--ink` outline (V1.5.0) |
| 2 | `focus` (when ≠ selected) | dashed `--review` outline |
| 3 | `focus-upstream` | lighter `--review` accent + 0.85 opacity |
| 4 | `related` | full opacity (V1.5.0) |
| 5 | `dim` | 0.4 opacity (V1.5.0) |

`isSearchHit` is a separate boolean flag layering a `--tint`
box-shadow overlay; it does NOT displace state 1–4.

### Lineage chain chip strip (plan §9 Layer 2)

`LineageChainSection` is now a clickable chip strip:
- left-click on a chip → `useLineage().select(nodeKey)` (opens/
  activates that node's tab)
- right-click → workbench context menu (Pin / Focus upstream, Copy
  lineage path, etc.)
- chip label uses `summary || title` for parity with `Copy lineage
  path`'s output

## Back-compat & migration

All V1.5.0 / V1.5.1 surfaces continue working unchanged via thin
re-export shims:

- `lineage/GraphWorkbench.tsx` re-exports `workbench/views/GraphView`
- `lineage/LineageRouteContainer.tsx` delegates to `workbench/WorkbenchRouteContainer`
- `lineage/detail/sections/sectionRegistry.ts` re-exports from `workbench/registry/sectionRegistry`
- `LineageContext` / `useLineage()` unchanged — drawer + decision
  panel + chip strip all keep consuming it

Legacy `?node=` URLs migrate to `tabs=&active=` on load; writer
drops `?node=` going forward. `tab=lineage` and `project_root`
are preserved as unknown params.
