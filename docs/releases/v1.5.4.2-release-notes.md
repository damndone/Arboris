# V1.5.4.2 — Release Notes

**Theme:** Close GUI gaps where backend econometrics capabilities existed but were unreachable from the UI, plus an iOS design language for the new controls.

**Branch:** `workbench-v1.5.4.2` (base: `main`, includes shipped `v1.5.4.1`)
**Gates:** Backend 751 passed (full extras) · Frontend 582 passed · golden + invariants + behavior-snapshot 14 passed (0-drift) · CLI auto-path smoke ✅

## What shipped

Three backend capabilities — present since V1.5.3.2 but reachable only via `config.yml`/CLI — are now surfaced end-to-end through the GUI, with their results displayed:

1. **Panel OLS entity/time columns.** Users can specify the individual (entity) and time columns from the run form (either one suffices). Injected by overriding the auto-detected candidates in `RoutingStage`; user input is normalized to match cleaned column names (so headers like "Company Unit" work).
2. **Panel covariance type.** `robust` (default) / `clustered` / `unadjusted`, forwarded to `run_panel_ols(cov_type=...)`.
3. **Prediction / ML models.** Lasso / Ridge / Random Forest with cross-validation folds and imbalanced sampling (SMOTE / oversample / undersample). Prediction params now follow **request-over-config** precedence. Results (Test R², Test RMSE, CV R²) render in a new `PredictionResultCard`.

Supporting changes:
- **Capability manifest (schema_version 2):** `GET /capabilities` now returns `prediction_models`, `sampling_methods`, `covariance_options`; the frontend renders the new controls dynamically. A drift-guard test pins the manifest's prediction/sampling keys to the backend's supported sets.
- **`POST /runs`:** six new optional form fields (`entity_col`, `time_col`, `covariance`, `prediction_model_type`, `prediction_cv_folds`, `prediction_sampling_method`).
- **iOS design language:** new run-form controls and the prediction-result card use an iOS token system (grouped cards, system font/colors); applied without restructuring existing page markup.
- **Client-side validation:** blocks submit on `entity == time`, Panel OLS selected without columns on non-panel data, or prediction enabled without an algorithm.

## Backward compatibility

All new backend parameters are **optional and inert when unset** — omitting them reproduces prior behavior byte-for-byte (golden snapshots 0-drift). Empty `entity_col`/`time_col` → auto-detection; empty `covariance` → `robust` (the pre-existing default); no prediction request + config disabled → no prediction runs.

## Deferred

- **IV / 2SLS** → V1.5.4.3 (the only remaining stranded capability; requires registering a new estimation handler in the engine `CORE_PACK`, so it is isolated for risk).
- Agent Harness and editable/partial rerun remain on the roadmap after V1.5.4.3.

## Notes / known minor

- The run-form validator uses `isPanelData: false` (no reliable client-side panel detection pre-run), so selecting Panel OLS prompts the user to specify a column. Acceptable UX; a future enhancement could relax it with client-side panel hinting.
- iOS surfaces use hardcoded light-appearance values, consistent with the existing V1.5.4.x hardcoded surfaces (failure card, imputation controls); a unified theme-aware pass is out of scope here.
