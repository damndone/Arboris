# Workbench v1.8.7 — 发布说明

> 状态：**未发布**（未 push、未建 PR、未 merge、未 tag）。
> 以下只描述已实现且有验证证据的能力，并逐条标注验证等级。

## 相较 v1.8.6 的主要变化

- **复杂抽样设计的方差引擎。** 可声明分层、初级抽样单元（PSU）、抽样权重、有限总体校正、
  单 PSU 层策略与重复权重（含数据自带的），得到 Taylor 线性化或重复权重的设计方差、
  正确的设计自由度，以及据此（而非正态近似）计算的置信区间。
- **设计与估计量正交。** 引擎接受任何满足「确定性重估」契约的估计量；模型族通过
  `ModelFamilyContract` 的一条声明接入，不按族分支、无「族 × 设计」支持矩阵。
  一个测试用**临时注册的合成估计量**跑通完整设计方差路径，未改动任何设计层代码。
- **ANOVA / ANCOVA。** I / II / III 型平方和、偏 eta²、Tukey / Bonferroni 事后比较。
  **平方和类型必须显式声明**——SPSS 默认 III、R 的 `aov` 默认 I，非平衡设计下两者不同。
- **统一结果契约。** 系数、区间、边际效应、诊断与图表投影收敛到一份 result envelope；
  `result_shape` 从封闭三值枚举改为可声明扩展点。
- **GLM 平均边际效应。** logit / probit / poisson 产出 AME。
- **测量级别声明与提示。** 未声明的整数量表不再静默跑 Poisson 而无任何说明；
  声明后按声明路由。
- **抽样设计前提检验。** 数据里存在疑似分层/PSU 列、设计效应明显大于 1、
  权重极端时，系统摊开事实并**提问**。
- **v1.8.6 四个模型族补上外部 oracle。** 见下方验证等级表。
- **Agent 可达性。** 抽样设计、模型族切换、批量测量级别声明均可由 Agent 提出
  typed proposal，经确认后执行并留 lineage。
- **界面英文化。** `frontend/src` 的界面字符串统一为英文（中文版后续再做）。

## 验证等级（A3-2：按能力分别标注）

三档：**对外部实现逐位验证** / **在声明容差内与外部实现一致** / **仅内部一致性测试**。

### 对外部实现逐位验证

| 能力 | 参考实现 | 容差 |
|---|---|---|
| 线性化设计方差（系数 / SE / CI） | R `survey::svyglm` | ~1e-13。`x1` SE = 0.177324041106902 |
| 重复权重：BRR / jackknife / bootstrap / provided | R `survey::withReplicates` | 逐位 |
| 五种单 PSU 层策略 | R `survey`（`options(survey.lonely.psu=)`） | 逐位 |
| 子总体（设计内取子集） | R `subset(design, …)` | 逐位 |
| DEFF / Kish n_eff | R `svymean(deff=TRUE)`、`(Σw)²/Σw²` | 逐位 |
| 调整 Wald 检验（分母自由度=设计自由度） | R `regTermTest` | 逐位 |
| ANOVA I / II / III 型平方和、偏 eta² | R `car::Anova` | 逐位。非平衡 fixture 上 I 型 166.74 对 III 型 104.05 |
| Cox 比例风险（系数 / SE / 风险比） | R `survival::coxph`（Efron） | ~1e-13。`x1` = 0.7252246388237762 |
| GLM 系数（logit / probit / poisson） | R `glm` | 逐位 |

### 在声明容差内与外部实现一致

**不可宣称「与 R 逐位一致」。** 差异来自求解器，不是实现错误：

| 能力 | 参考实现 | 实测差异 | 原因 |
|---|---|---|---|
| 分位数回归 | R `quantreg::rq` | ~1e-6 | quantreg 用 Barrodale-Roberts 单纯形精确求解；statsmodels 迭代拟合 |
| 有序 logit | R `MASS::polr` | ~3e-5 | 同一似然、不同优化器。`x1` = 0.7120182116428941 |
| 多项 logit | R `nnet::multinom` | ~3e-5 | nnet 用 BFGS 优化神经网目标；statsmodels 用 Newton |

结果 artifact 的 `validation` 字段按族携带这些声明；**声明了外部 oracle 却不写明参考实现，
契约会拒绝**。

### 仅内部一致性测试（无外部实现可对照）

- **平均边际效应（AME）** 的求导本身。底层拟合已对 R `glm` 验证，但本机无第三方 AME 包，
  边际效应值只做定义式核对。
- **`frequency_weight`** 的展开行语义。v1.8.6 已对「展开行」oracle 验证，
  **本机无 Stata，无法与 Stata 对照**。

## 行为变更（升级前请注意）

- **计数型 run 现在可能附带测量级别提示。** 因变量为少水平整数且带值标签时，
  结果会多出 `measurement/advisory.json`。**路由与统计结果一字不变**，
  只是多了一条说明。这是有意的产品决定。
- **未声明设计的 run 可能附带 `measurement/design_precheck.json`。** 同上，只增不改。
- **`sampling_weight` 不再建议 `entity_col + covariance=clustered`。** 那条旧提示是错的：
  按实体聚类不是抽样设计，给出的方差也不同。现在的拒绝信息指名缺哪个设计字段。
- **两个组合现在会被拒绝：**
  - 面板形状数据（同时声明 entity 与 time）+ 抽样权重 + 未声明 `survey_weight_frame`
    → `SURVEY_WEIGHT_FRAME_REQUIRED`
  - 时间序列族 + 抽样设计 → `SURVEY_DESIGN_DOES_NOT_COMPOSE`。
    措辞刻意不说「暂未支持」，因为它不会在后续版本被补上（见下）。
- **界面字符串改为英文。** 中文界面后续版本再做。

## 已知限制

**「用户自己发现不了的那些」才是必须写的。**

- **列级前视仍无法检测。** 无 availability/provenance 声明时，系统不能判断某列是否偷看未来；
  把时间序列声明为 IID 时，一个显式未来位移的特征可跑出 r² > 0.9 而不被拦截。**本版未改变。**
- **有序 logit 未声明顺序时按字母序排类别。** 这是 v1.8.6 起就存在、本版外部 oracle
  才发现的行为：示例数据上顺序变成 `high < low < mid`，`x1` 系数由 **+0.712 变成 −0.355
  （符号相反）**，而 run 成功、报告正常、每个系数都有标准误和 p 值。
  未自动修正——标签是 `a/b/c` 时字母序常常正确，引擎无从知道语义顺序；
  但测量级别 advisory 会就此提示。**声明 `outcome_order` 可确定地避免。**
- **多项 logit 的默认基准类别不是首个水平**，与 R `nnet::multinom` 的约定不同。
  不显式声明 `base_category` 时，全部系数与 R 不可比。
- **含 0 的整数列不会触发测量级别提示。** 含 0 是计数的强信号（李克特量表极少从 0 起），
  这条规则用来避免对真计数数据误报。**代价是 0–10 这类从零开始的量表会被漏掉**，
  需要用户自行声明。
- **重复权重方差依赖 replicate 数。** 数量不足时 SE 不稳定；本版报告 replicate 数与失败数，
  但**不代替用户判断该用多少**。
- **测量级别 advisory 与设计前提检验都是提示不是判定。** 系统举证，判断权在用户。
- **时间序列 + 抽样设计不支持，且这是概念性的。** 抽样设计描述单元如何从总体中抽出；
  时间序列是一个过程的单次实现，没有「被抽样的单元总体」。**不会在后续版本补上。**
- **抽样设计目前只接入 OLS / logit / probit / poisson。** 有序、多项、Cox、分位数、
  IV、面板 FE、DID 尚未接入（顺延）。
- **Agent 回合上限 120 秒 / 10 步**（`DEFAULT_TIMEOUT_S`，与 `WORKBENCH_LLM_TIMEOUT_S` 无关）。
  工具轮次较多的请求会超时；本版实测抽样设计与测量级别的请求可在预算内完成，
  **模型族切换在 deepseek-v4-flash 上会超时**——契约层与执行层有测试覆盖，
  但「自然语言 → 族切换」这一跳**未在本机证明**。
- **Agent 从零创建分析走 `operation.multi_step`，不走独立的 `model.genesis` 提议。**
  `model.genesis` 本身保持 `natural_language_enabled=False`，但它在 multi_step 的步骤词表里，
  所以「用一句话建一个分析」是可达的——只是路径是组合式计划而非单步提议。
  （本版早期的说明写成「Agent 无法从零创建分析」，那是过强的，已更正。）
- **`code.execute` 与 `model.custom` 仍不开放自然语言。** 二者 `risk_level=high`，
  属于「Agent 自研/扩展能力」范畴，按既定决定留待后续版本，本版不做。
- **`linear_mixed_effects` 现可被 Agent 命名与组入计划，但执行仍受两道既有闸门约束。**
  本版把它从孤岛状态接了进来（见下），Agent 能提出 LMM 计划、缺列会被指名拒绝；
  但真正执行需要：① `WORKBENCH_EXECUTION_PROFILE=local_contained` 的冻结容器准入
  （v1.7.3 起的安全边界）；② 一份 live admission，**只有 `/runs` 与 rerun 提交路径会创建**
  （它密封一份不可变的预执行输入证明）。
  因此 **multi_step 的 draft 执行路径能否为 LMM 建立 admission，本版未验证**——
  Agent 组计划可以，那条路径端到端跑 LMM 属未验证区。
  这两道闸门是有意的，Agent 与手工表单走同一道门、拿同一个错误码，已由测试钉住。
- **DID 三族（`cs_did` / `sa_did` / `dcdh`）没有 agent 结果投影。** 它们声明了自有的
  result shape，但读取走各自的诊断卡片，未接入统一的族证据投影。**这是 v1.8.7 之前
  就存在的状态，本版未改变**，已由测试显式列为已知 GAP（新增族不再享有这个豁免）。

## 第二轮独立复核发现的缺陷

第一轮自评「已完成」后，逐条复核 §6 的 39 条验收标准，发现 7 条不满足并补齐。
补齐过程中真机又抓到 3 个缺陷——**全部测试通过、全部用户可见**：

### 1. 设计标准误只到了 JSON，报告里一字没有（可见性缺陷）

报告标题写着「ols with **robust** standard errors」，而实际用的是设计方差。
比缺失更糟：它主动说了错的。现在报告事实列表载明方差方法、分层/PSU 列、设计自由度、
设计效应与有效样本量；未声明设计的 run 不出现该段。导出的回归表同样带上。

### 2. 截距拿到的是朴素标准误（正确性缺陷）

结果 payload 把截距叫 `Intercept`，设计引擎叫 `(Intercept)`，合并时**静默跳过**不匹配的项。
浏览器里的表现：

| 项 | 修复前 | R `svyglm` |
|---|---|---|
| Intercept | 0.7804 | 1.5955 |
| x1 | 0.177324041107 | 0.177324041107 |
| x2 | 0.088882344697 | 0.088882344697 |

截距的区间只有真实宽度的一半，紧挨着两个与 R 吻合到 12 位的斜率。
修的不只是命名：**未匹配的项现在直接报错**——一个系数悄悄保留引擎从未产出的方差，
比一次失败的 run 更糟，因为那个数字看不出异常。

### 3. 控件接进了没人打开的那个表单（可达性缺陷）

survey 与 ANOVA 控件接进了 `RunForm`，而用户从「Import data and create analysis」
进入的是 `GenesisWizard`。190 个文件、1643 个前端测试全绿，界面上一个控件都没有。
两个组件 import 同一批控件、用同一个 capabilities hook、结构几乎一样，**源码里看不出来**。

### 4. Agent 拿到的 schema 与校验器不是同一份

`model.rerun` 有两份 schema：`editable_schema` 描述操作，`proposal_schema` 才是交给
语言模型的那份。放开 survey 字段时只改了前者与校验器，模型看到的工具契约仍是
`additionalProperties: false` + 仅 `model_options`——**模型根本发不出这些字段**。
我为此写的「schema 与校验器一致」测试读的也是 `editable_schema`，照样绿。
现在两份 schema 与校验器由同一张声明表生成。

### 5. 新加的 agent 工具在真机上每次调用都抛异常

`inspect_design_advisories` 的测试断言了「方法存在」「ToolDefinition 存在」，
**从没真正调用过它**。真 DeepSeek 连续两轮撞上 TypeError 并绕开。两个原因叠加：
相对导入多写一层，以及 `_tool_active_head` 少传一个参数。
测试已改为**走注册的 handler**——那是 Agent 真正走的路径。

### 6. Agent 能提议新能力，却读不到结果

可达性有两半，第二半容易漏：**能不能问**验过了，**能不能看懂答案**没验。实测发现：

| 能力 | agent 能提议 | agent 能读结果（修复前） |
|---|---|---|
| 抽样设计 | ✅ | ❌ 拿到系数和 SE，但不知道那是设计方差、不知道 degf 与 DEFF |
| ANOVA / ANCOVA | ✅ | ❌ 族投影返回 `None` |
| GLM 平均边际效应 | — | ❌ 结果里有，投影里没有 |
| 验证等级（A3） | — | ❌ 无法说明某个数字的验证强度 |

第一条最严重：agent 会照着标准误谈论「估计有多精确」，而**没有任何途径知道**
这个区间用的是 8 个设计自由度而不是 80 个观测。

修法：`survey_design` 与 `marginal_effects` 随系数一起进结果摘要（有资格谈精度时，
限定条件必须同时到手）；ANOVA 加一条族投影声明；验证等级在通用投影里对所有族生效。
并加了一条断言——**声明了自有 result shape 的族必须有对应投影**，否则「能问不能读」会再犯
（DID 三族走各自的诊断卡片，作为已知 GAP 显式列出而非静默排除）。

### 7. 自然语言建的第一个分析用不上本版新增能力

`operation.multi_step` 是「用一句话驱动整个工作台」的入口，但它的 `model.genesis`
步骤契约有三处脱节：

- **可选族名是一句写死的散文**，列了 18 个族、**没有 `anova`**。加一族要改文案，
  漏改不会报错——因为那是文字。现在由注册表推导。
- **没有 survey 设计字段**：抽样设计只能在 rerun 上声明，意味着用户得先手工建好分析，
  Agent 才碰得到——与「一句话驱动」正相反。
- **没有 `labels`**：无法在创建时声明测量级别。

更隐蔽的是执行侧：即使契约放行，`build_model_params` 是**每族一个**，全都只返回
`model_type/y/x/model_options`，**会把这些字段静默丢掉**——Agent 写了设计、run 成功、
拿回普通标准误，没有任何提示。这些是数据与采集方式的属性、不是模型的属性，
因此改为在调用点统一附加（`genesis_run_params`），一处覆盖全部族，新增族自动继承。

### 8. `linear_mixed_effects` 是个孤岛：能建、不能改、Agent 叫不出

盘点「22 个模型族里哪些能用自然语言发起」时，LMM 是唯一一个两条路都不通的。
根因不是漏了一条声明，是它的能力声明里 **`params=()`**——一个空的参数列表：

- UI 靠硬编码的 `LmmControls` 驱动它，不走 capability；
- 因此 **rerun 会把它的每个字段当未知字段拒掉**——建得出来，改不了；
- 也因此它进不了 `MODEL_FAMILY_CONTRACTS`，multi_step 的计划里叫不出这个名字。

修法是把它按其余 21 个族的方式声明出来：能力参数（五个输入本就走 `model_options`，
这只是让它们可见）、`ModelFamilyContract`（含 `subject_id/time/group` 必填——
缺了会拟合成一个普通回归却自称重复测量模型）。**执行路径一行未改**：
options 契约、预执行密封、packet envelope 全部原样。

### 9. 对象类型参数在节点抽屉里显示为 `[object Object]`

`labels` 发布给所有族后，节点抽屉的重跑面板没有 `kind: "object"` 的控件，
回退渲染直接把值字符串化。过滤改为按 kind 而非按 key——原来的守卫只挡
`model_options`，所以下一个对象参数照样复现。

## 真机验收证据

均为真实服务器（backend `:8027` + vite `:5187`）与真实 DeepSeek provider：

- **抽样设计端到端**：浏览器配置分层/PSU/FPC/抽样权重 → 三个系数与 R `svyglm`
  吻合到 ~1e-15；`degf=8`、`residual_degf=6`、DEFF=1.98、n_eff=75.6。
- **Agent 声明抽样设计**：一句英文描述 → 模型读操作契约、回上游节点确认列存在 →
  提出 `{sampling_weight, survey_strata_col, survey_psu_col, survey_fpc_col}` →
  浏览器确认 → 子 run 三个 SE 全部对上 R（截距 1.5955，父 run 为 0.7199）。
- **测量级别端到端**：带值标签的李克特 run 跑成 poisson 并给出提示 →
  真 DeepSeek 读 advisory → **只提议 `satisfaction`，未把连续列 `x` 塞进去** →
  浏览器确认 → 子 run 走 `ordinal_logit`，落地 labels 与提议逐字一致，advisory 消失。
- **设计前提检验**：普通 OLS 自行发现 `stratum` 与 `psu`，并报出 psu 嵌套在 stratum 内；
  声明设计后报出「design effect 1.98：这 80 个观测所含信息约相当于简单随机抽样下的 76 个」，
  引用值与引擎产出逐位一致。
