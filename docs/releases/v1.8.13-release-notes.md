## 版本定位

v1.8.13 是 v1.9.0 界面重做的后端：让 Workbench **不配置任何模型服务也能完整手动使用**，Agent 走同一份能力声明、校验和执行服务。同时拆分 Agent 大文件、补齐数据操作命令行、减少共享层里写死的模型族分支。界面入口由 v1.9.0 提供；本版本身不改界面实现。

## 新增与改进

### 不依赖模型的手动能力（新增接口）

- **`GET /operations`**：从现有操作合同与能力目录推导出全部操作（实测 122 项：108 个工作流操作、14 个专用入口）。
  - 每项给出名称、说明、字段类型与控件提示、必填/默认/范围/枚举、列约束和目标要求。
  - 给定目标时返回能否使用及具体拒绝原因。
  - 读取目录不产生任何业务记录；新注册的操作自动出现。
- **`POST /operations/run`**：预览 → 确认的两步执行。
  - 复用 Agent 与命令行的同一个编译和执行服务，记录真实来源。
  - 处理多步依赖、部分失败、重复提交和产物归属，不信任客户端提供的授权或指纹。
  - 同一计划里可以先做数据操作再拟合模型（`spec.source` 绑定数据集，`model_ref` 绑定已完成的模型）。
- **手写报告**：草稿 → 手写保存 → 历史 → 导出，全程不调用模型。
  - 草稿由已计算的事实生成；正文是用户写的，不能替换登记过的统计数值；作者明确记为用户。
- **验收**：在没有配置模型、并由测试阻止任何模型调用的情况下，经真实 HTTP 完成上传 → 目录 → 同一计划内重编码/描述统计/t 检验/IV/Wald/弱工具诊断/PCA → 两份报告保存、历史与 HTML 导出。报告中的数值与登记值逐一核对。

### 命令行

- 数据操作命令由同一份合同生成，包括 subset、recode、merge、reshape，以及在选定数据集上拟合。
  - 实测命令行跑通“数据操作 → 拟合 → Wald → 导出 Stata 脚本”：69 行数据，系数与来源和 HTTP 结果一致。
- `--help` 不加载统计库：数据、subset、fit 的帮助分别约 0.17 / 0.13 / 0.14 秒（含进程启动），在 0.5 秒预算内。

### 结构与分层

- Agent 的 `context_tools.py` 从 5445 行拆成 128 行的入口加按职责划分的模块（最大 1488 行）；公共接口、返回结构、预算截断、只读边界与外发脱敏行为保持不变。
- logit、probit、Poisson、负二项、GLM 五个模型族的数值运行代码迁入模型包；族级展示与执行策略改由声明提供。
  - 按修正后的统计口径，共享层的模型族字面量从 74 降到 54（同口径对 ARMA-GARCH 变换去重后为 53）。
  - OLS、面板、IV、DID 的数值运行仍在中心模块。
- ARMA-GARCH 变换选项只有一个来源。

### 统计与结果

- **分类项可读名**：如 `C(Q('arm'), Treatment(reference='a'))[T.b]` 显示为 `arm: b`；计算键和系数定位不变，引号、反斜杠、冒号列名均覆盖。
- **线性混合模型的总体边际效应（连续变量）**：与原生 R、Stata 在原定容差内一致（ML 与 REML、随机截距与随机斜率）。
  - 真正的交互项来自经验证的设计矩阵信息，而不是按列名里的冒号猜测。
- 数据集来源与运行族祖先分开记录，Notebook 新建运行族不会被改写。
- gate 改用整机共享的排他锁，不同工作目录的两次 gate 也会互斥。

## 已知限制

- **线性混合模型的似然比检验仍关闭**：原始的同样本 ML LR 数值与 R/Stata 一致，但生产中的比较还缺少对分组与随机结构相同、方差边界的验证，不能开放。
- **NB1 原生 R 重新估计未运行**：当前 R 环境没有 glmmTMB；没有安装依赖，也没有用结果回放冒充原生估计。
- **界面验收不在本版**：本版只验收了后端接口与原有界面的部分路径。新的目录表单、执行预览/确认与手写报告界面由 v1.9.0 实现并验收。
- 会话令牌与 Linux 支持仍按计划延后。

## 升级说明

- 只新增接口，v1.8.12 的接口、参数、响应与错误约定保持兼容；前端只更新了自动生成的类型文件。
- gate 锁位于整机共享位置；仍在用旧版 gate 的工作目录，请继续手动保证同一时间只跑一套 gate。
