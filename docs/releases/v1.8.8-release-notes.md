# Workbench v1.8.8 — 发布说明

> 状态：v1.8.8 本地最终发布基线。本文只描述当前整合树中已经存在、并且有对应证据的内容。
> 未完成项、阻塞项和验证边界单独列出，不把自动化覆盖写成真人浏览器证明，也不把本地协调器写成真人身份证明。

## 版本定位

v1.8.8 是 Workbench 从“能力实现”走向“声明驱动、可组合、可审计 Agent 能力”的整合版本。
本版重点不是追求 SPSS/Stata 的模型数量，而是建立以下基础：

- 一个能力只需实现自己的契约、注册和适配器，就能自动进入 Agent/workflow 词表；
- 统计操作通过 typed contract、确认边界、Graph lineage 和 durable artifact 接入；
- 失败、依赖缺失、证据不足和未接线状态都 fail closed；
- Agent 能读取受约束的精确结果证据，而不是只看到 artifact 元数据；
- 批量验收、规划评测和报告/Notebook 消费者都有独立的证据等级。

Agent workflow 已支持带预览、确认、持久化和 Graph lineage 的：

Temporal/panel generic prediction 在没有对应安全 split profile 时保持 fail closed。

### 统计能力与 P7

当前树包含并接入 Agent/workflow 的能力包括：

- ANOVA/ANCOVA、MANOVA、重复测量 ANOVA、Tukey/Bonferroni、效应量；
- Ordinal Logit、Multinomial Logit、Quantile Regression；

P7 当前由 18 个声明 family 派生出 64 个 operation handler，并通过通用 `operation.multi_step` 接入 Agent。P7 operation 多数是组合 workflow step，不是 64 个独立顶层模型按钮。

## 关键正确性修复

- Matching 的实际几何固定为 `standardized_covariate_euclidean_v1`；absolute logit difference 只作为 support 证据和确定性 tie-breaker；不执行 trim，并输出 `trim_applied=false`。
- Hurdle positive-count 的标准误明确标记为 `bfgs_inverse_hessian_approximation`，p 值标记为 `approximate`，标签会传播到 Agent/Report 证据。
- Hurdle Negative Binomial 同时保留成功 fixture 和预期的 `GLM_NONCONVERGENCE` fail-closed fixture。
- 旧 ledger migration 实现、CLI 和 migration-only 测试已删除；无当前 `.control.json` 的旧 ledger 不会自动迁移，仍 fail closed。
- workflow capability 的重复 validation 已收敛为单一请求归一化、单一结果 validation 边界；误导性的 callable 注入构造参数已删除。
- Witness replay 不再信任 ledger 中自报的 trust level；回放必须重新验证 provider 决策并绑定 durable result chain。

## 未完成、延期和阻塞项

### 有意延期，不是本地代码缺口

- 没有安装具体的远程 witness provider，因此没有真人身份或 Anti-Agent 证明。
- provider-backed LLM planner benchmark 尚未执行，仍为 `NOT VERIFIED`；deterministic evaluator 不能代表真实 LLM 的规划质量。
- 没有把 64 个 operation 逐个做成 64 次浏览器人工会话；批量 runner 证明的是注册、准入、执行、持久化和 fail-closed 行为。
- 没有把 World ID 或其他具体远程 provider 接入本地 workbench；保留的是 provider-neutral、fail-closed witness 核心。

这些事项需要未来的网络化产品、独立 provider、信任根、浏览器采集路径和明确威胁模型，不阻塞本地 Workbench v1.8.8 发布。

### 当前产品边界

- 直接数据操作 HTTP/UI 面板目前开放的操作少于 Agent workflow；完整数据管理内核已接入，但普通用户界面尚未覆盖全部数据变换。
- 结果包是“统一核心字段 + family-specific evidence”，不是所有 64 个 P7 结果都强行拥有系数、置信区间和边际效应。
- 通用 ML 当前主要是 Lasso、Ridge、Random Forest；分类 workflow、严格分类 CV、超参数搜索、AutoML、SHAP/重要性稳定性和深度学习不属于本版。
- 尚未实现 AFT、竞争风险、GEE、GLMM、Tobit、CFA/SEM/GSEM、Bayesian、RDD、Dynamic Panel/System GMM 和空间回归。
- 剩余第三方/upstream warning 与少数退化 fixture warning 未通过全局过滤器掩盖，按 warning inventory 保留。

### 已遇到但已解决的阻塞

- Report provider deadline、报告契约修正轮、Notebook upload-only workflow source、ETS preflight、Report export curation、P7 manifest 完整 SHA、witness chain/replay 等问题均已记录并解决。
- 这些历史事件保留在 formal retrospective 中，不应被误读为当前仍未解决的产品缺陷。

## Ledger 与升级说明

当前版本不承诺旧 P7 ledger 自动迁移。没有 `.control.json` 的旧 ledger 会明确拒绝；旧实现和旧迁移原型可从 Git 历史查阅，但不承诺兼容。

## v1.8.9 起点

建议 v1.8.9 先做 P0 基础增强，而不是继续堆模型：

1. 统一所有 family 的 Agent 精确结果、诊断和图表投影；
2. 补齐数据管理的直接 UI、变量标签和值标签；
3. 完成通用分类 ML、严格交叉验证、模型比较和可解释性基础；
4. 再进入 GEE/GLMM、生存扩展、SEM、RDD、System GMM 等模型扩展。

本版不宣称已经达到 SPSS/Stata 的完整功能 parity；本版交付的是可组合、可审计、fail-closed 的 AI-native 统计底座。
