# V1.5.7.1 — honest-DID ΔSD / FLCI（smoothness 平滑性 + 固定长度置信区间）

honest-DID 的第二条 track：在已发布的 **ΔRM（相对幅度）** 之上，补齐 R `HonestDiD`
的**头牌限制 ΔSD（smoothness 平滑性）**，并用其默认推断方法 **FLCI（fixed-length
confidence interval，固定长度置信区间）**给出稳健区间。**同一个 `honest_did` 复选框
现在一次产出两条 track**。**点估计不变**（纯后处理）。0 新 Python 依赖（仅 SciPy）、
opt-in、degrade-not-fail。

## 做了什么

- **ΔSD / FLCI 引擎端口（self-implemented）。** 忠实移植 R `HonestDiD` 0.2.8 的
  `findOptimalFLCI`：given-`h` 的最坏偏差凸子问题（`scipy.optimize` SLSQP）、
  `findLowestH` / `findHForMinimumBias`（hMin / h0）、以及在 `[hMin, h0]` 上的导数
  二分（带 grid 兜底）。**0 新 Python 依赖**（仅 SciPy）。R `HonestDiD` 0.2.8 **仅
  用于生成已提交的 JSON oracle——测试套件从不调用 R**。
- **嵌套 honest 块（永远可解释）。** `cs_did.json` 的 `honest_did` 块改为**嵌套**：
  `{"rm": {...}, "sd": {...}}`，每条 track 各带 `status ∈ {"ok","degraded",
  "not_available"}` + `reason`，失败永远有解释、绝不静默丢弃。rm 结果行用 `Mbar`
  键、sd 结果行用 `M` 键。
- **adapter {rm, sd} 重塑。** adapter 从**同一份冻结的 Σ 快照**（沿用 CS 的
  cluster-robust 影响函数）出发，两条 track 不重算 Σ，各自整形为嵌套块。
- **前端三态渲染。** 每条 track 独立三态：`ok` → 完整 M 网格面板；`degraded` →
  折叠 + reason；`not_available` → 不可用 + reason。`null` 端点渲染为 "—"。
- **M 网格（绝对曲率尺度）。** 与 ΔRM 的无量纲 M̄ 不同，ΔSD 的 M 是**绝对曲率尺度**。
  data-adaptive 默认 **M ∈ {0, 0.5, 1, 1.5, 2} × s**，`s = max(sqrt(diag(Σ)))`
  （最大事件研究 SE），下限 floored 到 **1e-8** 以防近退化 Σ 上网格塌缩。
- **additive golden + nan-safety。** golden 钉死开启 honest-DID 的 CS run 形状
  （status / artifacts / 点估计），**不冻结 FLCI 数字**；非有限 CI 端点 sanitize 为
  `null`（→ FE "—"）。

## 关键决策

- **确定性（核心修复）。** FLCI 半长用 folded-normal 临界值；R 的 `.qfoldednormal`
  是**蒙特卡洛模拟**（`set.seed(0); rnorm(1e6); quantile(...)`），其 oracle 带
  ~1e-3 MC 噪声、不可解析复现——正是 v1.5.7 C-LF 的同类问题。我们改用**解析
  folded-normal 分位数**（在 folded-normal CDF 上做 Brent 求根，确定性），并把解析
  分位数经 `assignInNamespace` 注入 R 重新生成 oracle。**无蒙特卡洛 / 无 bootstrap /
  无随机抽样 → 无随机误差的统计来源。** （不主张逐位确定：SciPy QP 受 BLAS / 求解器 /
  浮点漂移影响，所以 golden 只冻结 status/artifacts/coef、绝不冻结 FLCI 数字；正确性
  由 engine oracle 测试断言。）
- **可识别性修正 vs 设计 spec。** spec 曾假设 `num_pre ≥ 2` 是可识别性要求（源自一个
  2-equality 推导）。R 的实际 `findOptimalFLCI` 只施加**一个** sum-weights 等式、对
  `num_pre ≥ 1` 即可计算；我们验证 R 在 `num_pre = 1` 下干净运行。因此 `honest_sd`
  守卫 **`num_pre ≥ 1`**（与已校验的引擎及 ΔRM 一致），**不是 ≥ 2**——这是刻意的
  **忠实于 R** 选择。
- **M 数据自适应的注意点。** 因 M 是 data-adaptive，`M = 1` 在不同数据集**不是同一个
  物理量**（曲率尺度 vs 估计噪声尺度）——按设计接受；应在数据集**内部**比较 M 网格。

## 校验

- **FLCI 半长**对照 R **<1e-9**（所有 M）。
- **CI 端点**对照 R **<1e-6**（M > 0）。
- **M = 0** 退化为 minimum-SD 经典 CI（半长 = `z_{0.975}·hMin`），精确到 **1e-8**。
- **M = 0 的 CI 中心**对照 R 仅 ~**2.25e-6**（**已记录，非 bug**）：M = 0 时最坏偏差
  目标沿一个退化流形是平的，R 的 CVXR/ECOS 在 hMin 留 ~2e-10 松弛、被 ~1e4× 放大进
  权重向量；CI **宽度**（统计上有意义的量）精确。追 R 的求解器松弛会得到**更不最优**
  的估计量，故未追。

## 为什么安全

- **纯后处理：点估计逐字不变。** ATT(g,t) 与四种聚合就是 CS DID 已算出的值；ΔSD 只
  放宽 inference。
- **确定性：** 解析 folded-normal 分位数，无 RNG（见上）。
- **永不失败：** 整个 honest 块（两条 track）降级而非失败。已知守卫
  `HONEST_NO_PRE_PERIODS` / `HONEST_NO_POST_PERIODS` / `HONEST_DEGENERATE_SIGMA`
  → `status:"not_available"`；意外错误 → `status:"degraded"`。
- **逐元素校验：** 见上。

## 成本 / 性能

- ΔRM ~157s（不变，1000 点网格 × LP）+ **ΔSD/FLCI ~秒级**（小 QP × h-grid）≈ 总体
  **基本不变（~157s）**。两条 track 从**同一份冻结 Σ 快照**计算，不重算。opt-in、
  异步、不阻塞其余 CS 输出。
