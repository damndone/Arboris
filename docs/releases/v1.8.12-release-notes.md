## 版本定位

v1.8.12 是基础加固版，为 v1.9.0 界面重做铺路：

- 本地服务不再能被别的网页驱动。
- 前端只用由后端生成的接口类型。
- 命令行与界面、Agent 走同一套声明和服务。
- 合同分层清楚，界面线可以从一个冻结的接口合同开始并行开发。

## 新增与改进

### 安全

- **本地服务只接受本机请求**：
  - Host 只认 `localhost`、`127.0.0.1`、`[::1]`。
  - 带 `Origin` 的请求（所有方法）必须来自本服务或允许的界面源。
  - 改状态的请求拒绝 `Sec-Fetch-Site: cross-site`。
  - 拒绝时返回明确的错误码，并记入外发审计（限速，防刷盘）。
  - 命令行、脚本等不带 Origin 的本机客户端照常使用。
  - 实测：另一个本机端口的网页无论直连还是经 Vite 代理，读和写都被拒绝。
- **有副作用的 GET 改正**：Notebook 选项列表改为 POST；查询不存在的会话或记录不再建目录。
  - 测试会枚举所有 GET 路由，任何写盘都会失败。
- **外发脱敏补漏**：受保护列的分类取值原来只在单引号写法的项名里被识别。
  - 现在任何引号和转义写法都能识别；无法解码的项名一律隐去。
  - 运行流水线会先把列名规范为 `[0-9a-z_]`，所以此前的遗漏无法经正常运行触发，本版按纵深防御修复。

### 前端接口类型由后端生成

- 133 个接口全部声明响应结构；128 个 JSON 接口中有 127 个在测试中按真实响应严格校验。
- 前端 API 函数返回手写服务端结构的数量从 66 降到 0，由编译器级不变量测试守住。
- 切换过程中修正了 10 处合同与实现不一致，如 Frequencies 预览返回 422。
- 节点级“从哪个节点重跑”的来源补齐并持久化，冲突时失败关闭。
  - `run_inputs` 中混用的三种来源形状已分开。
  - 修复了重跑子运行导出脚本时的错误。
- Notebook 删除了由客户端提交执行授权的入口；授权只由服务端在确认时签发。

### 命令行由同一套声明生成

- **`workbench run`**：
  - 参数由 `POST /runs` 的字段表生成，经与界面相同的服务提交，所以模型选项、三种权重、预测数据结构、统计检验、分组运行都可用。
  - JSON 参数可以内联，也可以 `@文件`。
  - stdout 只输出 run id。
- **`workbench postestimation <操作>`**：每个后估计操作一个子命令，参数由步骤合同生成，经 Agent 同一个工作流引擎执行。
- **`workbench export-targets` / `export-script`**：与界面的导出相同，可要求完全原生。
- **`workbench models [模型]`**：列出能力目录。
- 启动时不加载统计库与 Web 框架，`--help` 约 0.1 秒。
- 每条命令都记入分析台账。
- **负二项 NB1 可原生导出到 Stata 与 Python**：Stata 用 `nbreg …, dispersion(constant)`，Python 用 statsmodels 的 nb1，模型与 Wald、lincom 都在真实 Stata 与 Python 中对照通过。
  - R 没有参照级的 NB1 实现，仍用 Workbench 结果并写明原因。
- **验收**：命令行完成 NB1 → Wald → 导出完全原生的 Stata 脚本 → Stata 实跑，19 项自检全部通过。

### 结构与证据

- **合同分层**：
  - 模型族合同表和结果形状注册表移到 `contracts/model/`。
  - 引擎、编排、准入、运行事件都不再依赖 Agent 层。
  - 分层守卫测试静态检查函数内的导入。
- **族名分支棘轮从 165 降到 119**：
  - Notebook 的产物词表改由各族合同声明推导，去掉一份手写重复。
  - 剩余计数中有 45 处是正则把草稿节点 id 误当作族名，下一版先修正口径。
- **公式项名的引号统一由一个实现处理**：前后端 8 处手写解析都改用它；含引号的列名在 ANOVA 中不再拟合失败。
- **证据管理**：
  - `local/` 的测试证据每类保留最近 3 份，失败的那份始终保留。
  - 仓库证据有每版体积预算。
  - pre-push 护栏脚本入库，可一键安装。

### 开发环境

- 所有 checkout 共用一个虚拟环境，其中 Workbench 的 editable 安装现在指向主仓库目录。此前它指向一个已存档的工作目录。
  - 以前不自带 `PYTHONPATH` 的子进程测试，加载的其实是那个旧版本的代码。
  - 该目录移除后，`workbench` 命令一直无法启动。
- 新增 checkout 守护：在某个工作目录里启动的进程（或由它启动的子进程）使用该工作目录的代码，旧工作目录无需改动。
- gate 每次检查安装路径和 `workbench` 命令能否启动。
- 移除工作目录前的检查已写入存档流程。
