# V1.5.4.1 — Release Notes

> **性质：功能版（feature release）。**
> 把 V1.5.3.2 已有的后端能力（显式 `model_type`、MICE 插补、结构化失败）
> **接上前端方向盘**——通过 **capability manifest（能力清单）** 驱动:后端暴露
> `GET /capabilities`(派生自 `MODEL_REGISTRY` + `IMPUTATION_REGISTRY`),前端动态渲染。
> 解决 V1.5.3.2"引擎造好了,但没方向盘"的缺口。
>
> 分支:`workbench-v1.5.4.1`(独立 worktree + venv,base = `origin/workbench-v1.5.4.1` slice-1 基线)。
> Tag `v1.5.4.1` 在 `5ff37a8`,已 merge 进 `main`(`6429dea`)。
> `workbench-v1.5.4.1` 是 `workbench-v1.5.4` 的严格超集(领先 22 commit)。

## 1. 用户能看到的新东西

- **模型下拉从 4 个变 10 个**:`ModelTypeSelect` 按 group(Linear / Binary / Count / Panel / GLM)
  分 optgroup,选项**全部来自 `/capabilities`**,后端注册新模型即自动出现,前端零改动。
- **MICE 缺失值插补开关**:`ImputationControls` —— 单方法时渲染 checkbox,多方法时渲染下拉;
  无能力/空列表时不渲染(不挡表单)。
- **结构化失败故事卡**:显式 `model_type` 拟合失败时,`FailureCard` 渲染"你选的模型(logit)
  无法在此数据上拟合" + 根因 + **一键"Re-run with auto"**(`recommended_actions` 驱动,
  primary 动作带 `form_overrides: {model_type: auto}`)。
- **插补结果面板**:run 完成后 `ImputationSummary` 展示方法 / 插补行数 / 列 / lineage
  (stats 跑在 `cleaned_dataset`,模型用 `imputed_dataset`)。

## 2. 架构:capability manifest 驱动

- 后端 `engine/capabilities.py::build_capabilities()` 是**单一事实源**,派生自
  `MODEL_REGISTRY` + `IMPUTATION_REGISTRY`,**不 hard-code 列表**——消灭"加新东西要前后端联动"的根。
- 前端 `useCapabilities()` 启动拉取,`ModelTypeSelect` / `ImputationControls` 以 `capabilities`
  为 prop(App.tsx 只调一次 hook,两组件共用)。
- 落地承诺:**新 model_type / imputation method = 后端注册即可,前端零改动**(新增 imputation
  方法从 checkbox 自动变 select 也已覆盖)。

## 3. 关键设计决策（防翻车点）

- **`evidence` 键,不是 `details`**:`GuardrailIssue.to_dict()`(`domain.py:102`)序列化键名是
  `evidence`。plan 多处误写 `details`——后端注入、前端消费、e2e 断言三处统一用 `evidence`。
- **`recommended_actions` 同名两 schema,严格隔离**:
  `preview.recommended_actions`(`{action_key, severity, message}`,一般建议)与
  `issue.evidence.recommended_actions`(`{key, label, severity, form_overrides, hint}`,失败恢复)
  同名、不同来源、不同语义。`FailureCard` 只消费后者,不交叉。
- **`imputation` 线格式**:`POST /runs` 的 `imputation` 字段是 JSON 字符串 `{"method":"mice"}`,
  空则回退 `config.imputation_method`(契约 `docs/api-contracts/runs-post.md`,前后端对齐)。
- **`imputation=None` 默认路径字节不变**:既有 config 驱动的插补路径不受影响
  (`test_golden_imputation` 仍绿)。

## 4. 协作方式（本版特有）

- 18 个 task 拆分:controller 自留高风险/跨文件(9 / 14 / 15 / 17),其余 7 个外包给一名工程师
  (BE 6/7/8/10 + FE 12/13/18)。
- **外包全程本地推进、不走 GitHub**:工程师在 `.worktrees/workbench-v1.5.4.1-{backend,frontend}-ext`
  自己的 ext 分支提交,从不 push/PR;controller 用本地 `git merge --no-ff` 集成,每次全套守门。

## 6. Release 拓扑决策

- **没有**往回合进 `workbench-v1.5.4`(那会让两分支指向同一 commit,版本身份在分支层面模糊)。
- 改为:tag `v1.5.4.1` 锚定版本身份 + **前向**合进 `main`;`workbench-v1.5.4` 原封不动留作历史标记。
- 合并仅一处文档 add/add 冲突(`...v1.5.3.1...backend-analysis...md` 几行 CLI 示例),
  取 v1.5.4.1 版(正确的 `env PYTHONPATH=backend .venv/bin/python -m workbench.cli ... wage --x`)。
- main 的 `backend/frontend/tests` 与 release tag **逐字节相同**,只在其上叠加文档。

## 7. 结论

V1.5.3.2 的引擎能力现在有了完整 UI 方向盘,且是 capability-manifest 驱动的——
后续新模型 / 新插补方法只需后端注册,UI 自动跟上。全套绿,已发布。
