## 4. orchestrator.py 合并细则（核心）

`_run_workflow` 里两条线各加了东西，**互不替代，都要保留**。合并后该函数的工作流顺序应是：

```
load → profile → validate → 统计检验
  → [1.5.3.1] 若 config.imputation_method == "mice"：MICE 预处理，得 modeling_frame
  → 估计阶段：
       [1.5.3.1] 显式 model_type 分支（probit / negative_binomial / glm:* / panel_ols）
                 —— 放在 y-type auto 路由之前
       [既有]    auto：binary→Logit / count→Poisson / continuous→OLS-robust
  → [v1.5.x]  估计后：_model_summary + GraphRecorder decision-point 血缘记录
  → 诊断
  → [1.5.3.1] 若 config.prediction_enabled：prediction（写 prediction_results/）
  → report / artifacts
```

**合并要点**
1. 1.5.3.1 的显式模型分支插在估计分支**最前面**；`auto` 行为字节不变（spec §5 / DoD）。
2. v1.5.x 的血缘记录段（`_model_summary` / `_safe_flush_recorder` / decision-point）**完整保留**。理想情况让新模型结果也走血缘记录；但 spec §10 允许"新 artifact 前端未知仍能渲染"，所以**血缘覆盖新模型是 nice-to-have，不是 blocker**——不要为它阻塞对接。
3. imputation：统计检验后、估计前；estimation 输入从 `cleaned` 改 `modeling_frame`（仅估计，不动 profiling/检验/可视化输入）。
4. `run_workflow` 签名要带 `model_type: str = "auto"`，并透传到 `_run_workflow` 与 `_write_manifest`。
5. `_MODEL_TYPE_MAP` 加 `probit→binary`、`negative_binomial→count`；**不要**给 `glm:*` 建映射（保持 y_type 数据驱动）。
6. structured failure：显式模型失败要写 `MODEL_FIT_FAILED` 结构化 issue（engine/model_type/model_id/step），**不得 silent fallback 到 OLS**。

合并完 `git add backend/workbench/orchestrator.py`，`git commit`（先别加 `--no-verify` 之外的花样，让冲突 commit 干净）。

## 6. 三大风险（排序）

1. **orchestrator 是工作流总线**：模型路由 / MICE / prediction / structured failure / 血缘记录全在 `_run_workflow` 汇合。合并后最该重点测它 —— 既要新模型能跑，又要 v1.5.x 血缘节点不丢、auto 行为不变。
2. **CLI / docs 漂移**：smoke 文档命令历史上和真实 CLI 不符。**必跑真实命令**，不只看文档；合并 cli.py 后参数顺序/名称要实测。
3. **optional deps 必须保持 lazy import**：合并后若某处 import 被提前执行，会把 `linearmodels/scikit-learn/imbalanced-learn` 变成硬依赖。用 Gate F 守住。
