# V1.5.4.3 — Release Notes

**Theme:** Foundation hardening. Turn silent failure modes into loud, gated ones; make the antifragility gates executable; split the App.tsx god-component — with **zero user-facing behavior change**.

**Branch:** `workbench-v1.5.4.3` (base: `main`, includes shipped `v1.5.4.2`)
**Gates:** Backend 761 passed (full extras) · Frontend 582 passed · golden + invariants + behavior-snapshot 14 passed (0-drift) · `tsc --noEmit` 0 errors · bare `pytest` 0 collection errors · `./scripts/gate.sh` → GATE PASSED

This is a pure guardrail / structural-debt release. No new user-visible features; behavior is frozen and verified byte-for-byte by the golden snapshots.

## What shipped

### 1. Backend pack guardrail — silent no-ops become loud errors
The `AnalysisPack` extension surface declared several contribution slots the engine did not actually consume, so a pack populating them got a silent no-op. Three of those sockets are now either wired or alarmed:

- **Fail-loud registration.** `register_pack` raises `PackContractError` if a pack populates a not-yet-wired field (`diagnostics`, `report_blocks`, `recommended_actions`, `interpretation_restrictions`). Each alarmed field is annotated inline with its planned wiring version, so the roadmap is self-documenting in code.
- **`StageInsertion` explicit-insertion API.** A pack can now splice a stage into `PIPELINE` at a named anchor (`after`/`before`), with a clear `PackContractError` (listing the known stages) on a bad anchor. The splice helper lives in the `stages` module that owns `PIPELINE`, keeping the import direction clean; nothing is mutated on a failed anchor.
- **`rerun_actions` reference wiring.** Pack-declared `RerunAction`s register into `RERUN_ACTION_REGISTRY` and flow through to `actions_for_model_fit_failure`, mapped to the FailureCard `form_overrides` schema. Proven live by a test pack and a "delete-the-wiring → red" reverse-check.

### 2. Frontend type gate (zero-error)
Added `frontend/tsconfig.json` (`strict: true`) + a `typecheck` script and fixed **all 16** `tsc --noEmit` errors at the source — no `@ts-ignore`/`as any` suppressions, no loosening. Type fixes are annotation-only and behavior-preserving (prop-type widening to match the real data source, precise named-type casts on JSON fixtures, an additive optional union field, test-fixture required props). `tsc --noEmit` is now a real gate.

### 3. App.tsx run-form split (behavior-frozen)
Extracted the run-form container out of the 939-line `App.tsx` `SubmitRoute` into a focused `src/runForm/RunForm.tsx` (App.tsx → 401 lines). Pure relocation: the `onRun()` body, `runWorkflow(...)` call, validation, SSE/poll wait, activity/error strings, sessionStorage handling, and form JSX are unchanged. The `requestState` cross-disabling between the Project panel and the Run button is preserved by threading shared chrome as props. `validatePanelPrediction` stays exported from `./App` (existing test import path intact). The type gate landed first specifically to catch any relocation breakage.

### 4. Tooling
- **pytest footgun fixed.** `pythonpath = ["backend", "."]` puts the repo root on the path, so bare `pytest` (not just `python -m pytest`) collects the `tests.contracts...` imports — no more phantom collection errors.
- **One-command gate.** `scripts/gate.sh` runs the backend full suite, the golden/invariants/snapshot 0-drift set, vitest, and `tsc --noEmit`, and exits non-zero on any failure. It is now the single source of truth for the version gate.

## Backward compatibility / behavior freeze

The only production pack, `CORE_PACK`, populates none of the alarmed fields, adds no stages, and declares no rerun_actions — so `RERUN_ACTION_REGISTRY` stays empty, `PIPELINE` is unchanged, and production output is **byte-identical** (golden snapshots 0-drift). Every backend task carries a golden 0-drift step; the rerun_actions wiring has an explicit reverse-check. Frontend type fixes and the RunForm split changed no runtime logic (582 vitest unchanged).

## Deferred (honored — not touched here)

- **IV / 2SLS** → V1.5.4.4 (requires registering a new estimation handler in `CORE_PACK`; isolated for risk).
- **`orchestrator.py` file split** → V1.5.4.5.
- **`diagnostics` / `report_blocks` / `recommended_actions` / `interpretation_restrictions`** wiring → V1.5.6+ / agent. These remain declared-but-unwired — now alarmed and annotated, not silently no-op'd.

## Notes / known minor (non-blocking)

- `RERUN_ACTION_REGISTRY` has no dedup on `key`; two packs sharing a key would render colliding FailureCard buttons. A fail-loud guard would fit the file's philosophy — a candidate for a future pass (no real pack hits this today).
- `RunForm` imports `validatePanelPrediction` from `../App`, forming a benign App↔RunForm cycle (pure function, referenced only at call-time). The lower-churn choice per plan; could later move to `runForm/validation.ts` with an App re-export.
- `tsconfig` `include` is `["src"]`, so root config files (`vite.config.ts`, `vitest.setup.ts`) are outside the type gate — defensible for a source gate.
