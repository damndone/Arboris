## 0. 核对结论：分支拓扑（先纠正一个常见误解）

实际 git 拓扑（已用 `git merge-base` 核实）：

```
a06cea3  (main 的一个早期点：chore: ignore frontend/dist)
   │
   ├─► workbench-v1.5.0 → … → workbench-v1.5.2 (3dbaa78) → workbench-v1.5.3
   │        （携带 v1.5.0–1.5.2 全部后端 + 血缘图历史 + v1.5.3 纯前端）
   │
   └─► codex/workbench-v1.5.3.1   (从 a06cea3 分出，22 个 commit，纯后端扩展)
```

- **1.5.3.1 不是从 v1.5.3 分出的**，而是从 main 的 `a06cea3` 分出。两线的共同祖先是 `a06cea3`，彼此无父子关系。
- 因此「`git checkout v1.5.3 && git merge codex/workbench-v1.5.3.1`」**可以做**，但它是两条独立线的三方合并，不是快进。冲突点要预判。

## 2. 真正的冲突热点（这是对接的核心，不是前端）

把 1.5.3.1 改的文件，与 v1.5.3 相对 main 改的文件求交集，再看后端漂移：

| 文件 | v1.5.x 链相对 main 的改动 | 1.5.3.1 的改动 | 冲突性质 |
|---|---|---|---|
| **`orchestrator.py`** | +246 / −21（血缘图记录：`GraphRecorder`、`_model_summary`、decision-point） | model routing 分支 + imputation/prediction wiring | **文本冲突，需人工合并**。两者都在 `_run_workflow` 主函数体内，但触碰不同区域（一个"估计后记录血缘"，一个"估计前选模型"）。是同函数不同段，非逻辑互斥。 |
| `cli.py` | +103 / −1（v1.5.x 的 CLI 演进） | `--model-type` 等新选项 | 文本冲突，小，函数签名层面。 |
| `pyproject.toml` | +1（v1.5.x 依赖微调） | optional extras（panel/ml/imbalanced/imputation） | 极小冲突，`[project.optional-dependencies]` 段，手动并段即可。 |
| `diagnostic_summary.py` | +1 / −1 | 1.5.3.1 也改了 | 极小，逐行看。 |
| `tests/test_config_and_domain.py` | +155 | 1.5.3.1 加了 config 字段测试 | 大概率追加式，并列即可。 |
| `README.md` | +1 / −1 | 后端用法示例 | 文档，手动并。 |

**statistical_tests.py：main 与 v1.5.3 零差异** → 1.5.3.1 对它的大量扩展可无冲突直接落地。
**api.py：v1.5.x +26 行，1.5.3.1 未碰** → 无冲突。

→ 结论：**唯一需要认真人工合并的是 `orchestrator.py`**；其余 5 个是小并段。前端零风险（文件集完全不相交）。

## 3. 推荐对接流程（修正版）

### 3.1 固定基线
- 基线 = `workbench-v1.5.3`（HEAD `2b31a73`，已收官、FE 549 / BE 621 全绿）。
- 不直接动 v1.5.3 分支本身（版本隔离）。

### 3.2 建独立 integration worktree（不污染任一版本）
```bash
cd /Users/jiayuanren/项目规划
git worktree add -b codex/integrate-v1.5.3.1 \
  .worktrees/integrate-v1.5.3.1 workbench-v1.5.3
cd .worktrees/integrate-v1.5.3.1
git merge codex/workbench-v1.5.3.1
```
> 用独立 worktree + 独立分支承接合并，符合「每个版本各自隔离」的规则；v1.5.3 与 1.5.3.1 原分支都不被改写。

### 3.3 冲突处理原则
- **前端**：理论零冲突。若 git 报任何 `frontend/**` 冲突 → 立即停，说明合错了东西。
- **orchestrator.py**：保留**两边都要**——v1.5.x 的血缘图记录 **AND** 1.5.3.1 的 model routing。合并要义：
  1. 在估计分支**之前**插入 1.5.3.1 的显式 model_type 路由（probit/nb/glm/panel）；
  2. 保留 v1.5.x 在估计**之后**的 `_model_summary` / GraphRecorder decision-point 记录；
  3. imputation 在统计检验后、估计前；prediction 在诊断后。
  4. 确保新模型结果也走 v1.5.x 的血缘记录路径（否则 graph 里看不到新模型节点 —— 但 spec §10 允许"新 artifact 对前端未知时仍能渲染"，所以这是 nice-to-have，不是 blocker）。
- 小文件（cli/pyproject/diagnostic_summary/test_config/README）：并段，不取舍。

### 3.4 独立 venv
1.5.3.1 worktree 已有自己的 `.venv`。integration worktree 需要**新建独立 venv**并装上 optional extras 来跑全测：
```bash
~/.local/bin/python3.11 -m venv .venv
./.venv/bin/python -m pip install -e ".[dev,panel,ml,imbalanced,imputation]"
```

### 3.5 验证门槛（合并后必须全绿）
1. **前端零改动**：
   ```bash
   git diff --name-only workbench-v1.5.3..HEAD | grep -E 'frontend/src/(workbench|lineage)|frontend/package.json' && echo "VIOLATION" || echo "OK: no frontend touched"
   ```
2. **后端全测**：`./.venv/bin/python -m pytest -q`（含 1.5.3.1 新测 + v1.5.x 既有测；optional extra 缺失时应 `importorskip` 跳过，不报错）。
3. **前端回归**：`cd frontend && npx vitest run` 仍应 549（前端没动，必须不变）。
4. **CLI smoke（用修正后的命令，不要用 console script）**：
   ```bash
   env PYTHONPATH=backend .venv/bin/python -m workbench.cli create /tmp workbench-v1531-smoke
   env PYTHONPATH=backend .venv/bin/python -m workbench.cli run /tmp/workbench-v1531-smoke \
     examples/datasets/cross_section.csv wage --x education
   ```

5. **行为门槛**：
   - 默认 `auto` 仍只走 OLS/Logit/Poisson（显式模型不得 silent fallback 到 OLS）。
   - optional 依赖缺失 → 结构化 issue（`OPTIONAL_DEPENDENCY_MISSING` 等），不得泛化 traceback。
   - 无 `*.pkl/*.pickle` 隐藏产物，无 >20MB artifact：
     ```bash
     find /tmp/workbench-v1531-smoke/runs -name '*.pkl' -o -name '*.pickle'
     find /tmp/workbench-v1531-smoke/runs -type f -size +20M
     ```

## 4. 三大风险（按优先级）

1. **orchestrator 是工作流总线**：显式模型路由、MICE、prediction、structured failure、血缘记录全在 `_run_workflow` 汇合。合并后最该重点测的就是它 —— 既要新模型能跑，又要 v1.5.x 的血缘图节点不丢。
2. **CLI 与 docs 漂移**：Task 12 已暴露 smoke 文档命令与真实 CLI 不符。对接后**必跑真实命令**，不能只信文档。注意 v1.5.x 的 cli.py 与 1.5.3.1 的 `--model-type` 合并后，参数顺序/名称要实测（spec 用 `--y/--x`，但本仓库实际 CLI 是位置参数 `wage --x education` —— 以实跑为准）。
3. **optional deps 必须保持 lazy import**：`linearmodels / scikit-learn / imbalanced-learn` 不能因合并后某处 import 被提前执行而变成硬依赖。验证：在**不装** extra 的 venv 里跑全测，应靠 `importorskip` 跳过而非 ImportError。
