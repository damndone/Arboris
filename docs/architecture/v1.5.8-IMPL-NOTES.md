# v1.5.8 SA estimator — VALIDATED implementation recipe (controller notes)

> Working notes carried between tasks. The plan's Task 3 pseudocode (entity-demean
> only + `scipy.linalg.qr(pivoting=True)`) is **WRONG** — it keeps all 18 candidate
> cells with the wrong basis and does NOT match `fixest::sunab`. The recipe below was
> derived empirically against the committed oracle (Task 1) and reproduces fixest

> ALL THREE fixtures (balanced/unbalanced/collinear). Use THIS, oracle is authoritative.

## Key finding: what sunab actually estimates
`feols(y ~ sunab(cohort, year) | id + year)` == plain saturated
`feols(y ~ i(rel, cohort, ref=-1) | id + year)` fit on **treated-only rows**
(never-treated cohort = NaN rows excluded from the interaction design). Verified
identical kept-cell set AND coefficient values. The 6 "extra" candidate cells fixest
drops are **genuine EXACT collinearities** (6 exact-zero singular values after two-way
absorption), arising because at all-treated calendar years (e.g. the last period where
every treated cohort has a post-period and no never-treated breaks it) the sum of
treated interactions spans the year FE. They are NOT a numerical-tolerance artifact.

## The recipe (reproduces fixest exactly)
1. **Treated-only rows.** Drop never-treated (non-finite cohort) rows from the design.
   They do NOT affect the interaction coefficients (FWL); they re-enter only as
   zero-IF rows in the bundle (counted in N_all, row_cohort sentinel 0.0).
2. **Two-way FE absorption** via alternating id/year demeaning to convergence
   (max|Δ| < 1e-13; ~a few thousand iters worst case). Demean y and every interaction
   column. (Entity-demean-only + year dummies does NOT reproduce fixest's collinearity
   detection — must absorb BOTH.)
3. **Interaction columns in fixest natural order = period-primary**: iterate `e`
   ascending (excluding e=-1), then `g` ascending; keep a column only if it has ≥1
   observation. (Matches fixest coef-name order `year::E:cohort::G`.)
4. **Sequential collinearity removal** (modified Gram-Schmidt, NATURAL order, NO
   pivoting): maintain orthonormal basis Q of kept columns; for column j drop it iff
   `(||v_orth|| / ||v_0||)^2 <= 1e-10` (fixest `collin.tol` default). This drops the
   same 6 (balanced/unbalanced) / matching set (collinear) fixest drops.
5. **Solve** `lstsq(Dkept, y_demeaned)` on the kept columns → CATT(g,e).
6. **Influence function** (Task 4 命门): per treated entity i,
   `phi_i = N_all * (Dk'Dk)^+ @ (sum_t Dk_it * eps_it)`  where eps = within residuals.
   Place into an `(N_all, K)` matrix in `np.unique(entity_all)` order with
   **never-treated rows = 0**. Scale factor is `N_all` (total entities incl never-tr).
7. **vcov reconstruction check**: entity-clustered `_se(phi[:,k], row_cluster, N_all)`
   from `cs_aggregate._se` gives `sqrt(sum phi^2)/N_all`; its square == fixest bare
   cluster vcov diagonal. Never-treated rows contribute 0, so N_all vs N_treated in the
   scale is consistent as long as the SAME N multiplies phi and divides in _se.

## Scaling convention (read from cs_attgt / cs_aggregate, do NOT reinvent)
- `EffectEstimateBundle.influence_func` = (N,K) ENTITY rows, RAW influence (O(1)/entity,
  NOT /N), mean-zero columns (OLS normal equations make column sums exactly 0).
- `cs_aggregate._se(col,row_cluster,N) = sqrt(sum_c S_c^2)/N`, S_c = cluster-sum.
  Unclustered (entity==cluster): `_se = sqrt(sum_i col_i^2)/N`. honest adapter Σ=(S'S)/N².
- So SA's N-scaled `phi` makes `_se^2` and honest Σ reproduce the BARE sandwich (locked
  `ssc(adj=FALSE,cluster.adj=FALSE)`), matching the oracle. This is the §2.3 hard test.

## v1.5.8 fixture-hardening (folded in, 2026-06-22): no-never-treated guard
**Finding.** Hardening the SA estimator surfaced a correctness divergence in the
**no-never-treated** path (every entity eventually treated; spec §3 "last-treated as
reference cohort"). It was NEVER validated against the fixest::sunab oracle — all three
v1.5.8 fixtures (balanced/unbalanced/collinear) carry a never-treated group, so the
`has_never is False` branch was exercised only by a self-consistency unit test with no
oracle. On a no-never panel the engine:
  1. EXCLUDES the last cohort wholesale (textbook Sun-Abraham control choice); fixest
     does NOT — `sunab` keeps all cohorts and relies on its own collinearity removal.
     → cell sets differ structurally (engine {3,4} vs fixest {3,4,5}); shared cells
     disagree (e.g. (3,1): fixest 0.376 vs engine 1.321 — engine is closer to the
     DGP truth 1.3 because fixest's no-never estimates are contaminated by already-
     treated cohorts serving as controls, the very reason SA recommends dropping the
     last cohort).
  2. KEEPS unidentified high-event-time cells ((3,2)(3,3)(3,4) ...) — the Gram-Schmidt
     collinearity drop does NOT fire on the exclude-last-cohort construction → SILENTLY
     emits garbage CATTs (~0.95 vs true 1.8/2.3/2.8). Worst failure mode for the tool.

**Root cause.** Spec/oracle mismatch born in v1.5.8: the spec chose an identification
scheme (exclude-last-cohort) that the chosen validation oracle (fixest::sunab) does not
implement, so there was no oracle for the no-never path; the test matrix had no no-never
oracle fixture; and the GS collinearity guard (which would at least have dropped the
non-identified late cells) is bypassed by that construction. Pure v1.5.8 issue — the
files (`sa_spec.py`, `sa_attgt.py`) were born this version.

**Fix (this fold-in).** Fail loud: `validate_sa_input` raises `SA_NO_NEVER_TREATED` when
no non-finite (never-treated) cohort exists → structured MODEL_FIT_FAILED end-to-end. The
`select_reference_cohort` last-cohort branch is kept as DORMANT scaffolding for a future,
properly-validated no-never path. Also added an EXPLICIT test that the genuine-collinearity
GS drop matches fixest's `$collin.var` on panel_balanced (was only implicitly covered by
the kept-cell set equality).

**Future (worth doing later, NOT urgent — lower priority than v1.5.9 dCDH).** A proper
no-never implementation = keep exclude-last-cohort + ALSO run genuine collinearity removal
so unidentified late cells are dropped. CANNOT be validated against fixest::sunab (it does
not exclude the last cohort) → needs a different oracle strategy (did2s / hand-derived
identified-design / simulation vs known DGP). Research-grade → its own version. No-never
(fully staggered) panels are common, so it is worth doing eventually.
