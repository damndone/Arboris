V1.5.2: extension-first direction

The goal is not to ship every prototype feature at once, but to land the backbone that lets complex models, editable operations, AI audit, and richer views plug in later without rewiring the app.

A

Workbench Spine

Build the durable shell: Graph/Table/Pipeline route slots, search command model, bottom panel framework, top-right action slots, node context menu, selection/path highlighting, and node-level AI/edit placeholders.

Best foundation. Mostly frontend contracts and state boundaries; avoids premature backend commitments.

B

Editable Rerun MVP

Make clean/transform/model nodes actually editable: structured op controls, code editor window, dirty state, discard/commit-and-rerun, downstream highlighting, and run event timeline.

Most user-visible. Requires stronger backend contracts for partial rerun and audit snapshots.

C

Platform Leap

Introduce Pipeline as a first-class entity, model registry, node execution records, artifact references, LLM audit records, and report-generation endpoints.

Most future-proof long term. Too large for a narrow V1.5.2 unless split into a design-only milestone.

Recommended sequence

A in V1.5.2, then B in V1.5.3, then model registry / Table / Pipeline depth in V1.6+. C should become the V2.0 platform spec, not a single sprint.
