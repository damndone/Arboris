? 剩余 3 个技术点

1. Pipeline 模式 vs 交互模式

我建议：pipeline 仍端到端跑（不变），跑完后用户可以从图谱任意节点分叉/回滚/再跑。AI（V1.6+）以"节点旁建议"形式出现，不打断 pipeline。
→ 替代方案是用户驱动每一步，但那是大改，且你的需求看起来不需要。

2. AI 介入的"挂载点"形态

基于你"AI 只做客观判断和数学，主观判断/解释才介入"的原则，V1.4 数据模型为这两类挂载点留位置：
• 节点注释（read-only，AI 评论某个变量/阶段）
• 建议分叉（AI 提议"从此处试 X"，以"幽灵"分支预览，用户决定是否物化）
→ 不做：AI 自主修改图谱、自主跑分析。

3. 现有代码的改造范围

V1.4 必然要动的：
• orchestrator.py 改造为往图谱写节点（向后兼容）
• 新增 graph_model.py、graph_store.py
• 新增 /runs/{id}/graph 系列 API
• 前端新增 Lineage Tab
顺手做但不强制：拆分 diagnostic_preview.py（你之前提的脆弱点之一）。
