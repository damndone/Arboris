## Future guidance

- A Graph-first recommendation plan must specify both existing-run and pre-run Draft materialization, exact provenance pins, and bounded evidence before implementation starts.
- A cross-language contract lock must test legacy defaults and each rejection rule on both sides; green language-local fixtures are not proof of wire parity.
- A generic typed envelope must be checked again against the target Draft editable schema before any materialization write.
- A graph-first Notebook acceptance must prove both the visible story and the absence of an unapproved Run; deterministic provider fixtures are appropriate for local UI QA when external provider output is not contract-clean.
- A materialized lifecycle state must be written only after the matching Draft and provenance record exist, and low-level append APIs must validate their immutable foreign keys rather than trusting callers.
- A persisted trace identity also needs serialized sequence allocation; shared single-worker write coordination must cover replay, numbering, and append as one operation.
- A provenance-dependent lifecycle state must validate the immutable provenance record at the state transition, and tests must reject the direct state path.
- A versioned successor contract must preserve legacy public constructors and use an explicit parser or successor type until every write path is migrated atomically.
- Assert the locked public wire value from the contract module rather than re-deriving a symbolic display string in a route test.
- At a contract boundary, validate the raw container before conversion and validate the outer object before any field lookup; conversion-first parsing can manufacture valid-looking data from invalid wire values.
- Before starting a version, grep docs/superpowers/specs for accepted ADRs and start each devline from a frozen Context Pack; the discipline surfaces binding constraints the memory index does not.
- Browser-check the serialized boundary, not only the typed in-process context; every execution-gating fingerprint required by the UI contract must be present in the HTTP packet.
- Claim identity creation before triggering state or URL updates so asynchronous route initialization cannot duplicate the RunFamily.
- Contract language must name the strongest fact actually verified at its layer; record linkage is not Draft existence.
- Default identity invariants must be tested across independent service instances and validate the persisted key formula, not merely a nonempty key on one instance.
- Evaluate terminal lifecycle actions before freshness so executed, rejected, and archived options remain closed even when their historical context is stale.
- Every packet from_dict must reject unknown fields symmetrically; a permissive parser turns a field vanishing on round-trip into an invisible defect.
- Every persisted Notebook lifecycle transition must be returned by the public projection and hydrated by the route; local UI state cannot be the only record of a Draft handoff.
- Every read projection must fold both immutable revision data and lifecycle/execution state; serializing the revision alone is not a current-state snapshot.
- Every runtime-required typed field must be required in the provider-facing schema, and every rejection must identify the exact missing or unknown field; compatibility must be a named branch rather than a global additionalProperties escape.
- Every transition into materialized must validate the corresponding immutable record; callers must not be trusted to have created it first.
- For source identity, lock the entire resolve-or-create decision before any migration write, and make lock registries and concurrency tests explicitly bounded.
- Graph-bound Notebook routing must recover an existing single projection on reload; ambiguity across multiple projections must remain explicit rather than silently choosing a family.
- HTTP planner fixtures must preserve the same batch-level decision binding fields as the real typed provider result; route tests should exercise the public contract, not a simplified pre-contract Option shape.
- Hand-authored numeric fixtures must be checked for internal arithmetic identity between AIC, BIC, log-likelihood and the parameter count before they become a shared lock.
- Importability is not implementation evidence when a public seam is intentionally fail-closed; domain exceptions carrying HTTP status must also survive thin route adapters without generic remapping.
- Keep component-level action evidence separate from browser-level native selection evidence; do not promote a test-only result to manual browser acceptance.
- Keep result-contract metadata separate from model-input options; a fail-closed pack must not accept fields that only belong to the output packet.
- Lifecycle tables must be tested for forbidden edges as well as intended happy paths, especially where an intermediate provenance record is mandatory.
- Mark asynchronous route initialization as claimed before triggering state or URL updates; identity creation must be idempotent under React effect rerenders.
- Materialization fixtures must be built through the same GraphStore and forest-key conventions as the source-bound write validator; hand-written graph JSON is not an acceptable substitute for a valid lineage graph.
- Notebook navigation state must be durable and request retries must be idempotent at the public operation boundary; materializers must validate against the published capability vocabulary without rejecting fields that the typed proposal contract legitimately carries.
- On a runner or session interruption, commit the interrupted lane's work in progress immediately so no work is lost and the lane can resume from a clean commit rather than restart.
- Prompt and JSON Schema alone do not make a provider typed; the server must project operation and artifact contracts, validate them before persistence, and offer bounded correction without silently repairing model payloads.
- Provider prompts can improve compliance, but semantic source and evidence pins remain server-owned and must fail closed when the model omits them.
- Read projections must fold append-only lifecycle state over immutable revisions before crossing the HTTP boundary.
- Recover a unique durable Notebook projection before deriving a new projection from the currently focused Run; view URL parameters are navigation hints, not the source of Notebook identity.
- Run formal development-control commands with the active worktree package explicitly selected, and verify the imported module path before trusting process evidence.
- Serialize every execution-gating fingerprint at the HTTP boundary and verify the browser-facing packet, not only the in-process object.
- Shared domain constructors may centralize validation, but existing HTTP adapters must preserve their documented status and detail classification at the boundary.
- Stable option identity must make identical proposal retries idempotent; never append a duplicate revision number.
- Task 9 acceptance must record both the visible graph-first story and the service-level stale rejection code.
- Time-box delegated work to one observation window; if no concrete diff, test result, or blocker arrives, close it and reclaim the task rather than extending waits.
- Treat a silent implementation worker as a process failure: preserve its patch, stop it after bounded retries, and take over only with explicit verification and ownership boundaries.
- Treat recommendation rank as a validated evidence outcome, not as list order; preserve structured proposals without materializing unselected Graph branches.
- Treat selected text as an ephemeral UI anchor carrying a typed source ref; action handlers may prepare or route a question but must not bypass proposal validation or confirmation.
- Use one bounded review window after a validated slice; reclaim the path when no concrete findings arrive instead of extending waits.
- When a contract adds a semantic field, wire it through input validation, sample audit, result construction, and result identity before claiming the contract is implemented.
