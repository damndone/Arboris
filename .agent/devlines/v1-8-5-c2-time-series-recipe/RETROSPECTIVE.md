## Goal

# v1.8.5 C2 — Time-Series Recipe Objective  This is the bounded FMS objective for C2 of \`2026-07-31-v1.8.5-typed-memory-and-model-family-design.md\`. The parent design remains the only version-scope authority.  ## Objective  Admit the existing ETS and ARMA/GARCH capabilities to Notebook and Agent genesis through a server-owned \`RecipeContract\`. A Recipe has time/value input semantics and its own published model-options vocabulary; it is not a regression branch with empty predictors.  ## Scope  - Define \`time_series.ets\` and \`time_series.arma_garch\` RecipeContracts with   input-column validation, published option fields, expected artifacts and   bounded Agent/Table/Report result projections. - Compile a selected Recipe only into an independent dataset \`model.genesis\`   Draft. The server validates \`time_column\` and \`value_column\` against the   current dataset, validates \`model_options\` through the existing owner   contract, and preserves server-owned binding facts. - Genesis Draft validation derives the absence of regression predictors from   the RecipeContract. It does not retain an ARMA/GARCH model-name exception,   and it never treats a Recipe as an \`operation.multi_step\` regression branch. - Add TDD coverage for accepted ETS/ARMA-GARCH paths and refusal paths:   missing time/value columns, invalid or unconfirmed ARMA/GARCH transforms,   missing predictors being accepted only for recipes, and legacy regression   genesis still requiring the fields its ModelFamilyContract declares.  ## Explicit non-scope  - No estimator, diagnostics, numerical-method, model-options-contract, pack,   capability-registration, custom-capability, memory-default, or frontend   redesign. - No time-series multi-step workflow, model-family alias, automatic frequency   inference, visual conclusion without an evidence packet, or change to   historical manual Runs.  ## Acceptance  Tests must first fail, then pass for both RecipeContracts and their Notebook materialization. Existing ETS and ARMA/GARCH known-truth tests must remain green. A later browser acceptance run must demonstrate Dataset → Notebook option → Draft → confirmation → execution → Result/Table/Report for both recipes, while unsupported or incomplete inputs fail closed before a Draft is persisted.

## Future guidance

- A Recipe contract error must give the next model turn the exact server-owned required input fields, not only a generic retry instruction.
- A policy test should assert both planner and adapter timeout views against the one server-owned constant, never against repeated numeric literals.
- A public Recipe vocabulary must omit server-owned fields, and the genesis materializer must add immutable source values before applying the owner contract.
- A remount may restore display state, but it must not autonomously issue a billable planning request; only an explicit current user action may start a new attempt.
- A server-owned Recipe field must be injected consistently at every validation seam, then passed to the frozen owner contract; publishing it as an Agent input is neither necessary nor safe.
- A successful minimal provider stream establishes configuration and connectivity only; preserve the Notebook tool-planning incident until a comparable request completes and creates an option batch.
- Admit a time-series capability only through a RecipeContract that owns its input columns, artifacts, and result projection.
- After a real provider error, inspect the bounded local trace and configuration metadata before retrying; do not relabel it as a product acceptance failure or repeatedly spend calls without evidence.
- Dataset-rooted RecipeContracts remain model.genesis regardless of a visible active result head; only run-rooted proposals require rerun pins.
- Distinguish the provider per-call timeout from the Notebook total planning deadline before changing either policy or interpreting a browser timeout.
- Every newly frozen test path must either exist before a gate runs or be created as the next TDD step.
- Every user-visible Agent initiation needs one terminal success, failure, or cancellation record in the project activity timeline and, when it has a Notebook trace, a typed terminal trace event.
- Every visible Agent initiation must have a bounded terminal activity outcome, irrespective of whether its provider call succeeds, fails, or is cancelled.
- For a backend behavior change, restart the backend before treating a browser result as acceptance evidence; refreshing Vite alone is insufficient.
- Immutable node identity and human-facing presentation have different merge rules: preserve the result identity, but project the newest label and summary deterministically.

- Lineage labels and summaries must read the authoritative typed result payload, not assume all model families use the legacy outer result shape.
- Publish Recipe choices from the owning model contract rather than a parallel list of field names.
- Record a live-provider timeout as unavailable acceptance evidence; do not fabricate an option, Draft, or execution receipt to close the gap.
- Represent no aggregate Notebook deadline explicitly; do not reinterpret it as a hidden multiple of the per-call timeout.
- Server-side option and recommendation validation must re-enter the same bounded correction policy as a typed provider submission instead of being relabeled as a route request error.
- Treat a browser planning timeout as provider evidence only after the frontend proxy and backend are verified to share local connectivity.
- Use a temporary repository-relative event file when appending formal FMS evidence.
- Use normalized hyphenated identifiers for formal FMS lesson keys before appending an event.
- Use the documented formal CLI surface and inspect the frozen Context Pack and event stream when no status subcommand exists.
