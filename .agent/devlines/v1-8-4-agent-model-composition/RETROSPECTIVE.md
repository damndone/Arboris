# Retrospective — v1-8-4-agent-model-composition

## Goal

v1.8.4 Agent Model Composition  Objective  Expose the existing server-validated OLS term vocabulary through the Notebook Agent lifecycle, so a user can request a model with declared categorical terms and declared polynomial terms, review the typed workflow, confirm it, and receive the completed results as bounded evidence.  Add only two server-defined post-estimation result operations required to interpret such models generically: a joint test over a declared model-term group and the stationary point of a declared quadratic term.  Both must be derived from the completed model branch, carry artifact provenance, validate their semantic preconditions, and reject unsupported requests.  Non-goals  No arbitrary formulas, code execution, raw-data browsing, automatic execution, dataset- or exercise-specific column names, or implicit changes to an existing model.  Every workflow remains typed, server-validated, and subject to the existing Proposal/Risk confirmation lifecycle.  Acceptance  Focused tests prove that the Notebook planner accepts only a source-pinned operation.multi_step proposal, the published workflow vocabulary permits categorical and polynomial declarations, invalid selectors fail closed, and the two post-estimation results are reproducible from a completed branch with durable artifact references.  A Workbench UI acceptance run must show Agent recommendation -> user confirmation -> completed workflow -> evidence-backed answer without a backend code-upload path.

## Future guidance

- A branch-level inference setting must travel unchanged through runtime context, Draft model parameters, and persisted model evidence; labels cannot be treated as execution proof.
- A durable checkpoint must separate repository inconsistencies from host containment availability before it is committed.
- A durable user-confirmation proposal is a valid terminal outcome and must not require another model completion turn.
- A global evidence protocol must forbid turning covariance-output differences or schema cardinality into diagnostic or longitudinal claims and require conditional wording when the user supplies a design premise.
- A model capability is not Agent-available merely because the manual form can run it. Every model family must have an explicit workflow semantic contract, matching runtime materialization, result evidence, and per-step artifact admission.
- A numerical-answer protocol must require mechanical copying and an internal consistency check over returned estimate, standard error, p value, and interval fields; prose is not an independent numerical source.
- A planner must consume the exact server-published rerun pins or choose genesis when lineage does not admit a rerun; it must not leave a user at a contract error after an otherwise usable request.
- A progress display that carries a budget must be anchored to the attempt, not to the component; adding a denominator to a mount-anchored counter degrades it.
- A progress figure shown next to an authoritative bound must itself be authoritative; anchoring it to component lifetime makes it reset exactly when a reader most needs it.
- A robust-versus-nonrobust comparison supports reporting changed standard errors, intervals, and significance labels. It does not by itself identify a false result or establish the mechanism behind one coefficient's change.
- A single \`apply_ols_covariance\` helper now applies the declared estimator on refit, and the branch spec persists the covariance it was fitted under; the estimator is validated fail-closed instead of defaulting.
- A test that submits a real run shares the process-wide event manager, so it must claim a clean slot explicitly; diagnose a full-suite-only failure from the recorded step error before assuming the change under test is at fault.
- A visible notebook identifier is not sufficient evidence that its persisted planning lifecycle can still be loaded.
- All 22 were fixed at source. Structural guards were kept as guards: each exemption is paired with a new real assertion rather than merely widened.
- An event's timestamp must be the moment it is recorded; a closing event that predates the incident it closes is invisible to any timestamp-ordered reader.
- Before expanding a frozen allowlist, check the formal validator's minimum backend path depth and prefer an already-mounted narrow router plus a leaf service module.
- Bind prose claims through exact structured evidence references and hashes; do not make user-visible natural language carry internal parser tokens.
- Both indicator and polynomial construction now reuse a persisted column after proving it is value-identical (including the missing-value mask) to the requested term, and still refuse a merely similarly named one.
- Bounded context must project server-owned numerical results and figure evidence by explicit artifact identity, not rely on metadata-only discovery.
- Bounded evidence tools and their protocol must provide one explicit low-step path from visible candidate runs to a completed workflow receipt, branch evidence, and a direct answer.
- Browser acceptance needs a fixture that clears generic input guardrails, and blocked runs must remain visibly distinct from historical lineage records.
- Closed with the same repair; both tests pass.
- Distinguish a browser-controller policy denial from a Workbench product failure and do not bypass the UI acceptance boundary with HTTP or another browser.
- Do not render a zero-run empty state until persisted Draft hydration has settled.
- Enforce user-selected interaction limits at every public lifecycle ingress, not solely in the model-facing planner.
- Establish whether a red suite is inherited before attributing it, by re-running the same selection with only the current line's changes withdrawn; and treat a checkpoint that ships a red full suite as an open debt rather than a baseline.
- Event text must avoid words that can look like a credential field followed by a value, even in ordinary product prose.
- Every durable public evidence projection needed by a project-level answer requires an explicit, bounded Global Agent reader; node-scoped availability alone is not an Agent integration boundary.
- Execution pins must carry the server-resolved registry artifact identity, while presentation lineage may separately retain a CAS reference.
- Expose common post-estimation diagnostics as declared typed steps only when their result can be reproduced from an immutable completed model design.
- Fixed as part of the full-suite repair; the frontend suite is green with no assertions dropped.
- For any typed workflow field with a non-obvious JSON shape, publish both the exact shape and a corrective response that mechanically distinguishes omission from an empty or malformed value.
- For typed workflow envelopes, publish omission semantics, exact JSON shape, and a concrete valid example in both initial instructions and corrective feedback.
- Formal evidence records must use a real digest of their cited artifact rather than a placeholder, even when the browser result is also observed directly.
- Keep draft visibility independent from URL tab restoration so a newly created project can render its genesis draft.
- Keep provider catalog behavior and its test expectation synchronized, and do not repair unrelated catalog policy during a streaming-runtime change.
- Keep unrelated dirty-route failures separate from the scoped result-view evidence rather than changing another feature during a focused fix.
- Model diagnostic artifacts and their bounded Agent evidence must be published as one generic capability. A planner must describe automatic artifacts instead of requiring an invented plotting step, and an Agent must receive only aggregate bins rather than row-level chart inputs.
- Name equality is insufficient for model-term reuse. A persisted indicator may be reused only after an exact finite value comparison against the server-derived contrast; otherwise the workflow must fail closed.
- Notebook identity selection and interaction-mode vocabulary need end-to-end browser acceptance, not only unit-level mode controls.
- Notebook receipts require a separate bounded evidence bridge; Agent operation records are not a substitute for committed workflow lineage.
- Only reads that return completed or partial evidence become idempotent; failed reads remain retryable while their trace stays auditable.
- Overlay acceptance must check ancestor clipping in addition to sibling collision geometry.
- Post-estimation statistics must own one explicit, scale-stable auxiliary-design rank policy and turn non-identifiable designs into descriptive typed failures; never propagate a library assertion into workflow state.
- Project model specification and inference metadata through the same bounded evidence reader as coefficients, and explicitly prohibit diagnostic or causal claims that a covariance comparison alone cannot establish.
- Provider and total planning deadlines must be explicit, bounded, and reflected by the user-visible planner state; cancellation alone is not a substitute for a defined terminal timeout.
- Provider-facing evidence and capability contracts must publish exact positive and negative affordances, while server recommendation admission must bind only the completed evidence records actually supporting the candidate cohort.
- Publish every server-enforced bounded tool limit in the model-facing protocol and protect it with a route test.
- Ranking vocabulary is only honest where the agent actually ranked; a single-Draft surface must say what the Draft is, not where it placed.
- Requested post-estimation quantities must be explicit workflow steps with direct model dependencies; narrative report sections never execute a calculation.
- Result-view interaction surfaces need explicit overflow, dismissal, and shell ownership contracts instead of positioning controls inside the content plane.
- Reuse only canonical no-argument inspections whose source is exactly the current server-pinned run; retain fail-closed behavior for changed arguments or targets.
- Review adjacent cardinality and loading states, not only the primary multi-run interaction.
- Run frontend verification from frontend/ and keep backend and frontend commands separate.
- Supply formal event input through an allowed repository-relative staging file, then restore that staging file before ordinary source verification.
- The attempt start instant now lives with the request and is passed down, so the counter survives a remount; covered by a deterministic unmount/remount test.
- The auxiliary regression now drops collinear cross terms before fitting, so the declared test completes on the same branches that previously failed it.
- The planner now answers that rejection with the exact rerun preconditions when an eligible target exists, and directs to \`model.genesis\` when none does.
- The route now enforces and publishes a 180s planning deadline, and the surface renders elapsed against that budget and marks the pass overdue once it is exceeded.
- The stale route-level expectation was rewritten to the implemented contract and split, so the env-to-local materialization claim is still asserted separately rather than deleted.
- Treat an upstream provider error and a tool-protocol error as separate fail-closed boundaries; do not retry with more prompt variants during acceptance testing.
- Use the control event enumerations independently for cause, preventability, and resolution instead of assuming similarly named values are shared.
- User-visible terminal state must be derived from both the stop reason and durable proposal lifecycle.
- Validate FMS event enums against the control schema before attempting to append a gate result.
- Verify a reported gap against current source before repairing it; an append-only event stream keeps showing the original open record after the behaviour has been fixed elsewhere.
- When a returned fit and a returned summary can disagree, a consumer that needs the fit will silently inherit the wrong covariance; give the estimator one application site and assert the inference differs on a deliberately heteroskedastic design, since asserting only the label would have passed against the bug.
- When a terminal workflow boundary becomes explicit, tests must assert both its user-visible status and the intentionally removed provider round-trip.
- When validated execution determines registered output identities, derive the persisted artifact contract server-side instead of making a provider guess it.
