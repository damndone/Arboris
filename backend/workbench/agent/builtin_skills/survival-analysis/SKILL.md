# Survival analysis

Use for a complete survival question, not an isolated coefficient lookup. Preserve the question, time origin, event code, censoring rule, independent unit, sample and target interpretation in the visible plan before estimation. State which changes are pre-fixed and which follow result inspection; never choose the event definition to improve significance.

## Analysis and evidence

1. Inspect the registered data and dictionary. Distinguish follow-up time, calendar time and event status; check invalid durations and event coding. Do not turn censoring into an event. Delayed entry currently lacks a calibrated completion profile and stays partial.
2. Fit a supported native Cox model through the common operation/proposal/approval path. The seed OLS model does not answer this question. Read the actual model reference, coefficient scale, usable uncertainty, ties handling, convergence, independent unit and analysis sample from persisted products.
3. Inspect the model-bound native PH evidence. Its fixed log-time interaction score definition and ties convention matter; it is not interchangeable with an unspecified Schoenfeld test. A rejected PH check requires an explicit applicable model/design revision; non-rejection is not proof of PH. A diagnostic file existing is not a successful diagnostic.
4. Compare a justified, pre-fixed alternative control set, tie convention or defensible analysis sample, with actual fitted products and source/sample identities. Do not repeatedly search transformations until a test passes. Changing a label or uncertainty display alone is not point-estimation sensitivity.
5. Report the estimand, risk/hazard interpretation, censoring limits, actual PH finding and sensitivity result. Every number must refer to the right source/model/term. Missing event, source, native diagnostic or sensitivity evidence remains partial.
